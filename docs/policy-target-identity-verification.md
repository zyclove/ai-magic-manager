# 策略预览：应用身份必须属于目标设备

更新：2026-10-16。

## 本阶段修正

应用目录描述包名、平台、目标用户空间和允许的签名。它不能证明应用已经安装在某台设备，更不能证明同一设备重新注册之后仍然符合这些声明。

现有规则编译入口只有共享的目录和设备能力，没有逐设备的应用核验事实。本阶段移除该入口对目录 `INSTALLED_VERIFIED` 状态的采信：带应用标识的规则即使能力标记可用，仍返回 `UNVERIFIED / APPLICATION_IDENTITY_NOT_VERIFIED`。管理员预览不会因其他设备或旧注册的目录声明而看到“等待执行”。

该修正保留以下行为：

- 不关联应用的网站规则可以继续显示能力支持、等待执行；这仍不表示已生效。
- 系统运行时权限的自动授予继续返回 `UNSUPPORTED / AUTO_GRANT_NOT_AVAILABLE`。
- 已撤销设备继续显示 `UNAVAILABLE / DEVICE_NOT_ACTIVE`。
- 原有平台、用户空间和能力限制继续适用；本轮没有新增客户端权限、执行指令或数据库迁移。

## 尚未完成的正向接入

这是一项预览判断修正，不能代替逐设备证据接入或真实系统执行。后续仍需实现[阶段 4 接入](managed-agent-binding-plan.md#阶段-4逐设备证据与执行接入)：

1. 合规提供方读取绑定到租户、设备、当前注册和提供方资源的应用事实，验证签名、用户空间及有效期。
2. 编译器接收经过核验的逐目标证据；已核验的 A 设备和未核验的 B 设备必须产生不同结果。
3. 发布前重新核对可撤销授权、绑定版本和证据有效期，随后经持久任务发送策略并核对精确版本回执。
4. 管理端显示逐设备的实际应用结果；只在具备真实能力证据时开放对应系统动作。

本阶段不开放 ENFORCE，不把目录状态修改或设备端自报升级为提供方证据。44 项通过只证明本次定向及策略流程范围；没有重新运行完整后端套件。真实 EMM、Android / TV 系统执行和完整平台回归仍须独立完成。此修改尚未部署到当前运行版本。
