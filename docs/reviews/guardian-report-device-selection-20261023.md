# 使用报表：设备选择流程优化

本阶段采用现有 Flutter Material 组件，修改一个界面文件；没有新增依赖或改变后端协议。代码已静态审阅，**尚未格式化、编译、测试或部署**。

## 操作与反馈

- 搜索框增加清除入口；清除后保留键盘焦点，方便重新查找。
- 增加“仅看已选”和当前筛选数量，批量选择后可集中复核；切换筛选不会丢弃已选设备。
- 保留明确选择与原数量上限；超过上限时提示缩小范围，不自动截断。
- 正文整体可滚动，设备列表有独立有限高度并按需构建；取消和确认位于对话框操作区。短窗口、大字和软键盘效果仍需实际验证。
- 设备标识使用共享缩写显示，短标识不会因截取固定长度而异常。

## 异常与退出

- 一旦观察到工作空间或权限失效，就锁定本次选择、清空选择并隐藏旧设备；恢复权限也不会复活旧选择。
- 失效后仍可关闭自己的对话框；覆盖在上面的其他窗口不会被取消操作关闭。
- 确认要求当前路由仍有效且位于最前，并再次核对设备存在、非空和数量上限。
- 单项添加和批量选择在动作执行时重新核对当前数量，防止快速连续操作使用旧按钮回调绕过上限。
- 关闭同步锁定；退出动画期间旧确认回调不能再完成一次选择。监听来源更新时迁移监听并保留失效状态。
- 对话框打开时复制设备注册、档案归属、平台和选择上限。之后观察到设备增减、归属/注册/平台变化、重复设备或上限变化时，清空旧选择并显示重新打开的提示；名称更新和顺序变化保留当前草稿。不会静默删减选择，也不会留下可点击却无反馈的确认操作。

独立审查与应用指纹见 [本阶段证据](../evidence/guardian-report-device-selection-20261023/application-receipt.json)。主文件保留原 LF，与独立审阅的候选逐字节一致。

复用输入检查是后续独立提交的补充，指纹与审阅见 [输入绑定记录](../evidence/guardian-report-device-selection-inputs-20261023/application-receipt.json)。它在重建、访问事件或动作执行时观察普通列表，不会自动监听没有通知的 List，也不能发现两次观察之间已经恢复的 A→B→A。

## 待恢复窗口后的验证

原有两项选择器用例和报表正常旅程全部保留。本轮没有改写测试，也没有执行以下检查：

1. 201 台不可直接全选、筛选后选择、恰好 200 台、已有选择与筛选结果合并。
2. 仅看已选、逐项取消、清空选择、清除搜索后焦点和结果数。
3. 初始无权限、选择中失权、权限恢复、监听迁移及未发通知时的旧回调；目标删除、注册/档案/平台变化、同列表原地修改、重复 ID、上限变化及名称/顺序更新。
4. 对话框被覆盖、返回、重复关闭、关闭后旧确认及旧批量/勾选回调的数量复核。
5. 小窗口、横屏、大字、键盘弹出及长名称，实际点击确认/取消并核对无溢出。
6. 新源码完整分析与浏览器回归；旧 r8 通过和 r9 失败均不能证明本阶段新界面通过。
