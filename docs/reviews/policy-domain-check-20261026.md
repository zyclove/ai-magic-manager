# 草稿域名规则检查

日期：2026-10-26。基于 `d535ac8` 后的本批增量；本阶段完善配置解释与操作流程，不更新运行服务。

## 行为与界面

- 含域名规则的策略详情新增按需展开的检查区，单个输入、单个检查动作；支持中文域名、首尾空白和大小写输入，规范化由后端统一处理。
- 后端只检查当前授权草稿的精确 `DOMAIN_ACCESS` 命中；拒绝优先，未命中返回 `NO_MATCH`，不隐式覆盖子域。规则编号按需查看，多个命中时说明拒绝优先。
- 检查绑定强 `If-Match` 与草稿版本；并发变化提示重开详情。输入变化清除旧结果，普通失败保留输入；旧响应、覆盖弹窗的旧动作、账号／空间／角色变化及父路由结束均不能继续暴露或派发旧上下文。
- 复用现有 Material、API 请求与详情作用域，没有引入依赖、数据库表、检查历史、DNS／HTTP 网站请求或设备执行。固定结果中的 `effectiveEffect=null` 与 `NOT_EVALUATED` 保持预测和执行的区别。

## 实现与核对

规则保存和检查共用 policy 内部 `DomainNames`，保留原有保存规则必须规范 ASCII 的限制。新的只读端点沿用 `PolicyService.get` 的当前成员与租户授权，返回 `no-store`；不要求写入幂等键或近期 MFA。

客户端按捕获的策略、版本和域名规则验证响应的固定八字段、匹配编号排序、预测结果及非执行状态；不会借用随后修改的草稿映射。IDN 转换由同一个后端规范器负责，客户端不另实现算法。正式契约见[应用、时间与策略](../policy-application-schedule-contract.md)。
