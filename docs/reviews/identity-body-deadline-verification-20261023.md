中断检查的 `callerExitedBeforeBodyRelease`、`interruptPreserved`、`writeFailedBeforeCleanup` 均为 true；只能证明本次自有 HTTP/1.1 交换的可观察收敛，不能外推所有网络条件或 JDK 版本。

## 后续实现必须解决的问题

1. 不能再把 `HttpRequest.timeout(5s)` 单独当作原实现已保证整次正文期限的依据。本次原同步 transport 已有行为反例；完整功能仍需修复。
2. 继续优先评估成熟官方 SDK 和其公开的超时、取消及传输接入能力，核对精确依赖版本和实际运行路径。读取正文的上限、整次期限、并发复用和生命周期应分别验收，不能以等待 Future 超时替代真实 I/O 结果。
3. 供应商结果不明确时仍保留原请求身份和恢复/核对流程，不能因本地超时自动创建新的发送或兑换操作。
4. 本次 4 MiB 正文用于刻画原始无界读取和观察连接行为，**不是未来实现必须接受的正文大小**。已有 64 KiB 业务检查也不能被描述为原传输层已做了有界读取。
5. 后续有界实现可以合法地提前拒绝超大正文。因此不能不加调整地把本覆盖层当作最终 SDK 验收：应分别覆盖限额内正文的整次期限、超限正文的提前拒绝，以及取消后的真实 I/O 收敛。原验证器及本次失败记录不得为此改写。
