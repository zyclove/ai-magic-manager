# 列表操作归属与设备窗口关闭

本阶段沿用现有 Flutter Material、StatefulWidget、Repository 和后端接口，修改四个界面文件，并同步一条既有回归用例的旧行为预期。

- 共用列表的搜索、清除、刷新、分页、新建、详情及重新验证绑定原资源；切换范围或替换处理器后，旧事件不操作新列表。写后必要刷新保留。
- 通知中心的批量已读、单条操作、翻页、筛选与重试绑定所属页面代次；失败的当前操作仍可用原通知编号重试，旧页不能改动新页操作上下文。
- 审计日志的重试绑定原筛选与分页代次，旧控件不打断新筛选；分页目标在构建时捕获，迟到详情与日期结果按归属检查。
- 设备管理只允许当前活动窗口关闭，先锁定再通知宿主；旧父窗口关闭不会弹出覆盖的子窗口。读取可关闭、写入不可关闭的规则保留。
- 原通知回归曾要求旧刷新打断当前读操作，现调整为当前读操作正常完成；保留原请求时序、两次写入及旧 owner 不得动作的断言，没有新增或跳过用例。

全部改动已由 Root 和交叉审阅者静态复核。尚未运行编译、测试或真实界面验证；当前服务未更新。原测试和历史通过结果不能证明本阶段行为正确。
