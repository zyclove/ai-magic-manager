# 列表搜索与儿童档案操作流程改进

本阶段基于 `e303580030192497a63492d1147156e465082706`，改动三个生产文件。未新增依赖、测试或历史兼容逻辑。

## 用户可见变化

- 列表可按统一中文标签搜索，例如设备状态“已注册”；原始名称、编号和状态值仍可搜索。多个关键词用空格分隔，支持跨字段组合查找。空搜索保留完整已加载列表，分页和清除搜索操作不变。此能力覆盖 JSON 原值和统一标签，不保证任意自定义组件或格式化日期文本均可搜索。
- 取消编辑儿童档案或取消归档确认，保留原详情。只有成功保存或归档才结束原详情，再由原列表读取最新记录；失败继续显示在原流程中。
- 儿童档案读取、编辑和归档绑定原账户、工作空间、角色、权限代次与窗口。旧窗口失效后拒绝后续旧操作并隐藏内容；存活子窗口仍可安全关闭。已发请求的完成只结束捕获的原详情，不关闭随后覆盖的其他窗口。
- 通用详情的失效提示统一使用“原窗口内容”，适用于档案、额度等不同记录。

原昵称/年龄段字段、请求内容、编辑请求标识和并发版本保持。归档仍需确认。未自动重新提交过期版本或把旧操作转到新工作空间。

## 检查结果与边界

搜索与儿童档案候选经过独立静态审阅，完整差异和前后文件指纹已核对。Root 最后显式保留详情 GET 后的 `context.mounted` 检查。没有运行本阶段源码的分析、测试或界面渲染，因此上述交互仍需真实验收。

本轮另外实际执行了四项无 SDK 的固定任务退出与清理检查：正常退出、失败退出、超时与嵌套子进程清理均满足各自预期，自有 Job 最终为空。这些结果只证明固定验证宿主的行为，不代表应用功能通过。

曾对旧基线 e303 启动一次限时离线分析任务。预检将受保护进程 PID172 记为名称未知，任务约18.5秒自然退出1，Flutter 实际调用为0；另一个只读进程工具显示其名称为 Secure System。完整源码、包映射、缓存与运行时的事后指纹检查完成，但应用分析未执行，结果为 NOT_ACCEPTED。独立结果回读正确拒绝，随后确认自有进程退出、SDK0并释放窗口。原始失败记录和静态准备时的历史状态均保留。

本阶段改动后，e303 的410文件快照及 r10 提案属于历史输入，不能据此证明新源码。下一轮须绑定本阶段提交，并改进受保护进程名称的可靠读取；未知进程门槛没有被跳过。完整181个前端回归入口仍待验证，80项浏览器用例仅是其中的子集。身份服务、后端集成、真实设备与提供方等整体验证也未由本阶段完成。
