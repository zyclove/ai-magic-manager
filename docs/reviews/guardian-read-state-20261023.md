# 求助与权限状态：减少误导，保护确认操作

本阶段继续使用现有 Flutter Material 组件，修改两个产品文件。

- 求助记录首次读取失败时显示“读取尚未完成”，只有成功读到空列表才显示“暂无记录”。重试与重新安全验证沿用现有入口。
- 刷新开始以后才出现的确认结果未定状态，不会被较早发出的读取解除。后续刷新只核对其开始时已捕获且未改变的操作代次。
- 同一条求助的旧确认框，在另一份确认已发送后不能再次发送；必要的成功后刷新保留。
- 权限观察明确区分未知、确认中、已关闭和已开启；真实读到应用清单后才显示空清单。功能构建开关仍默认关闭。

作者、Root 与独立审阅均完成静态检查。尚未运行编译、测试或真实界面验证；不代表所有原有确认竞态或权限操作均已解决。相关场景已列入[后续验证清单](../evidence/guardian-read-state-20261023/application-receipt.json)。当前服务尚未更新。

补丁、原问题报告的逐字副本与独立审阅记录保存在[证据目录](../evidence/guardian-read-state-20261023/manifest.json)。原问题报告及其他会话工作保持原样。
