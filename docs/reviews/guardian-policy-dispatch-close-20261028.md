# 策略请求派发后的关闭与列表核对

基线：`306d3bfe0fff7351090d0bc3fc692723da0417d7`。本阶段修复静态确认的信号丢失：编辑、模板复制或回滚已交付 HTTP 客户端，响应仍在等待时，原详情路由被独立移除，外层会先返回；子窗口之后才记录的核对结果无法传回原列表。

`ApiWriteDispatch` 仅保存带键写请求的交付事实。借用 API 保留祖先观察器、原作用域、待决写入及客户端；取得客户端并通过作用域和期限检查后，才在交付带键 POST／PUT／PATCH／DELETE 前标记。等待客户端准备、只读查询及带键读取不标记，后续失败不清除已发生的交付事实。它不记录正文，不证明物理网络派发或服务端执行，也不替代原操作结果查询。

策略详情与编辑、复制、回滚共用该事实，原详情独立关闭时仍能请求既有列表核对；账号、工作空间或原列表失效时仍返回无核对信号。未发起写入的普通取消和派发前关闭保留原列表。设备组的既有 API 委托同步转发新借用方法，保留原拒绝处理。
