# 短信与微信管理配置

平台工作台的「短信与微信」用于管理中国大陆消费者短信登录和微信移动应用登录配置。本轮继续补齐受控发布、实际身份实例确认与历史配置回退，详细流程见 [受控发布说明](family-identity-controlled-release.md)。家庭端继续使用原来的登录与「账号与安全」流程。

## 管理员操作

1. 从「平台管理 → 短信与微信」进入。无家庭或机构工作空间的平台管理员也能使用；家庭所有者、监护人或机构管理员身份本身不授予供应商配置权限。
2. 查看短信、微信两张状态卡和当前需要完成的一步。需要重新安全验证时，先完成平台多因素认证，再重新填写密钥。
3. 点击「配置短信与微信」，填写短信签名、模板编号和微信移动应用 AppID；需要替换密钥时才打开相应输入项。未提交的现有密钥保留；清除 STS token 必须明确选择。
4. 保存新配置版本。保存后只显示「已配置／未配置」，不回显密钥、掩码、密钥摘要或服务器秘密路径。页面提交、离开、转到后台、会话变化或重新认证时清除临时密钥。
5. 检查配置格式。格式齐全只表示可以继续准备，不等于短信已送达、微信已授权或身份服务已经生效。
6. 准备受控发布，得到可查询的准备记录。服务器只在固定受限目录写入加密包；浏览器不能下载明文秘密。
7. 在「发布与生效」卡核对目标并提交发布，等待绑定部署主机执行，再核对全部身份实例。只有后端确认实际加载的配置和身份扩展一致、入口开关均关闭，才显示「配置已加载，登录入口待验收」。需要回退时先选择服务器提供的历史确认版本并查看影响，随后重新部署和确认。
8. 按「准备环境 → 手机完成 → 核对结果」进入联调验收，自动使用当前确认版本及 APK/JAR 摘要建立十二项待办，并查看最近五次登记。配置变化或登记超过 24 小时后重新准备。真实收码和微信授权在独立受限成人试点、正式签名家长 App 的正常流程中完成，管理台不提供粘贴授权码、勾选通过或开售按钮。详见 [验收入口与收费门禁](family-identity-acceptance-gate.md)。

断网或没有收到保存结果时，页面保留的只有原操作编号和类型。先查询该操作，不自动重发密钥或短信；未找到记录也要重新核对当前配置，不能直接宣称原操作没有发生。多人同时修改使用基础版本检查，冲突后刷新再填写，不能覆盖他人的配置。

## 首次部署准备

供应商管理使用独立加密密钥环，不能复用报表、审计导出、签名或验证码密钥。运行 [`initialize_identity_provider_admin.ps1`](../scripts/initialize_identity_provider_admin.ps1) 创建全新受限目录；工具不会修改已有部署、身份域或服务。

```powershell
./scripts/initialize_identity_provider_admin.ps1 `
  -Directory .local/family-identity-admin `
  -EnvironmentId family-cn-pilot
```

新目录包含独立 `provider-keyring.json`、加密发布准备区和非秘密 `identity-admin.env`。将该环境片段与 [`compose.identity-admin.yaml`](../deploy/compose/compose.identity-admin.yaml) 一起审查后接入已验证的后端部署。只给后端只读加密密钥挂载和可写加密准备区，不挂 Docker socket，不提供远程命令或任意路径参数。Linux 按实际部署 UID/GID 设置所有权，Windows 核对受限 ACL 和容器实际读写；不要放宽密钥权限解决挂载问题。

新身份域模板包含五个独立平台角色。已有身份域必须先导出备份，再用 [`merge-identity-provider-admin-realm.ps1`](../deploy/keycloak/merge-identity-provider-admin-realm.ps1) 转换为新的私有输出文件、审查并按身份服务变更流程合并；工具仅精确升级已知旧映射，拒绝未经核对的扩权映射，不调用管理 API、不覆盖原导出、不导入运行中身份域、不自动给任何用户分配角色。

| 平台角色 | 授予的专用权限 |
| --- | --- |
| `identity-provider-viewer` | `identity-config:read` |
| `identity-provider-operator` | `identity-config:read`、`identity-config:manage` |
| `identity-provider-tester` | `identity-config:read`、`identity-config:test` |
| `identity-provider-publisher` | `identity-config:read`、`identity-config:test`、`identity-config:publish` |
| `identity-provider-rollback-operator` | `identity-config:read`、`identity-config:test`、`identity-config:rollback` |

角色可以按职责组合授给已经获准的平台管理员。家长客户端不获取这些 scope；所有配置读取、写入、检查、准备和恢复查询还要求服务端核验近期 MFA，手机号验证码不能替代管理员 MFA。

首个草稿会为本管理模块生成验证码 HMAC，后续版本沿用本模块已有值；不会自动读取旧身份部署的 HMAC 文件。首次将新版本合并到既有身份部署需要作为 HMAC 变更协调处理，核对未完成验证码、所有实例及恢复边界。旧密钥环需独立备份，并保留历史加密版本仍引用的密钥。

## API 与数据边界

API 前缀为 `/api/v1/platform/identity-providers`。全部响应 `no-store`，专用权限与近期 MFA 由服务端独立判定。

| 接口 | 作用 |
| --- | --- |
| `GET /status` | 当前配置版本、非秘密设置、凭据存在状态和准备条件 |
| `POST /versions` | 按客户端 UUID 和基础版本保存不可变加密草稿 |
| `GET /versions/{id}` | 查询原保存结果，不回传秘密 |
| `POST /versions/{id}/validations` | 离线配置格式检查 |
| `POST /versions/{id}/release-preparations` | 准备固定目录内的加密完整版本 |
| `GET /release-preparations/{id}` | 查询原准备结果 |
| `POST /acceptance-runs` | 创建固定配置、环境和产物版本的真实联调待办 |
| `GET /acceptance-runs/{id}` | 查询原联调记录及十二项待办 |
| `GET /acceptance-status` | 当前版本绑定、登记有效期、下一步和收费门禁 |
| `GET /acceptance-runs` | 同环境最近五次登记 |
| `GET /release-status` | 最近确认版本、当前活动操作与可回退历史目标 |
| `POST /release-operations`、`GET /release-operations/{id}` | 批准明确目标的发布／回退，以及查询原操作 |
| `POST /release-operations/{id}/runtime-checks`、`GET /runtime-checks/{id}` | 主动核对固定身份实例，以及恢复原核对结果 |
| `POST /release-operations/{id}/cancellations`、`GET /cancellations/{id}` | 取消尚未领取的操作，以及恢复原取消结果 |

配置、密文、原操作请求及独立平台审计使用专用表。秘密及原请求只以用途、环境、版本绑定的 JWE `dir/A256GCM` 落库，原操作重复核对在解密后进行，不进入通用幂等正文或日志。审计只有管理员引用、动作、配置版本、结果码和时间。任何旧记录、错误响应或人工输入都不能将验收改成通过，也不能打开销售。

项目沿用未发布 1.0 初始化基线，本轮新表只在全新隔离数据库验证；没有迁移或清空已有本机数据库。已有库不能通过清库、重建或修复校验值来绕过变更，接入前另行备份并制定向前迁移与恢复方案。

五个新表登记在现有数据存储目录中：配置版本属于共享平台配置，配置审计属于审计保留，其余版本头、发布准备和联调待办属于运行元数据。它们不保存儿童、设备、家庭标识或接收手机号，家庭档案清理不会删除整个平台的供应商配置。原有全表、全列保护继续生效；未知表或新增未登记字段仍阻断数据清理，不通过关闭保护取得测试通过。这是存储范围说明，不代表所有隐私或合规发布条件已经完成。

受控发布追加独立运行版本头、发布操作、实例核对与机器请求随机数四个运行元数据表，精确列清单同步登记，不改变上述清理保护或原有家庭数据范围。

配置草稿及加密准备仍为 `APPLY_REQUIRED`。受控执行器只重建已绑定的身份服务，后端主动核对实际实例；确认后为 `APPLIED_CLOSED`，表示配置已加载但消费者入口保持关闭。新操作进行中时，旧记录只是最近确认的历史，页面显示当前部署待核对。后端没有 Docker socket，浏览器不能提交命令或任意路径；回退也必须经过同样的实际确认。

真实验收入口建立和查询待办，不自动发送短信、不执行微信授权、不自动采集真实供应商证据；真实供应商十二项仍需独立通过。付款、设备能力、正式签名和收费准入继续使用各自门禁。
