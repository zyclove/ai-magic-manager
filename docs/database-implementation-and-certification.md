# 智能管家：MySQL / OceanBase 数据库实施与认证规格

> 版本：Draft 1.0；日期：2026-10-09。  
> 上位决定：[平台蓝图第 20～22 节](parental-control-platform-design.md)。  
> 本文定义实施/验收目标；已有 H2 行为测试不能作为 MySQL 或 OceanBase 生产认证。

## 1. 选型结论及复核边界

**首期默认 MySQL 8.4 LTS + InnoDB，业务方言沿 MySQL 主线；OceanBase MySQL 模式作为独立认证的区域/私有化 profile。** 此选择延续现有代码和 Flyway 体系，适合先把短事务、权限、策略、账本、账单与恢复闭环做完整。Spring Boot/Modulith 仍为主后端，不因更换数据库改用 Go。

MySQL 官方将 LTS 定位于稳定功能集合与较长支持周期；8.4 是项目选定基线，不代表永远不评估后续 LTS。部署锁定实际验证过的补丁、驱动与工具，不使用浮动镜像标签。[MySQL 发布模型](https://dev.mysql.com/doc/refman/8.4/en/mysql-releases.html)

OceanBase 的分布式架构提供另一种扩容和资源管理路径，但其 MySQL 兼容不等于 MySQL 8.4 全量等价。当前官方兼容对比主要描述 MySQL 5.7/8.0 的大部分功能与语法；本项目的 8.4 排序规则、锁、迁移、JSON、驱动与第三方组件需要逐项认证。[OceanBase 架构](https://oceanbase.github.io/oceanbase/architecture/)、[兼容对比](https://www.oceanbase.com/en/docs/common-oceanbase-database-standalone-1000000006076943)

### 1.1 三类选择

| 场景 | 推荐起点 | 切换/例外条件 |
|---|---|---|
| 首期 SaaS 与中小私有部署 | 托管或认证 HA 的 MySQL | 实测写入/恢复/成本连续不达标后复核 |
| 明确分布式容量/隔离需求的客户 | MySQL 与 OceanBase 同负载 PoC | OceanBase 版本、edition、许可、运维与所有硬门槛通过 |
| 客户已有强 OceanBase 团队与资源 | OceanBase 可作为该客户优先候选 | 必须通过应用和第三方组件认证，不沿用“已有集群”豁免 |

百万注册设备、Java/Go 并发性能或单表记录数，都不能单独决定数据库。优先比较关键事务正确性、P95/P99、长尾锁等待、恢复、升级和总拥有成本。

## 2. 数据域和责任边界

| 数据域 | OLTP 核心事实 | 辅助存储/处理 | 关键一致性 |
|---|---|---|---|
| Identity/Tenancy | 当前成员/范围、邀请、交接 | IdP 使用其官方支持数据库 | 撤权即时重新鉴权，不读陈旧副本 |
| Fleet/DeviceIdentity | 注册周期、密钥引用、凭证摘要、轮换 | 高频心跳聚合/缓存 | 认领唯一；已撤销身份不复活 |
| Catalog/Schedule/Policy | 应用身份、不可变定义、草稿与版本 | 可失效读缓存 | 草稿并发保护；发布版本连续且不可变 |
| Delivery | 目标/游标、尝试、回执、重试事实 | Kafka/Artemis 提醒；文档按授权获取 | 旧周期/旧版本回执不覆盖当前 |
| Approval/Quota | 决定、例外、租约、用量账本 | 设备本地有界检查点 | 不超发、重复扣减、撤销后不续租 |
| Reporting/Retention | 聚合口径、作业状态、删除清单 | 加密对象存储与异步聚合 | 事实去重；导出权限重验 |
| Billing/Entitlement | 经核验购买/合同、容量、权益来源 | 官方供应商对账 | 重复/乱序通知安全；投影可重建 |
| Audit/Consent | 操作、用途授权、撤回、责任事实 | 按保留策略归档 | 业务与审计同事务；撤回用途停止处理 |

Kafka 保存事件流，Redis 保存可失效缓存/限流，Broker 承担连接；均不能代替额度、身份和购买事实源。重报表走聚合/分析路径，不在策略授权事务中执行长扫描。

应用 tenant 与 OceanBase 数据库 tenant 是不同概念：默认多个业务租户以 `tenant_id` 隔离；专用数据库资源仅作为明确部署档位。不得让 API 参数直接选数据库 tenant 或连接凭据。

## 3. 表、字段与索引规则

### 3.1 公共字段

- 所属业务资源必有 `tenant_id`；必要关联以 `(tenant_id, resource_id)` 限定，查询和写入显式授权。
- 外部主体采用经过验证的 issuer + 精确 sub 命名空间；目前单 issuer 实现的身份摘要迁移另行设计。默认大小写不敏感 collation 不能决定身份是否相同。
- UUID API 使用统一规范格式；设备周期单独使用 `registration_id`。旧设备命令不能仅靠可重复使用的硬件标识匹配新周期。
- UTC 瞬时使用明确精度字段；IANA 日程时区独立存储。数据库/session 时区统一配置，禁止服务器本地默认时区影响账本。
- 金额为最小货币单位整数/明确 Decimal，并含币种；额度为有界整数秒；版本/序号受上限校验。不使用浮点表示金额或配额。
- JSON 用于有界快照/扩展字段，常用筛选/权限/幂等字段用有索引的关系列。不把全部业务对象塞入一个 JSON 表。
- 敏感凭证保存摘要或外部密钥引用；私钥/支付秘密由密钥系统或外置安全配置管理，不放普通业务表/日志。

### 3.2 建议索引模式

下表是新功能的设计模式，**不是可直接复制到现有库执行的迁移**。实际索引必须结合已有 DDL、数据分布、执行计划及写入成本评审。

| 查询/不变量 | 建议键模式 | 说明 |
|---|---|---|
| 租户对象读取 | UNIQUE `(tenant_id, id)` | 作用域 JOIN 与关联约束 |
| 当前成员 | UNIQUE `(tenant_id, exact_actor_key)` | 撤权查主事实源；角色范围单独建模 |
| 策略编号 | UNIQUE `(tenant_id, policy_id, source_sequence)` | 并发发布需聚合锁/CAS，不只依赖唯一键 |
| 交付拉取 | `(tenant_id, registration_id, cursor)` | 使用游标和 limit，控制扫描 |
| 当前策略流 | UNIQUE `(tenant_id, registration_id, policy_id)` | 旧尝试与当前期望分开 |
| 请求幂等 | UNIQUE `(tenant_id, actor_key, operation, key_hash)` | 同键异载荷冲突；过期清理有界 |
| 设备遥测去重 | UNIQUE `(tenant_id, registration_id, event_kind, sequence)` | 序号作用域按契约固定，不靠客户端时间 |
| 租约预留 | UNIQUE `(tenant_id, subject_id, quota_bucket, lease_request_id)` | 重试返回原租约，已过期不重复发放 |
| 供应商事件 | UNIQUE `(provider, provider_account_key, event_id)` | 验签后落收件事实；跨账号区分 |
| 状态后台任务 | `(state, due_at, id)` 或带域分片 | 小批认领、租约/占用、防止全表扫描 |

UUID 存储格式保持现有 schema 兼容；是否改为二进制 ID 由性能证据决定。不可只为节省字节改写已发布 API 或 Flyway checksum。

数据库级关联要与锁顺序一同评估，避免外键导致跨域锁反转。对于刻意不加外键的边界，记录所属模块的验证/对账责任和删除顺序，不能静默放弃完整性。

## 4. 事务与并发设计

### 4.1 必须同事务的操作

| 操作 | 原子范围 | 提交后动作 |
|---|---|---|
| 成员权限修改/移交 | 当前关系版本、权限变更、审计、通知事件 | 发提醒、更新可失效缓存 |
| 策略发布 | 草稿/预览重验、不可变版本、操作、目标投影、审计/事件 | 网络投递/EMM 调用 |
| 审批批准 | 决定、限时例外/额度来源、审计、事件 | 下发并等实际证据 |
| 额度预留/结算 | 桶余额/预留、租约/账本、幂等记录 | 更新展示/下一次租约 |
| 购买事实更新 | 验证事件、事实版本、权益事件 | 重建权益投影、通知成人 |
| 凭证撤销 | 当前周期状态、凭证失效、审计/清理任务 | Broker 身份收敛、本地清理 |

业务 JDBC 事务内不等待 Broker、EMM、IdP 或支付网络调用。外部动作由持久事件/任务驱动；供应商执行成功但落库未知时查询原操作事实，不无条件重发具有擦除/扣费后果的动作。

### 4.2 锁与重试

- 公布每个聚合操作的锁顺序，同批设备按稳定 ID 排序；避免先锁设备再锁策略、另一路先锁策略再锁设备的反转。
- 聚合局部使用版本 CAS 或短 `FOR UPDATE`；所有事务有超时与行数上限，禁止长事务中做报告或用户交互。
- 隔离级别按 profile 明确。默认隔离级别不是一致性证明；RR 快照读取与当前锁定读取分开设计。
- 死锁/锁超时只对已经证明可重试的事务执行有界退避；结果未知先以幂等键查询事实。验证失败/不支持/越权不重试。
- 调度认领的 `SKIP LOCKED`、租约和时间语义需在目标 DB 认证。不能只依赖 H2 上“可以跑”。

额度示意不变量：`已确认消耗 + 有效预留 ≤ 已批准可用额度`。租约释放/到期、设备累计结算、补偿与追加均写账本并防重；单纯 Redis 减计数不能证明跨设备不超发。

## 5. 可配置负载与容量模型

令 `N` 为注册设备，`p` 为峰值在线比例，`H` 为心跳秒数，`A` 为事件聚合倍数，`B` 为广播目标数量，`W` 为广播扩散秒数，`R` 为重连窗口秒数：

- 在线连接：`C = N × p`。
- 心跳入口速率：`Qh = C / H`；是否写 OLTP 与写入频率由持久化策略决定。
- 遥测聚合写入：约 `原始事件速率 / A`，另计迟到/去重与聚合复杂度。
- 广播目标处理：`Qb = B / W`；网络、数据库、供应商配额分别计量。
- 全部在线设备重连入口：约 `C / R`，测试还要覆盖突发分布和 TLS/身份开销。

**仅用于解释的情景：** `N=1,000,000、p=0.2、H=300` 时，连接为 200,000，心跳入口约 667/s；这不是数据库 QPS、已测容量或业务峰值承诺。心跳还可能附带库存/遥测，必须独立建模。

数据库压测分开测管理员交互、规则发布、按设备游标查询、回执、额度并发、遥测聚合、账单对账和报表。混合压测包含热点学校/家庭、长尾租户、离线补交、版本广播与故障重试。

连接池预算由副本数决定：`应用副本数 × 每副本最大池 + 作业/迁移/诊断连接 ≤ DB批准预算`，预留恢复余量。扩应用副本前校验 DB 连接与队列预算，不能无限放大池。

## 6. MySQL 生产 profile

1. 固定 MySQL/Connector/J/Flyway 组合，TLS、字符集、session 时区、事务隔离、SQL mode 与超时外置且启动校验。
2. 数据库账户按应用读写、迁移、只读诊断分权；生产应用不持有全局管理权限。密钥轮换包含连接重建。
3. 授权、额度、最新策略/注册事实走主一致性路径；允许滞后的统计读副本必须给出数据截止时间。
4. 批处理有 size、速率、事务时长和重试上限；幂等/事件/审计清理作业均记录删除范围及保留依据。
5. 备份、binlog/PITR、复制拓扑、切换及刷盘配置由 DBA 明确；用恢复演练测得 RPO/RTO，不能凭框架宣称零丢失。
6. 大表分区先检查索引/唯一约束与外键条件；不能为方便按日期分区破坏全局去重或关联完整性。

## 7. OceanBase 专项认证

### 7.1 兼容记录必须精确

记录 `DB版本 / edition / mysql模式 / OBProxy版本或直连 / driver / Flyway / collation / isolation / topology / licence / supportOwner`，绑定应用 build 和结果。

| 认证项 | 用例 | 不通过后的处理 |
|---|---|---|
| DDL/迁移 | 从空库、前版本升级、全部索引/外键/约束 | 编写显式 vendor 脚本，不关闭约束掩盖问题 |
| 排序规则/身份 | 大小写、Unicode、尾空格、精确 actor 与 UUID | 采用已认证映射并迁移对账 |
| 时间/类型 | UTC、精度、布尔、Decimal、JSON、null | 在 repository/映射层明确差异 |
| 事务/并发 | 发布、认领、撤权、额度、重复回执、故障未知提交 | 修复不变量/锁顺序，不能仅增加重试 |
| SDK 内部表 | Spring Modulith 事件 UUID/时间、序列化长度/查询 | 专项 vendor DDL 与真实事件回归 |
| 执行计划 | 同数据分布下关键 JOIN/分页/批处理 | 调整索引/分区；仍不达标维持 MySQL |
| 分布与资源 | 热点租户、跨节点事务、重平衡、资源限额 | 定义共置/资源方案并测成本 |
| HA/升级恢复 | 节点/Zone 故障、代理重连、备份恢复、升级 | 不签该部署档位生产承诺 |

Keycloak、EMM、报表或其他第三方的数据库认证独立进行。Keycloak 官方列表提供 MySQL 支持条件；不能以 MySQL 协议连接成功推断 OceanBase 已被官方支持。[Keycloak 数据库支持](https://www.keycloak.org/server/db)

### 7.2 同预算 PoC 报告

相同业务数据、负载分布、持久性要求和恢复目标下比较，明确节点/存储/网络/副本数量；报告吞吐、P95/P99、锁等待/死锁、错误率、资源、恢复时间、重平衡影响、许可证/支持成本与 DBA 工时。

至少含常态、热点、广播、重连风暴、单节点故障和恢复六组情景。故障前后对账策略版本、账本、购买/权益及事件待办，无遗漏/重复业务后果才通过正确性门槛。吞吐胜出但核心事实丢失/错误，结果仍为未通过。

## 8. 迁移与回退操作步骤

### 8.1 Schema 演进

expand（兼容增加） → 分批 backfill（幂等/限速） → 对账 → 新旧读取对照 → 切换 → 观察 → contract（结束兼容窗口后删除旧结构）。

已发布 Flyway 迁移不可改 checksum；生产不使用 `clean` 或自动 `repair` 掩盖漂移。大表变更预演锁、磁盘、复制延迟和窗口。回滚应用前确认 schema 仍兼容，删除旧列后不能承诺简单回滚。

### 8.2 MySQL → OceanBase

1. 完成版本/类型/索引、SDK 和业务正确性认证，批准维护窗口与回退截止点。
2. 用适用的成熟迁移工具做全量与增量同步；密钥/驻留与访问符合部署范围，工具能力先核验。
3. 校验租户计数、唯一关系、引用、策略内容哈希、额度余额/租约、购买来源与事件待办；抽样与关键事实全量对账分开。
4. 切换前暂停生产写入和后台消费者/调度，等待在途事务与增量收敛；保留原事件 ID，防重复消费业务后果。
5. 确认最终差异为零或已批准处理，再切连接与恢复任务；先小范围验证读写、幂等、事件和签名配置。
6. 观察延迟、错误、锁、重试与业务对账；达到已批准退出条件才结束切换。
7. 目标库已产生新写入后，回退必须冻结并按预先认证的反向同步/对账方案执行。不能直接切回陈旧旧库。

迁移范围包括任务/事件登记/幂等事实，不能只搬业务主表；否则可能重发旧消息、重复计费或丢失审批。跨区域迁移另有驻留与授权门槛。

## 9. 运维看板与 runbook

| 面板 | 必须指标 | 对应动作 |
|---|---|---|
| 核心交易 | 延迟、失败/超时、幂等冲突、连接池等待 | 区分负载/锁/网络，限制非核心任务 |
| SQL 与锁 | 慢查询、扫描/返回、锁等待、死锁、长事务 | 执行计划与聚合锁顺序审查 |
| 容量 | 数据/索引/日志、增长、磁盘/IO、连接余量 | 归档/保留、扩容和恢复余量规划 |
| 异步一致性 | 事件积压、最老年龄、重试、失败分类 | 限速、熔断、人工复核；不无限重放 |
| HA 与恢复 | 副本延迟、切换、备份成功、恢复演练 | 隔离延迟读、副本恢复、按既定流程切换 |
| 业务对账 | 版本/回执、余额、购买/权益、撤销差异 | 停止有风险写入，按原事实补偿并审计 |

报警阈值来自对应 profile 的容量与目标，不写通用“CPU 超过 80% 即切换”。Runbook 必须包含影响、证据查询、责任人、恢复步骤、对账与结束条件；日志不含 token、私钥、支付秘密或儿童自由文本。

## 10. 认证交付件与当前事实

数据库放行包包含版本锁、配置基线、完整 Flyway 结果、关键 SQL 计划、并发正确性、故障/恢复与压测报告、许可证/支持、迁移/回退方案和签收责任。

当前代码包含 MySQL 连接与 Flyway 路径，以及 MySQL/H2 的消息事件 vendor schema；自动化行为验证运行于 H2。**未完成真实 MySQL/OceanBase 认证或容量/HA/恢复验证**，现有测试不能替代本文件的门槛。

最终选型复核由后端、DBA/SRE、交付和产品共同依据证据批准；财务评估成本，安全/隐私确认数据边界。详细待办保留在[实施计划](implementation-plan.md)，结果记录在[实施记录](implementation-progress.md)。
