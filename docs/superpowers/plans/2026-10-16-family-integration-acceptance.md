## 联调发现与追加修复

- 实际跨端配对恢复测试预置一台待确认设备，再新增第二台，被正确的免费单设备名额拒绝。仅补测试中的明确三台会员前提，并复测免费及到期边界；不关闭名额检查。
- Keycloak 26.8 实际 JSON 往返复现：`auth_time` 可能重复序列化，手机号标准字段反序列化后不在 `OtherClaims`，导致当前会话接口误拒绝合法登录。修复身份映射及读取为标准字段 API，加入严格重复字段与真实序列化回归；两项 Jackson 模块仅作测试依赖。
- MySQL 工具自身的 hostname 必须与生产一致包含 `/identity`。表单路由只允许预期同源登录动作，不能通过重写错误 URL 掩盖配置问题。工具及供应商夹具修复后使用新尝试记录，保留原始失败。
- 真实 MySQL RR 两类红例：已持锁后的 Hibernate `refresh` 仍可能发普通快照 SELECT，导致新属性不可见并报错；独立不改属性的测试还确认会读回旧 `enabled=true`。修复采用锁定的当前基础字段投影并保留原 UserEntity／adapter，属性保留 collection wrapper 并重新锁定加载。禁止 `em.clear()` 或 detach 用户导致已有写入丢失；新增完整基础字段和原模型引用写入验证。Keycloak 26.8／MySQL 表结构依赖与单节点边界明确记录。
- 同类问题进一步在 `byWechat`、`wechatForUser` 两处真实复现，原实体锁定后刷新会导致新微信归属在旧快照中不可见。已改为微信当前投影读取并保留唯一归属及版本冲突拒绝。最终 66 项身份模块测试及 21 项实际 MySQL／OIDC 验收全部通过，供应商仍为夹具。
