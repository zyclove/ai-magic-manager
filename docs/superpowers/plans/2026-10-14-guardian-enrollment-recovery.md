# 管理台 1.0.0：设备连接与未知结果恢复

## 目标与现有事实

延续已授权的功能完善与流程简化，在一个对话框内完成选择档案、显示一次性凭证、读取进度、现场确认及取消；关闭、刷新或重新认证后可回到原请求。使用现有 Flutter / Material 3、uuid、qr_flutter、http、oauth2 和既有后端接口。

当前通用添加设备表单没有发送 `Client-Request-Id`，网络未知后重试可能创建另一张票。后端已接受规范小写 UUIDv4、拒绝重复编号且不回放秘密，并提供仅原创建者可读的安全结果查询。现有状态与取消语义必须保留：EXPIRED 是派生状态，不能当作已撤销；错误现场码会提交失败次数，不能自动重试。

## 可观察验收条件

1. 每次新建先冻结原档案、平台、BYOD、身份范围和 UUIDv4；恢复记录保存并读回成功后才发请求。使用专门请求头，不混同普通幂等键。
2. 一次性 token 与现场配对码仅在内存；恢复记录只含严格校验的非秘密指针。后台、关闭、身份或工作空间变化时隐藏秘密；离开再返回不能使旧响应复活。
3. 未知创建结果只恢复原请求。404 不清记录或换编号；用户可明确继续原请求，沿用同 UUID 和原内容，唯一键冲突后只读核对，不自动生成第二份凭证。
4. reload / 认证跳转后不自动写入。按 actor、tenant、role 分隔的标签页记录保留原指针；损坏记录阻止新建，不能伪装为空。
5. 票据与安全状态 DTO 严格字段及身份绑定。凭证过期不展示或复制；读 401/403 隐藏旧资料。网络失败不抹去原请求。
6. 现场确认失败或结果未知后读取最新注册状态和失败次数，不自动再发现场码。只显示配对事实，不从 CONFIRMED 推断设备当前在线或规则已执行。
7. 取消始终针对原注册。只有确认 CANCELLED / LOCKED，或已完成配对后用户明确连接另一台，才允许清原指针并开始新请求。EXPIRED 仍提供明确取消。
8. 当前作用域检查覆盖 OAuth 内部令牌刷新等待结束后、实际业务 HTTP 发送前；迟到响应不展示。退出后旧刷新不能重新保存凭据。
9. 首页与设备页可见恢复入口；重复入口不会并发打开同一流程。手机与放大字体可操作，加载、错误、认证、未知结果和终态都有明确下一步。

## 执行步骤

1. 确认既有创建、creator-bound 查询、确认与取消契约，以及真实 oauth2 刷新发送时序。
2. 编写测试和最小可编译协议壳；冻结候选，实际观察行为断言 RED，不能将语法错误当作回归证据。
3. 实现请求范围保护和条件存储；验证等待刷新期间切 scope 不发业务请求、保存失败不发送、错 scope / 损坏存储不创建。
4. 实现控制器：同编号重试、409 查询、404 保留、严格响应校验、终态与取消、现场码不重放、生命周期和旧响应隔离。
5. 实现本地既有设计体系的专用界面与恢复提示，接回原添加设备入口；不新增付费或上传工作流。
6. 运行专项、管理台全套、分析与正式 Web 构建；运行真实 Dart ↔ Spring HTTP 场景并明确其测试身份/数据库范围。
7. 独立审查、隔离组合验证、精确提交与推送。本机更新前备份当前前端及配置，更新持久发布指针，逐项检查运行文件与其他服务实例。

## 发布与边界

保持 1.0.0，不增加历史迁移。当前源码的后端契约足够，无需新增生产接口；但实际运行 JAR 对应的旧源码尚无请求编号及恢复查询，且当前 V1 建库已包含新的归属字段。因此发布门槛包括已提交后端与新 V1 的独立初始化环境，先备份并保留旧项目及数据，完成前后端验收后切换同一入口；常规启动必须持久指向新环境。不能仅替换前端后声称恢复可用。

真实 MFA、硬件扫码/安装、系统管控能力和跨标签页全局单实例不由组件或测试 JWT 证明。sessionStorage 恢复限当前标签页，关闭标签页后的恢复保障需另行设计。外部 12ui 付费及内部界面上传已被自动审批拒绝，本阶段使用已有本地设计体系。
