# 家庭 P0：支付维护、日账单对账与售后

继续执行已批准的中国大陆家庭订阅方案：人工审核、原交易全额原路退款、手动续费。新增能力不开放销售，不自动批准退款，不改变既有订单周期、设备容量或试用资格。

## 本轮验收行为

1. 十五分钟未付订单由后台主动查单；微信确认未支付后请求关闭，再读取可信关闭结果。超时、错误或结果未知不能假装关闭；迟到付款按冻结周期入账且不重复发权益。
2. 支付/退款外部请求置于数据库事务外。短事务持久预约与租约防止多个实例重复处理，失效租约不能覆盖后来结果。已审核退款由系统推进，家长无需操作供应商接口；所有未知结果恢复原交易与退款编号。
3. 按上海交易日获取微信官方账单，校验申请响应、下载范围、文件哈希、格式、精确金额和汇总；按订单/退款来源核对。缺失账单、解析失败或证据不足不得显示“对账一致”。CSV不能直接授予或撤销权益。
4. 独立售后/财务权限与近期 MFA 保护平台工作台：查看退款队列→核对影响→确认审核；查看日账单任务与差异→重新核验原交易或记录跟进。跟进不把差异改成已对平。申请人不得自审。
5. 家长订单页显示简单状态与下一步：待付款、核对中、已关闭、已付款、退款审核中、处理中、已退款或需要协助。家长只能申请/查看退款，共同监护只读；保留未知结果恢复日志，账号和前后台变化使旧确认失效。

## 实施分工与边界

- 支付维护：复用现有微信 v3 与账本，增加可信查单/关单、已批准退款调度和事务外请求。
- 日账单：独立下载/解析边界、持久任务与不可变处理尝试、差异证据、有界重试和默认关闭的 worker。
- 售后：复用既有退款审批接口，补队列/详情/重试入口与管理台；平台权限与家庭成员权限独立。
- 数据与交付：新增表/列纳入保留目录，沿用未发布 1.0.0 初始化基线，在隔离数据库验证；不迁移或清空现有本机数据库。

本轮源码基线保存于 `.local/family-p0-commerce-20261016/baseline/`，含 1680 个源码文件、HEAD 与原有差异。保留已有未提交工作，所有供应商与销售默认关闭。

## 验证

关键缺口先 RED 再实现：网络调用无事务、到期关单与迟到付款并发、租约过期、退款丢回包、幂等/越权、签名与哈希、账单重复/错金额/缺行/日期和外部业务隔离。再进行完整后端、家长端与管理台回归、静态检查、构建及本地虚构数据页面检查。

真实商户关单、账单下载、真实付款退款到账、国内网络、受支持真机与发布准入仍需外部验收；本轮不发送真实支付/退款/账单请求，不部署，不提交。

支付维护、日账单、售后接口、家长与管理台界面、独立平台权限、初始化与部署开关已实现并完成本地回归和构建。验证及剩余外部收费门槛见 [交付记录](../../family-p0-commerce-operations.md)。真实商户与真机门禁继续保留，不按软件测试通过开放销售。
