2026-10-16，接续完整策略传输阶段。读取与核验已完成定向验证；执行编排仍待实现，不表示真实设备执行入口已开放。

## 当前缺口与实现顺序

完整文档编译及传输已经接受 API 等级和管理模式，但这两个参数还没有接入当前提供方的设备事实读取。执行编排器不能从儿童客户端的系统信息推导受管权限，也不能把历史绑定模式当作永久有效。

1. 在 `managedandroid` 领域定义不可变、日志脱敏的设备执行资料，仅包含精确远端设备名称、管理模式、整数 API 等级、期望/已应用设备状态和最近报告时间。
2. 通过现有官方 SDK 读取最小字段，限制响应体，严格拒绝重复键、错误 JSON 类型和不匹配设备。读取不修改策略、不分配设备；没有资料与读取失败分别保留原因。
3. 增加可复用的当前资料核验：精确设备、受支持的模式/API、有效设备状态、可配置报告时效及未来时间容差。时效基于服务端时钟，旧资料不能无限缓存放行。
4. 接入已有连接器契约；默认连接器不支持，Google 明确声明读取能力。中国大陆 Google 禁用及外部准入条件保持有效，合作方需要实现同一契约并通过本地契约验证。
5. 执行编排器在入队和每次外部写操作前重新核验可撤销授权；网络读取放在数据库事务外，事务内检查版本与绑定上下文没有变化。资料匹配不替代签名证据、机构权益、资源归属或写入归因。

## 来源与边界

Google [Device 资源](https://developers.google.com/android/management/reference/rest/v1/enterprises.devices)列出了 `managementMode`、`apiLevel`、`state`、`appliedState`、`lastStatusReportTime`；[设备 PATCH](https://developers.google.com/android/management/reference/rest/v1/enterprises.devices/patch)与读取分开。于 2026-10-16 核对。

本阶段仅建立读取与核验能力。实际状态为受管不等于某条应用规则已生效；后续还需核对指定策略名称、精确版本、设备回执及不合规信息。未经真实提供方和设备验收，不对外声明系统级强控制可用。
