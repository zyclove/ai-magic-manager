# 审批文档交付实施记录

归属完整计划 Task 5/7。已有批准、撤销和到期记录；本轮补齐设备可验证文档、回执和管理诊断，后续仍须原生规则执行、离线恢复、通知及使用额度追加。

## 决定

- 访问窗口与使用额度独立。文档绑定原审批、版本、儿童、设备注册周期、应用、规则和基础策略版本；原批准截止时间不因下载、重试或断网延长，`quotaEffect=UNCHANGED`。
- 当前基础策略只支持 CONFIGURE_ONLY，因此文档也明确 CONFIGURE_ONLY；设备接收、存储、拒绝均是未验证的设备报告，不转成 APPLIED。真实执行适配器及证据未就绪前不启用执行模式。
- 使用 Nimbus ES256、独立 JWS 类型及现有外置密钥；文档与审批版本唯一绑定并持久存储，重试返回相同文档。签名失败不影响已经保存的管理员决定，也不会产生部分文档/审计。
- 设备按当前注册周期分页读取曾批准申请的状态和版本，并逐个下载当前文档。每轮同步从首页完整扫描；UUID 分页不是变化游标。撤销/到期返回更高审批版本的 REMOVE_ACCESS_WINDOW，客户端持久保存每申请的最高版本，不因移除或重启忘记水位。
- 原授权期限是离线最晚截止；离线设备不能即时得知撤销。移除文档在期限之后仍有意义，不因原窗口过期而忽略移除。旧批准文档不能覆盖更新的撤销版本。
- 文档不含儿童理由、请求人或审批人身份。回执仅接受固定阶段/原因枚举；同正文重试幂等，矛盾终态拒绝，旧文档回执不影响当前审批交付状态。
- 锁顺序沿用主体→设备→凭证→审批→文档。现有审批与生命周期事务保留权威，设备读在当前锁下重查身份绑定并持久校正到期/失效状态。归档主体仍可取得撤回文档；已撤销注册不再接受业务凭据。
- Ruling：先补充签名审批状态文档，再接使用额度追加 — 现有审批窗口不能直接增加额度，额度撤销需要独立消费/未知预留归属 — 此阶段不能宣称加时或设备解锁已完成。

## 行为检查

1. 真实 opaque 凭据和 Nimbus 验签；绑定完整、无理由/成人身份、固定截止及重复文档一致。
2. 匿名/用户 JWT/跨设备/注册撤销拒绝；未批准申请不产生授权文档。
3. 撤销、到期、基础变化、成员失效和旧回执不复活授权；已归档主体仅交付移除。
4. 收到/存储/拒绝回执状态、重复与冲突、并发下载唯一文档、故障事务回滚和缺签名配置。
5. 全量后端、真实 MySQL、前端分析/组件/构建与实际浏览器交互；真实设备执行和真实 OTP 写入分别记录。

## 临时拒收恢复（V16）

Ruling: 保留审批文档与 JWS 不变，独立创建交付尝试 — 文档描述授权事实，尝试描述传输；不能为修复存储故障重新批准或延长期限 — 客户端需保存尝试编号，并在回执中显式提交。

- V16 增加尝试与尝试回执，V15 记录迁移为第一次尝试，原历史保留。省略尝试编号的旧回执只属于第 1 次，绝不默认匹配最新尝试。
- 设备对 BASELINE_MISSING/STORAGE_FAILED 可显式重试。每个失败尝试至多生成一个后继；并发/丢响应重复调用返回相同后继；30 秒指数退避、最长 5 分钟、每份文档最多 10 次。永久错误需要排查，不能自动循环。
- 过期/撤销后拒绝重试旧批准，设备重新获取当前撤回文档。撤回文档不受原批准截止后的重试限制。重试不修改审批版本、签名内容、签发时间或额度。
- 当前交付和文档历史显示尝试次数、拒收原因、恢复状态与最早重试时间；尝试历史按时间顺序有界读取。管理员查看诊断，设备独立凭据执行重试。
- 覆盖并发、重复、退避/上限、旧回执、注册/主体/审批失效、事务回滚和非空旧数据迁移；后端全量、真实 MySQL 与管理端响应式交互分别记录。
