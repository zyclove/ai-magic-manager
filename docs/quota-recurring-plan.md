# 重复额度计划实施说明

归属：完整实施计划 Task 6/7。上一轮已有可运行每日账本；本轮补齐无需逐日手工配置的使用流程，完整原生执行等范围继续保留。

## 行为与决定

- 一个儿童和额度范围只有一个长期计划；时区继承现有额度日历约束。每周七天分别设置秒数，0 表示该日无可分配时间；最多 60 个明确日期例外覆盖周规则。
- 新建可从今天或明天开始；当天应用已有租约时，不能补建应用限制而漏计历史消费。手工已有每日池保留，自动计划不覆盖其调整、消费或预留。
- 修改或暂停从指定时区的次日生效；版本留存，当天已生成池不重算，不退还不确定消费。更新同一个次日配置时采用最后确认的版本，历史修订仍可查询。
- 每日池保存来源计划和配置版本。后台按有索引的到期时间、有界批次、逐计划短事务创建当天池；设备新租约前补齐当天所有适用计划，避免总额先创建、应用额度尚未创建的空窗。
- 停机恢复只生成当前日，不补发过去日期预算。旧周期保留原池和结算，不复活已关闭额度。
- 锁顺序沿用主体→设备（设备请求）→凭证域→日历→计划→池；后台和管理路径不持有设备锁。所有自动创建、审计与事件在事务内提交。
- 沿用 Spring JDBC/Flyway、Spring Scheduler、java.time、Nimbus 和 Flutter Material，复用现有错误、MFA、ETag、幂等、分页与表单组件。

## 界面

共享额度页提供“每日账本”和“重复计划”切换。新建/修改表单说明生效日期，提供工作日/周末快捷填充、每日分钟数、日期例外和暂停选项。计划详情展示最新已保存配置、生效日与历史版本；每日池标明来源。儿童/审计角色仅查询。

## 证据门槛

1. 创建/重试、跨租户/儿童只读、近期 MFA、强版本冲突。
2. 周规则、日期例外、次日修改/暂停、手工池优先、源版本绑定。
3. 多实例并发生成无重复账本；设备实时生成后总/应用额度交集；已有租约不能补建遗漏用量的应用计划。
4. DST 23/25 小时、服务停机跨日只生成当前日、回退时钟不重发预算、故障回滚。
5. 全量后端、真实 MySQL 专项、Flutter 静态/组件与桌面/手机真实接口交互。

本轮实际结果：后端 179 项、MySQL 专项 19 项、Flutter 14 项通过；静态分析和 Web release 构建成功。实际 Chrome 读取、表单操作和认证拒绝流程通过。夏令时及目标名称显示另用明确标识的只读浏览器夹具检查；独立审阅发现的两项问题已修复。详细时间、日志和真实敏感写入限制见[实施记录](implementation-progress.md)和[管理端记录](management-console-delivery.md)。

时区安全迁移、审批追加时间、签名策略绑定、可靠设备计时/停止、OceanBase/容量仍是完整目标中的独立待完成项，本阶段通过不等于总目标达成。
