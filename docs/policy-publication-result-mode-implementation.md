# 发布结果查询的显式模式接合

状态：本阶段源码已合并并完成针对性验证，2026-10-18；尚未部署。后端结果查询已绑定必填 `mode`。受管执行完整链路属于独立阶段，本补丁不启用该能力。

## 最小改动

结果查询仍为只读 `GET /api/v1/tenants/{tenantId}/policies/{policyId}/publication-results/{requestId}`。显式绑定必填 `mode`，与原请求的租户、操作者、操作名、幂等键、策略、修订和预览指纹一起核对；禁止在服务端默认改成 CONFIGURE_ONLY。

| 输入 | 结果 |
| --- | --- |
| 缺失、空或未知模式 | 400，不查询原发布结果 |
| 合法 CONFIGURE_ONLY，与原提交一致 | 查询该配置发布的当前结果 |
| 合法 ENFORCE，与原提交一致 | 可精确读取已存在的对应记录；查询不启用或发起执行 |
| 模式与原提交不一致 | 幂等指纹冲突；不能返回另一模式的结果 |
| 同一模式但无可读取结果 | 404 表示结果不可确认，不证明原提交未发生 |

保留原当前角色、操作者、租户、预览及版本校验；保留 `Cache-Control: no-store`。调用方刷新和重新查询不会创建版本、发布记录或 outbox，不续期原授权，不重新发送 POST。当前客户端只提供 CONFIGURE_ONLY，不能因此删除服务端合法 ENFORCE 的精确查询能力。

发布顺序：先交付显式携带模式的客户端，再上线强制模式参数的服务端。旧客户端的无模式查询会收到 400，必须在升级说明和最低支持版本中明确；不能为兼容旧客户端悄悄猜测原操作模式。Web 与 Android 等客户端分别核对版本，浏览器通过不代表已安装移动客户端已升级。切换前保留原待核对记录，升级后继续查询同一请求。

## 调用方的恢复流程

1. 发布前冻结规范 UUID 请求键、策略与修订、预览 ID 与摘要、原提交模式。重试查询沿用这组字段，不从当前编辑中的表单重新生成。
2. 收到完整成功响应后核对发布对象；超时、连接中断或响应缺字段时保留原意图，显示“查询发布结果”。
3. GET 使用与原提交相同的 `mode`。成功结果包含 `id`、`versionId`、`sequence`、`mode`、`state`、`createdAt`；配置保存状态不能表述为设备已执行。
4. 未找到结果时提示“暂时无法确认”，不自动创建新请求。模式指纹冲突时停止自动恢复，提示核对原记录；权限变化时重新确认当前账户和管理范围。
5. 查询成功后显示对应发布版本。若旧预览或幂等重放期限已经过期，读取历史记录不延长这些期限，也不重新授予写入权限。

| HTTP / 业务码 | 含义与界面动作 |
| --- | --- |
| 200 | 返回原模式的当前发布记录，成功响应禁止缓存 |
| 400 | 缺少或无法解析模式，或引用参数非法；客户端升级/修正请求，不猜测模式 |
| 401 | 登录认证无效；重新登录后使用原请求引用查询 |
| 403 | 当前账户不再具有该范围的管理权限；停止读取和提交 |
| 404 / POLICY_PUBLICATION_RESULT_UNAVAILABLE | 没有可读取的原请求结果，不能据此断言提交未发生 |
| 409 / IDEMPOTENCY_KEY_CONFLICT | 原意图与查询字段不一致；保留记录并核对，不换键重发 |
| 500 | 服务端记录不一致或异常；保留原意图并联系支持，不解释为成功或可安全重发 |

机构端与家长端当前源码均已携带模式，但这不等于已部署所有终端。服务端强制参数的发布门槛是受支持客户端已升级；Android 验证仍待后续资源窗口。该改动不改变认证、设备注册或执行准入，不开放新的系统级控制能力。
