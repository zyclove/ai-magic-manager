# 受管儿童端关联数据清理

日期：2026-10-16。基线：`bf526dd`。本阶段补齐 `managed_agent_bindings` 的内部清理处理，使用现有 Spring JDBC、事务、数据目录检查和恢复账本。

## 范围

关联表包含学生、设备注册、提供方资源、原设备公钥指纹以及已消费证明的摘要。目录登记只说明这些字段属于受保护数据；必须有单独的执行处理和验收，才能处理删除请求。

本处理仅删除已终止的本地关联记录，保留以下数据供各自流程继续处理：

- 提供方注册意图和提供方设备身份。
- 注册审计事件及机构审核记录。
- 设备、凭证及其他领域的数据。
- 合同权益和设备名额。

没有新增公开删除接口、自动调度器或“全部删除成功”状态。公共预检的 `executionAvailable=false` 不变。系统退管和全局资料删除仍需要其他步骤完成与独立验收。

## 执行前提

`ErasureManagedBindingProcessor.process(claim, limit)` 是包内接口，接收现有恢复任务的有效工作租约，每批 1–25 条。`ErasureRecoveryJobs.applyBatch` 负责恢复任务身份、隔离状态、租约检查与原子事务。

| 检查 | 处理方式 |
| --- | --- |
| 数据目录与当前表结构不符 | 沿用目录检查失败，停止执行 |
| 学生当前设备或关联记录超出已确认的设备/注册范围 | `ERASURE_SCOPE_CHANGED` |
| 范围内设备仍管理中、授权范围活动或凭证仍有效 | `ERASURE_DEVICE_EXIT_REQUIRED` |
| 关联对应的注册意图属于其他学生 | `ERASURE_MANAGED_BINDING_SCOPE_CORRUPT` |
| 关联仍为 PENDING 或 VERIFIED | `ERASURE_MANAGED_BINDING_EXIT_REQUIRED` |
| 终态仍保留挑战值、活动关联槽位，或版本无效 | `ERASURE_MANAGED_BINDING_STATE_CORRUPT` |
| 工作租约失效或已被接替 | 沿用 `ERASURE_RECOVERY_LEASE_LOST` |

校验后按 ID 稳定排序，锁定最多 25 条记录；删除条件再次限定租户、学生、关联 ID、版本、终态与已清空的挑战/活动槽位。实际删除行数不符时整批回滚。

## 恢复与审计

- 使用独立步骤码 `MANAGED_AGENT_BINDINGS`、处理版本 1；不会改写已有 `DEVICE_IDENTITY` 步骤的含义。
- 删除记录与累积行数、批次数、步骤状态在同一事务提交。
- DATA 表示仍有记录；DONE 只表示该表在本次核验范围内已清理，不表示整个恢复任务完成。
- 重复调用 DONE 步骤不重复计数。若出现新记录，返回 `ERASURE_STEP_RECHECK_REQUIRED`，交由恢复流程重新核对。
- 不兼容处理版本、异常游标、非法阶段或计数溢出均停止执行。
- 复用恢复账本中的请求、操作者摘要和范围记录；不把挑战值、签名正文或设备凭证写入日志。

建议整体执行顺序：先结束本地关联与设备访问、核对提供方退管，再执行各域数据清理；提供方注册记录必须保留到退出核对完成。本处理本身不会调用提供方，也不会因删除本地记录释放合同名额。

关联终止应在正式接受删除请求、隔离业务流量之前完成；不能依赖隔离后的后台到期任务继续推进状态。完整执行编排仍需处理剩余数据域、外部副本、审计保留和恢复完成条件，本阶段不提前解除全局隔离。
