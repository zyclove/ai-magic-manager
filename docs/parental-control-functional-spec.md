> 版本：Draft 1.2；更新：2026-10-09。
> 上位决策：[平台设计蓝图](parental-control-platform-design.md)。  
> 状态：实施规格，部分基础后端已落地；实际接口与测试见[实施记录](implementation-progress.md)。本文中的设备、模型、商业和真机验收项不代表已实现。

各编号的完整交付工作包、状态机、审批/批量任务、页面信息、边缘场景与商业责任见[完整产品交付与商业运营模型](parental-control-product-operating-model.md)。它补充本文件的流程，不改变系统能力、授权和隐私边界。

## 1. 范围与统一判定

服务家庭监护人和机构管理员，让其设置合理、可解释的访问规则；儿童可以理解限制、申请例外和获得必要帮助。第一阶段为 Android 手机/平板，电视按型号纳入支持；后续平台分别验证系统接口。

每个可操作控件必须同时满足：**操作者有权 × 套餐有权益 × 设备有能力 × 必要授权有效 × 当前状态允许**。任何一项缺失都返回稳定原因码。套餐购买不能提升操作系统权限，家长确认不能替代平台接口资格。

| 设备模式 | 访问管理产品表现 | 验收边界 |
|---|---|---|
| 家庭普通 Android/BYOD | 授权引导、可用统计、提醒、受控浏览器/网络过滤、有限访问管理 | 被撤权、强制停止或旁路后显示保护退化；不声称所有应用不可绕过 |
| 工作资料 | 仅对受管理资料实施许可策略 | 个人资料能力单独核验；不推定可以控制私人应用 |
| 机构全受管/专用设备 | 经 EMM/DPC 系统接口实施应用、配置、安装、启动与合规策略 | 供应商资格、OS/OEM、字段支持及生效证据全部通过 |
| Android TV/Google TV | 受控入口、共享会话、遥控器交互及平台许可策略 | Launcher 不等于系统封锁；HDMI、投屏、系统首页、其他用户须分别报告 |

产品优先级：P0 是核心旅程必需，P1 是完整商业版本增强，P2 是完成独立验证后的扩展。P0 不表示每种模式都有相同执行能力。

## 3. IAM-01 / FAM-01：身份、家庭和组织

### 3.1 正常流程

1. 成人通过 OIDC 登录，创建家庭或机构；登记目标区域、默认 IANA 时区和必要联系方式。
2. 创建儿童/学生主体，使用昵称和年龄段满足规则需要；不默认索取身份证、精确出生日期、面部照片。
3. 邀请共同监护人或机构操作员。邀请限定租户、角色、对象范围和期限；被邀请人登录确认后才生成成员关系。
4. 管理者在权限预览中看到“可以修改哪些孩子/班级/设备，哪些操作需要再次认证”。
5. 学生与家庭/学校关联需要合法授权；关联只提供必要身份映射，不把家庭活动报告自动开放给教师。

### 3.2 权限与恢复

- API 从可信身份与成员关系计算范围；对象 ID、二维码、客户端 role 和 tenantId 都不是授权凭证。
- 新增管理员、放宽限制、退出管理、导出和批量删除要求服务端验证的最近认证。设备本地指纹验证不能单独作为服务端 MFA 证据。
- 机构可启用审批分权：规则编辑者不能批准自己的高影响全校变更；家庭双监护审批为可选配置。
- 成员移除立即失效其服务端授权、会话及相关待审批操作；不删除孩子或撤销整个机构的设备。
- 监护关系争议进入受限核验流程，不允许客服凭联系方式直接转交管理员权限。客服仅通过客户授权的限时 support grant 接触必要诊断资料。

**验收 IAM-01-A：** 儿童直接调用策略修改 API 被拒绝；跨家庭/跨班级对象均不能读取或变更；过期邀请和已移除成员不能重新使用旧授权。

## 4. DEV-01：设备注册和能力体检

### 4.1 添加设备向导

选择儿童/学生 → 选择自有或机构设备 → 显示适用模式/数据后果 → 签发一次性短期注册凭证 → 设备认领 → 完成用户授权或 EMM 注册 → 探测能力 → 预览基础规则 → 发布 → 核对首份生效证据。

- 正式受管注册可能需要初始设置/恢复出厂，不把安装普通 APK 描述成自动成为设备所有者。
- 注册码不承载长期密钥；重复使用、错误租户、过期及设备证明失败分别显示错误。设备密钥通过平台安全存储生成/保护。
- Android Device Policy 模式由官方 DPC 管理，伴随应用不持有 EMM 服务凭据。
- 有 GMS、无 GMS、国内发行版、海外发行版分别验证供应商与分发通道；缺少 Google 服务不能推定 AMAPI 可用。
- 完成绑定但只能实现部分能力时显示 LIMITED，列明“能控制什么、哪些可绕过、下一步如何授权”。

### 4.2 能力记录

CapabilityRecord 至少含 deviceId、managementMode、scope、capabilityKey、supported、grantStatus、provider、osBuild、agentVersion、evidenceSource、checkedAt、limitationCode。证据来源区分供应商报告、本地系统读取和仅观察到的行为。

系统升级、应用升级、撤权、重新注册和供应商能力变化触发重新评估；旧证据超过新鲜度门槛显示 STALE，不能继续标记“当前全部受保护”。缺失心跳只证明不可观察，不能证明孩子绕过。

**验收 DEV-01-A：** 同一型号在 BYOD/全受管模式呈现不同能力；无 GMS、无授权、注册取消、首策略失败均有可恢复状态。订单购买后仍不能跳过设备能力校验。

## 5. APP-01 / PER-01：应用与细粒度权限

### 5.1 应用规则

管理员选择设备/主体 → 搜索应用 → 查看身份、评级来源和可控制项 → 设置安装、启动、时段、额度、权限和网络规则 → 查看冲突/影响 → 发布并逐项确认。

| 规则 | 数据 | 执行要求与交互 |
|---|---|---|
| 安装允许/禁止 | appId、来源、发行渠道、版本约束 | 只有许可的受管能力可强制；家庭模式提供审核建议/平台原生限制入口 |
| 卸载控制 | protectionMode、原因 | 阻止卸载与主动卸载分开；主动卸载显示可能丢失应用数据 |
| 启动允许/禁止 | effect、目标资料范围 | 不把“安装阻止”自动映射成“暂时不可打开” |
| 每应用时长 | 单位秒、周期、额度池 | 与总额度、时段求交集；不能由某个允许规则覆盖总额度耗尽 |
| 网络访问 |域名规则/受管浏览器配置 | 按实际可见范围控制，不能声称读取全部 HTTPS 内容 |
| 运行时权限 | permission、GRANT/DENY/DEFAULT | 仅对公开管理接口支持项执行，显示不支持或需用户确认 |

AppIdentity 使用 platform、packageName/bundleId、管理资料、发行渠道及可获得的签名证据。签名正常轮换按平台支持的签名谱系校验，不能简单把每次证书变化判成恶意。重复包、多用户、克隆应用和私密空间必须探测是否可管理，不能按包名声称覆盖所有实例。

**实现约束：** AMAPI 应用的 installType=BLOCKED 可能导致卸载，不应用于日常学习时段的短期启动限制；disabled 或其他能力也须核验管理模式、系统应用例外、应用数据后果和恢复行为。[官方应用策略字段](https://developers.google.com/android/management/reference/rest/v1/enterprises.policies)

### 5.2 权限详情

将相机、麦克风、位置、联系人等运行时权限与悬浮窗、使用情况访问、通知访问、VPN、无障碍、设备管理等特殊访问分开。展示声明状态、观察状态、管理员期望状态和生效证据；不知道的值显示 UNKNOWN。普通应用不能静默改写第三方权限，特殊访问不能套用统一运行时权限开关。

管理员可以降低权限暴露，但敏感授权仍遵循平台、发行规则和明确告知；默认不批量授权儿童设备上的相机/麦克风。关闭相机识别授权不等于关闭其他 App 相机权限，两个规则分别展示。

**验收 APP-01-A / PER-01-A：** 未安装、隐藏系统应用、签名轮换、资料实例变化、API 部分写入均有结果；临时通行不重装已卸载应用、不自动授予相机；按本地和供应商证据分别核验。

## 6. SCH-01：时间与科学使用引导

- 睡眠、学习、娱乐、自定义时段分别设置工作日/周末、节假日覆盖、可用应用和结束提醒。
- 建议采用可编辑年龄段模板；模板是管理建议，不能包装成医学结论或保证改善学习成绩。
- 连续使用达到门槛提示休息，是否强制间隔由监护人设置；提醒频率、静音与夜间通知可配置。
- 紧急联系不计入普通娱乐额度；学习 App 是否豁免总额度由管理员显式选择，不按应用名称自动判定。
- 时段采用起点包含、终点不包含；跨午夜拆为可解释区间。DST 缺失本地时刻移至下一个有效时刻，重复时刻覆盖两次对应区间，服务端预览实际 UTC 范围。
- 日额度按策略指定时区的本地日期编号，DST 日不假设等于 24 小时。时区调整在下一周期生效，不能立即制造新额度；设备墙上时钟回拨不得返还已消费时间。

**验收 SCH-01-A：** 覆盖跨午夜、DST 前进/后退、旅行、管理员改时区、手动改时钟、节假日例外和重启。儿童端显示实际下次开放时间而非模糊“明天”。

## 7. QUO-01：单设备与跨设备共享额度

### 7.1 产品口径

默认按已确认的应用使用秒数累计，显示采样范围和最近同步时间。两台设备同时娱乐 10 分钟默认消费 20 分钟；“真实注意力时长”没有可靠观测依据，不自动推断。后台音乐、画中画、投屏、屏幕关闭与电视外接源是否计入必须由平台探测和配置定义。

三种模式分别展示：单设备硬额度（执行能力验证后）、跨设备共享硬额度（计时/执行/离线预留均验证后）、跨设备估算汇总（数据不完整时）。不把后两种混为一个付费功能。EMM 提供应用禁用字段不意味着原生提供按秒时长限制；缺少可靠本地执行路径时不开放硬额度。

### 7.2 共享额度流程

~~~mermaid
sequenceDiagram
  participant D as 支持硬额度的设备
  participant Q as Quota 领域服务
  participant DB as MySQL / 认证 OceanBase
  D->>Q: 申请额度租约（周期/池/幂等键）
  Q->>DB: 短事务预留余额并写租约与 outbox
  DB-->>Q: 提交结果
  Q-->>D: 签名租约（设备/周期/单位/到期）
  D->>D: 在额度与时段内本地计时
  D->>Q: 累计消费结算（租约/序号）
  Q->>DB: 幂等更新消费与未结算预留
  Q-->>D: 确认序号及新余额
~~~

1. 建立 QuotaPool：tenantId、subjectId、scope、periodId、timeZone、limitSeconds；每应用限额与总限额独立求交。
2. 设备申请短期 QuotaLease，绑定 registrationId、deviceId、sessionId、poolId、periodId、reservedSeconds、notAfter、sequence。建议起始预留粒度为数分钟，最终按真实执行和网络条件配置。
3. 事务用条件更新或行锁保证可用余额足够，同时写账本、租约和 outbox；不以 Redis 缓存余额作为最终授权来源，不在事务中等待设备。
4. 设备只消费已验证租约，持续持久化消费进度；租约单位、截止时间、应用限额和时段任一耗尽即结束当前允许会话。
5. 结算使用累计消费值与递增序号，重复消息不重复扣减。设备丢失不能确认剩余额度时，预留部分保持占用；不能仅凭租约超时就把全部额度返还，否则会与已经发生的离线消费重叠。
6. 已确认归还或结算的未使用部分才释放；允许次日对已关闭周期补交对账，但不能把旧周期额度带入新日。

不变量：`available = limit - settledUsed - outstandingReserved`，其中 outstandingReserved 只包含尚未转入 settledUsed 的部分；两者不能重复计算同一消费。数据库故障时不得发新租约，可在现有有效预留内继续；有未确认余额时向管理员解释“部分额度等待设备同步”。

### 7.3 离线和硬额度边界

- 离线继续使用的前提是有效本地基础策略、可信时间与尚未消费的预留额度；离线不创造新全局额度。
- 重启后无法确定租约剩余时间或计数时，不续长临时娱乐额度，转入安全基础规则；紧急帮助保留。
- 未受管设备可被强制停止/撤权，不能保证本地额度停止生效；此类设备只显示估算和提醒，不参与“严格共享额度”承诺。
- 若产品选择每设备预分配整日额度，需明示“离线配额固定，联网后可调整”，不得同时承诺随时全局精确共享。
- 全局硬额度消耗是热点事务，应按主体/额度池建模和限速；OceanBase 横向节点不自动消除同一孩子账本热点。

账本保证授权预留不超额，实际应用停止仍可能存在系统执行/采样延迟。每个受支持模式必须验证并公开最大允许偏差与统计口径；超出门槛或只能等待云端轮询的设备不列为硬额度支持。消费进度采用原子持久化与开机/会话标识；崩溃后不确定的本地时间段按已占用处理，不能重新发放同一预算。不能把普通应用计时写成不可篡改的系统计量。

**验收 QUO-01-A：** 两设备并发预留不超总额；重复/乱序结算不重复扣减；租约丢失、断网、数据库切换、重启、周期切换不返还未知消费；不支持的设备明确退化。

## 8. POL-01：规则发布和执行闭环

草稿保存 → 输入校验 → 权限/能力/冲突校验 → 生效预览 → 管理员重新认证/必要共同审批 → 不可变版本 → 分批投递 → 接收证据 → 规则级应用证据 → 对账/告警 → 必要时发布回滚版本。

| 层级 | 状态展示 | 成功证据 |
|---|---|---|
| 服务端意图 | 已发布，版本 42 | 数据提交与 outbox 记录 |
| 传输 | 已送达伴随 App / 供应商已接受 | 接收确认；不代表系统限制已生效 |
| 执行 | 全部生效/部分/失败/未知 | 每规则可验证的系统/供应商结果 |
| 持续合规 | 当前生效/陈旧/退化 | 证据新鲜度与定期对账 |

预览返回 matchedRuleIds、不可覆盖底线、会受影响的例外、需重新授权项、数据损失风险、目标快照和不支持原因。试点一小组通过后扩大下发；取消发布仅停止尚未送出的目标，已应用设备须用新版本恢复。

紧急联系人不能采用一个可任意编辑的普通应用白名单代替；还需核验系统拨号/求助入口、受管浏览器帮助页及管理员恢复。系统设置在受管模式中可以受限，但必要恢复入口必须可用。

**验收 POL-01-A：** 过期 ETag、乱序旧版本、目标错租户、签名错误、必需规则不支持、部分写入、批量取消和回滚失败均有结果。汇总分母固定为本次发布目标快照，离线设备不计入成功。

## 9. APR-01：临时通行与复核

儿童在限制页选择目标与原因 → 提交有期限申请 → 管理者收到去重通知 → 查看命中规则与不可覆盖底线 → 最近认证 → 决策 → 生成限时例外 → 设备应用 → 到期恢复基础规则。

- 申请限定资源、规则、设备/会话和所需时长；儿童理由为可选短文本，设置长度和保留期限，不接受原始私聊/截屏作为默认附件。
- 状态为 PENDING、APPROVED_PENDING_DELIVERY、APPLIED、DENIED、EXPIRED、REVOKED、FAILED；批准与真正生效分别展示。
- 批准决定同时记录 absoluteNotAfter、maxUsageSeconds、审批者、被覆盖 ruleIds、基础策略版本。到期从签发时计算，晚送达不延长有效期。
- 同一申请只接受一次终态决策；共同审批者必须不同，已失去监护范围的第二批准无效。
- 临时例外不能放宽 nonOverridable 底线、不赋予管理员角色、不自动安装/授敏感权限。相关基础规则修改或主体移交后重新校验例外，必要时撤销。
- 离线无法送达撤销时，管理员看到“已撤销，设备待确认”，设备最晚仍按原签名期限到期；没有远程即刻撤销保证。
- 防止反复申请造成疲劳：按儿童/资源设置冷却、合并重复请求，紧急帮助不受申请限流阻挡。

**验收 APR-01-A：** 批准后断网、重复批准、迟到命令、审批者撤权、基础规则改变及重启都不让例外无限续期；到期后恢复已验证基础规则。

## 10. TVS-01：共享电视身份与遥控器体验

### 10.1 会话模型

电视启动进入最小权限访客/儿童基线 → 遥控器选择孩子 → 载入适用规则与额度 → 如需成人会话，扫码由有权成人手机批准 → 签发该电视限时会话 → 成人退出/空闲超时/重启恢复基线。

选择头像只表达当前使用声明，不是身份认证。没有系统用户隔离或可信认证的共享电视，不能证明是哪个孩子在看；报告标识 attribution=SELF_DECLARED/VERIFIED_SESSION/UNKNOWN。多个孩子同时观看由监护人选择共享归属，不通过摄像头推断。

成人入口不列在儿童可任意切换的同级卡片中。批准绑定 deviceId、nonce、scope、expiry，扫码链接不携带管理员长期 token；重放或换电视失败。离线成人恢复仅在平台支持、预先授权的限时恢复机制下开放，不能共用固定通用 PIN。

### 10.2 控制边界

- 使用受控 Launcher、专用设备锁定任务或 OEM 合作方案分别展示强度；无系统支持时，遥控器 Home/设置/商店/投屏可能绕过入口。
- HDMI 游戏机、电视直播、机顶盒和外部投屏不是普通 Android 应用，未取得 OEM 输入源控制/计时接口时只提供提示，不计入已强制管控范围。
- TV 默认没有相机；外接相机缺失、被拔出或权限撤回不影响基础访问策略。
- 主界面大字、焦点环、明确返回路径；D-pad 每个可操作元素都可达，弹窗关闭后回到原焦点；避免要求电视输入长密码。

**验收 TVS-01-A：** 陌生用户/儿童不能直接切成人模式；扫码过期、重放、兄弟姐妹切换、HDMI/投屏、Home、重启、断网及不同遥控器布局分别报告能力结果。

## 11. WEB-01：网站、分类和媒体安全

管理员选择年龄段/类别 → 显示分类来源、更新时间和盲区 → 加域名允许/阻止 → 验证语法和规则冲突 → 下发 → 展示最近分类/拦截结果 → 误分类申诉。

- 域名规范化使用成熟 URL/IDNA 库；明确定义 exact 与 includeSubdomains，`example.com` 不匹配 `badexample.com`。公共后缀和国际化域名需检查，不能以字符串包含匹配。
- DNS/VPN 只对可观察的目标范围声明有效。IP 直连、DoH、QUIC、第三方 VPN、IPv6、缓存、CDN 共用域名和网络旁路分别评估，无法归属的流量显示 UNKNOWN。
- URL 路径/页面内容规则仅在受控浏览器或明确支持的服务接口内执行。禁止以安装根证书拦截全部 HTTPS 作为默认方案。
- 黑名单/白名单、分类置信度和分类服务不可用策略可配置；不确定时的提醒/拒绝由管理员预先选择，紧急域名与恢复入口独立保护。
- 影视分级来自合法区域资料/平台配置，版权/接口/分类许可证列入供应商清单。视频 App 无可用内部控制接口时只提供整 App、时段和平台原生家长设置。
- 下载安全优先平台 Play Protect/OEM 安全服务或有授权的专业供应商；不宣称普通 App 可扫描所有文件、全部应用私有目录和即时恶意内容。

**验收 WEB-01-A：** 精确域名、子域、IDNA、冲突、缓存、VPN 切换、分类失效及媒体平台盲区有明确行为；报告不保存 URL 查询参数和页面正文。

## 12. SAF-01：紧急帮助、恢复与通知

紧急联系入口始终可发现；是否具备系统紧急拨号由设备模式决定，电视显示家长联系/求助路径而非虚构电话能力。任何锁定模板先验证恢复通道，否则不能发布。

告警状态：NEW → ACKNOWLEDGED → INVESTIGATING → RESOLVED / DISMISSED。事件等级区分访问申请、同步异常、能力退化、疑似账号失陷，不将一次离线视为违规。通知按区域使用成熟推送/短信/邮件供应商；推送失败不改变审批或策略事实。

管理员恢复经可信身份核验后生成最小范围短期恢复授权；离线恢复仅用经平台验证的机制，绑定单设备/注册周期/用途/期限。没有可靠时间或防重放存储时，不开放离线扩大访问。不能把远程恢复成功作为客服口头保证。

**验收 SAF-01-A：** 策略误配、管理员手机丢失、云服务中断、通知失效、恢复授权重放都有处理；必要求助不被娱乐额度/套餐到期阻断。

## 13. ORG-01 / EXT-01：机构管理与集成

- 组织层级、班级和设备组独立建模；一个设备可在多个动态组，冲突预览必须说明具体来源。
- 批量导入先校验/预览，返回逐行结果，不用一次导入覆盖全组织；错误行可下载脱敏报告。名册使用外部稳定 ID，避免姓名匹配产生错绑。
- 教师创建课堂会话需班级权限、开始/结束时间、许可模板；课堂结束恢复常规规则，不授予永久管理员权限。
- 调班只改变授权范围，转校走移交流程。校内设备归机构管理，不因学生离开自动允许旧家长继续操作。
- 家校互通仅共享经授权的必要状态，如“申请由学校处理”；不默认向学校同步家庭晚间活动或向家长开放其他学生资料。
- 身份/名册优先 OIDC/SAML、SCIM 或目标系统成熟 SDK；供应商 webhook 验签、幂等、租户映射、重试和死信告警。具体标准是否支持须以供应商为准。
- 平台连接器统一 enroll、inspectCapabilities、applyPolicy、getStatus、deprovision、revoke 接口；返回执行证据、限制和数据后果，而非供应商不透明 success 布尔值。

**验收 ORG-01-A / EXT-01-A：** 教师不能操作他班设备；名册重复、转班、已离职会话、回调重放、供应商配额/停服和异步部分失败可对账。

## 14. INS-01 / VIS-01 / AIA-01：智能化能力

### 14.1 行为趋势优先

使用获准聚合量识别连续使用、深夜使用、频繁申请和长期不同步；规则引擎/统计先实现可解释建议，不为简单阈值引入训练平台。建议包括“调整提醒”“复核时段”“检查设备授权”，由监护人选择，不给儿童贴成瘾、智力、情绪或健康标签。

报告同时呈现覆盖设备、数据完整度和同步延迟；观察到使用减少不自动证明心理或学习改善。不做按键记录、私聊监控或秘密录屏。

### 14.2 可选视觉辅助

优先探索主动打开的短时前台安全提示，例如针对明确物体/场景的本地辅助；场景尚未验证价值、准确性和平台准入时不售卖。禁止人脸身份识别、自动判断成人/儿童、情绪、注意力和健康推断。当前用户身份来自授权会话。

流程：用途说明 → 单独授权 → OS 相机授权 → 儿童可见状态 → 本地推理 → 低置信不输出结论 → 提示或家长复核 → 结束并释放相机。进入后台、屏幕锁定、撤回、系统撤权或相机占用时停止本场景处理；重启不自动恢复拍摄。Android 相机有 while-in-use 和前台服务限制，不能承诺持续后台自动观察。[Android 相机后台限制](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start)

ML Kit 可提供本地视觉 SDK，但通用物体检测不等于儿童安全模型；特定场景仍需合法模型、适用人群评估和模型许可证审查。原始帧只驻留内存、不存盘、不上传；撤回清理未处理帧与可选结果队列。若保留提醒事件，只保存已授权的类别、模型版本与时间，设短保留期限。[ML Kit](https://developers.google.com/ml-kit/guides)、[物体检测能力边界](https://developers.google.com/ml-kit/vision/object-detection)

ModelCard 登记用途、禁用用途、输入范围、训练数据合法来源、地区适用性、错误率评估、置信度阈值、功耗、版本签名和退役方案。没有证明数据不能填写准确率。模型失效/不可用回退到基础规则，不扩大权限、不自动处罚。

### 14.3 管理员规则助手

成人输入“工作日晚上九点后只保留学习和联系” → 成熟模型 SDK 生成结构化草稿 → JSON Schema 校验 → 领域授权/时间/冲突/能力校验 → 展示差异与理由 → 管理员编辑、认证、发布。助手不持有策略执行、账号提升、擦除或支付权限。

云端模型仅发送经明确同意的最小规则上下文，不发送儿童原始活动、相机帧和敏感聊天；私有化可禁用或使用经认证本地服务。模型输出不可信，应用/域名标签里的指令不能获得工具权限；失败回到手动编辑。费用预算、限流、供应商停服与模型切换独立配置。

**验收 INS-01-A / VIS-01-A / AIA-01-A：** 不完整数据不产生确定性诊断；撤回立即停止采集；无相机/后台/低置信可降级；提示注入、越权生成、冲突策略和模型超时不能直接改变设备规则。

## 15. RPT-01：报告、审计和诊断

报告维度为孩子/班级、设备、应用类别、日/周，展示观测覆盖率、估算范围与规则状态。儿童看到自身摘要和解释，不看到其他儿童记录或管理员邮箱。机构管理者按授权范围汇总，不默认展示家庭私人记录。

导出创建异步任务：权限检查 → 范围/时间确认 → 最近认证 → 生成限时加密对象/下载链接 → 下载审计 → 到期删除。完成导出不代表完成法定删除；删除另跟踪事务库、分析副本、事件保留、对象存储和备份恢复后的再删除清单。

诊断包包含脱敏版本、能力、错误码、策略哈希、最后确认时间、correlationId；排除 token、密钥、原始媒体、完整 URL 和儿童自由文本。远程诊断权限短期授权，不开启隐蔽相机或录屏。

**验收 RPT-01-A：** 导出/下载均检查范围，旧链接到期失效，缓存结果不跨租户；删除后备份恢复不得重新公开已删除主体。

## 16. OFF-01 / END-01：离线、恢复和退出

| 情况 | 设备行为 | 管理端表现 |
|---|---|---|
| 短期断网 | 延用已验证持久基础策略；限时授权按原到期 | 离线、最后证据时间、当前结果不可确认 |
| 长期离线/凭证过期 | 不无限续长例外；需要重新认证连接 | 告知待恢复，不假装远程撤销已送达 |
| 普通 App 强制停止/撤权 | 无保证后台重启；下次启动进行体检 | LIMITED/UNKNOWN、修复步骤 |
| 设备重启 | 受管系统策略依其系统能力保留；恢复可信计数 | 单调时钟重置独立处理，不重新补满额度 |
| 策略验证失败 | 保留已验证基础配置并报告；部分写入需对账 | 失败规则、补偿状态、恢复入口 |
| 正常退出管理 | 后果预览/再认证 → 撤销普通业务访问 → 独立限时清理/正式 EMM 解除 → 分别收集证据 | 云端 REVOKED 与本地/供应商结果分开；自报不能当独立清理证明 |
| 账号/设备失陷 | 立即撤销访问；独立供应商通道/人工恢复 | REVOKED 与“本地是否清理”分开 |
| 全受管解除导致擦除 | 独立权限、认证、确认，按供应商执行 | 显示将丢失数据；无损路径不支持则明确说明 |

AMAPI 删除设备会尝试擦除且长期离线时不保证成功，不能因供应商资源已不存在就确认设备已擦除。[官方删除语义](https://developers.google.com/android/management/reference/rest/v1/enterprises.devices/delete)

**验收 OFF-01-A / END-01-A：** 注册重新开始不接受旧租约、旧例外/旧命令；正常清理通道限用途且过期；紧急撤销后的清理不可假报成功；个人、工作资料和全受管的删除后果分别验收。

## 17. API、数据与模块落地补充

### 17.1 关键 API

所有路由位于 /api/v1，延用 OpenAPI 3.1、OIDC 用户身份和独立设备凭证。设备 ID 对应关系在服务端认证上下文中校验。

下表是完整产品逻辑 API 范围；具体已实现路径以[当前后端接口](backend-api-status.md)及其契约为准。当前退出流程使用 `/tenants/{tenantId}/devices/{deviceId}/deprovision/previews` 和 `/operations`，撤销后的原密钥清理命名空间、后果与限制见[退出管理契约](device-deprovision-contract.md)；不把规划中的 EMM/擦除接口当成已实现能力。

| 路由 | 契约要点 |
|---|---|
| POST /enrollments | mode、subjectId、目标设备信息；返回短期一次性凭证和注册风险说明 |
| GET /devices/{id}/capabilities | 支持范围、授权、证据来源、新鲜度、限制 |
| POST /policies/{id}/preview | 目标快照、匹配规则、能力缺口、不可覆盖底线、擦除风险 |
| POST /policies/{id}/publish | If-Match、幂等键、最近认证；202 operationId |
| GET /operations/{id} | 目标分母、逐设备/规则状态、截止时间和失败原因 |
| POST /access-requests/{id}/decision | 单次终态决策、审批要求、notAfter、maxUsageSeconds |
| POST /device-api/quota-leases | 当前注册/会话认证、周期/池、请求秒数、幂等键 |
| POST /device-api/quota-leases/{id}/settlements | 累计消费、序号、时间证据；拒绝跨设备结算 |
| POST /devices/{id}/adult-session-requests | 随机 nonce、限时审批；不能凭头像开启 |
| POST /devices/{id}/deprovision-preview | 返回模式、实际数据后果、confirmationHash 和有效期；不执行退出 |
| POST /devices/{id}/deprovision | 提交近期认证和确认哈希后创建异步退出；设备模式/供应商后果改变时需重新预览 |
| POST /devices/{id}/revoke | 立即撤销，和本地清理确认分别记录 |
| POST /subjects/{id}/exports、/deletion-requests | 范围、近期认证、异步状态和审计 |

错误码至少包括 SCOPE_DENIED、CAPABILITY_UNSUPPORTED、CONSENT_REQUIRED、ENTITLEMENT_REQUIRED、BASELINE_NON_OVERRIDABLE、POLICY_VERSION_CONFLICT、QUOTA_UNAVAILABLE、TIME_UNTRUSTED、PROVIDER_RATE_LIMITED、DEPROVISION_DATA_LOSS_CONFIRMATION_REQUIRED。设备错误和 HTTP 错误不得泄露其他租户对象存在与否。

### 17.2 核心数据约束

| 实体 | 必需约束 |
|---|---|
| Membership / GuardianRelation | tenant_id 必填，主体范围、有效期、撤销记录；不得仅靠 token role |
| Registration / CapabilityRecord | 独立注册周期 ID、模式、资料范围、供应商引用、证据时间 |
| PolicyVersion / RuleResult | 版本不可变、目标快照、不可覆盖标志、期望/实际状态、证据 |
| QuotaPool / QuotaLease / UsageLedger | 主体/周期唯一池，租约注册绑定，序号幂等、余额事务一致 |
| AccessRequest / TemporaryGrant | 申请终态唯一、批准范围、绝对到期、使用上限、撤销与送达分别存储 |
| DeviceSession | 身份可信度、成人授权范围、过期、重启恢复基线 |
| ConsentReceipt / ModelVersion | 用途与版本、授予/撤回时间、合法来源、模型签名与评估 |
| DeprovisionOperation | 数据后果、清理通道期限、供应商证据、本地清理状态 |

SQL 遵循 MySQL 公共子集、短事务、组合租户索引和 outbox；OceanBase profile 独立验证。跨租户外键按 `(tenant_id, id)` 建复合唯一键与对应关联约束，防止仅 ID 关联错租户；分区事实表无法使用外键时采用受控写入与巡检。敏感读不使用滞后副本。

## 18. 页面与交互状态规格

| 页面 | 首屏主信息 | 主要操作 | 必须处理的异常 |
|---|---|---|---|
| 家长今日 | 当前规则、数据新鲜度、待审批、必要告警 | 查看孩子、审批、编辑计划 | 没设备、全离线、数据不完整 |
| 儿童限制页 | 当前限制原因、剩余额度、下次开放、求助 | 申请通行、查看规则 | 无网、申请处理中、申请被拒 |
| 设备详情 | 管理模式、当前能力、期望/实际策略 | 修复授权、同步、退出管理 | 撤权、供应商失败、证据陈旧 |
| 规则编辑 | 场景/对象/应用/时段/额度、冲突解释 | 预览、保存草稿、发布 | 权限不足、版本冲突、紧急路径失效 |
| 机构仪表盘 | 目标设备数、执行状态分布、异常组 | 分组、批量任务、审计 | 批量部分失败、配额不足、热点限速 |
| 电视首页 | 当前会话、允许应用、剩余时间、焦点 | D-pad 选择、申请、成人扫码 | 访客、断网、扫码失效、身份不可信 |

手机突出单任务，平板提供列表/详情双栏，Web 提供批量表格与筛选，电视突出远距离可读文字和遥控焦点。状态不得只靠颜色区分；字体缩放、读屏语义、键盘/D-pad 操作均纳入交付。敏感数据在切换儿童/组织时清除旧缓存视图；加载期间不能短暂展示上一个主体记录。

## 19. 逐项验收与证据包

每项功能按“服务端授权 → 客户端交互 → 原生/供应商执行 → 回执 → 报表/审计 → 离线恢复”验收，不以 UI 开关出现作为完成。

| 验收组 | 对应功能 | 必需证据 |
|---|---|---|
| 身份/隔离 | IAM/FAM/ORG/EXT | 儿童、被撤销成员、跨租户、跨班级负向结果 |
| 应用/权限/发布 | DEV/APP/PER/POL | 真机型号、OS、管理模式、供应商版本、规则级生效/失败 |
| 时间/额度/例外 | SCH/QUO/APR/OFF | 边界时间、并发/幂等、不可信时间、断网和重启结果 |
| 电视/内容 | TVS/WEB | 各输入源、遥控器路径、身份归属、过滤盲区及误分类 |
| 安全/智能 | SAF/INS/VIS/AIA | 求助恢复、撤回采集、误报复核、越权草稿及模型失败 |
| 数据/退出 | RPT/END | 受控导出、清理/撤销分离、擦除确认和删除范围 |

证据包记录 featureId、testCaseId、build、环境/设备、期望与实际、correlationId、截图或日志摘要、失败原因及负责人。隐私材料脱敏，不保存儿童原始视觉作证明。非功能另覆盖模块边界、契约兼容、迁移、依赖扫描、HA、备份恢复、重连风暴和配置化百万注册设备压测；当前均未运行，完成后才能对外声明。

实施顺序：身份/租户 → 设备能力 → 应用与时间 → 策略闭环 → 例外/恢复 → 额度 → 机构/TV/商业集成 → 可选智能化。任何阶段不得绕过设备模式与外部平台准入门槛。

## 20. 主体维护与权限生命周期补充

主体详情与编辑使用强版本 ETag，更新需 If-Match；缺失前提返回 428，陈旧版本返回 412，防止两位监护人相互覆盖。年龄段属于资料输入，不构成自动降低内容限制的依据；关联策略必须独立预览和发布。

邀请可以主动取消，取消与接受并发以数据库事务结果收敛；失效邀请不能重新生成成员关系。token 只返回一次，列表/审计不返回原秘密。角色撤销后每次重试（包括幂等响应）重新检查授权。

归档仅将主体从常规选择列表移除，不代表设备已解绑、数据已删除或付款已终止。后续设备/策略模块必须阻止对归档主体新增绑定或发起新授权，已有系统规则与恢复通道仍按生命周期管理。归档需近期认证与版本检查；数据删除、正常退出和合同终止分别有独立流程。

管理员交接、逐端入口、全量功能闭环及商业对应见[产品实施规格](parental-control-product-delivery-spec.md)。
