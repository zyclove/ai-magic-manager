# 1.0.0 设备配置副本清理实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: executing-plans；已有删除契约内联实施，结束时一次独立最终复核。

**Goal:** 按已接受的主体注册范围删除设备配置下发、回执、流及游标副本，保持共享策略和其他设备数据，并修正首版初始化索引基线。

**Architecture:** 沿用 JDBC、独立账本、恢复作业和事务内步骤检查点。新增内部 `CONFIGURATION_DELIVERY` 处理器，每批最多 25 个物理行；四表按照外键顺序删除。复用既有租约、fencing、清单和维护闸门，不引入新的框架。

**Tech Stack:** Java 17、Spring JDBC/事务、Flyway、JUnit、H2、MySQL 8.4。

**Spec:** `data-erasure-contract.md`、`version-1.0.0-initialization.md`，总计划 Task 10。

## Global Constraints

- 全新 1.0.0 业务基线。将 V3 工作台三条索引原样并入 V1，保留数据库专属 V2；不修改运行中的数据库或发布物。
- 只删除账本接受的 tenant/device/registration 元组。先验证当前主体设备范围及已撤销状态，拒绝仍可用凭据和活动范围。
- 校验配置头、下发、流和回执的双向注册关联；任何一端落入目标的跨注册关联必须在删除前阻断，不能删到其他注册。
- 先回执/流，再下发，最后头；不依赖级联漏计行数。状态、签名或回执内容不会使已选择副本免于清理。
- 四个存储共用批次预算，删除和检查点同一事务；提交前仍校验独立账本、租约和 fencing。
- DONE 重入重新查四表，发现数据再现必须拒绝完成。步骤 DONE 不完成全局作业、不解除维护状态。
- 保留设备主记录、共享策略草稿/预览/版本/发布，以及退出、本地清理与注册证据，交由完整编排处理。删除设备服务器配置副本不证明终端本地副本已清理。
- 共享目录其他 WIP 保留；基于 `1634fc2` 的独立源码快照验证，只覆盖本阶段文件。

## Review Focus

- 相同设备 ID 重新注册到其他主体，旧注册清理不得删除新注册。
- 配置头与下发设备不一致，回执或流指向另一个注册；任一方向涉及目标均须先阻断。
- 实际删除后租约失效或存储异常，行数与检查点必须一并回滚。
- 小批次重建处理器与并行执行，不能漏删、重复计数或越过 25 行预算。
- 初始化仍只执行完整 V1/V2 且三条索引列顺序正确；已有开发库不隐式迁移。
