# 策略预览的设备目标选择

## 当前行为

管理端策略预览允许管理员分页挑选最多 50 台设备。机构 OWNER/ORG_ADMIN 还能从一个活动设备组一次选取当前有效关联成员；上限按**当前有效成员**计，而不是按组内历史总记录计。即使组内超过 50 条记录，只要当前有效成员为 1–50 台，仍可一键选择。超过 50 台当前有效设备的组需要拆分或手动选取。旧注册周期、未激活设备和已归档档案成员被排除并显示数量。家庭监护人只看到本人有权限的设备列表，儿童和教师无策略入口。

设备组选择采用“读取组版本 → 读取完整状态汇总 → 读取 `status=CURRENT` 成员页 → 再读组版本”；汇总的组版本、总数或四类合计不一致，以及当前有效数量与成员页不一致时拒绝选择。两次组版本不一致也拒绝。预览前和确认保存配置前再核对当前组版本。管理员手动增删选择后，来源标记清除。策略预览提交明确设备 ID 列表及可选的 `groupId/groupVersion`；服务端在同一事务中锁定组版本，核对目标集合恰好等于当前有效成员，并在设备快照中再次比对注册周期。分组来源写入预览快照和指纹。确认保存配置时服务端重新核对组版本、成员范围、注册周期及快照指纹；任何变化都要求重做预览。返回目标或分组来源与请求不一致时，客户端停止发布。

这是**一次性目标快照**，不是动态设备组策略。设备组后续增减成员不会自动改变已发布的配置；来源虽然随预览与配置快照留存，但不会触发持续的组继承或自动重发。真正动态按组发布仍需冲突预览、逐设备执行回执和变更后对账。当前 `CONFIGURE_ONLY` 发布不会执行系统级应用限制。

## 服务端契约

手动选择沿用 `{ "deviceIds": ["<uuid>"] }`。由机构设备组选择时，预览请求增加 `groupId` 和 `groupVersion`；两者必须同时存在或同时缺省。仅机构 OWNER/ORG_ADMIN 可使用设备组来源，家庭与其他角色的策略预览仍按自身权限处理。服务端验证设备列表与组内**当前有效成员**完全相同，而不是接受任意子集；设备组状态或版本变化、成员增减、设备重新注册、档案归档、设备失活均返回 `POLICY_GROUP_CHANGED`，要求重新选择并预览。超过 50 台当前有效设备须拆分为明确的较小设备组或手动选择；历史失效记录不占用单次预览目标名额。

预览快照含 `groupSelection: {groupId,groupVersion}`，并纳入哈希；手动选择不写该字段。发布引用已保存的预览，服务端再次核验来源与每台设备注册周期。即使客户端绕过界面版检查，服务端也不会把变化后的组范围当作已审阅目标。已有不带组来源的预览不获得动态组语义；部署后若旧预览指纹不兼容，须重新预览，不能自动放宽校验。

## 交互与错误处理

选择器同时展示已选数量、组来源版本、排除设备数和明确的非动态边界。设备列表、组列表均分页，最多选择 50 台；空态、网络失败和权限变化有可见处理。切换工作空间、角色或账号时关闭选择器并废弃旧结果，已打开的发布预览立即隐藏旧范围内容。组过大、空组、归档组或版本变化都要求重新选择；发布前仍由管理员核对预览规则及设备，再完成近期多因素认证。

## 验收缺口

当前只完成编译、静态分析与 Web 构建；还需浏览器窄屏/键盘检查、真实机构账号操作、组增删并发、设备撤销、旧注册周期、50 台上限和策略预览/发布 HTTP 流程。不能把配置快照或构建成功当作系统执行证明。
