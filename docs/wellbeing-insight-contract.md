# 近七日使用复核建议：阶段契约

## 定位与授权

监护人和机构管理员在使用报表中，针对一台当前可见设备按需生成建议。`GET /api/v1/tenants/{tenantId}/devices/{deviceId}/wellbeing-insight` 只允许 `OWNER`、`GUARDIAN`、`ORG_ADMIN`；仍复用报表的当前成员、儿童档案、设备注册周期、观察授权和数据范围核验。儿童、教师和审计员不能通过该入口读取建议。响应 `Cache-Control: no-store`，不新增持久画像或后台自动扫描。

该功能是确定性、可解释的规则引擎，**没有使用机器学习模型、摄像头、面部或情绪识别**。观察权限未获批准或被撤回时不生成建议。设备上报的汇总记录未经独立验证，不能当成医学诊断、成瘾标签、惩罚依据或设备系统策略已执行的证明。

## 输入、计算与限制

- 服务端按租户 IANA 时区取最近 **7 个完整自然日**，不包含当前未完成日；夏令时按当地日界计算实际毫秒数。只查询一台当前授权设备，不接受客户端自选时间窗或把旧注册周期拼接。
- 复用现有使用报表的重叠区间去重、记录下界、查询覆盖和未授权状态。查询时间覆盖不足 80% 时返回 `INSUFFICIENT_COVERAGE`，不以缺失数据推断没有使用。
- 仅对当前主用户资料中的非安全关键应用计算：在 7 天中，至少 3 个自然日的**前台使用时长下界**各达到 2 小时，才产生 `REVIEW_APP_TIME` 建议。最多 3 条，按达标天数排序；不把多个应用的时长相加为“总屏幕时间”，不声称检测到单次连续使用。
- 结果状态为 `NOT_AUTHORIZED`、`NO_DATA`、`INSUFFICIENT_COVERAGE`、`NO_PATTERN` 或 `SUGGESTIONS`。建议只供监护人复核使用安排和既有规则，不自动编辑、发布或执行策略；阈值仅用于提示，不能当作科学诊断标准。

## 响应示例

```json
{
  "schemaVersion": 1,
  "tenantId": "11111111-1111-4111-8111-111111111111",
  "deviceId": "22222222-2222-4222-8222-222222222222",
  "registrationId": "33333333-3333-4333-8333-333333333333",
  "generatedAt": 1791676800000,
  "from": 1791043200000,
  "to": 1791648000000,
  "timeZone": "Asia/Shanghai",
  "evidenceStatus": "AGENT_REPORTED_UNVERIFIED",
  "status": "SUGGESTIONS",
  "queryCoverageMillis": 570000000,
  "suggestions": [
    {
      "kind": "REVIEW_APP_TIME",
      "packageName": "com.example.video",
      "displayName": "示例应用",
      "days": 3,
      "minimumDailyMillis": 7200000
    }
  ]
}
```

示例中的时间和标识为虚构资料，不代表真实报告；生产响应必须满足 `from < to <= generatedAt`。前端核对租户、设备及注册周期，结果只在当前工作空间和页面生命周期内显示。按需重新生成时使用最新报告，不把旧建议当成持续监测或规则执行状态。建议出现时，有当前规则管理入口的成人可跳转查看现有规则；覆盖不足时可跳转检查设备和观察授权。跳转时沿用页面现有工作空间及权限复核，不自动创建草稿、保存或发布策略。

## 后续产品工作

如需加入夜间使用、连续使用提醒或 AI 模型，须分别证明时间粒度足够、设备模式可执行、监护授权、误报处理、年龄适配、撤回和模型/规则版本回滚。本阶段的日级汇总**不足以**判断连续使用、具体内容或儿童行为动机。
