# 儿童端申请与持久恢复实施计划

承接 `c9f90cd`，完成申请协议在儿童端的产品闭环。使用现有 Flutter Material、设备 SDK、Sembast、平台加密存储与请求生命周期；不增加身份提供方或重新实现数据库。

## 验收要求

1. 从当前设备在线选项选择应用、规则、时长及理由，提交前明确展示内容；保存原正文和原幂等键后才发送。
2. 申请列表与详情展示待审、批准待同步、拒绝、取消、到期、撤回及失效；取消有确认与强版本；错误、加载、空态和分页均可操作。
3. 断网、超时、进程退出、收到响应但本地写失败均保留原操作；未知结果不能换键重新申请或删除记录。恢复不自动发送变更，儿童主动确认原操作重试。
4. 当前主体/注册改变、凭证撤回、前后台切换或宿主关闭时隐藏旧资料、取消在途请求；安全绑定核对成功后才恢复可见内容。凭证轮换不改变原注册的请求归属。
5. 申请不代表系统解锁，批准不延长原截止时间；和现有签名窗口同步保持不同状态，儿童不能修改规则或执行成人审批。
6. 单元及文件库回归、真实 HTTP、界面/遥控焦点/小屏、Web/Android 构建、原生持久恢复按阶段验证。逐阶段精确提交并推送 dev，保留并行报表文件。

## 实施顺序

- 在 `packages/device_access` 提供按完整设备范围隔离的持久申请日志：单条未解决操作、预写意图、原键/正文、不可静默丢弃的未知结果、单调版本事实与有界缓存。
- 儿童宿主保存并验证在线上下文，复用带原生提交屏障的安全绑定与加密文件库；单独存储申请记录，不将请求状态用于执行权限。
- 补齐超过统一幂等 24 小时期限后的专用授权恢复查询。过期键不能证明未提交，未知记录在当前阶段禁止删除或换键。
- 接入会话、申请页面/表单/取消确认与恢复入口；优先清晰错误和可解释状态，再完成真实终端验收。

## 设计决策

Ruling: 每个设备主体范围同一时间只保留一条未解决变更 — 防止进程重启后失去原请求键、重复发送或交错取消 — 成本是未知结果需先确认，不能继续创建其他申请。

Ruling: 请求结果缓存和授权执行分离 — 原有窗口接收已有签名与时钟规则，申请事实不能构成许可 — 成本是界面需分别展示申请审批状态和同步状态。

Ruling: 沿用已交付儿童端视觉 — 12ui 托管服务已有明确地区拒绝，原工具安装也有 Windows 限制 — 使用当前设计稿和组件，并以实际渲染及遥控焦点验收，不能宣称生成了新托管设计。
