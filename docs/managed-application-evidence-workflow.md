# 逐设备应用证据工作流

当前状态（2026-10-16）：后端刷新、查询、最小证据持久化及清理已实现，11 个套件共 254 项定向检查通过。尚未部署，未完成本阶段的前端对接、策略编译与执行接入；Android 原生验证按用户安排延期。原始范围、各轮结果和内容摘要见[验证记录](evidence/managed-application-evidence-20261016.json)。

## 用户能知道什么

管理员可以针对已验证绑定中的一个已声明应用刷新报告并查询结果。结果区分“正在核验”“等待报告”“应用身份已核验”“报告过期”“核验未通过”“暂时读取失败”。结果不等同于系统策略已经执行：提供方应用报告缺少本地用户空间证明时，始终显示 UNKNOWN，`systemControlAvailable` 保持 false。

应用目录的安装状态不参与判断；同一目录应用在不同绑定、注册或设备上的结果不能互相继承。Android TV 与 Android 手机的平台声明不能互换。

## 事务与外部读取

1. **开始短事务**：重新检查当前成员、合同、企业归属、学生状态、设备注册、绑定版本及发布签名信任修订；读取目录身份元数据。平台不匹配或连接器未声明应用报告能力时拒绝刷新。
2. **记录尝试**：每个租户/绑定/应用只有一条当前记录，分配随机尝试 ID，递增版本并清除上一轮可用事实。绑定锁串行化创建与容量检查；每个绑定最多 200 个目录应用，重复刷新不追加历史报告。
3. **事务外读取**：先读提供方注册来源，再读该应用报告，最后再次读取注册来源。网络期间不持有成员、设备、合同或证据行锁。
4. **接受短事务**：重新读取全部当前上下文，比较捕获前后的权限代次、绑定/注册/企业修订、目录摘要和连接器修订。核对尝试 ID、版本及截止时间，再校验两份注册来源和应用签名、安装状态、报告时间。
5. **保存结果**：只保存最小签名集合及报告/获取/截止时间，不保存提供方完整响应、注册令牌、挑战或用户视频。缺少报告保持等待；不可信报告明确拒绝；外部读取失败保存可重试原因。

刷新默认间隔 30 秒，尝试窗口 120 秒；进行中的尝试不允许并发覆盖。窗口到期后可发起新尝试，迟到回调不能覆盖新一轮。应用证据不是任务执行队列，服务崩溃后不会假装刷新成功；查询显示尝试过期，由管理员显式重新刷新。

## 查询与失效

查询重新检查当前授权及绑定，再核对上下文摘要和时间。有效期同时受报告最大年龄及获取缓存期限限制；查询不能延长它。失去权限、绑定撤销、重新注册、目录元数据变化、提供方连接器修订变化后，旧记录不再可接受。

证据上下文摘要不包含发起人的个人身份。另一位当前有权的管理员可读取同一设备事实；网络中的原发起人被撤销或权限代次发生变化时，本轮结果仍拒绝接受。策略发布必须再次读取当前状态，不能把接口返回值当成可长期复用的执行凭证。

## 数据与删除

`managed_application_evidence` 通过 `(tenant_id,binding_id)` 外键归属于本地受管绑定，应用定义仍属于租户共享配置。绑定删除时级联删除其最小证据；租户及应用外键防止交叉挂接。

现有受管绑定清理器先验证学生/注册范围及绑定已终止，再按批删除绑定。每个绑定的应用数限制为 200，因此现有 25 条绑定批次最多级联移除 5000 条证据；清理进度中的行数仍表示绑定条数，不能解释为全部物理删除行数。若发现导入或损坏数据超过 200 条，整批回滚，返回 `ERASURE_APPLICATION_EVIDENCE_LIMIT_EXCEEDED`，由运维检查。清理不删除共享应用目录、提供方设备或合同记录。

仍采用未发行的 V1 初始化基线，只在新建隔离数据库验证。生产发行后的升级须独立向前迁移；本工作流不会直接修改运行数据库。

## 已实现接口

路径基于 `/api/v1/tenants/{tenantId}/managed-android/agent-bindings/{bindingId}/applications/{applicationId}/evidence`：

| 操作 | 约束 |
| --- | --- |
| `POST /refresh` | 当前 OWNER/ORG_ADMIN，近期多因素认证，`If-Match` 为绑定版本；只读取提供方，不修改设备策略 |
| `GET` | 当前 OWNER/ORG_ADMIN，`If-Match` 为绑定版本；不调用提供方、不刷新有效期 |

返回禁用缓存，包含证据状态、稳定原因码、尝试/结果版本和必要时间。默认不暴露提供方资源名、签名、公钥或上下文摘要。暂时失败允许显式重试；报告缺失不代表应用卸载。

`If-Match` 必须来自绑定资源的当前版本，例如 `"2"`；不能使用下列响应的证据 `version` 代替。一个刷新分成开始和结束两次状态变化，证据版本分别递增；GET 不递增版本。刷新没有接受设备事实的请求体，不允许浏览器提交“已安装”或签名来代替服务端读取。

响应示例（字段结构示意，非真实设备结果；时间均为 UTC Unix 毫秒）：

```json
{
  "bindingId": "<binding-uuid>",
  "applicationId": "<application-uuid>",
  "state": "VERIFIED_IDENTITY",
  "reasonCode": "MANAGED_APPLICATION_PROFILE_UNVERIFIED",
  "version": 2,
  "profileScope": "UNKNOWN",
  "systemControlAvailable": false,
  "reportedAt": 1792108800000,
  "retrievedAt": 1792108805000,
  "expiresAt": 1792108925000,
  "nextRefreshAt": 1792108830000
}
```

### 界面对接规则

以下是前端对接契约，当前阶段不声称已完成对应界面：

| 状态 | 界面文案 | 主操作 |
| --- | --- | --- |
| ABSENT | 尚未核验 | 核验应用 |
| PENDING | 正在核验 | 禁止重复提交，允许离开页面 |
| WAITING_REPORT | 等待设备报告 | 展示下次可刷新时间 |
| VERIFIED_IDENTITY | 应用身份已核验 | 展示报告时间与有效期；仍说明“系统控制尚不可用” |
| STALE | 核验结果已过期或环境已变化 | 重新核验 |
| REJECTED | 应用信息未通过核验 | 根据原因查看签名、注册或报告时间问题 |
| FAILED | 暂时无法读取设备报告 | 到达下次可刷新时间后重试 |

操作只放在当前设备的应用详情中。默认显示一条状态说明和一个主操作；稳定原因码放在可展开的诊断详情，供支持人员定位。不能将身份核验成功显示为“管控已生效”。未经核验的结果不显示历史签名或旧的有效期。

HTTP 错误沿用统一问题响应。常见情况：非法 `If-Match` 为 400，未满足近期认证为 401，无目标租户权限或当前角色为 403；已通过路径租户授权、但该租户下找不到绑定为 404；状态/容量/尝试冲突为 409，绑定版本变化为 412，目录缺少可信签名为 422，缺少 `If-Match` 为 428，冷却期为 429，连接器不可用为 503。该列表不穷尽所有领域校验；前端遇到 412 应重新读取绑定再由管理员确认操作，不能静默换版本重试。

## 配置与连接器接入

| Spring 配置键 | 默认 | 允许范围 |
| --- | --- | --- |
| `manager.emm.application-evidence.max-report-age-seconds` | 600 | 1–3600 秒 |
| `manager.emm.application-evidence.max-reuse-age-seconds` | 120 | 1–300 秒 |
| `manager.emm.application-evidence.clock-skew-seconds` | 15 | 0–30 秒 |

非法时间配置使组件初始化失败；这些配置参与上下文摘要，修改后旧事实失效。200 个应用上限、30 秒刷新间隔、120 秒尝试窗口是当前实现的固定保护值，不宣称已支持后台可视化修改。达到上限时已有应用可以刷新，新应用被拒绝；当前阶段尚未提供单条证据移除入口。

连接器必须显式声明 `supportsApplicationReports()` 及非空 `applicationReportRevision()`，实现注册来源读取和最小应用报告读取。默认接口返回空修订号，避免新连接器误用已有证据。修订号只允许 1–128 位字母、数字、点、下划线和连字符。

Google 适配器的当前修订为 `google-application-report-v1`。发布时如调整报告解释、提供方信任或相关配置，维护者必须递增修订号；这是显式版本契约，不是自动检测所有配置变化。中国大陆默认路径仍不启用 Google，正式 EMM 准入与合作方连接器验收仍是部署前提。

日志与审计只使用租户、操作者、记录 ID、固定动作和原因；内部对象的 `toString()` 隐去报告及上下文。不要记录原始提供方异常，其正文可能包含凭证。当前审计动作包括 `MANAGED_APPLICATION_REFRESH_REQUESTED` 和 `MANAGED_APPLICATION_EVIDENCE_<状态>`，可按证据记录 ID 关联。

## 验收范围

必须覆盖真实 MVC、数据库事务、授权与绑定核验；提供方可以用明确的本地夹具模拟。至少验证正向保存与读取、网络期间无事务、角色与跨租户、绑定撤销和权限变化竞态、平台不匹配、报告缺失/陈旧/签名不可信、注册来源前后不一致、重复刷新/迟到尝试、缓存到期和清理级联。夹具不能证明正式 EMM 准入、真机或电视执行能力。
