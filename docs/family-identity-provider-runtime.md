# 短信与微信配置的受控发布

管理端批准发布后，受限部署主机执行原操作，身份服务实际读取新版本；服务端再向真实进程发随机挑战，只有所有固定实例均匹配才能显示“配置已加载”。首次版本始终保持短信、微信、账号安全入口和销售关闭。

主机管理员按顺序准备：

1. 新建独立的 [运行核对目录](../scripts/initialize_identity_provider_runtime.ps1)，与已有加密配置目录使用同一环境别名。密钥保留在受限文件中，不发送到聊天。
2. 审查正式 identity 镜像和 provider JAR，用 [目标准备工具](../scripts/initialize_identity_provider_target.ps1) 绑定已有 ConsumerIdentity 部署、实际镜像 ID、JAR SHA256、固定后台地址及两个私有配置目录。工具检查实际镜像中的 JAR，但不会启动该镜像或修改现有服务。
3. 管理员在“短信与微信”选择配置版本、核对安装包与身份扩展，批准本次发布。
4. 在该部署主机运行 [受控执行器](../scripts/run_family_identity_release.ps1)，传入固定目标文件和原操作 ID。执行器仅重建该项目的一个 identity 实例，不覆盖原 `.env` 和秘密目录，不改变账号数据库或身份域。
5. 管理端显示“配置已加载，入口仍关闭”后，继续真实短信、微信及账号流程验收。配置加载成功不表示供应商验收成功，也不开放收费。

发布中断时，先查询原操作。发送 BEGIN 前主机已经保存“待核对”指针；普通启动会暂停，不能悄悄回到旧版本。执行器重新运行时查询原结果；对已发送 BEGIN 的操作不重复重建。准备阶段失败且尚未执行 BEGIN，服务端可安全取消原操作，再重新批准。

普通启动和发布全程共用同一个主机锁，避免两个操作互相覆盖。旧操作的成功记录只用于查询，不能替换更新的生效版本。服务端明确证明“尚未开始”时，可以安全取消原 claim；取消后的旧版本恢复和首次待核对状态解除，都需要服务端当前资格与本机签名、文件核对通过。执行结果未知时不会自动回退。

回退也必须新建审批操作，选择服务端曾实际确认的历史版本。OTP HMAC 或微信 AppID 变化的历史版本，本轮不支持自动回退；账号数据、手机号和微信解绑结果不会随配置回退而恢复。

正常 [部署启动](../scripts/start-deployment.ps1) 会验证受认证的生效指针、版本文件和秘密文件是否变化，保留加密配置及运行核对目录的挂载。身份实例使用固定镜像；后端与网页保持原构建流程。未经核对、文件变更或执行结果未知时，工具会停止并要求查询原操作。

当前主机执行器只支持单身份实例。多实例目标会在领取或重建前拒绝，必须另行完成分批发布和全部实例核对设计。真实短信与微信仍需主体配置、授权测试手机号和正式签名安卓设备。

精确接口、签名和状态规则见 [运行合同](superpowers/plans/2026-10-17-provider-runtime-contract.md)。本轮验证证据由主交付说明汇总；HTTP/Docker 边界替身测试与真实 Keycloak 进程验证分别记录。
