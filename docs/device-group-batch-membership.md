# 机构设备组批量入组

## 行为与边界

机构 OWNER/ORG_ADMIN 在设备组详情一次选择 1–50 台当前已激活设备。选择列表分页，展示设备名称、平台、状态和 ID；提交前核对数量与部分名称。需要近期多因素认证。设备组成员只是目录关联，不会自动下发应用规则或证明系统策略执行。

`POST /api/v1/tenants/{tenantId}/device-groups/{groupId}/devices/batches` 接收：

```json
{"devices":[{"deviceId":"<uuid>","registrationId":"<uuid>"}]}
```

要求 `If-Match: "<group-version>"` 和稳定的 `Idempotency-Key`。返回更新后的组详情与 `ETag`。设备 ID 不得重复。服务端按设备 ID 排序锁定当前注册记录，核对机构租户、活动状态、注册周期和儿童档案未归档。已有且注册周期相同的成员跳过；旧注册周期、失效设备、已归档组、旧组版本或超过 5000 台容量，整批拒绝且事务回滚。真正新增成员逐台记审计，整批只递增一次组版本。组成员已存在时不重复写入。

网络结果不明时界面保留原请求内容、版本和幂等键供重试。版本冲突由管理员刷新设备组后重新选择。当前不支持动态分组策略、批量系统执行、逐设备命令回执或自动撤销现有独立策略。

## 发布前核对

需要真实 MySQL/OceanBase 上核对批量原子性、并发组编辑、成员权限撤销、重复请求、旧注册周期、容量边界与审计；还需浏览器窄屏、键盘和机构账号核对。本阶段的静态分析和构建不构成这些运行证据。
