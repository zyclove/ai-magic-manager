# 设备限时支持授权

承接已批准诊断计划步骤 3。配对码只核对接收人，实际授权由客户当前管理员明确提交。

## 授权内容

- 一个授权绑定单一租户、设备、档案、注册周期、接收人 OIDC 主体及授予者成员版本。
- 三种可组合诊断类型：DEVICE_STATUS（版本及设备状态）、CAPABILITIES（脱敏能力证据）、CONFIGURATION_METADATA（当前下发元数据、哈希及确认时间）。不含策略正文、密钥、儿童自由文本或执行权限。
- 创建允许 5–1440 分钟，界面默认一小时。服务器在首次成功创建时计算截止时间；重放返回同一授权的当前状态，不延长期限。
- 客户确认接收人主体、配对码、设备注册周期和设备版本后，原子消费配对请求并创建授权。同一个配对请求最多用于一个授权。授权设备必须处于 ACTIVE；退出管理或重新注册使支持访问失效，客户管理员自己的撤销设备诊断预览仍保留。
- 使用当前 OWNER／GUARDIAN／ORG_ADMIN 与近期 MFA；写入要求 Idempotency-Key，创建 If-Match 对应设备版本，撤销 If-Match 对应授权版本。幂等记录只保存授权引用及请求摘要，不能保存配对码。
- 接收人必须具有当前 IdP 成人资格与近期 MFA。授权不赋予租户成员身份，也不允许使用普通客户或设备列表接口。

## 每次读取

按授予者成员→档案→设备→授权行锁定，重新核对成员版本、设备状态、注册周期、档案、接收人、诊断类型及期限。只读取选中诊断类型的数据，序列化完成后再次检查到期时间，再记录成功读取审计。撤销与读取通过授权行锁串行化。数据响应 no-store，并按 Authorization 区分。

客户可列出本租户授权并随时撤销；接收人只能分页查看发给自己的授权。列表状态不替代实际读取的当前权限检查。权限变化、设备生命周期变化与到期均无法通过旧链接、旧配对码或幂等重放恢复访问。

创建按租户互斥，防止跨实例重复提交或容量竞争。每个租户最多 200 项未过期授权，每台设备最多 20 项；通过当前锁定读取判断。每次创建、撤销及支持诊断成功读取写入客户审计。配对、授权和即时诊断管理界面见 [support-collaboration-ui.md](support-collaboration-ui.md)；诊断包、加密下载及到期产物删除按后续步骤继续实现。

## 接口

| 操作 | 路径 | 当前权限 |
| --- | --- | --- |
| 创建设备授权 | POST `/api/v1/tenants/{tenant}/devices/{device}/support-grants` | 客户管理员、近期 MFA、设备 If-Match、幂等键 |
| 查看客户授权历史 | GET `/api/v1/tenants/{tenant}/support-grants` 及 `/{id}` | 客户管理员、近期 MFA |
| 撤销 | POST `/api/v1/tenants/{tenant}/support-grants/{id}/revoke` | 客户管理员、近期 MFA、授权 If-Match、幂等键 |
| 查看收到的授权历史 | GET `/api/v1/support/grants` 及 `/{id}` | 本人、成人资格、近期 MFA |
| 读取授权范围内诊断 | GET `/api/v1/support/grants/{id}/diagnostic-preview` | 本人资格及完整的当前授权检查 |

分页使用既有 ItemPage 限额和游标协议。对象响应返回版本 ETag；所有成功响应禁止缓存。三种诊断类型有固定顺序；未获授权的诊断部分返回 null，不输出该部分数据。到期或已撤销授权在读取设备能力之前即拒绝，获得事务锁后与序列化之后还会再次检查，避免以容量错误暴露失效授权的设备状态。

配对消费、授权插入、创建审计及幂等结果在同一事务中提交。任一步失败，配对仍可用于后续有效重试。不同租户不能同时消费同一码；与取消竞争时，先成功提交的一方确定结果，后续使用需遵守当前状态与版本。

## 验证范围

H2 组合检查包含配对、授权、管理员预览、严格投影、模块边界，以及非空 V25→V26／V26→V27 升级。授权专项覆盖三个独立数据范围、敏感正文排除、同键重放、不同键／不同租户竞争、取消竞争、容量回滚、成员版本变化、注册变化、归档、撤销、到期、序列化失败与超限、读取中到期以及撤销等待读取事务。

这些身份检查使用隔离测试 JWT，不是管理员真实完成 OTP 的证据。生产 Dart 客户端授权 HTTP 旅程与支持协作界面已实现并单独验证；诊断包与完整阶段审阅仍待后续完成。本文件不代表部署记录。
