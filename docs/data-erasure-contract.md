# 主体数据删除、保留与恢复契约

## 目标与适用范围

承接总计划 Task 10、功能规范 RPT-01-A。删除必须覆盖事务数据、派生报表和诊断、事件/缓存、外部副本及备份恢复后的再删除；归档、撤销观测授权、设备退出、商业合同终止仍是不同操作。本契约不构成某地区法律合规结论。

当前实现顺序：完整存储清单及删除前检查 → 持久化作业和访问隔离 → 域内删除/匿名化与外部回执 → 独立恢复账本及恢复闸门 → Flutter 确认/进度/失败恢复 → MySQL、备份恢复、并发与全阶段验收。前置检查的交付不能视为删除功能完成。

## 权限与操作

- 主体级删除由 FAMILY 的 OWNER 或 ORGANIZATION 的 ORG_ADMIN 发起；GUARDIAN、TEACHER、CHILD、AUDITOR 不能发起整份主体资料删除。租户、成员当前版本和近期 MFA 每次重新检查。
- 前置检查只提供当前范围和待处理事项，不产生删除授权。返回不包含姓名、邮箱、儿童理由、凭据或存储内容；响应禁止缓存。
- 正式提交前必须展示主体、关联设备、会被删除的数据、明确保留的数据及原因、外部处理状态和备份恢复规则。独立的未预勾选确认、版本条件、短有效期预览和幂等键缺一不可。
- 不用删除操作隐式擦除设备。先完成设备退出；紧急撤销凭据与本地清理完成分开显示。未确认的本地副本在结果中保留为未完成项。
- 凭据、观察授权、支持授权及既有下载必须在作业接受后隔离，后续请求与后台生成均不能重新公开目标内容。已经下载至用户电脑的副本不承诺远程收回。

## 存储覆盖

`backend/src/main/resources/retention/subject-data-stores.json` 是代码审核的表/列清单。新增、删除或重命名表列需要显式更新分类，不能默认为无关。元数据与清单不一致时拒绝生成有效检查结果；不能跳过未知存储继续声称完成。类型、长度、约束及字段语义变更仍需单独进行结构与隐私评审，当前清单不自动认证这些变化。

每个表记录所属域和处理类别：

| 类别 | 处理义务 |
|---|---|
| SUBJECT_DATA | 删除或匿名化目标主体内容及其依赖，保留不可逆、无显示资料的最小防复活标记 |
| DEVICE_DATA | 按不可变注册代际处理目标设备内容、凭据和恢复凭据；不串到重新注册的设备 |
| DERIVED_COPY | 清除已有导出、报表、诊断与重试/幂等响应中的副本；禁止在删除后重新生成 |
| AUTHORIZATION | 撤销目标主体关联身份、邀请、班级关系和支持授权；跨租户共享账号不能整体删除 |
| AUDIT_RETENTION | 逐地区政策决定最小审计与保留依据；未配置政策不能宣称全部法定删除 |
| SHARED_CONFIGURATION | 判定结构化文档内对主体/设备的引用，解除引用且不得删除其他主体共用配置 |
| SHARED_ACCOUNT | 保留无目标个人内容的租户/商业/平台数据；个人引用仍须单独审查 |
| OPERATIONAL_METADATA | 去掉携带主体内容的事件/重放/缓存，纯计数或锁行可保留 |

表级分类不等于删除 SQL。处理器还必须覆盖列、JSON 内引用、外键顺序、历史快照、幂等缓存、事件重放及同一任务中多个主体共享的报表。特别禁止仅删除 `subjects` 行或仅按当前设备列表清除历史注册数据。

不能仅为消除覆盖回归的失败而重新生成清单。必须先评估新增字段的个人内容、引用关系和处理器，再更新受评审的分类。

## 作业和完成判定

- 状态：待确认、已接受、正在隔离、正在清理、等待外部处理、需要重试、已完成。接受后不可恢复原资料；提交前可取消预览。
- 作业采用有界批次、持久化检查点、租约及 fencing token；恢复和重试不重复发放外部权限，不能把异常吞掉后标记完成。
- 每个已配置存储适配器有明确回执；未配置存储标记为未使用，无法核验的已使用存储标记为待处理。时间截止不能自动转为完成。
- 审计保存任务 ID、目标不可逆标识、数据类别、计数、政策版本、操作者、时间和失败码，避免重新存入已删除的个人内容。
- 个人数据保留期需按类别、租户/地区配置；读取时过滤过期内容，后台物理清理单独验收。审计保留与使用摘要保留不可混用。

## 备份恢复

- 删除账本必须独立于业务库的备份/恢复范围，持久记录已经接受的删除目标与不可变范围，先可靠落账再对用户返回接受。
- 业务库与账本之间失败必须可恢复：账本已接受、业务作业未建立时由恢复协调器补建；禁止丢弃账本记录。
- 恢复后的实例在重新开放业务接口、设备接入与后台生成之前，先对独立账本核对水位并重新隔离/清理。缺少账本、读取失败、未知版本或回执不全时维持维护状态。
- 不能只把删除账本也备份到同一个 SQL 文件；恢复同一份旧备份会让两者一起回退。
- 恢复验收必须用“创建个人数据 → 做旧备份 → 删除 → 恢复旧备份 → 启动隔离与再删除 → 才开放访问”的真实过程验证。

## 实施记录与判定

- Ruling：先采用主体级删除，另保留未来账号/整租户范围，原因是批准规范已有主体与设备生命周期；不把主体删除扩展为跨租户账号或合同删除。
- Ruling：新删除功能未完成全部执行/恢复链路前，不提供可执行的删除按钮。前置检查明确 `executionAvailable=false`，不能出现“可安全删除/已全部删除”的误导状态。
- Ruling：沿用 Spring Security、JDBC 事务、Flyway 与现有领域接口；恢复账本的部署与凭据须独立配置，不复用业务备份来声称抗恢复。

## 持久化删除准备（1.0.0 开发中）

该步骤保存短期准备记录，供确认流程恢复使用；没有接受删除请求，也没有启动删除作业。`executionAvailable=false` 始终保留，快照内 `readyToErase=false`。

- 创建：`POST /api/v1/tenants/{tenant}/subjects/{subject}/erasure-previews`，必须带当前主体的强 `If-Match` 和非空、最多 128 字符的 `Idempotency-Key`。
- 恢复：同一路径下 `GET /{id}`。返回准备记录自己的 ETag、创建/到期时间、状态和可用时的前置检查快照；响应禁止缓存，按 Authorization 区分。
- 取消：`POST /{id}/cancel`，必须带准备记录的强 `If-Match`。重复相同取消不重复审计，不恢复已移除的快照。
- 每次请求先锁定当前成员权限、校验近期 MFA，再锁定目标主体。准备记录绑定创建者及当时成员版本；其他管理员、已撤权或成员版本变化后的身份不能读取或重放该记录。
- 同一创建者、同一主体至多保留一份 PREPARED 快照，新记录将之前的标记 SUPERSEDED 并立即清空快照。不同管理员的准备记录互不覆盖。
- 记录有效期为 5 分钟。到期标记 EXPIRED，主体版本变化或已审核存储清单变化标记 STALE；这些状态、CANCELLED 和 SUPERSEDED 均不返回旧快照。未知物理表/列仍拒绝提供有效准备结果，但允许管理员取消自己的准备。
- 幂等只保存记录引用和请求摘要；同键重试读取当前状态，不返回旧的 PREPARED 响应。原键不能绑定新主体版本。键只在同一租户、主体和创建者范围内有效，数据库只存键摘要。
- 每创建者、每主体一小时最多新建 20 份，重复已存在的请求不消耗新名额；到限额不覆盖当前准备记录。
- 默认每 60 秒运行有界清理：一批最多 50 份到期快照，另清理最多 50 份已终止且创建超过 24 小时的记录。可通过 `manager.erasure-previews.cleanup.enabled` 关闭调度；`interval-seconds` 调整间隔。物理清理只针对准备缓存及其幂等记录，不代表业务数据、审计或备份已删除。

快照只是 `evaluatedAt` 时的计数与清单。设备、关联成员和其他内容之后仍可能变化；PREPARED 不代表范围冻结，不允许据此执行删除。正式提交必须重新验证所有范围、明确保留政策与外部处理器，并先可靠写入独立删除账本。

### 本步骤记录

- Ruling：沿用现有主体锁与成员版本锁，使用数据库唯一键约束并发重试；不额外引入 Redis 或另一个持久化框架。准备记录属于 DERIVED_COPY，新增表及 12 列已显式纳入存储分类。
- Ruling：5 分钟有效期、24 小时幂等记录留存是短期操作缓存的默认值，不作为个人数据或法定审计的保留政策；正式删除政策仍另行实现。
- 已验证：首批接口缺失测试 4 项均以 404 失败；实现后 15 项通过；扩展 H2 24 项通过（准备 12、前置检查 10、全新初始化 1、模块边界 1），真实 MySQL 准备/前置检查/模块边界 23 项与独立全新初始化 1 项通过。一次独立静态复核未发现缺陷，完整业务回归结果见 `releases/stage-erasure-preview-verification.json`。

## 独立账本基础（1.0.0 开发中）

独立 JDBC 账本提供显式新库初始化、连续记录、规范化请求幂等、独立提交及有界链读取；删除前检查返回未配置、身份不匹配、损坏或待协调等阻断原因。配置、部署和已验证范围见 [账本实施记录](erasure-ledger-plan.md)。

账本的读取游标不是业务已应用水位，读取到尾部不能使删除完成或开放恢复后的访问。全局维护闸门和首批域处理器的后续实施见下文；完整处理器覆盖及真实旧备份恢复演练仍未完成，没有公开删除提交入口。

## 恢复作业基础（1.0.0 开发中）

新增业务库恢复读取状态与持久作业，直接进入首版初始化基线。恢复协调器每页至多导入 100 条独立账本记录，作业和读取游标在同一业务事务提交；整页失败会回滚，已接受的独立账本记录不随业务回滚丢失。已读范围缺失作业、身份变化、内容损坏或数据库失联时拒绝继续。

内部处理接口支持数据库时间租约、续租、过期重新领取及延后重试，每次领取递增 fencing token。领取时对照独立账本核验范围；旧持有者不能覆盖新持有者。作业只允许 ACCEPTED、CLAIMED、RETRY_REQUIRED 三个内部状态，不提供完成操作，也没有自动删除 worker。

启动保护始终核对业务读取状态和独立账本，空账本也不能绕过身份及回退检查；非空账本至多持久化一页待恢复记录，然后继续拒绝就绪。到达读取尾部不会解除保护。公开删除提交、跨节点隔离、域处理器、外部回执、已应用水位与真实备份恢复再删除仍未完成，前端仍不得显示删除已可执行。

作业保存恢复所需的不透明租户/主体标识、注册代际和请求摘要，避免重新保存姓名、邮箱、理由或凭据。存储分类为 AUDIT_RETENTION，不代表已经确定永久保留依据或完成作业清理。实现决策与阶段证据见 [恢复作业实施记录](erasure-recovery-jobs-plan.md)。

## 运行期许可与接受屏障（1.0.0 开发中）

HTTP、定时、异步和事件入口登记独立账本工作许可；同步嵌套复用同一许可，异步线程重新登记。短事务登记后执行业务，结束后明确释放。许可不按时间自动清除；进程中断、释放失败及取消、超时或异常完成 Future 的未知完成状态均不能充当排空证明。

内部账本接受操作发现仍有工作时，先独立提交不可变暂停意向，再报告尚未接受。暂停立即拒绝新工作；原工作退出后，同一请求重试才可写入接受记录。暂停意向不能被不同范围请求覆盖。该协议当前保持全局维护，尚未实现其他租户继续工作的目标级隔离体验；公开提交和进度控制面仍未开放。

维护响应为不缓存的 503，管理端提示结果暂时无法确认，并保留原操作内容和幂等键供重试。就绪探针与存活探针分开。不得通过清空许可、重建账本或忽略就绪失败重新开放访问。实现与验证范围见[运行期许可实施记录](erasure-runtime-admission-plan.md)。

## 使用观测与报表处理（1.0.0 开发中）

首个内部域处理器实际删除目标注册代际的使用批次、观测头、应用清单、观测设置，以及含该主体的使用报表任务和分片。共享报表按整份副本清除，其他主体原始记录保留；不同租户或重新注册后的其他主体设备不按旧设备 ID 一并清除。

每批在锁定恢复作业并核对独立接受账本后执行。数据删除与步骤检查点同一事务，提交前再次核验独立账本与数据库时间租约。报表每批最多扫描 25 个任务，每任务最多 200 个分片；观测批次每次至多删除 25 行。选择摘要、分片集合、历史注册或存储清单不一致时回滚。检查点可跨处理器重建恢复；未知处理器版本拒绝继续。

步骤 DONE 只表示该六个存储的当前处理阶段完成。它不完成整个作业、不解除维护状态、不替代审计保留、其他派生副本、授权、事件、共享配置、外部副本和备份恢复的处理。当前仍无自动删除调度、公开提交或完成接口。具体范围与证据见[观测处理器实施记录](erasure-observation-plan.md)。

## 审批与配额处理（1.0.0 开发中）

第二个内部处理器覆盖审批请求与理由、申请槽位、决定、签发授权、投递尝试与回执、关联通知及阅读记录，以及主体配额日历、计划及修订、池、租约、分配、明细和配额事件，共 17 个存储。沿用独立接受账本与同事务检查点，按不可变注册代际核对历史请求/租约/槽位。

先有界扫描配额事件，核对支持的事件类型、严格 JSON 字段、聚合标识与父记录归属，再清理数据关联图。每批最多扫描 25 个事件或删除 25 行；关联明细先于父记录删除，共享策略、应用定义和其他主体的数据保留。缺失历史范围、跨主体配额边、孤立事件或损坏载荷会回滚当前批次并阻断；不自动猜测归属或补偿其他主体余额。

重试从 EVENTS/VERIFY/DATA 检查点恢复；每次数据批次前逐页复核保留事件的严格载荷、标识与归属。DONE 重入通过 RECHECK 再次逐页核验，未检查完时不会返回完成，且重新出现的关联数据会阻断。通知叶子显式逐行处理，不依赖级联漏计。这些核验仍以业务入口已排空并保持暂停为前提。

此步骤仍不结束全局恢复作业，也不代表通用幂等、其他消息副本、审计、设备凭据或所有外部副本已处理。具体决策与验证见[审批与配额处理计划](erasure-access-quota-plan.md)。

## 支持授权与诊断副本处理（1.0.0 开发中）

内部 `SUPPORT_DIAGNOSTICS` 步骤按已接受的租户、主体和不可变设备注册范围，先物理删除诊断包，再删除对应支持授权。诊断包的加密内容与元数据同一行，所有任务状态均进入清理；每批最多删除 25 行，删除与检查点同事务提交。

每批核对当前设备和历史诊断/授权范围；同一注册被其他主体占用、未接受的历史注册、诊断包与授权的主体/设备/注册不一致均阻断。处理器重建后恢复原检查点；过期持有者不能继续工作，DONE 重入发现目标数据再现时拒绝返回完成。

租户级锁行以及支持人员的全局配对资料保留。配对资料描述支持人员账号，目标主体的关联路径随支持授权行删除；主体删除不会扩展为跨租户账号删除。通用幂等响应、审计、其他事件及用户已下载的外部副本仍需后续处理。本步骤不开放公开删除提交、自动 worker 或全局完成状态。实施和验收记录见[支持与诊断处理计划](erasure-support-diagnostics-plan.md)。

## 设备身份附属数据处理（1.0.0 开发中）

内部 `DEVICE_IDENTITY` 步骤删除已接受注册范围内的凭据轮换、设备凭据、凭据范围、设备组成员和能力记录。轮换叶子先删除，每批总共最多 25 个物理行；数据与检查点仍通过独立账本核对和带租约的事务提交。

当前主体设备必须全部处于已接受的范围并已退出。同一元组被他主体占用、仍活跃的凭据范围或仍可用的活跃凭据会阻断。涉及目标的轮换记录两端必须是同一租户、设备和注册，不能借轮换关联删除他人的凭据。能力记录通过当前设备的完整元组选取，旧注册的删除不影响重新注册的能力资料。

共享设备组、其他设备成员及设备主记录保留；主记录仍供后续处理器核对关联。注册申请/证明、配置下发、退出回执、共享策略以及通用缓存和外部副本仍由完整编排继续处理。本步骤不会隐式退出或擦除设备，也不开放公开删除或全局完成。实施和验证见[设备身份处理计划](erasure-device-identity-plan.md)。

## 权限观察覆盖（1.0.0 开发中）

`device_permission_observation_settings`、`device_permission_observation_snapshots`、`device_permission_observation_rate` 的 23 列属于 observation 域 DEVICE_DATA。设置包含个人操作理由，快照包含应用/权限内容，速率记录仍关联设备注册；不能因为授权关闭或数据仅为计数而跳过目标清理。

三个存储加入现有 `OBSERVATION_REPORTS` 的 DATA 阶段，共享最多 25 个物理行的批次预算，并与检查点处于同一事务。选择与删除均绑定已接受的租户、设备、注册元组；相同 ID 的其他租户及重新注册的其他主体不受影响。任一表的数据再现都会使 DONE 复查拒绝继续。删除中途失去租约或保存检查点失败时，已删记录一并回滚。

该范围不涵盖可能存在于事件、审计、幂等响应和其他域中的派生副本；它们仍必须由完整删除编排覆盖。沿用业务排空和独立账本约束，不增加公开删除入口，不将内部步骤完成作为全局完成。权限观察功能开关保持默认关闭。

## 设备配置副本处理（1.0.0 开发中）

内部 `CONFIGURATION_DELIVERY` 步骤清理已接受注册范围的配置回执、配置流、下发内容及签名副本、配置游标，共四个存储。回执和流先于下发删除，配置头最后删除；四表共用每批最多 25 个物理行的预算，不依赖级联删除。

每批核对当前主体设备范围、设备撤销和凭据不可用。配置头与下发的设备字段、流和回执的注册关联必须一致；任一端涉及目标的错误关联会在删除前阻断。下发归属校验同时检查关联两端的设备 ID，避免错误设备字段隐藏在另一注册的头下面；实际删除仍严格限定已接受的 tenant/device/registration 元组。该检查可能阻断同设备 ID 的其他注册中已损坏的关联，不会推断或修复归属。

删除与步骤检查点通过既有独立账本和租约事务提交；重建处理器后继续已有步骤，旧 worker、未知处理器版本或损坏检查点不能继续。DONE 重入重新检查四表，目标数据再现时拒绝返回完成。阶段完成仍不结束恢复作业或开放业务。

共享策略草稿、预览、版本、发布及设备主记录保持不变，注册申请、退出回执、本地清理证据、共享文档内引用、其他缓存/事件/审计和外部副本仍由后续完整编排处理。服务器配置副本已清理不代表终端本地副本已清理。实施及验证范围见[配置处理计划](erasure-configuration-plan.md)。

## 注册与设备退出副本处理（1.0.0 开发中）

内部 `DEVICE_LIFECYCLE` 步骤覆盖注册申请、注册证明、退出预览、退出头、清理回执和退出操作六个存储。注册申请与证明按明确的租户/主体归属选择；申请的非空设备 ID 必须属于已接受范围，不能按设备 ID 删除另一主体的申请。四个退出存储严格按租户/设备/注册元组选取，重新注册后其他主体的数据保持不变。

退出头和预览没有数据库外键保证操作归属，因此每批在删除前核对关联两端。涉及目标的缺失操作、跨设备/注册关联或未知退出状态/证据均阻断；空操作引用可正常清理。当前主体设备范围、撤销状态与凭据不可用仍须先验证。

未到期且未取消的退出操作阻断该批，包括已上报清理的操作：设备仍可能需要原确认响应。该保护保留协议记录，不改变当前全局维护闸门，也不保证维护期间接口可访问。过期或取消仅终止服务器清理协议的可用性，不证明终端数据已删除。每次返回的 `unverifiedLocalRegistrations` 从独立接受清单重新计算，即使退出记录不存在或已删除，目标注册也不会被解释成本地清理已验证；完整编排必须保留这个未完成边界。

先注册证明后申请，先预览/头/回执后退出操作，每批共用最多 25 个物理行的预算。实际删除与持久检查点同事务，提交前再次核验账本与租约；DONE 重入检查六表数据再现，保持本地未验证计数。此步骤不会结束全局作业、释放维护许可或开放删除入口。

设备主记录、受管供应方注册、共享策略引用及其他缓存/事件/审计/外部副本仍需后续处理；服务器副本清理不能替代设备实际清理或备份恢复验收。实施与证据见[生命周期清理计划](erasure-lifecycle-plan.md)。

## 通用幂等结果归属与内部清理（1.0.0 开发中）

通用响应增加同事务、不可变的显式主体归属；首个业务接线为创建档案，使用实际生成的主体 ID。清理响应正文、原始调用者、原始操作和请求摘要后，保留不透明拒绝重放标记。旧请求即使过期或内容变化，也在执行和只读原结果查询中返回 410，不能重新创建或恢复已清理结果。

内部步骤采用 DATA、父行 VERIFY、独立归属 RECHECK 及 DONE 检查点，按 UUID 有界续扫；归属不明的全局缓存和绕过外键恢复出的孤立归属均阻止完成。其他生产调用仍待逐项接线，内部 DONE 不代表作业完成，不解除维护暂停，也不开放公开删除入口。范围与后续接线见[幂等结果清理计划](erasure-idempotency-plan.md)。

审批、设备审批、配额和配额计划的 10 个操作已按实际返回记录的主体接入归属。沿用原有权限、主体/设备检查和缓存后的状态协调顺序；已清理的原请求键不能通过过期、改变内容或只读恢复重新生成结果。租户资源路径在授权入口要求规范 UUID，避免数据库大小写别名绕过资源身份边界。具体范围、验收和仍未覆盖的调用见[审批与配额归属计划](erasure-access-quota-idempotency-plan.md)。
