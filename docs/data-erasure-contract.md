# 主体数据删除、保留与恢复契约

## 目标与适用范围

承接总计划 Task 10、功能规范 RPT-01-A。删除必须覆盖事务数据、派生报表和诊断、事件/缓存、外部副本及备份恢复后的再删除；归档、撤销观测授权、设备退出、商业合同终止仍是不同操作。本契约不构成某地区法律合规结论。

当前实现顺序：完整存储清单及删除前检查 → 持久化作业和访问隔离 → 域内删除/匿名化与外部回执 → 独立恢复账本及恢复闸门 → Flutter 确认/进度/失败恢复 → MySQL、备份恢复、并发与全阶段验收。前置检查的交付不能视为删除功能完成。

## 权限与操作

- 主体级删除由 FAMILY 的 OWNER 或 ORGANIZATION 的 ORG_ADMIN 发起；GUARDIAN、TEACHER、CHILD、AUDITOR 不能发起整份主体资料删除。租户、成员当前版本和近期 MFA 每次重新检查。
- 前置检查只提供当前范围和待处理事项，不产生删除授权。返回不包含姓名、邮箱、儿童理由、凭据或存储内容；响应禁止缓存。
- 正式提交前必须展示主体、关联设备、会被删除的数据、明确保留的数据及原因、外部处理状态和备份恢复规则。独立的未预勾选确认、版本条件、短有效期预览和幂等键缺一不可。
- 不用删除操作隐式擦除设备。先完成设备退出；紧急撤销凭据与本地清理完成分开显示。未确认的本地副本在结果中保留为未完成项。
- 凭据、观察授权、支持授权及既有下载必须在作业接受后隔离，后续请求与后台生成均不能重新公开目标内容。已经下载至用户电脑的副本不承诺远程收回。

## 存储覆盖

`backend/src/main/resources/retention/subject-data-stores.json` 是代码审核的表/列清单。新增、删除或重命名表列需要显式更新分类，不能默认为无关。元数据与清单不一致时拒绝生成有效检查结果；不能跳过未知存储继续声称完成。类型、长度、约束及字段语义变更仍需单独进行迁移与隐私评审，当前清单不自动认证这些变化。

每个表记录所属域和处理类别：

| 类别 | 处理义务 |
|---|---|
| SUBJECT_DATA | 删除或匿名化目标主体内容及其依赖，保留不可逆、无显示资料的最小防复活标记 |
| DEVICE_DATA | 按不可变注册代际处理目标设备内容、凭据和恢复凭据；不串到重新注册的设备 |
| DERIVED_COPY | 清除已有导出、报表、诊断与重试/幂等响应中的副本；禁止在删除后重新生成 |
| AUTHORIZATION | 撤销目标主体关联身份、邀请、班级关系和支持授权；跨租户共享账号不能整体删除 |
| AUDIT_RETENTION | 逐地区政策决定最小审计与保留依据；未配置政策不能宣称全部法定删除 |
| SHARED_CONFIGURATION | 判定结构化文档内对主体/设备的引用，解除引用且不得删除其他主体共用配置 |
| SHARED_ACCOUNT | 保留无目标个人内容的租户/商业/平台数据；个人引用仍须单独审查 |
| OPERATIONAL_METADATA | 去掉携带主体内容的事件/重放/缓存，纯计数或锁行可保留 |

表级分类不等于删除 SQL。处理器还必须覆盖列、JSON 内引用、外键顺序、历史快照、幂等缓存、事件重放及同一任务中多个主体共享的报表。特别禁止仅删除 `subjects` 行或仅按当前设备列表清除历史注册数据。

不能仅为消除覆盖回归的失败而重新生成清单。必须先评估新增字段的个人内容、引用关系和处理器，再更新受评审的分类。

## 作业和完成判定

- 状态：待确认、已接受、正在隔离、正在清理、等待外部处理、需要重试、已完成。接受后不可恢复原资料；提交前可取消预览。
- 作业采用有界批次、持久化检查点、租约及 fencing token；恢复和重试不重复发放外部权限，不能把异常吞掉后标记完成。
- 每个已配置存储适配器有明确回执；未配置存储标记为未使用，无法核验的已使用存储标记为待处理。时间截止不能自动转为完成。
- 审计保存任务 ID、目标不可逆标识、数据类别、计数、政策版本、操作者、时间和失败码，避免重新存入已删除的个人内容。
- 个人数据保留期需按类别、租户/地区配置；读取时过滤过期内容，后台物理清理单独验收。审计保留与使用摘要保留不可混用。

## 备份恢复

- 删除账本必须独立于业务库的备份/恢复范围，持久记录已经接受的删除目标与不可变范围，先可靠落账再对用户返回接受。
- 业务库与账本之间失败必须可恢复：账本已接受、业务作业未建立时由恢复协调器补建；禁止丢弃账本记录。
- 恢复后的实例在重新开放业务接口、设备接入与后台生成之前，先对独立账本核对水位并重新隔离/清理。缺少账本、读取失败、未知版本或回执不全时维持维护状态。
- 不能只把删除账本也备份到同一个 SQL 文件；恢复同一份旧备份会让两者一起回退。
- 恢复验收必须用“创建个人数据 → 做旧备份 → 删除 → 恢复旧备份 → 启动隔离与再删除 → 才开放访问”的真实过程验证。

## 实施记录与判定

- Ruling：先采用主体级删除，另保留未来账号/整租户范围，原因是批准规范已有主体与设备生命周期；不把主体删除扩展为跨租户账号或合同删除。
- Ruling：新删除功能未完成全部执行/恢复链路前，不提供可执行的删除按钮。前置检查明确 `executionAvailable=false`，不能出现“可安全删除/已全部删除”的误导状态。
- Ruling：沿用 Spring Security、JDBC 事务、Flyway 与现有领域接口；恢复账本的部署与凭据须独立配置，不复用业务备份来声称抗恢复。

## 持久化删除准备（1.0.0 开发中）

该步骤保存短期准备记录，供确认流程恢复使用；没有接受删除请求，也没有启动删除作业。`executionAvailable=false` 始终保留，快照内 `readyToErase=false`。

- 创建：`POST /api/v1/tenants/{tenant}/subjects/{subject}/erasure-previews`，必须带当前主体的强 `If-Match` 和非空、最多 128 字符的 `Idempotency-Key`。
- 恢复：同一路径下 `GET /{id}`。返回准备记录自己的 ETag、创建/到期时间、状态和可用时的前置检查快照；响应禁止缓存，按 Authorization 区分。
- 取消：`POST /{id}/cancel`，必须带准备记录的强 `If-Match`。重复相同取消不重复审计，不恢复已移除的快照。
- 每次请求先锁定当前成员权限、校验近期 MFA，再锁定目标主体。准备记录绑定创建者及当时成员版本；其他管理员、已撤权或成员版本变化后的身份不能读取或重放该记录。
- 同一创建者、同一主体至多保留一份 PREPARED 快照，新记录将之前的标记 SUPERSEDED 并立即清空快照。不同管理员的准备记录互不覆盖。
- 记录有效期为 5 分钟。到期标记 EXPIRED，主体版本变化或已审核存储清单变化标记 STALE；这些状态、CANCELLED 和 SUPERSEDED 均不返回旧快照。未知物理表/列仍拒绝提供有效准备结果，但允许管理员取消自己的准备。
- 幂等只保存记录引用和请求摘要；同键重试读取当前状态，不返回旧的 PREPARED 响应。原键不能绑定新主体版本。键只在同一租户、主体和创建者范围内有效，数据库只存键摘要。
- 每创建者、每主体一小时最多新建 20 份，重复已存在的请求不消耗新名额；到限额不覆盖当前准备记录。
- 默认每 60 秒运行有界清理：一批最多 50 份到期快照，另清理最多 50 份已终止且创建超过 24 小时的记录。可通过 `manager.erasure-previews.cleanup.enabled` 关闭调度；`interval-seconds` 调整间隔。物理清理只针对准备缓存及其幂等记录，不代表业务数据、审计或备份已删除。

快照只是 `evaluatedAt` 时的计数与清单。设备、关联成员和其他内容之后仍可能变化；PREPARED 不代表范围冻结，不允许据此执行删除。正式提交必须重新验证所有范围、明确保留政策与外部处理器，并先可靠写入独立删除账本。

### 本步骤记录

- Ruling：沿用现有主体锁与成员版本锁，使用数据库唯一键约束并发重试；不额外引入 Redis 或另一个持久化框架。准备记录属于 DERIVED_COPY，新增表及 12 列已显式纳入存储分类。
- Ruling：5 分钟有效期、24 小时幂等记录留存是短期操作缓存的默认值，不作为个人数据或法定审计的保留政策；正式删除政策仍另行实现。
- 已验证：首批接口缺失测试 4 项均以 404 失败；实现后 15 项通过；扩展 H2 24 项通过（准备 12、前置检查 10、全新初始化 1、模块边界 1），真实 MySQL 准备/前置检查/模块边界 23 项与独立全新初始化 1 项通过。一次独立静态复核未发现缺陷，完整业务回归结果见 `releases/stage-erasure-preview-verification.json`。
