# 智能管家：完整产品交付与商业运营模型

> 版本：Draft 1.0；日期：2026-10-09。  
> 适用：产品、设计、Flutter、原生、后端、QA、商务、支持与运维。  
> 本文补齐现有设计的执行细节；所有表中的目标能力均须实施并验证。当前状态以[实施记录](implementation-progress.md)和[实际 API](backend-api-status.md)为准。

## 1. 统一交付口径

产品交付按“用户能完成一个有结果的任务”组织。每个功能必须具备入口、授权判断、操作预览、执行过程、结果解释、异常恢复、审计、帮助和退出方式。页面、接口、消息、设备规则与销售描述使用同一功能编号。

**完整范围保持为家庭、机构、电视、跨设备、安全、智能辅助与商业交付。** 分期仅改变实现先后。对某型号不支持的能力，交付结果是明确的限制和替代路径，不能把接口成功当作系统执行成功。

### 1.1 四种事实分别展示

| 事实 | 可信来源 | 示例 | 不能推导的结论 |
|---|---|---|---|
| 购买权益 | 经核验订单/合同与权益版本 | 已购买多设备管理 | 已取得设备所有者权限 |
| 管理授权 | 当前监护/成员范围、近期认证、用途授权 | 可以修改该儿童规则 | 系统必定支持该规则 |
| 配置期望 | 不可变策略版本与目标快照 | 已发布禁止游戏规则 | 游戏已被阻止 |
| 实际结果 | 合格设备/EMM 证据、时间与范围 | 指定资料的启动规则已应用 | 永久不能绕过、全部资料已受控 |

管理端分别显示“配置版本、投递进度、执行证据、保护健康”；儿童端显示与其相关的当前限制、来源、恢复时间和求助入口。未知、离线、过期证据、部分支持独立显示。

### 1.2 功能卡标准

每项需求使用下列模板，作为 Ready 检查条件：

- `requirementId`、场景、目标用户、价值、前置条件和能力模式。
- 入口页面、关键字段及单位、正常状态、空态、失败状态与可执行下一步。
- 角色/对象范围、隐私用途、权益键、数据保留和敏感操作认证。
- REST/事件契约、业务不变量、并发与幂等、离线/重启与补偿行为。
- Flutter/原生/供应商责任、验收用例、证据来源与兼容目录条件。
- 埋点口径、诊断字段、操作手册、支持责任和产品退役方式。

下表细化[功能规格](parental-control-functional-spec.md)的编号。所有跨模块写入经所属模块公开接口或版本化事件，不共享可变 repository。

| FAM-01 | 建立家庭/机构、邀请、调整权限、共同监护、所有者交接 | Tenancy/Subject → 邀请与转移操作 → Audit | 精确身份匹配；唯一有效所有者；交接后权限收敛 |

| APP-01 | 应用清单、逐应用允许/阻止、安装/卸载与更新治理 | Catalog → Policy → 平台许可执行器 | 包/资料/签名身份匹配；不把不可见应用当作未安装 |
| PER-01 | 查看与调整系统支持的运行时权限和特殊访问 | 原生权限目录 → 能力评估 → Policy → 执行证据 | 权限未授予、不可强制、需本地确认分别显示 |
| SCH-01 | 作息、学习/睡眠、节假日、连续使用与休息提醒 | Schedule → 策略快照 → 本地计算 | 时区/DST、跨日、日期例外、通知被拒绝均有结果 |
| QUO-01 | 总额度、逐应用额度、跨设备共享、追加时间和纠错 | 可信会话 → 额度租约/账本 → 本地执行 → 对账 | 并发无超发、离线有界、重启不重置、重复结算不扣两次 |

| APR-01 | 申请临时访问、家长批准/拒绝、撤销和自动到期 | Child → Approval → 限时例外 → Delivery/Quota | 批准与实际可用分开；旧基线、超时、重复批准安全处理 |
| TVS-01 | 选择儿童/访客、验证成人、会话交接与遥控操作 | TV UI → Session → 有限范围令牌 → 策略/额度 | 未知身份用默认安全规则；成人会话超时；输入源边界披露 |
| WEB-01 | 域名/类别管理、受控浏览器、申诉和过滤健康 | Content adapter → Policy → 许可 DNS/VPN/浏览器 | HTTPS 内容盲区、VPN 冲突、DNS 绕过与媒体应用限制明确 |
| SAF-01 | 风险查看/复核、求助、管理员恢复与通知 | Safety → 经授权恢复操作 → 执行器 → 证据 | 无误判自动处罚；必要联系可达；恢复权限不等同擦除权限 |
| ORG-01 | 名册、班级/分组、委派教师、课堂、批量维护 | Organization → Scope → Bulk operation → Policy | 名册差异预览；任期/班级范围；逐项进度与取消语义 |
| EXT-01 | IdP/EMM/名册/通知/分类集成与连接健康 | 官方 SDK → Integration adapter → 领域接口 | 准入、配额、字段映射、回调验签、断连/撤销与替代路径 |
| INS-01 | 用量趋势、计划效果、家长复核建议 | 聚合数据 → Insight → 可解释建议 | 样本覆盖、数据不足、来源与纠错；不诊断心理或健康 |
| VIS-01 | 可选前台视觉提示、授权撤回与质量复核 | Consent → 本地推理 → 最小化结果 → 提示 | 可见采集、无原始视频留存、误报/低置信度/不可用流程 |
| AIA-01 | 成人自然语言生成规则草稿 | 授权上下文 → 成熟模型 SDK → schema 校验 → 人工预览 | 注入防护、越权引用拒绝、成本预算、无自动发布 |
| RPT-01 | 范围报告、审计、导出、删除、限时支持诊断 | 聚合/审计 → 异步作业 → 加密产物/删除清单 | 再鉴权下载、过期、撤销、备份删除计划、无跨租户泄漏 |
| OFF-01 | 断网、重启、时钟异常、版本对齐与补交 | 本地安全存储 → 可信时间 → 增量同步 → 对账 | 最后有效规则、例外不续期、有限缓存、撤销注册不复活 |
| END-01 | 正常解除、设备失陷、转让、注销与退役 | 后果预览 → 再认证 → Deprovision → 清理/撤销证据 | 撤销远程身份与本地清理分别报告；擦除单独明确授权 |
| COM-01～03 | 兼容体验、购买恢复、续费、降级和退出 | Catalog → 官方支付事实 → Billing → Entitlement | 不重复计费/赠权；不因购买扩大系统能力；基础恢复保留 |
| COM-04～06 | 机构售前/交付、私有化、渠道、支持与续约 | CRM/合同引用 → 受控开通 → 验收 → 服务运营 | 可售证据、责任划分、财务/支持/设备操作分权 |

## 3. 关键状态机与失败收敛

### 3.1 生命周期拆分

| 对象 | 主要状态 | 关键规则 |
|---|---|---|
| 注册操作 | CREATED → CLAIMED → ADMIN_CONFIRMED → COMPLETED；EXPIRED/CANCELLED/FAILED | 操作完成后签发独立注册身份；自报不升级受管模式 |
| 设备注册周期 | ACTIVE → REVOKED / DEPROVISIONING → DEPROVISIONED | REVOKED 禁止远程访问；本地清理可以仍是 UNKNOWN |
| 策略版本 | DRAFT → PREVIEWED → PUBLISHED | 发布不可变；修改与回滚生成新版本 |
| 规则执行 | PENDING / RECEIVED / VERIFIED_APPLIED / REJECTED / EXPIRED / SUPERSEDED / UNKNOWN | VERIFIED_APPLIED 仅给合格执行证据；伴随 App STORED 是配置存储事实 |
| 临时申请 | PENDING → APPROVED / DENIED / CANCELLED / EXPIRED | 批准生成有界授权，不直接代表设备解锁 |
| 例外授权 | ISSUED → ACTIVE → EXPIRED / REVOKED；FAILED | 绑定主体/设备/规则/基线、用途、截止时间与额度 |
| 风险事件 | OPEN → ACKNOWLEDGED → RESOLVED / DISMISSED | 复核原因和证据保留；数据缺失不能判为违规 |
| 异步作业 | QUEUED → RUNNING → SUCCEEDED / PARTIAL / FAILED / CANCELLED | 每项子任务独立；取消后已执行动作不假装回滚 |
| 产品发布 | DRAFT → VALIDATED → PILOT → GA → SUSPENDED / RETIRED | 状态绑定功能、型号、模式、区域与版本 |

这是目标模型，不要求将相同枚举复制到所有领域。当前 CONFIGURE_ONLY API 只接受接收、保存、拒绝回执，契约见[签名配置交付](configuration-delivery-contract.md)。后续执行证据另建契约，不能扩大当前 STORED 的含义。

### 3.2 临时审批完整事务

1. 儿童选择目标应用/时间，查看现行原因，提交有上限的请求；自由文本可选且不进入普通日志。
2. 服务校验所属主体、基线、频率、同目标待决请求及可申请性；拒绝覆盖紧急底线或申请其他儿童对象。
3. 管理员收到脱敏提示，打开后重新鉴权；展示增量、截止时间、目标设备和基线变化。
4. 管理员通过近期认证批准；同事务记录决定、例外/额度来源、审计和交付事件。
5. 请求状态为已批准，设备状态为待同步；真实执行器确认后才显示可用。
6. 重复决定使用持久幂等；第二个不同决定返回冲突。基线改变需重验，不能盲目覆盖新版限制。
7. 到期/撤销只移除该例外来源，并重新计算其余有效规则。设备离线不能延长例外。

额度、时间窗口、应用启动例外分别建模；“允许启动 10 分钟”必须明确是在截止时间内可启动，还是额外增加 10 分钟使用额度。UI 不用同一“加时”按钮混淆两种语义。

### 3.3 机构批量执行

管理员筛选并保存目标快照 → 预览能力/权益/授权与差异 → 确认批次 → 分批限速下发 → 逐项证据 → 汇总失败 → 重试可重试项或生成补偿版本。

- 批次保存目标快照与来源范围版本，不随列表变化悄悄新增设备。
- 教师授权到期后暂停尚未执行部分；管理员可接管，已完成的事实不改写。
- 暂停/取消对未开始任务生效；已执行规则的恢复另建操作，不承诺全局事务回滚。
- 供应商限流、永久不支持、临时错误、离线和证据未知使用不同状态。相同永久失败不无限重试。
- 重试绑定原目标、源版本和幂等键；重试前复核当前能力与权限，避免新注册设备接到旧命令。

## 4. 产品交互详细约定

### 4.1 页面任务与信息优先级

| 页面 | 首屏核心信息 | 主操作 | 必须保留的异常入口 |
|---|---|---|---|
| 家长今日页 | 今日规则/额度、待审批、需修复设备、最后证据时间 | 查看孩子、审批、修复 | 无数据、未激活、部分控制、离线 |
| 儿童今日页 | 可用应用、剩余额度、下一恢复时间、当前限制解释 | 打开、申请、求助 | 权限退化、时间不可信、申请未同步 |
| 设备详情 | 注册周期、模式、授权健康、配置与执行版本 | 授权修复、规则预览、诊断 | 需本地操作、不支持、重注册、解除后果 |
| 规则编辑器 | 目标范围、规则来源、增量影响、底线提示 | 保存草稿、预览、发布 | 冲突、过期预览、部分支持、目标变化 |
| 审批工作台 | 原因、目标、增量、截止、决定与同步状态 | 批准、拒绝、撤销 | 已被其他人处理、基线变化、无执行路径 |
| 应用权限页 | 包/资料身份、观察时间、系统权限、可调整范围 | 设置规则、修复授权 | 应用不可见、签名变化、无法强制授予 |
| 报告页 | 时间范围、来源覆盖、用量趋势、缺失比例 | 切换、导出、纠错 | 未知不算零、估算标记、保留期限 |
| 机构设备台 | 分组与过滤、执行覆盖、待修复、批次进度 | 批量预览、课堂操作 | 无范围权限、能力混合、离线目标 |
| 商业账户页 | 渠道、产品版本、到期、容量与账单事实 | 管理购买、取消、影响预览 | 支付待验证、权益异常、不可售区域 |

### 4.2 规则可解释结构

限制页只展示与当前访问有关的原因：规则名、适用主体/设备、限制类型、当前条件、来源角色类型、恢复时间、申请资格和求助。儿童不看到监护人的邮箱、手机号、财务资料或其他儿童情况。

默认展示主要原因，展开后列出其他同时限制；不能说“额度已恢复”却隐藏仍有效的睡眠时段。恢复时间无法确定时写“等待管理员处理/设备同步”，不虚构倒计时。

发布预览分别计算更严格、更宽松、无变化、不支持与未知。目标混合时显示“本次 8 台支持、2 台待授权”等有分母的信息；全部成功必须来自目标快照中全部必需规则的合格证据。

### 4.3 手机、桌面与电视适配

- 手机单任务操作与底部导航；平板/桌面支持列表详情分栏、批量选择、键盘访问和明显的当前租户。
- TV 每屏保留稳定焦点路径、大字号、可见高对比焦点，方向键/确认/返回全程可达；返回不会默认进入成人会话。
- 电视不强迫儿童输入长密码；成人通过另一设备完成限时确认，本地会话令牌有用途和到期时间。
- 共享电视不采用摄像头自动认人。身份切换、访客模式、投屏、HDMI、系统首页各有明确适用规则及盲区。
- 学习/联系白名单由授权管理员维护并预览影响；“必要设置”仅开放所需恢复路径，不能笼统开放全部设置。
- 文案、颜色、图标不能独立传达状态；支持屏幕阅读器、字体放大、无障碍输入及减少动画。

## 5. 容易遗漏的产品场景

| 场景 | 完整处理设计 |
|---|---|
| 共同监护人意见不同 | 默认拒绝优先且保留来源；敏感移交走所有者流程；平台不判定法律监护争议，按地区流程核验管理权 |
| 学校与家庭共同使用一台设备 | 注册域与资产责任明确；工作资料只管该资料；跨域组合须有许可模式与双方授权，不叠加两个互不知情的强管理器 |
| 假期、转班、教师离职 | 日历版本与生效日期明确；名册变更先预览；撤销教师范围并暂停未完成任务，历史保持原责任人 |
| 孩子更换账号或创建系统用户 | 能力目录逐项披露用户创建限制；只在受支持模式执行；发现未知资料只报告保护覆盖未知 |
| 应用升级/签名变化 | 观察事实与可信身份验证分开；身份不符不自动沿用白名单；版本重新验证并提供学习/联系恢复 |
| VPN/DNS 与已有安全工具冲突 | 预检与清晰告知；冲突时停止宣称网络过滤有效，提供受控浏览器/受管网络替代 |
| 设备无摄像头/权限撤回 | 基础规则继续；关闭辅助推理及相关采集，删除待处理派生数据按用途保留规则执行 |
| 更改日期、时区、恢复出厂 | 墙上时间变更不重置账本；可信时间异常用有界规则；出厂后是否重新受管取决于已验证注册机制 |
| 智能内容类别判断错 | 支持成人申诉、有限范围例外和来源复核；类别未知不能显示“已确认安全” |
| 导出请求与撤权并发 | 作业执行、产物生成、下载都重验权限；撤权后停止访问，过期加密产物清理 |
| 家长手机丢失或 IdP 中断 | 通过正规身份恢复/预置受控恢复路径处理；不提供统一万能 PIN，不关闭签名校验 |
| 付款人离职、学生退学或换机 | 财务责任、管理责任和数据责任分开交接；数据不能跟着计费席位自动转给其他客户 |

## 6. 商业化产品与服务操作模型

### 6.1 商业发布的最小单元

可售单元为 `区域 × 渠道 × SKU版本 × 设备模式 × 已认证功能集合`。套餐、合同、兼容目录各有版本与生效日期。定价面向成人/采购责任人，儿童端无广告、购买催促或风险恐吓营销。

| 产品 | 实际销售对象 | 主计量建议 | 售前必须完成 |
|---|---|---|---|
| 家庭 | 监护人 | 家庭订阅含明确设备额度 | 型号/模式自检、有限控制说明、恢复路径演示 |
| 教育机构 | 采购与 IT/教育责任人 | 设备容量或学生席位择一 | 代表性真机试点、教师范围、名册、驻留与验收方案 |
| 私有化 | 客户 IT/采购 | 环境/容量许可 + 维护/实施 | 基础设施 sizing、外部依赖、数据库 profile 与升级恢复 |
| OEM/渠道 | 厂商/合作方 | 认证集成项目 + 合同服务 | 型号/固件/API 认证、售后分工、渠道数据范围 |

所有产品共享领域内核与版本链。定制内容收口到 connector、主题、配置或产品目录，不通过复制后端/客户端长期维护客户分支。

### 6.2 可售判定顺序

1. 区域/经营主体/渠道具备销售条件。
2. SKU 及目标型号/模式已发布且有未过期认证证据。
3. 必需供应商合同、配额和支持条件有效。
4. 购买主体、适用租户及容量关系明确。
5. 用户确认能力边界、价格、周期、续费/取消与数据用途。
6. 支付/合同事实核验后生成权益；设备系统授权仍需独立完成。

能力不足显示“不支持此设备/需要受管注册”，不显示“付费即可开启”。设备兼容目录撤回认证时暂停新销售并启动存量客户修复/替代/退出流程，不改写历史验收证据。

### 6.3 订单、权益与计量

商业领域保留购买事实、合同事实、容量占用和权益投影四类记录；各自有来源引用、版本、适用租户、期限、金额/单位、审核事实和撤销原因。

容量计量口径明确 ACTIVE 注册、预留名额、归还与换机关系。离线不释放席位；重试不重复占位；换机有明确容量转移，旧设备撤销与本地清理状态独立。超过容量冻结新增高阶资源，保留基础管理和安全退出。

多购买来源合并必须逐权益定义算法：布尔功能取有效来源并集；容量默认取最高有效档位，只有可加购 SKU 才求和；期限不从两个来源任意拼接；相互冲突的区域/合同不能自动合并。退款重算受影响来源，不撤销其他仍有效来源。最终规则以发布目录/合同为准。

### 6.4 机构商业交付步骤

~~~mermaid
flowchart LR
  A[合格商机与设备清单] --> B[技术兼容核验]
  B --> C[代表性试点与成本]
  C --> D[批准报价与合同]
  D --> E[租户和权益开通]
  E --> F[分批实施与培训]
  F --> G[逐功能证据和签收]
  G --> H[持续服务与续约]
  H --> I[扩容或安全退出]
~~~

每次转换记录责任人、输入版本、批准与出口产物。CRM 关系不是儿童数据授权；合同签署不是设备执行证据；销售不能直接修改数据库发权益。

报价分列软件、设备/EMM、第三方分类/消息、实施、迁移、培训、支持、客户基础设施与定制维护。试点通过后才能使用实际单位成本和服务能力确定价格与 SLA。特殊折扣有期限与批准来源。

### 6.5 成本核算与定价输入

`CM = 渠道后净确认收入 − 云资源 − 第三方费用 − 直接支持工时 − 交付摊销 − 渠道佣金`。

收入、税费、退款、现金流与 CM 采用财务批准的同一周期/币种口径；获客费用和研发分摊单列。该公式是管理模型，不替代法定财务核算。

| 成本驱动 | 数据来源 | 控制措施 |
|---|---|---|
| 在线连接与重连 | Broker 指标、连接分位与重试量 | 心跳分档、抖动、增量通知、每租户预算 |
| 核心交易与广播 | 请求/事件、目标数量、重试次数 | 批次限速、合并重复提醒、业务幂等 |
| 历史与报告 | 保留量、聚合量、导出大小 | 数据最小化、分层存储、保留作业 |
| EMM/分类/模型 | 有效合同、供应商账单 | 配额、熔断、替代 adapter、成本告警 |
| 支持与交付 | 有权工单工时、验收和实施记录 | 自助诊断、兼容自检、培训和标准部署包 |

不写未经确认的售价、获客成本或回本期限。价格实验只面向成人，预先定义观察期、分母、取消率和必要恢复质量，不能以孩子限制强度作为付费诱导。

## 7. 运营控制台与责任分离

| 角色 | 可以管理 | 默认不能访问 |
|---|---|---|
| 平台产品运营 | 目录草稿、地区配置、功能发布与帮助 | 儿童活动明细、设备擦除、支付秘密 |
| 财务 | 发票引用、退款/贷项、付款与对账 | 儿童使用报告、策略修改 |
| 客户成功 | 培训进度、合同、租户级健康与续约 | 默认儿童级敏感记录 |
| 支持 | 客户授权范围内诊断与工单 | 无期限诊断、跨客户查询、代替监护决定 |
| SRE | 服务指标、基础设施、脱敏故障证据 | 无授权浏览儿童内容或扩大商业权益 |
| 渠道/OEM | 合同范围内订单、型号兼容与交付状态 | 客户所有者权限、儿童活动 |
| 客户管理员 | 所属范围内设备、成员、规则与支持授权 | 其他租户、平台财务与运维密钥 |

支持提权由客户发放限时 support grant，按租户/设备/诊断类型授权，可随时撤销。客服不能索取密码/长期恢复码；日志只提供稳定错误、版本与 correlationId。

工单分为账户/计费、授权健康、策略执行、内容分类、恢复、安全/隐私与部署故障。安全误封/恢复不可达优先处理；财务争议不阻断紧急恢复。

### 8.1 成熟框架优先的实施边界

### 8.2 商店与地区发布条件

Google Play 对具监控功能的家长控制应用有明确的监控类别声明及透明性要求；若目标构建涉及这些能力，应核验 `isMonitoringTool` 分类、明显图标/持续通知、商店说明及适用政策。不得以隐藏运行包装家长控制。[监控标记](https://support.google.com/googleplay/android-developer/answer/12955211?hl=en)、[监控应用要求](https://support.google.com/googleplay/android-developer/answer/9888380?hl=en)

数字订阅的支付入口按上架区域、渠道与适用例外逐项核验；Apple 的 MDM 使用有资格与审核限制，不能因 Flutter 复用就宣称 iOS 支持相同管理路径。每次发布记录核验日期、政策版本、申报资料和责任人。[Google Play 支付](https://support.google.com/googleplay/android-developer/answer/9858738?hl=en)、[Apple 审核](https://developer.apple.com/app-store/review/guidelines/)

地区验收另含未成年人告知/授权、数据驻留/转移、保留/删除、通知渠道、语言/时区和支持责任。法域判断由相应责任人员复核；本文不宣称已获任何地区或商店批准。

## 9. 交付顺序与验收证据

| 波次 | 交付范围 | 依赖与出口 |
|---|---|---|
| A：平台基础 | 身份/租户、主体/成员、设备身份、审计、契约 | HTTP/事务/范围验证，真实数据库认证，管理交接与恢复 |
| B：规则执行 | 应用/计划、策略发布、签名交付、正式 EMM/原生执行、回滚 | 全链路执行证据；离线/重启/撤销/恢复通过 |
| C：日常产品 | 审批/额度、Flutter 成人/儿童、Android/TV、内容与告警 | 代表性设备旅程、遥控体验、额度守恒、误封恢复 |
| D：机构与服务 | 班级/批量/SSO、报告/删除、支持、部署/容量 | 机构试点、数据请求、私有包、真实 HA/恢复与压测 |

每份证据记录 `requirementId / environment / build / databaseProfile / model-or-device / managementMode / adapterVersion / outcome / observedAt / reviewer`。自动化、真实数据库、供应商沙箱、真机与客户签收分开登记。
