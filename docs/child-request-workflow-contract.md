# 儿童申请持久日志与宿主恢复契约

## 当前交付与后续入口

本阶段提供可复用的 `AccessSubmissionJournal`、儿童宿主 `ChildSubmissionReceiver` 及独立进程的真实 HTTP 恢复验证。当前尚未接入 `ChildSession`、`main.dart` 和申请界面，普通产品安装还不能从页面发起申请。下一阶段必须补足长期未知结果恢复接口、会话接入、手机/电视表单和完整终端验收；本记录不表示整个平台已完成。

沿用 Sembast 事务、现有 AES-GCM 文件编码器、设备传输 SDK、平台安全绑定与原生提交屏障。没有引入新的数据库、加密算法实现或第三方依赖。

## 1. 设备 SDK 持久日志

`AccessSubmissionJournal(database, scope)` 绑定 issuer、租户、主体、设备及注册周期，所有请求事实都须匹配范围。宿主负责提供已认证的范围、加密数据库及生命周期。申请与签名执行窗口使用不同用途命名空间。

| 操作 | 约束与结果 |
| --- | --- |
| `prepareCreate` | 原输入、原键、应用显示名称和创建时间先在事务内保存；同一范围最多一条未解决变更 |
| `prepareCancel` | 保存原申请 ID 与版本；申请必须待审，且不能使用比本地已知事实更旧的版本 |
| `markSending` | 在网络发送前持久标记结果未知；崩溃发生在标记和发送之间时也保守保留原操作 |
| `complete` | 对齐原键、身份和原输入后，同事务记录最新事实并移除操作；取消须明确推进为 CANCELLED |
| `reject` | 仅接受能证明本次未提交的已知领域错误；任意 HTTP 文字、认证失败、5xx 或过期键不能作为证明 |
| `discardUnsentOrRejected` | 仅允许儿童主动放弃从未发送或已明确拒绝的操作；不能丢弃未知结果 |
| `record` / `inspect` | 保护事实版本、原创建时间、待审期限和已有批准截止时间；旧版本不能覆盖新状态 |

申请操作有 PREPARED、UNKNOWN、REJECTED 三种本地阶段，与服务器的 PENDING、批准、取消等业务状态不同。恢复日志本身不会触发网络发送；重试必须由用户主动发起并使用原键、原正文和原取消版本。

每个范围默认缓存至多 100 个申请事实，配置范围为 1–256；超过容量淘汰较早缓存，不删除服务器申请。未解决操作单独持久保存，不因事实缓存淘汰而遗失。缓存按创建时间倒序展示，不表示已同步全部服务器历史。

同一版本出现不同事实、终态被改写、原时间或已批准期限被改变时拒绝入库。缺损或未知持久结构明确报错，不能自动重置。异常和 `toString` 不包含私人理由、原键或凭证。

## 2. 儿童宿主

`ChildSubmissionReceiver` 提供恢复、刷新、分页、详情、创建、取消、原操作重试、显式放弃和 pause/resume/close。每次在线操作先调用真实设备上下文接口，并在生命周期检查后执行。设备凭证每次由当前身份组件读取，轮换不改变注册范围；宿主不构造儿童 JWT。

安全绑定状态为 VALID、CHECKING、BLOCKED。在线检查前先持久写入 CHECKING：身份核对未完成时不能恢复旧缓存。仅检查前的可重试网络故障可恢复此前 VALID 绑定；401/403、无法读取凭证或主体不符会阻断旧范围。改变主体不会自动把原申请迁移到新儿童。

申请用途将服务 origin 纳入范围摘要，数据库与密钥使用单独的用途范围。复用现有 Android 安全键及加密文件 opener；绑定曾确认数据库存在后，恢复使用 `requireExisting=true`。文件丢失、错误密钥或损坏内容必须失败，不能生成空库后让儿童换键重新申请。旧调用方默认 `requireExisting=false`，保持原接口兼容。

前后台切换通过 epoch 取消排队工作及在途传输。进入后台清除内存选项与本轮确认集合；迟到响应不能作为前台新结果发布。关闭等待本实例任务结束，再关闭数据库，不删除未解决操作。

刷新分别读取选项与申请分页。`confirmedRequestIds` 只包含本轮实际核对的申请，未核对的缓存需要标注“上次保存，待核对”；不能把“设备连接正常”当作每条历史申请均为最新。空选项页可以有下一游标。每次选项加载有明确边界，后续界面需提供可理解的分页和边界提示。

这些结果均为申请事实。`systemEnforced` 仍为 false，批准后的签名交付继续由已有窗口接收流程处理。

## 3. 未知结果与长期恢复缺口

创建或取消超时、5xx、后台中断、异常成功响应或本地完成事务失败时保留 UNKNOWN。新申请不能覆盖它。明确的冷却、基础策略变化、规则不支持及版本冲突等领域拒绝可以保存为 REJECTED，用户确认后才放弃原操作。

现有统一幂等服务在 24 小时后返回 `IDEMPOTENCY_KEY_EXPIRED`。该错误不能证明第一次请求没有提交，当前日志因此继续保留 UNKNOWN。下一阶段需要服务端专用、重新授权的只读恢复查询，取得原幂等操作关联的当前申请事实；未完成该接口前，不能宣称任意时长断网后的恢复闭环已经实现。不能以自动生成新键、删除未知操作或任意匹配历史列表替代它。

密钥/文件丢失、身份撤销、恢复记录过期及数据清理仍需要受授权的管理员恢复与数据保留流程。儿童端不能通过清空身份或申请文件绕过该边界。

## 4. 验证证据范围

- SDK 验证原输入保存、单条未解决变更、重放、作用域隔离、历史版本/时间不可变、并发创建、完成写失败、容量和损坏结构。
- 宿主测试使用真实 Sembast 文件与实际 AES-GCM 编码器，注入合成密钥及受控 HTTP；覆盖响应丢失后关闭重开、文件中不出现理由/原键、认证/主体变化、文件丢失和后台中断。该测试没有调用真实 Android Keystore。
- Spring 测试启动真实 loopback HTTP 服务，分三个独立 Dart 进程运行：首进程持久保留未确认原操作，成人夹具批准后次进程从真实文件按原键恢复当前结果，撤回后第三进程验证原截止时间与交付引用。测试文件为 JVM 管理的合成数据，使用普通文件库；正式宿主加密路径由前一项验证。测试结束清理私密凭证夹具与申请文件，仅保留脱敏状态日志。
- Android 真机/模拟器上的新申请流程、界面、进程终止恢复、电视操作、后台任务及管理员生产 MFA 尚未在本阶段验证，不以单元或 HTTP 测试替代。
