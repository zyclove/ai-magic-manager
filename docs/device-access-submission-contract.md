# 儿童设备临时访问申请契约（V23）

## 1. 交付范围与权限边界

本阶段实现设备凭证申请接口、持久化状态、成人审批衔接及 Dart SDK。沿用现有审批、签名窗口与交付协议。安全持久申请日志、宿主恢复及过期键查询已有实现；儿童端申请表单和产品会话仍待下一阶段接入，不将接口联动写成完整终端交付。

设备只代表已由管理员确认的注册范围，不拥有 CHILD、TEACHER 或成人角色。服务端从有效 opaque 设备凭证推导租户、设备与注册周期，再读取当前设备主体。请求正文不能指定租户、主体、设备、注册、角色、状态或批准结果。未知字段返回 400。

成人继续通过现有管理接口、当前持久化成员权限及近期 MFA 审批。注册周期作为请求人身份，设备凭证 ID 作为认证事实：轮换后已激活的新凭证可以重试原申请，旧凭证、待激活凭证、撤销注册和已失去作用域的设备均不能读取或修改申请。

## 2. REST 接口

认证头统一为 `Authorization: Bearer <device credential>`。路径根为 `/api/v1/device-api/access-submissions`。成功响应采用 `Cache-Control: no-store` 与 `Vary: Authorization`；单条申请响应携带强 ETag，例如 `"0"`。

| 方法与相对路径 | 用途 | 关键约束 | 成功响应 |
| --- | --- | --- | --- |
| GET `/options` | 当前设备可申请的策略、应用和规则 | `limit` 默认 20、范围 1–100；可传 `cursor` | 200，`items`、`nextCursor` |
| POST `/` | 发起申请 | 必须提供原始 `Idempotency-Key` | 201，当前申请事实与 ETag |
| GET `/` | 当前设备注册周期发起的申请 | 同上分页；只含 DEVICE 类型的本人申请 | 200，`items`、`nextCursor` |
| GET `/{requestId}` | 查询当前状态 | 规范小写 UUID；当前主体、设备与注册均匹配 | 200，当前申请事实与 ETag |
| POST `/{requestId}/cancel` | 取消仍待审批的申请 | 原始 `Idempotency-Key`、强 `If-Match` | 200，当前申请事实与 ETag |
| POST `/recovery` | 恢复原创建关联的当前事实 | 原创建正文与原 `Idempotency-Key` | 200，当前申请事实与 ETag |
| POST `/{requestId}/cancel-recovery` | 恢复原取消关联的当前事实 | 原 `Idempotency-Key` 与原 `If-Match` | 200，当前申请事实与 ETag |

选项扫描按策略 ID 升序、每页至多扫描 `limit` 条当前版本，然后按设备目标及可申请规则过滤。因此可能返回空 `items` 和非空 `nextCursor`；客户端必须允许继续加载。申请列表按申请 ID 升序，不表示创建时间顺序。列表不接收客户端主体筛选器。

### 2.1 创建正文

```json
{
  "policyId": "11111111-1111-4111-8111-111111111111",
  "baseVersionId": "22222222-2222-4222-8222-222222222222",
  "applicationId": "33333333-3333-4333-8333-333333333333",
  "ruleIds": ["reading-window"],
  "requestedWindowSeconds": 600,
  "reason": "需要完成今天的阅读任务"
}
```

三个引用均为规范 UUID。规则 ID 为 `[a-z][a-z0-9_-]{0,49}`，每次 1–20 条、不重复；时长为 1–3600 秒；理由可空、至多 300 个 UTF-16 单元，并去除首尾空白。规则必须属于指定的当前已发布版本，覆盖本设备的当前注册；仅允许 APP_LAUNCH 的 DENY 与 TIME_WINDOW。平台保护应用不可通过申请放行，其他规则类型返回不支持。

创建重放使用原键与原正文。相同键且正文变化返回 409；新键不能绕过现有待审申请、尚有效的批准窗口及冷却限制。重放返回经当前授权和生命周期重新校验的最新状态，可能已经取消、到期或撤回，不能将第一次的 PENDING 快照当作最新事实。

### 2.2 原操作恢复

原变更键 24 小时过期后不能继续变更重放；专用恢复查询仅读取同租户、设备注册、操作名、键摘要与输入指纹对应的已提交资源引用，再校验当前主体、设备、注册及 DEVICE 请求人类型并返回当前事实。POST 避免私人理由进入 URL，不新建幂等记录、不改过期时间、不再次执行原变更。原取消必须提供原版本，不能换成当前 ETag。身份轮换仍需有效设备凭证，身份撤销或重新绑定不能继承旧范围。

404 `ACCESS_RECOVERY_UNAVAILABLE` 表示原引用不可取得，不证明原操作未提交；409 `IDEMPOTENCY_KEY_CONFLICT` / `REQUEST_IN_PROGRESS` 同样不能删除未知操作。当前生命周期核对可执行已有到期/失效/撤回及审计事件，因此恢复事务不是数据库只读事务。幂等记录清理、归档与数据保留必须另行保障恢复引用；当前实现不承诺数据丢失后的自动恢复。

### 2.3 申请响应

沿用 `AccessRequest` 的 19 个字段：`id`、`subjectId`、`deviceId`、`registrationId`、`policyId`、`baseVersionId`、`applicationId`、`ruleIds`、`requestedWindowSeconds`、`reason`、`state`、`requestExpiresAt`、`grantedWindowSeconds`、`issuedAt`、`absoluteNotAfter`、`reasonCode`、`executionState`、`version`、`createdAt`。时间均为 UTC Unix 毫秒。

`executionState` 在该契约中始终为 `NOT_ENFORCED`。批准只产生成人授权事实；系统执行结果应从后续签名验证、持久化、平台能力和实际执行回执判断。申请查询接口不返回设备密钥、凭证或管理员个人资料。

待审批使用 PENDING；批准使用 APPROVED_PENDING_DELIVERY；其他终态为 DENIED、CANCELLED、EXPIRED、REVOKED、INVALIDATED。待审失去基准或有效作用域可被失效；批准失去授权可被撤回。批准截止时间固定为 `issuedAt + grantedWindowSeconds * 1000`，重试和离线不得延长。终态保留历史事实。

## 3. 事务、身份与通知隔离

创建锁顺序为策略草稿 → 主体 → 设备 → 当前凭证 → 幂等记录/申请槽 → 申请。查询和取消在主体、设备及凭证锁内重检当前注册、主体和凭证；创建还需在同一事务内校验当前策略版本及目标。设备重新绑定不能继承原主体的申请。

`access_requests.requester_kind` 显式区分 MEMBER 与 DEVICE。设备审计名为 `device:<registrationId>`，但该文本及其哈希都不能授予成员权限。成员本人查询、取消、自我审批判断、成员撤权和组织范围失效逻辑均按请求人类型处理。设备仍能由具有对应家庭或机构范围的成人管理。

领域事件 `AccessRequestChanged` 与 `notification_events` 同样携带请求人类型。兼容的旧事件构造器明确为 MEMBER；事件不含申请理由和凭证。同申请、同版本重复事件只能保留相同主体、设备、请求人、类型与状态，冲突使事务失败。儿童与教师通知查询、未读计数、逐条及批量已读只允许 MEMBER 类型的本人通知；成人在当前授权主体范围可接收 DEVICE 通知。

申请、唯一槽、审计、通知与幂等结果处于同一事务。数据库或事件写入失败时整体回滚；不先返回成功再补记通知。所有接口沿用关联 ID，理由、凭证与原始请求正文不得写入诊断日志。

## 4. 错误与客户端行为

| 结果 | 处理要求 |
| --- | --- |
| 400：缺幂等键、未知字段、非法引用/分页 | 修正输入；不得将原键用于不同正文 |
| 401：失效或撤销凭证 | 停止当前请求流程，由既有身份恢复流程处理 |
| 403：设备/主体/注册/策略越界 | 隐藏旧空间资料；不能选择其他主体重试 |
| 409：基准变化、重复待审、现有批准、幂等冲突 | 重新读取当前事实；基准变化后需用户重新确认新申请 |
| 412：版本变化 | 重新查询详情，不盲改 `If-Match` 重发取消 |
| 422：保护应用或不支持的规则类型 | 展示该项不可申请，不降级成无限制 |
| 428：缺少强版本 | 用已读取的 ETag 发起取消 |
| 429：冷却/限流 | 显示等待状态；仅在服务端实际提供时采用 `Retry-After` |
| 超时、断网、5xx、重定向、异常成功响应 | 可能已经写入；保留原输入/键，明确“结果待确认” |

SDK 沿用受限传输、超时、主动关闭和不跟随重定向。提交与取消不自动重发；成功响应仍需严格校验结构、设备/注册/主体、原输入及状态/窗口一致性。不能解析或不匹配的变更响应视为未知结果，不能显示“未提交”并立即生成新键。仅展示允许的错误代码，不显示服务端任意文字或私人理由。

客户端后续接入必须先安全持久化原输入与键，再发请求；取消同时保存原请求 ID、版本与键。身份或注册改变时隔离旧记录，不能把旧申请迁移到新主体。离线可以查看经隔离的缓存状态，不能伪造新申请或批准。SDK 已提供持久日志，儿童宿主已复用现有加密存储；会话与界面尚未接入，不能将协议验证当作完整终端验收。

## 5. V23 数据升级与发布

Flyway `V23__device_access_submissions.sql` 为申请及通知增加非空 `requester_kind`，历史数据默认 MEMBER，并增加设备申请列表索引。V1–V22 文件保持不变。升级验证覆盖非空申请、通知、已读、决策和幂等记录不被重写，以及重复执行无新迁移。

DDL 扩展不代表旧版本业务代码能正确理解 DEVICE。正式启用该入口前，必须暂停相关读写与后台任务、完成备份、迁移并使全部应用实例升级，再开放流量；本阶段不允许新旧审批/通知代码混跑。启用后回滚至 V22 前须评估 DEVICE 数据及权限语义，不能直接回退旧镜像或删除列。不能把未执行的备份恢复演练列为已验收。

H2 MySQL 模式用于快速回归，真实 MySQL 用独立临时 schema 验证 SQL 与迁移。OceanBase MySQL 模式仍需在目标版本单独验证事务、锁、迁移、索引及故障切换，不能由 MySQL 通过推定认证。

## 6. 验收与剩余工作

本阶段检查覆盖真实设备 opaque 安全链、无儿童成员时创建、成人批准/撤回、同键当前状态、强版本取消、冷却、跨租户/设备/主体、轮换与撤销、成员同名及撤权隔离、通知类型重放、非空升级，以及独立 Dart 进程对真实 Spring HTTP 的提交/重试/批准/撤回查询。成人 MFA、设备注册及业务数据在该 HTTP 场景中是显式测试夹具；不代表已验收商用身份提供方或真实系统解锁。

后续交付需完成儿童手机/电视申请交互、持久重试恢复、权限撤回后的界面处理、真实设备验收，以及产品路线图中尚未完成的系统执行、后台可靠性、商业化和运维能力。项目总目标仍保持进行中。
