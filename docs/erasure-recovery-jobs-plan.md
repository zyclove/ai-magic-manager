# 1.0.0 删除恢复作业

承接已批准的主体删除契约，本阶段把独立账本接受记录可靠投影为业务库作业，并提供后续域处理器需要的排他租约和重试能力。正式删除入口、域执行、完成水位及运行期隔离仍须后续完成，本阶段不开放删除。

## 设计

- 首版 V1 新增恢复读取状态及作业表，显式更新受审核存储分类。作业保存不可变不透明目标及注册范围、账本摘要；不保存姓名、邮箱、理由或凭据。避免对可能已经不存在的租户/主体建立级联外键。
- 同一事务锁定业务恢复头，读取独立账本至多 100 条、逐条核验连续范围，保存作业并推进读取游标。失败整页回滚；账本提交不受业务回滚影响。重新构建空业务库时可重放账本重新建立作业。
- 读取游标仅代表作业已持久化，没有完成状态、完成接口或已应用水位。标准启动始终核对业务读取状态和独立账本，至多导入一页作业；非空账本仍在开放流量和调度前失败，已读到尾部也不放行。空账本也不能跳过业务身份和回退检查。
- 作业按序领取，每次领取递增 fencing token，租约使用业务数据库时间；过期重领、续租及延后重试均验证当前持有者和 token。旧持有者不能续租或覆盖新持有者。
- 领取时重新对照独立账本核验不可变记录；损坏、身份变化、失联和非法参数均拒绝。失败码为固定枚举，不保存任意异常内容。
- 暂不运行自动 worker；下阶段在全局隔离、域处理器和外部回执齐备后接入。不能因为租约可用就开始实际删除。

## 验收与复核重点

1. 新结构从空库初始化，表列覆盖清单一致；不新增历史升级脚本。
2. 分页恢复、重复导入、账本接受后业务回滚、导入中断、重新建立业务存储。
3. 并发导入/领取、有界批次、过期租约、fencing token、续租与重试时间、非法输入及损坏记录。
4. 启动恢复先持久化后拒绝就绪，读取尾部不当作删除完成。
5. H2、独立 MySQL、全后端回归及一次独立最终复核。复核尤其检查事务边界、未知身份、过期令牌、越界时间、不可变范围与任意错误内容泄漏。

## 进度

- [x] 失败覆盖及持久作业/分批导入。
- [x] 租约、重试及启动接入。
- [x] MySQL、回归、一次复核及阶段证据。

Ruling：使用现有 Spring JDBC、事务和独立账本；不引入新队列框架。读取游标绝不作为完成水位，宁可继续维护状态，也不能开放未处理目标的数据。

Ruling：对已读范围检查记录数和尾部锚点，领取时核验对应独立账本记录；该检查拒绝丢失和篡改，不提供自动修复或数据库管理员级防篡改保证。计数走序号索引，但尚未做大规模容量认证。

Ruling：作业表归入 AUDIT_RETENTION，表示删除恢复所需的最小保留记录；不据此宣布永久保留合规或已实现清理。生产保留期限、备份淘汰、账本压缩及已完成作业清理尚待完整删除协议确定。

本阶段只修改首版初始化基线。现有 18099 环境使用此前冻结版本，不对其旧基线原地升级；本阶段验收在全新隔离数据库进行。

一次最终复核发现 P1：空账本分支跳过已有业务读取游标，可能使同 ID 旧空快照或更换空账本绕过保护。两项失败用例均复现为未抛出预期拒绝；修正为始终先协调、再根据协调结果判断是否允许就绪，同时覆盖真正全新空库及重复启动。复核不再重复派发，修正通过回归验收。

## 最终验收

- 最终针对性 H2 回归 49 项全部通过；包含初始化、模块边界、前置检查、准备、恢复作业及生命周期保护。
- 最终 MySQL 恢复作业 17 项、真实 Spring 应用接线 2 项全部通过；分别使用独立临时业务库与账本库，结束后清理专用测试库及账号。
- 最终完整后端回归 588 项：583 通过、0 失败、0 错误、5 条件跳过。客户端联调使用已有冻结夹具，未把其他任务此后提交的客户端改动计入本次验收。
- 修正前候选的完整回归亦已结束（585 项、5 跳过），仅作为历史过程记录；最终结论以上述 588 项修正后结果为准。
- 六个生产/测试/结构文件均与最终验证候选哈希一致。复核仅进行一次，P1 修正由失败用例、H2、MySQL 及完整回归闭环；未声称复核者再次审阅修正。
