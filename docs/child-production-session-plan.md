# 正式儿童端会话组合与规则生命周期

## 目的与既有范围

按既有 Task 7/8，把 main 中的身份、签名规则、限时例外、申请和观察构建集中到正式工厂。报表仍由 ChildApp 外层接入，不复制另一套测试专用业务组合。复用现有 SDK、加密存储与平台 API，不新增依赖。

代码检查发现规则缓存的生命周期处理弱于申请和限时例外：同一注册凭证失效时未清除可见规则；后台或销毁后完成的工厂/同步仍可发布结果，迟到的工厂也可能遗留数据库所有者。先写失败回归，再修复这些实际缺口。

## 可观察条件

- 同一注册的认证拒绝或安全存储读取失败，立即隐藏规则并关闭接收器，不删除已签名持久数据，不重新注册。
- 切到后台隐藏规则；前台重新确认身份后恢复缓存，不自动重放规则同步或申请变更。
- 后台、身份变化或销毁后完成的工厂不能成为当前所有者；迟到接收器精确关闭。
- 已开始的规则同步可以保存其已验证事实，但迟到结果不得显示；重新前台只从当前身份下的存储恢复。
- 正常同范围身份刷新不丢失规则或重复创建接收器。
- 规则 HTTP 的 401/403 不得回退展示缓存；拒绝记录必须绑定该请求实际使用的凭证和完整注册范围，迟到的旧凭证拒绝不得阻断新凭证。
- 关闭失败阻止重新打开同一规则库；没有待关闭资源时不等待已完成的异步链，不影响申请分页、详情和确认界面。
- main 与正式工厂只有一份基础构建逻辑；默认开启全部适用的原生基础工厂，不能为通过测试关闭规则/例外/观察。
- 非 Android 界面不能启用 Android 原生工厂；平台失败仍如实返回不可用。

## 交付与分工

本阶段负责 `core/production_session.dart`、`core/session.dart`、规则工厂可注入的平台数据库端口及相应测试、main 的基础构建调用和本文件。报表业务、导航、V24/V25 与管理端保留协作任务所有权。

提交候选必须基于已提交头冻结；main 的基础改动与并行报表覆盖分别核对，不能把尚未联合验收的报表改动一并提交。按已授权流程执行失败回归、完整儿童端/后端回归、静态检查和构建，再提交 dev。

正式全部工厂的真实 Android HTTP 组合仍需后续独立证据。本阶段单元与构建结果不能替代签名交付、真实观察、报表组合、系统重启或 EMM/TV 验收；完整产品目标保持未完成。
