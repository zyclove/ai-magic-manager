# 儿童求助记录的主体删除步骤

`ErasureChildHelpProcessor` 是主体删除恢复作业中的一个内部处理器，只处理 `child_help_requests`。它不提供公开删除提交入口，不释放全局恢复闸门，也不表示整份儿童资料、审计、备份或设备已完成删除。

## 输入与执行

- 输入为独立删除账本中的租户、儿童档案、请求编号和不可变设备注册周期清单；每次作业领取后由现有 `ErasureRecoveryJobs.applyBatch` 核对租约与 fencing token，并在独立事务内提交数据和步骤进度。
- 每批最多删除 25 行；先核对受评审的表列清单，再核对当前设备与求助记录仍完全属于冻结范围。出现新增注册、设备改绑或记录归属不一致时拒绝继续，不跨档案删除。
- 目标设备仍非 `REVOKED` 时拒绝继续，避免设备在批次间继续提交新的求助。选取和删除使用相同租户、儿童档案与记录 ID 条件，且检查每条实际删除行数。
- 步骤码 `CHILD_HELP_REQUESTS`，版本 1。数据库同时保存累计行数、批次数和 `DATA`/`DONE` 状态；已为 `DONE` 的步骤再次检查源表，发现新数据则拒绝把旧回执当作当前完成。

## 仍需完成

完整删除编排尚未向管理端开放，尚无跨步骤完成判定或旧备份恢复再删除演练。后续编排必须在移除设备及儿童档案外键前运行此步骤，并处理同一主体的其他数据、审计保留依据、外部副本与备份。管理界面不得依据本步骤的 `DONE` 展示“资料已全部删除”。

本阶段仅执行后端编译与静态范围复核；没有执行数据库运行检查或真实恢复演练，不能把源码存在解释为已认证的删除能力。
