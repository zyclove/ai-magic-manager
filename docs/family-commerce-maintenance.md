# 家庭微信支付与退款后台维护

本轮实现软件闭环。销售开关、微信供应商开关及维护定时任务均默认关闭，没有访问真实商户、退款或清空已有数据库。

## 订单事实

- 普通订单有效期仍为 15 分钟，原报价、容量和会员起止时间保持冻结。
- `CREATED`、没有任何 `family_payment_attempts` 且没有渠道交易号的到期订单可写为 `EXPIRED`。账户锁确保与发起支付互斥，代表服务器从未预约支付，不代表微信渠道关单。
- 预约过支付的订单必须查原微信商户订单。`SUCCESS` 核对商户、App、金额、币种、交易号、支付时间及签名后入账；只有 `NOTPAY` 且到期才尝试关闭，再查原单取得最终 `CLOSED`。
- 关闭请求的 202、网络错误、超时或未知结果都不能本地写成 `CLOSED`。最终查单为 `SUCCESS` 仍入账，保留原订单周期；已入账的订单不会被较旧的关单快照降级。
- 已签名迟到支付会记录真实付款，重复通知不会重复增加来源或设备容量。客户端微信 SDK 返回始终不能开会员。

## 退款事实

- 申请保持 `AWAITING_REVIEW`，独立人工审核通过后才变为 `REQUESTED`。维护程序不自动批准；`DECLINED` 不提交。
- 原退款号先持久保存再访问微信。已通过审核的首次提交，或已验证原退款号不存在后的恢复，都使用同一退款号、原交易号、全额、原币种和相同参数。
- 结果未知后先查询原退款号。普通空响应、签名错误、超时均不视为“微信不存在”；已受理、处理中及售后异常只查询，不换号发起另一笔退款。
- 只有核实 `SUCCESS` 才撤销对应订单来源。`PROCESSING` 保留原权益；`ABNORMAL` / `CLOSED` 保留实际状态，交给售后继续查原单。
- 微信签名响应 `create_time` 保存为 `provider_accepted_at`，不得改用审核、发起或到账时间。已有受理时间不可改写；历史缺少可信日期的数据仍由对账标记证据不足。
- 家长接口返回可见的 `reviewNote`，不返回审核人员身份。

## 维护与并发

`FamilyCommerceMaintenance` 提供短事务入队 `enqueueOrderVerification` / `enqueueRefundVerification`；执行入口 `reconcileOrder` / `reconcileRefund` 必须在没有外层数据库事务的后台阶段调用。对账只能触发真实查单恢复，不能将 CSV 当作开通或撤销权益的直接证据。

`family_commerce_work` 持久保存原实体、任务类型、租约代际、重试时间、状态及稳定错误码，不保存用户退款说明、支付 SDK 参数、凭证或供应商原文。账户锁先于订单、退款和维护行；网络请求在事务之外。30 秒租约与代际核验阻止跨实例重复占用及旧响应覆盖，超时可在原任务恢复；重试从 1 分钟逐步退避至 1 小时。人工重查不会抢走仍有效的租约。批量上限在订单、退款和人工补查之间共用并去重，每轮开始处理下一项的预算为 20 秒，单次请求另有超时。

配置 `manager.family.commerce.worker.enabled=true` 才启用维护定时任务。默认间隔 30 秒，发布前仍需商户真实支付、关单、通知丢失、退款及对账联调。

## 微信边界

API 请求签名与响应验签复用同一服务端网关。关闭订单严格处理 204；退款不存在必须是已验签的 `RESOURCE_NOT_EXISTS`。下载账单只允许 HTTPS 的微信官方主域名、固定下载路径与单个 token，无跳转；下载时限制总字节数，并由申请响应中的摘要做二次核验。下载 URL 和原始账单不进入家长接口或日志。

查询订单的未支付、已关闭应答可缺少官方选填的金额字段；若提供仍与原订单核对。成功付款始终要求完整金额、币种、交易号及完成时间，缺项不得发放会员。家长接口的订单价格仍来自冻结订单，不从缺项应答补造供应商金额。

官方依据：[查单与关单指引](https://pay.wechatpay.cn/doc/v3/merchant/4012791870)、[退款恢复最佳实践](https://pay.wechatpay.cn/doc/v3/merchant/4014959631)、[退款查询](https://pay.wechatpay.cn/doc/v3/merchant/4012553002)、[账单下载](https://pay.wechatpay.cn/doc/v3/merchant/4013071238)。
