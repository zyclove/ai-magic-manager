# 正式儿童端 Android 联合旅程

## 目标与基线

上一阶段已分别验证真实 Android 申请恢复，以及正式入口的五类业务工厂。本阶段在同一专用 Android 安装与真实 Spring 随机端口服务之间，验证这些工厂共享一份经监护人确认的设备身份，并接入已审阅的儿童报表界面。

冻结输入以 `6848f8effb6bf0ca6b5714648de08eb4d764a445` 为已提交基线，覆盖 `.local/report-final-review` 的报表源码、补充和五项审阅修复，再加入本阶段代码。每层原始文件摘要和最终候选源码清单保留在本地；报表并行任务后续改动不自动进入这次验收。

## 实际操作

1. 后端创建唯一家庭、儿童、一次性注册票据；Android 在专用加密键中生成 ES256 认领证明并显示物理配对码。后端使用成人身份夹具确认配对。
2. 后端创建两项应用和一份 `CONFIGURE_ONLY` 策略，预览后发布。服务端测试密钥在隔离文件中生成；设备只接收其公开验证环作为固定部署输入，私钥不进入 Android。
3. 同一 Android 安装启动 `ProductionChildRuntime` 与 `ChildApp`，经真实设备心跳激活。正式签名规则接收器拉取、验签、保存并确认一份配置；限时例外与申请接收器读取同一设备绑定上下文。
4. Android Pigeon 来源读取平台授权状态和应用清单；不替系统授予 UsageStats，不凭空制造使用记录。儿童报表客户端先读设备上下文，再经真实 Spring 读取本设备报表，界面能到达规则与使用页面。
5. 后续原申请旅程继续检验真实提交、已提交响应中断、原操作恢复、取消、到期、离线、撤销和精确清理。新增联合阶段先占用心跳序号 1，提交阶段应为序号 2。

## 隔离和拒绝条件

- 身份沿用既有运行标记的独立加密键；规则、例外和申请数据库放入唯一运行目录。正式工厂通过平台存储端口打开这些文件，业务协议、HTTP、签名验证和申请日志均为正式实现。
- 普通身份、普通观察记录与普通规则数据库在联合阶段前后必须逐项相同；退出后由拥有该运行标记的最终阶段清理准确目录和密钥。任何一步失败保留诊断，不卸载或清空应用数据。
- 宿主只接受显式拥有的 `AIManagerChildApi34` 模拟器、同一安装身份及 JVM 所有的回环 Spring 地址；使用保持安装身份的显式覆盖安装和官方 Flutter driver 附着。
- 设备回执中的 `STORED`、报表中的 `NO_DATA` 或 `NOT_AUTHORIZED` 都不构成系统策略生效证据。`systemEnforced=false`，没有 DPC 或普通应用防强停承诺。

最终验收须逐项核对真实 Android PID、安装身份、源码／安装包摘要、签名配置和数据库事实、真实报表响应、清理结果、后端回归与其他未纳入能力。结果将独立记录，不复用旧阶段的通过结论。

阶段结果与剩余能力边界见 [联合验收记录](child-production-joint-acceptance.md)；逐阶段原始摘要见 [机器验收记录](releases/stage-child-production-joint-verification.json)。
