# 儿童端 Android → Spring 注册与申请验收

## 1. 验证范围

本旅程在同一专用 Android debug 安装和真实 Spring 随机端口服务之间，执行注册认领、监护人确认、心跳、临时申请、批准后原操作恢复、取消恢复、离线读取和设备撤销。原生加密存储与默认申请数据库为真实实现。

唯一认证替身是管理端 OIDC/JWT 与近期 MFA，由 Spring Security 测试设施提供。设备注册、ES256 公钥持有证明、配对码、opaque 凭证、请求鉴权、审批事务和 SQL 都由正式后端处理；不插入伪设备/凭证行，也不替换设备 HTTP 响应。

客户端使用正式 `ChildApp`、`ChildSession`、`DeviceIdentityManager`、`ChildSubmissionReceiver` 与申请界面。测试组合不包含正式 main 的签名规则接收、签名例外接收、使用观察和报表工厂，不能据此宣称这些功能已经一起联调。身份记录使用同一原生 SDK 的独立加密命名空间，避免覆盖普通产品的身份。ES256 为现有 Dart 身份组件实现，不声明硬件背书或不可导出私钥。

## 2. 阶段与服务端断言

| 阶段 | Android 行为 | 主机/服务端证据 |
| --- | --- | --- |
| enroll | 在正式表单输入管理端格式的完整凭据，真实生成 ES256 证明并认领 | 服务端新建设备/注册/凭证；等待确认；仅存公钥；配对码通过私有文件交接 |
| 管理员确认 | 管理 API 验证配对码，发布两个应用的 CONFIGURE_ONLY 规则 | 成人认证是夹具；设备策略仍无系统执行能力 |
| submit | 新进程读取原身份，用户检查确认状态，真实心跳后提交申请 | 真实 201 已提交、响应流已排空但结果尚未返回宿主时强停；心跳序号 1 |
| recover | 新进程读取 UNKNOWN 原正文/原键，用户核对后明确重试 | 普通原键过期返回 409，专用恢复 200；仍只有一份申请；原批准截止时间保持 |
| cancel | 第二应用正常申请，在线详情与二次确认后取消 | 真实取消 200 已提交时强停；原取消键、申请 ID、版本 0 已预写 |
| cancel-recover | 新进程明确重试原取消 | 过期 409 / 专用恢复 200；同一申请 CANCELLED、版本 1；总申请数为 2 |
| expired | 等待原批准的 60 秒真实期限后，新进程在线刷新 | 同一申请 EXPIRED，原截止时间不变；没有自动变更请求 |
| offline | 主机不建立该 Spring 端口的 adb reverse，新进程读取缓存 | 无自动变更；原批准期限与取消事实保持；不宣称系统解锁 |
| revoked | 管理 API 撤销设备，Android 读取业务和真实心跳被拒绝 | 隐藏私人申请，原生身份持久化认证阻断，服务端无有效凭证 |
| blocked | 再次离线启动 | 不使用旧身份发业务变更，不展示旧申请 |
| cleanup | 按本次运行标记与已验证身份清理独立命名空间 | 删除精确文件/键；不卸载、不清空应用数据；全程核对原产品记录未变 |

两项进行中中断使用真实后端已提交的响应作为检查点，主机终止 Android 进程及仅本次拥有的 Flutter 驱动。它们不是普通驱动通过；后续新进程必须读回原操作并完成恢复。其余阶段保留应用所有者到主机终止进程，不能用正常关闭数据库后重开代替。

只为测试普通幂等重放过期，服务端测试精确更新本租户对应操作的 `expires_at`，没有改写原操作正文、响应或业务申请行。网络离线由缺少专用端口映射实现，不替换客户端 HTTP。

申请表单请求 1 分钟，批准窗口为 60 秒。恢复期间允许后端按真实时间返回待下发或已过期，始终检查同一申请和原绝对期限。随后专门等待业务截止，在线读取并持久化 EXPIRED，再断网重开验证同一终态；不会为让测试通过而延长授权、改写业务截止时间或替换服务端时钟。

## 3. 安全运行与自动化

要求 Python 3、JDK 17、项目既有 Maven/Flutter/Android SDK、已启动且明确归属本次验收的 AVD。先在此 AVD 安装普通 debug 应用；后续驱动必须保留 UID 与首次安装时间。严禁真实儿童设备、真实账号、用户日常模拟器或 release 包。

运行入口为 `AndroidChildSubmissionJourneyTest`。仅显式设置 `device.android.runner` 才启用；普通后端回归会跳过设备旅程，不操作设备。专用运行必须设置所有路径与所有权参数：

```text
mvn -f backend/pom.xml -Dtest=AndroidChildSubmissionJourneyTest
  -Ddevice.android.runner=<absolute-child-tool/run_submission_android.py>
  -Ddevice.child.package=<absolute-apps/child>
  -Ddevice.python.command=<python>
  -Ddevice.adb.command=<adb>
  -Ddevice.flutter.command=<flutter>
  -Ddevice.android.serial=<owned-emulator-serial>
  -Ddevice.android.avd=<owned-avd-name>
  -Ddevice.android.owned=true test
```

上例为参数清单，按实际 shell 的换行规则组成一个调用。MySQL 运行通过进程环境外置 `ANDROID_CHILD_TEST_DATABASE_URL`、`ANDROID_CHILD_TEST_DATABASE_USERNAME`、`ANDROID_CHILD_TEST_DATABASE_PASSWORD`，使用新建的独立 schema；验收结束再删除该 schema。不能指向业务数据库，也不能把凭据放进命令参数或版本库。AVD 启停、普通主入口恢复与数据库建删由验收负责人管理，工具不会自动选择或启动任意设备。

主机工具使用 Python 标准库、官方 Flutter integration_test 和 adb：

- 先单独构建 APK，再显式执行 `adb install -r` 并核对安装身份，失败立即终止，不卸载、不重试安装。Android 暂停启动后，官方驱动通过 `--use-existing-app` 连接；不让 Flutter 代管安装。
- 明确拒绝物理设备、缺少所有权确认、非私有夹具目录及非本地 Spring 来源；核实实际 AVD 名称与启动状态。
- 检查并拒绝覆盖已有 adb reverse，仅建立本阶段所拥有的精确端口映射，阶段结束移除；离线/已阻断/清理阶段不建立映射。
- 凭据通过 stdin 写入应用私有目录，Android 读入后删除。秘密不进入 dart-define、安装包、驱动 reportData 或日志。
- 配对码仅通过应用私有短时文件交接给同一 JVM；交接完成删除两侧副本。`run-manifest.json` 只保留可定位精确范围的非秘密坐标，便于失败诊断。
- 核对真实安装 APK SHA-256、安装身份、PID、源码摘要及终止后 PID 消失；失败不写成功摘要。
- 每阶段和 JVM 都有等待上限；超时只终止自身启动的驱动树，不扫描或终止其他 Flutter/Java 服务。
- 最终清理只按本运行的加密标记、已确认身份和精确路径操作；失败保留诊断，不允许通配删除/清空数据掩盖问题。

主机拒绝条件可单独执行：

```text
python apps/child/tool/test_run_submission_android.py
```

其中 5 项覆盖输入/所有权拒绝条件，3 项覆盖安装失败不回退、安装身份变化拒绝及成功保留身份。

## 5. 已发现的验收工具风险

首轮 MySQL 尝试遇到 ADB 中断。原先由 Flutter 代管安装，Flutter 在安装失败后自动尝试卸载重装，导致专用 debug 模拟器的私有输入被删除。该次旅程和后续缺少运行标记的清理均判为失败，没有计入成功验收；独立数据库已经删除。此事件只涉及专用合成测试安装，不使用真实账号或儿童资料。

工具现改为显式保留数据安装和连接已运行应用，避免该自动卸载路径；安装失败不得清空数据重试。最终验收重新从明确的安装身份开始，逐阶段核对 UID/首次安装时间及 APK 摘要，先前无效尝试不与最终记录拼接。此约束也适用于其他原生集成测试；仅有 `--keep-app-running` 不能阻止安装失败时的卸载回退。

后续 H2 尝试中，日志记录到约十分钟的执行间隔并报告线程饥饿或时钟跳变警告。原批准已经自然到期，旧测试却固定期待待下发状态，因此失败；仅凭该警告不能确定是调度停顿还是时钟调整。该次未计入验收，精确清理完成。现将恢复过程的合法过期与专门的真实截止阶段分开断言；离线必须保持最后一次已确认终态和原期限。测试仍保留失败日志，不拼接失败尝试中的阶段结果。

最终恢复普通应用前，检查发现本阶段独占 AVD 上仍有 23 条调试转发，因此首次恢复检查主动停止，尚未安装普通应用。现有日志不足以确定每条残留的创建来源。确认两个设备旅程及恢复尝试均已退出后，按 AVD 名称、序列号和精确端口逐项移除，没有使用 remove-all，也没有改变其他设备的映射。随后恢复成功；普通入口核对与模拟器停止后再次检查均无残留。该收尾操作不作为任意设备的自动映射治理能力。
