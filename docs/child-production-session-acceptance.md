# 正式儿童端组合与规则生命周期验收

## 1. 本阶段实现

正式入口改为使用唯一的 `ProductionChildRuntime`。身份、签名规则、限时例外、临时申请和使用观察复用现有 SDK、HTTP 传输、签名校验及加密存储；没有新增框架或另建业务实现。平台端口只允许替换身份存储、观察存储/来源和规则数据库打开方式，不能通过端口关闭业务工厂或替换批准结果。构建工厂本身不查询系统、不采集、不联网。

Android 构建保留全部适用的基础工厂；不支持 Android 原生接口的平台不启用这些原生工厂。报表由外层界面注入，使用同一观察来源。提交基线是 `0474e7c411b77b31d4b7f14f825eec7e4a7f8dd4`，本阶段仅提交基础组合与生命周期修复；并行报表改动保留在工作区，需随后重新冻结组合验收。

### 规则接收与界面行为

| 条件 | 实际行为 |
| --- | --- |
| 进入后台 | 立即清除可见规则投影；已有签名库保留；迟到同步不能发布到界面 |
| 返回前台 | 重新确认身份后恢复当前身份的已验证缓存；不自动重放规则同步和申请变更 |
| 身份读取失败、同一注册认证失效 | 隐藏规则并关闭原所有者；不删除数据库、不重置身份或自动注册 |
| 工厂在后台、销毁或身份改变后返回 | 精确关闭该迟到接收器，不成为新所有者 |
| 原接收器关闭缓慢 | 等待关闭屏障后再打开同一数据库 |
| 关闭失败 | 返回固定存储错误并拒绝重新打开，避免同时持有不明确的数据库资源 |
| 正常同范围身份刷新 | 保留规则和原接收器，不重复创建 |
| 非鉴权同步失败，例如回执丢失 | 仅当前前台所有者可读回已经提交且验证的事实，同时保留同步失败结果 |
| 规则通道 401/403 | 不回退展示签名缓存；持久化与实际发送凭证绑定的认证阻断 |

`DeviceIdentityManager.recordCredentialRejection` 在现有 SDK 的串行修改边界内核对租户、设备、注册及该请求实际使用的凭证。旧凭证迟到拒绝、其他注册、等待管理员确认的身份不写入阻断。安全存储写入失败会抛出固定错误，不宣称跨进程持久化成功；正常的新认证心跳仍能解除已持久化阻断。日志只记录固定错误码，不记录凭证和原始失败内容。

## 2. 验证边界与回归证据

- 生命周期专项 14 项：包含真实 `ChildApp` 的后台/恢复/认证拒绝界面隐藏、迟到工厂与同步、销毁、慢关闭、关闭失败、同范围刷新等。该组使用合成已验证对象验证会话边界，不能作为签名验证证据。
- 正式组合专项 4 项：检查全部基础工厂的真实 SDK 类型、延迟构建、不支持平台关闭原生工厂、能力探测失败如实报告。系统来源和数据库是受控单元边界。
- 真实规则传输专项 3 项：用真实 ES256 签名校验器、规则日志、正式规则接收器、正式设备传输与身份管理器，验证 401/403 隐藏与持久化阻断、签名缓存不被删除，以及轮换后旧请求迟到拒绝不能阻断新凭证。HTTP 和内存数据库是受控测试边界。
- 身份 SDK 全量 43 项：新增 6 项覆盖拒绝持久化、重复拒绝、旧凭证/其他注册忽略、等待确认、存储失败及心跳恢复；静态检查无问题。
- 儿童端全量 112 项通过，静态检查无问题。原有申请界面 12 项全部通过，包含分页、详情、二次确认、鉴权拒绝隐藏、键盘焦点、大字和小屏布局。

测试先发现并复现 7 项规则生命周期失败，以及 2 项鉴权错误缓存回退失败。正式工厂的初次红灯仅证明接口当时不存在，不将编译缺失算作行为验证。全量回归还发现 4 项原申请界面失败：无待关闭资源时等待先前异步区域的已完成关闭链，影响界面异步完成。修复为只在实际有待关闭工作时等待；原申请界面与规则生命周期合计 26 项随后通过，全量 112 项再通过。失败记录保留在本地，没有以改弱断言或增加任意延时掩盖。

完整后端回归和正式 Android debug/Web release 构建的最终结果、源码摘要与产物摘要记入 [机器验收记录](releases/stage-child-production-session-verification.json)。测试日志与构建产物保留本地，不将凭证、数据库和安装包提交到仓库。

## 3. 交付与后续门槛

提交时精确核对冻结源码、暂存内容和提交 blob。正式 main 的基础抽取与并行报表注入分别核对，不能将未联合验证的报表改动混入本阶段提交；工作区报表注入继续保留，后续组合需要包含新的生产工厂、会话、规则接收器和身份 SDK。

本阶段 `systemEnforced` 仍为 `false`。单元测试和构建不能证明 DPC/EMM 系统执行、应用实际解锁、防卸载、防系统强制停止、重启恢复、电视兼容或商用认证已完成。前一阶段真实 Android → Spring 申请旅程使用独立申请组合，其结果不替代本阶段全工厂在真实 Android 上的联合验收。

下一步需在同一安装、同一服务和身份下，联合签名规则、限时例外、申请、真实使用观察及报表，验证版本、离线恢复、撤销和失败隔离。真实 OIDC/MFA、实体 Android/TV、受管模式、OceanBase 独立兼容验证、容量与商业发布流程仍按各自发布门槛推进。完整产品尚未交付完成。
