# 儿童端申请流程：真实 HTTP 与跨进程恢复验收

## 1. 目的和范围

本阶段连接真实 Spring HTTP 服务、设备不透明凭证鉴权、业务数据库事务、`ChildSubmissionReceiver`、`ChildSession` 和 `ChildApp`。验收从规则页进入申请表单，经过核对和明确提交，再从新 Flutter 进程恢复原操作。

设备初次注册、管理员 MFA 与本地文件加密密钥使用明确的测试夹具。申请相关 HTTP、服务端审批与撤销、持久操作日志、会话和界面使用产品实现。该验收不构成 Android Keystore、系统强制管控、后台常驻或真机重启验收。

## 2. 可重复运行方式

入口是 `DeviceAccessSubmissionJourneyTest` 中的 `actualChildSessionAndUiRecoverOriginalSubmissionAcrossProcesses` 和 `actualChildUiRecoversOriginalCancellationAcrossProcesses`；它们启动绑定 `127.0.0.1` 的随机端口服务，并逐阶段启动新的 Flutter 测试进程。

需要在 Maven 验收参数中明确设置：

- `device.child.package`：待验收快照的 `apps/child` 绝对路径。
- `device.flutter.command`：本机 Flutter 可执行入口绝对路径。
- `device.access.package` / `device.dart.command`：若同时运行已有 SDK HTTP 验收，设置相应快照路径和 Dart 入口。

运行前在待验收的 `apps/child` 执行 `flutter pub get --offline`，准备已锁定依赖。子进程使用 `--no-pub`，避免验收中途解析或下载依赖。未提供儿童端参数时，JUnit 明确标记这两项为跳过，不得将其计入已通过的跨端验收。驱动文件 `apps/child/tool/submission_http_session_test.dart` 不被正常应用入口引用；直接运行缺少 JVM 夹具的驱动会失败。

数据库默认使用隔离的 H2 MySQL 模式。设置 `ACCESS_SUBMISSION_TEST_DATABASE_URL`、`USERNAME` 和 `PASSWORD` 可运行同一流程的独立 MySQL 实库验收。凭证从本地安全配置注入，不写入文档或命令参数。

## 3. 申请与取消的跨进程验收契约

| 阶段 | 真实操作与故障安排 | 必须成立的结果 |
| --- | --- | --- |
| 提交 | 从规则页选取服务端返回的应用；输入理由，核对，再提交；客户端收到服务端真实 201 后故意丢弃响应 | 服务端只创建一份申请；本地原输入和幂等键已持久化，显示“结果待确认”；不能放弃未知操作 |
| 新进程恢复 | 服务端管理员批准并保存绝对截止时间；将原提交幂等重放窗口设为过期；重启 Flutter 进程 | 加密文件中原 UNKNOWN 操作仍在；用户核对原输入并明确重试；普通提交真实返回 409，恢复接口真实返回 200 |
| 恢复批准事实 | 恢复接口返回当前申请事实 | 清除本地未完成操作；保留原申请 ID、原批准截止时间；页面显示“已批准，等待配置同步”，不显示系统已解锁 |
| 新进程撤回 | 服务端管理员撤回；重启 Flutter 进程并刷新 | 恢复旧批准缓存后，以在线事实更新为“已撤回”；原 ID、原截止时间不变 |
| 凭证撤销与再次打开 | 服务端撤销设备凭证；两个新的 Flutter 进程依次打开 | 首次鉴权失败后隐藏旧申请资料并持久保存 BLOCKED 上下文；再次打开不能从加密缓存重新展示旧事实 |
| 取消响应丢失 | 独立设备范围正常提交申请；查看在线详情，先核对取消，再明确确认；真实 200 响应被丢弃 | 二次确认前没有发送取消；持久化原取消 ID、版本 0 和幂等键；显示“结果待确认”，不能丢弃未知操作 |
| 新进程恢复取消 | 服务端将原取消重放窗口设为过期；新的 Flutter 进程恢复并由用户明确重试原取消 | 普通取消真实返回 409，取消恢复真实返回 200；保留原 ID、版本更新为 1，显示“已取消”；服务端没有新增申请或延长原键期限 |

最终再次检查：服务端只有一份申请，原幂等记录的过期时间没有被恢复接口延长。

## 4. 生命周期、日志和隔离

真实 IO 验收定位并修复了一项界面缺陷：身份复核开始时将 `credentialReady` 暂时设为 false，会在安全存储较慢时卸载私人表单，成功提交后又显示新的空白选择弹窗。会话现改为取得完整身份、配对码和有效凭证结果后一次更新状态；复核期间动作保持忙碌，实际申请等待复核完成；读取失败则清除就绪状态、缓存视图和私人表单。独立回归分别覆盖慢速读取成功、读取失败，不能用内存读取过快掩盖问题。

- 每项验收使用 JVM 创建的私有临时目录；申请恢复使用五个、取消恢复使用两个 Flutter 进程，全部顺序运行，避免多个所有者同时打开同一数据库。
- 上下文和设备身份保存在 AES-GCM 编码的 Sembast 文件；申请日志通过产品数据库打开接口按完整设备范围隔离。测试密钥仅替代 Android 安全存储，不证明真机密钥安全性。
- 故障注入先排空服务端真实响应再丢弃，确保 UNKNOWN 覆盖“实际已提交，客户端未确认”，不制造虚假业务成功响应。
- 界面验收需要同时推进 Flutter 模拟时钟和真实 IO；仅等待真实时间会阻塞由界面回调启动的异步过程。产品代码不注入测试专用等待或绕过。
- 子进程有明确超时；日志只输出步骤和 PASS 标记，不打印设备凭证、身份记录、原始请求/响应或完整申请对象。
- 无论成功或失败，都清理本次 JVM 创建的夹具和数据库文件；安全阶段日志留在本地供定位。不得用共享服务或用户设备替代该隔离环境。

## 5. 后续发布门槛

实际 Android 进程终止后加密申请日志恢复、Android 安全存储与密钥丢失行为、设备系统重启、厂商后台限制及 TV 实机遥控输入仍需独立验收。申请批准事实也不能代替签名配置同步、设备执行回执或系统级管控证明。
