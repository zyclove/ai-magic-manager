# 管理台错误响应与权限失效处理

## 本阶段修复

管理台处理错误响应时，保留服务端原始 HTTP 状态，防止响应内容异常使已失效的操作继续留在界面中。

- 普通请求的 `errorCode`、`correlationId` 分别校验字符串类型；异常值采用 `REQUEST_FAILED`、空关联编号，不再产生类型异常。
- 有界读取中，错误响应的声明长度或累计字节超限时，取消该响应流，并保留原 HTTP 状态与安全错误码。成功响应超限继续作为响应契约错误处理。
- 硬 401/403 可以进入现有的永久撤权流程，清除执行记录详情、时间线及操作资格；旧回调不能继续发起请求。
- 正常 `401 REAUTH_REQUIRED` 继续保留用户主动安全验证入口。响应本身不会自动开始登录或重放提交。

## 验证范围

修复前真实复现 24 个行为失败断言：错误字段类型矩阵 16 项、有界错误体超限 4 项、已加载执行记录撤权 4 项。原始退出码为 1；实际失败分类与冻结源码均保留。

修复后先验证了 61 项定向回归，再对格式化后的同一源码快照运行完整 Guardian 分析、全部测试和生产构建。最终结果及源码、构建资产哈希以[验收记录](evidence/console-response-authorization-20261017.json)为准。完整测试基于独立快照，不包含其他会话尚未合入的家庭业务和原生端改动。

本阶段不证明真实提供方或 Android 设备已执行策略。当前设备执行、草稿生命周期、应用核验入口与其他界面增强继续按各自实施计划推进。
