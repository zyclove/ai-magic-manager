# 成员资料与权限调整实施合同

依据 IAM-01/FAM-01 的当前成员授权、精确身份匹配、角色与对象范围维护。沿用 Spring/JDBC/Flyway、OIDC、Flutter Material，补齐已有成员管理界面。

## 数据与权限

- 姓名和已验证邮箱来自身份服务签名的 JWT，只用于显示，不用于权限和成员匹配。以精确 subject 的 SHA-256 索引身份资料；不提供全局用户目录 API。较旧的 iat 不覆盖新资料，未验证邮箱不进入可分享资料。
- 成员分页在当前租户管理权限检查后取得资料，儿童成员不向此页面输出账户邮箱。缺失资料显示稳定身份标识，不推断姓名；资料时间明确为最近同步。
- 成员列表的资料与成员访问版本分开。`GET/PATCH /tenants/{tenantId}/members/{memberKey}/access` 使用 64 位 actor key 定位，访问描述只包含 actorId/memberKey/role/subjectId/version，强 ETag 对应权限版本，不随显示资料改变。
- PATCH 要求近期 MFA、If-Match，支持 Idempotency-Key。OWNER 不能由此接口修改或授予；必须使用双方交接。只有 OWNER 能授予/修改 ORG_ADMIN，机构管理员只能调整普通成员。家庭/机构角色和 CHILD/TEACHER 主体范围按同一授权规则校验。
- 儿童身份与成人身份不能通过管理员选项相互转换；需要重新邀请，由目标账户重新证明成人资格。成人角色之间可以调整；儿童仍可按授权调整关联档案。此边界防止管理员将儿童账号直接提升为成人。
- 权限或范围改变递增成员版本、记录审计，旧 JWT 立即受数据库当前权限限制。旧邀请、待确认配对、临时访问窗口和预览失效；已生效设备、已提交发布/退出保留。无实质变化的重复操作不增加版本。
- 移除后重新加入不能使旧邀请和敏感待办复活；成员变更与敏感待办清理同事务。共用 V17 成员控制行，按 actor_key 顺序锁成员，避免独占 tenants 外键父表。
- 为精确失效预览，V18 为策略预览记录发起人 key；旧预览发起人未知时保守失效，已发布预览保留。

## 界面

- 成员显示姓名、已验证邮箱/稳定账号、角色和关联档案；调整前重新读取访问版本，展示当前和目标角色/范围及待办影响。
- 根据操作者和目标身份过滤可选角色，CHILD/TEACHER 必填档案，其他角色不发送 subjectId。邀请与调整复用相同表单规则，修复教师邀请漏传范围。
- 角色改变、撤销、并发冲突、近期认证、结果未知重试与工作空间切换都明确反馈。所有权选择器沿用完整身份核对并显示新资料。

## 交付门槛

先记录 HTTP/Flutter 缺功能失败，实施后执行角色/范围/资料保密与新旧令牌回归、真实 MySQL 并发及迁移、完整后端和客户端联调、Flutter analyze/test/build、桌面/窄屏浏览器检查。真实用户 MFA 与浏览器夹具分开记录。整个产品目标继续有效。

## 已实现接口

| 路由 | 输入与返回 | 权限与并发 |
|---|---|---|
| GET /tenants/{tenantId}/members | 分页成员资料、角色、档案名称/归档标记、权限版本 | OWNER/ORG_ADMIN；儿童邮箱不输出，旧账户资料缺失时保留稳定标识 |
| GET /tenants/{tenantId}/members/{memberKey}/access | actorId/memberKey/role/subjectId/version，强 ETag | 当前管理权限；不含会独立更新的显示资料 |
| PATCH /tenants/{tenantId}/members/{memberKey}/access | role、可选 subjectId → 最新访问描述 | 近期 MFA、If-Match，支持 Idempotency-Key；角色和范围改变同事务清理旧待办 |
| DELETE /tenants/{tenantId}/members/{memberKey}/access | 无正文，204 | 近期 MFA、If-Match，支持 Idempotency-Key；旧撤销请求重放不撤销重新加入的新成员版本 |
| GET /tenants/{tenantId}/members/{memberKey}/access-history | limit/cursor → 角色/范围前后差异、版本、操作者、时间 | 当前管理权限；按成员版本倒序，游标限定当前成员与租户；包括撤销历史 |

memberKey 使用成员列表的 cursor 值，是精确 actor subject 的 SHA-256。旧 DELETE 原始 actor 路由保留兼容，管理界面已改用强版本的稳定标识接口。

角色变更历史从 V18 开始记录；加入和所有者交接分别在审计/交接记录中查看，不补造旧数据。身份资料在 `/me`、创建工作空间和接受邀请时同步，不从外部用户目录批量抓取。展示资料不会改变权限版本。

V19 后续已扩展到班级范围：教师可选择 1–50 个 classIds 或一个 subjectId，两者互斥；历史增加 previousClassIds/classIds，旧历史按空列表读取。班级授权绑定成员版本，重新加入不得复活旧范围。班级、学生及设备状态只读入口已接入；本人有限申请和班级失权联动已加入教师专项与真实 MySQL 回归，见 [机构工作流](organization-workflow-plan.md)。课堂会话与独立设备组继续实施。邀请令牌不写入幂等日志，传输结果未知时禁止直接重试创建，引导查看邀请记录并取消未取得令牌的邀请。

## 阶段验证

- 初始成员接口与资料用例 5 项失败，随后 50 项相关回归通过；敏感待办/历史新增 9 项中 3 项失败，再完成同事务监听器与历史接口。
- 增加稳定标识撤销、并发修改、历史分页和大小写身份隔离后，H2 相关 57 项通过；真实独立 MySQL 的成员 12 项与交接 14 项共 26 项通过，临时库与账号已清理。
- 新增监听器故障回滚验证，断言成员版本、角色、历史和待接受邀请整体回滚。完整验证与运行更新结果见实施记录。
- 日志在忽略的 `.local/member-*.log`；身份凭据和浏览器会话未进入版本库。全量测试曾因本机内存不足中断，后续用有界 JVM 堆和逐类进程执行，不把环境中断计为通过。
