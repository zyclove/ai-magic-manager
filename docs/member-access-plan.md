# 成员资料与权限调整实施合同

依据 IAM-01/FAM-01 的当前成员授权、精确身份匹配、角色与对象范围维护。沿用 Spring/JDBC/Flyway、OIDC、Flutter Material，补齐已有成员管理界面。

## 数据与权限

- 姓名和已验证邮箱来自身份服务签名的 JWT，只用于显示，不用于权限和成员匹配。以精确 subject 的 SHA-256 索引身份资料；不提供全局用户目录 API。较旧的 iat 不覆盖新资料，未验证邮箱不进入可分享资料。
- 成员分页在当前租户管理权限检查后取得资料，儿童成员不向此页面输出账户邮箱。缺失资料显示稳定身份标识，不推断姓名；资料时间明确为最近同步。
- 成员列表的资料与成员访问版本分开。`GET/PATCH /tenants/{tenantId}/members/{memberKey}/access` 使用 64 位 actor key 定位，访问描述固定包含 actorId/memberKey/role/subjectId/version/classIds 六字段，subjectId 可为 null，classIds 始终为列表，强 ETag 对应权限版本，不随显示资料改变。
- PATCH 要求近期 MFA、If-Match，支持 Idempotency-Key。OWNER 不能由此接口修改或授予；必须使用双方交接。只有 OWNER 能授予/修改 ORG_ADMIN，机构管理员只能调整普通成员。家庭/机构角色和 CHILD/TEACHER 主体范围按同一授权规则校验。
- 儿童身份与成人身份不能通过管理员选项相互转换；需要重新邀请，由目标账户重新证明成人资格。成人角色之间可以调整；儿童仍可按授权调整关联档案。此边界防止管理员将儿童账号直接提升为成人。
- 权限或范围改变递增成员版本、记录审计，旧 JWT 立即受数据库当前权限限制。旧邀请、待确认配对、临时访问窗口和预览失效；已生效设备、已提交发布/退出保留。无实质变化的重复操作不增加版本；真实变化严格递增1。
- 移除后重新加入不能使旧邀请和敏感待办复活；成员变更与敏感待办清理同事务。共用成员控制行，按 actor_key 顺序锁成员，避免独占 tenants 外键父表。
- 策略预览固定记录原发起人 key，以精确失效该成员的待办；缺少发起人时保守失效，已发布预览保留。

## 客户端访问事实

[member_access.dart](../apps/guardian/lib/core/member_access.dart) 的 MemberAccessTarget 在等待前复制并核对原列表 actorId/cursor；cursor 与访问 memberKey 都是64位小写十六进制，actorId 是原始OIDC subject，不要求UUID，不裁剪或改大小写，长度与空白准入保持服务端语义。MemberAccessSnapshot 仅接收当前六字段，版本必须为0～9007199254740991的精确整数；角色与工作空间种类一致，档案／班级引用遵循当前范围形状，班级唯一、最多50且深冻结。解析不查目录活动状态，归档仍保留完整引用。

首次与编辑前再次GET都对齐同一原目标；后者可看到更多版本变更，但拒绝版本倒退或同版本事实漂移。PATCH回执精确匹配原正文的角色、档案和班级集合，以及无变化原版本／真实变化+1；不接受版本跳跃或只匹配部分字段。姓名、已验证邮箱和资料时间单独从同一原行按白名单展示，不参与授权，也不以任意Map合并覆盖访问事实。回执不完整时不提示成功，沿原未知结果保护核对。

## 界面

- 成员显示姓名、已验证邮箱/稳定账号、角色和关联档案；调整前重新读取访问版本，展示当前和目标角色/范围及待办影响。
- 根据操作者和目标身份过滤可选角色；儿童必选档案，教师明确选择单档案或一个/多个班级，其他角色不发送 subjectId。邀请与调整复用同一范围规则。
- 角色改变、撤销、并发冲突、近期认证、结果未知重试与工作空间切换都明确反馈。所有权选择器沿用完整身份核对并显示新资料。

- 管理台只读查看成员、邀请及权限历史后保留已加载页与搜索；取消危险确认不刷新。实际尝试 PATCH/DELETE、读取观察到访问版本变化或编辑器要求核对后才重读列表，未知写入关闭仍需核对，不推断为未执行或保存成功。撤销确认展示原成员名称、完整账号/成员编号、权限版本及后果，取消邀请展示原邀请编号、角色和期限；原窗口或权限失效即停止旧确认，独立覆盖窗口保留。

- 列表当前读取明确401/403（非REAUTH_REQUIRED）或WORKSPACE_CHANGED，锁存页面读取失权并停止旧回调，重新进入页面才能重新读取。单个access／access-history的403也用于隐藏不存在、不属于租户或已撤销的目标，不能直接判定整页失权；只退役该成员详情及两层历史窗口，再由原列表租约核对一次。列表仍可读时其他成员照常管理，列表拒绝才退役整页。目标读取的非近期认证401或工作空间失效直接退役页面；目录读取、普通网络／近期认证错误及写操作拒绝不复用目标拒绝处理。目标通知贯穿历史详情，窗口失权后只结束所属OwnedDialogRoute，独立通知保留，不改变会话代际。

- 成员编辑或邀请提交前冻结原正文（含班级列表），首次明确拒绝仍可修正；已有网络/5xx未知结果后，后续认证、权限或普通4xx拒绝不证明旧操作失败，原内容保持锁定。412、409 IDEMPOTENCY_KEY_EXPIRED、410 IDEMPOTENCY_RESULT_EXPIRED/IDEMPOTENCY_RESPONSE_ERASED 停止旧请求重试，保留中文只读草稿与完整范围编号。未知关闭先在原表单内确认，明确关闭不等于取消操作；编辑返回 refresh，禁止重试的邀请返回 reviewInvitations，只核对记录，不自动重放。

- 邀请表单立即打开；调整权限在原详情中复核当前成员权限，读取中防重复点击，普通失败保留详情与原地重试入口，成功后才关闭详情并将所核验版本固定给编辑器；不在提交时静默取版。原详情被移除或失权后，迟到结果及拒绝不影响新旅程；独立覆盖窗口置顶时不自动打开编辑器，详情退出动画期间也不覆盖新窗口。新版本或当前角色已不可编辑时保留列表核对信号。按所选角色/范围读取必要目录，无范围角色不查目录；目录未读、失败和成功空结果分别显示，加载失败可就地重试。原档案/班级引用保留完整编号占位，成功目录缺少原项时提示重新选择；不静默清空、默认替换或放开无效范围提交。目录读取不改变未知写入状态，关闭编辑器同步停止其目录生命周期和后续分页。

- 班级多选可按名称/完整编号本地查找或仅看已选，使用有界懒列表；搜索与筛选不修改原选择，已选但目录缺失的编号可明确取消。上限50项在当前交互与原表单中共同约束，不能自动裁剪已有范围；必填/无效引用在选项已读后由表单就近提示。切换教师范围模式后，旧班级/档案控件不能继续修改其他模式的草稿。

## 已实现接口

| 路由 | 输入与返回 | 权限与并发 |
|---|---|---|
| GET /tenants/{tenantId}/members | 分页成员资料、角色、档案名称/归档标记、权限版本 | OWNER/ORG_ADMIN；儿童邮箱不输出，旧账户资料缺失时保留稳定标识 |
| GET /tenants/{tenantId}/members/{memberKey}/access | actorId/memberKey/role/subjectId/version/classIds，强 ETag | 当前管理权限；不含会独立更新的显示资料 |
| PATCH /tenants/{tenantId}/members/{memberKey}/access | role、可选 subjectId 或 classIds → 最新访问描述 | 近期 MFA、If-Match，支持 Idempotency-Key；角色和范围改变同事务清理旧待办 |
| DELETE /tenants/{tenantId}/members/{memberKey}/access | 无正文，204 | 近期 MFA、If-Match，支持 Idempotency-Key；旧撤销请求重放不撤销重新加入的新成员版本 |
| GET /tenants/{tenantId}/members/{memberKey}/access-history | limit/cursor → 角色/范围前后差异、版本、操作者、时间 | 当前管理权限；按成员版本倒序，游标限定当前成员与租户；包括撤销历史 |

memberKey 使用成员列表的 cursor 值，是精确 actor subject 的 SHA-256。旧 DELETE 原始 actor 路由保留兼容，管理界面已改用强版本的稳定标识接口。

角色变更历史从 V18 开始记录；加入和所有者交接分别在审计/交接记录中查看，不补造旧数据。身份资料在 `/me`、创建工作空间和接受邀请时同步，不从外部用户目录批量抓取。展示资料不会改变权限版本。

V19 后续已扩展到班级范围：教师可选择 1–50 个 classIds 或一个 subjectId，两者互斥；历史增加 previousClassIds/classIds，旧历史按空列表读取。班级授权绑定成员版本，重新加入不得复活旧范围。班级、学生及设备状态只读入口已接入；本人有限申请和班级失权联动已加入教师专项与真实 MySQL 回归，见 [机构工作流](organization-workflow-plan.md)。课堂会话与独立设备组继续实施。邀请令牌不写入幂等日志，传输结果未知时禁止直接重试创建，引导查看邀请记录并取消未取得令牌的邀请。

## 阶段验证

- 初始成员接口与资料用例 5 项失败，随后 50 项相关回归通过；敏感待办/历史新增 9 项中 3 项失败，再完成同事务监听器与历史接口。
- 增加稳定标识撤销、并发修改、历史分页和大小写身份隔离后，H2 相关 57 项通过；真实独立 MySQL 的成员 12 项与交接 14 项共 26 项通过，临时库与账号已清理。
- 新增监听器故障回滚验证，断言成员版本、角色、历史和待接受邀请整体回滚。完整验证与运行更新结果见实施记录。
- 日志在忽略的 `.local/member-*.log`；身份凭据和浏览器会话未进入版本库。全量测试曾因本机内存不足中断，后续用有界 JVM 堆和逐类进程执行，不把环境中断计为通过。
