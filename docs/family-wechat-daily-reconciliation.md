# 家庭微信日账单对账

本轮实现范围是服务器账单核验、差异排队、可信查询修复与永久财务审计。默认关闭外部商户调用和账单定时任务，未调用真实商户，未改动本机已有数据库。构建和隔离数据库测试通过不代表真实付款、退款或对账验收通过。

## 家长与运营的操作

家长只看到订单与退款当前进度。运营在独立财务入口选择账单日、查看差异、排队核对原交易，必要时填写处理备注。账单差异不会直接修改会员；原交易查询核实后，再重新对账产生新的证据。

| 状态 | 含义 |
|---|---|
| PENDING / RUNNING | 等待处理 / 正在核对 |
| MATCHED | 当前快照中全部账单行均映射本系统家庭订单，金额、流水、交易日与本地可信记录相符 |
| PARTIAL | 存在未映射的其它业务流水或历史退款受理日不完整，不能称为整商户对平 |
| DIFFERENCES | 已知家庭订单存在未确认付款、缺单、金额、流水、商户、日期等差异，或账单出现重复流水 |
| UNAVAILABLE | 账单未生成、不存在、服务不可达或验签无法确认；可保留原任务重试 |
| INVALID_BILL | 摘要、格式、汇总或完整性未通过，不能作为对账证据 |
| ATTENTION | 任务租约反复中断并耗尽尝试，需要人工检查，避免阻塞后续任务 |

差异的“已记录处理”只保存备注、操作人摘要和时间，不删除差异，不把任务改为对平。未映射条目保留不透明流水号、金额与行摘要，不导入为家庭订单，也不能发起不存在的家庭交易查询。再次对账新建一次尝试；旧尝试和差异仍保留。

## 可信边界

- 申请现代 `ALL` 账单，使用上海交易日。昨日账单须到上海时间次日 10 点后申请，支持前三个自然月，不按固定 90 天估算。
- 申请响应沿用已有微信 v3 商户签名与平台验签。下载只允许官方 HTTPS 主域名和两个已文档化路径，禁止重定向；下载请求仍签名，文件本身使用申请响应中的 SHA1 验证。
- 首发不请求压缩格式。下载最多 8 MiB，最多 20,000 明细，单行最多 16 KiB；UTF-8、现代 ALL 表头、七列汇总、所有金额和明细数量严格校验。未知旧格式明确失败，不猜测字段。
- 金额以整数分比较；核对订单总金额和申请退款金额，不能拿优惠后的应结金额替代订单金额。汇总同时验证应结、退款、充值券退款、手续费、订单及申请退款金额。
- 退款账单是受理时的快照，`PROCESSING` 不会将后来已确认的 `REFUNDED` 降级。退款交易日来自已验签查询响应 `create_time`，保存为 `provider_accepted_at`；不得使用审核时间、调用时间或退款到账时间替代。
- 每个家庭订单必须绑定当前商户、AppID、普通商户模式、APP 交易、币种、金额及流水。其它业务不自动认领。原始账单、付款人 OpenID、商品名称、下载凭证不进入运营响应或日志。
- CSV 只能形成差异。发放、撤销或恢复会员始终依赖已有查单／查退款验签与原订单证据。

## 任务与恢复

账单任务按商户与 AppID 的摘要、交易日唯一。入队和备注只使用短事务；网络下载不能在外层数据库事务中执行。每次执行先持久化两分钟租约，再在事务外下载，最后校验租约令牌后发布。旧工作者失去租约后不能覆盖新尝试。

定时任务 `manager.family.bills.worker.enabled` 默认 `false`，间隔默认 60 秒。启用后从昨日开始持久保存日游标，停机后逐日补排，人工补单不会跳过游标。每轮最多补排三天、执行三个任务；服务不可用最多自动尝试六次，人工可保留原任务再次排队。尝试累计上限 50，过期租约耗尽进入 ATTENTION，不再占用后续任务队列。超过官方三个月窗口的停机缺口须通过商户平台资料人工核对，不能由接口补取或宣称已核对。

财务表为 `family_bill_tasks`、`family_bill_attempts`、`family_bill_differences`、`family_bill_cursors`、`family_bill_audit_events`。初始化片段只合并到未发布新库基线；不会对现有开发库执行清空或升级。账单与审计不是儿童观察数据，不能因设备退出或孩子数据删除而抹掉金融证据。

平台接口需要独立 `family-finance:manage` 与近期 MFA，家庭角色不能替代财务权限。入队、重试、备注及可信核对排队均带幂等键。`family_bill_audit_events` 可以记录没有租户归属的商户条目，不伪造家庭租户以绕过审计约束。

## 验证与收费前检查

隔离测试覆盖 SHA1 损坏、截断和未知格式、全列汇总、精确分、重复流水、跨商户／AppID／日期、未映射条目、缺单、退款受理日、实际订阅服务退款状态、外层事务拒绝、并发领取、过期工作者、耗尽租约、原任务重试与永久审计回滚。详细结果由本轮交付记录汇总。

仍须使用正式商户完成真实日账单、迟生成、无流水日、跨日支付及退款、通知丢失补查、实际退款成功与商户平台金额核验；同时验证生产 MySQL 并发与租约恢复。此记录不替代真实支付退款验收。
