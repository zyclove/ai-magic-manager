# 受管执行：重新核实设备状态

状态：2026-10-19 的隔离实现候选，尚未集成、部署或开放生产。实际接口回归结果另行登记，本文不能作为功能已上线的证明。

## 1. 操作目的与边界

管理员在任务“待复核”时，可以请求一次新的有界设备观察。该操作适用于已有可信策略写入回执、暂时未能确认设备应用结果的任务。服务再次查询设备，只有精确策略版本、受管模式及合规结果都符合要求，才将任务更新为“已应用”。

操作不会重新发送策略、重新分配设备、覆盖取消请求或延长原任务有效期。管理员没有“强制标记成功”或“忽略不确定结果释放占位”的入口。

## 2. 使用流程

1. 管理员打开任务详情，查看最后结果、时间线和最新版本。
2. 对符合条件的待复核任务，选择“重新核实设备状态”。说明文字为：“将重新查询设备是否已应用这份规则。原有规则和有效期保持不变。”
3. 完成近期多因素认证；提交时携带刚查看的任务版本。
4. 服务在短事务中核对当前管理员、原执行者权限、绑定关系、冻结发布版本及任务状态，登记新的观察轮次。
5. 受理后显示“等待核实”，继续展示时间线；受理成功不等于设备已应用。
6. 独立设备证据满足条件才显示“已应用”。读取失败按现有有界重试处理；仍无法确认则保留待复核状态和设备占位。

设备重新注册、管理员撤权或绑定变化后，旧任务不能借此入口恢复执行。

## 3. 请求契约

`POST /api/v1/tenants/{tenant}/managed-android/executions/{id}/recheck-device`

| 项目 | 约束 |
| --- | --- |
| 身份 | OIDC 管理员，近期多因素认证 |
| 角色 | 当前租户 OWNER / ORG_ADMIN；原执行者的当前权限也必须有效 |
| 并发 | 必须提供单个强 `If-Match`，例如 `"8"` |
| 请求数据 | 不接收客户端指定的提供方版本、远端资源、期望结果或成功标记 |
| 返回 | 最新执行详情；新 ETag；`Cache-Control: no-store`；`Vary: Authorization` |
| 成功状态 | `WAITING_DEVICE`，原因 `MANUAL_DEVICE_RECHECK_REQUESTED` |
| 副作用 | 重置本轮观察次数、增加版本、追加时间线和操作人审计，保留原有效期及全部绑定事实 |
| 外部调用 | HTTP 请求事务内不调用提供方；既有观察消费者稍后领取只读租约 |

只有同时满足以下条件才受理：

- 状态为 `NEEDS_REVIEW`，未取消，且有可信的策略写入回执版本。
- 当前连接器匹配原任务提供方，设备观察消费者可用。
- 无仍有效的租约，原到期时间至少还剩一个完整执行租约。
- 原绑定上下文及冻结发布版本没有改变；版本/代次尚未达到安全上限。

同一 `If-Match` 重发返回 412；客户端刷新详情检查最新状态，不自动以新版本重复提交。已经进入 `WAITING_DEVICE` 的任务不能再次清零观察次数。本接口没有独立请求 ID，不能把其他管理员产生的新状态归因为本次请求成功；读取到旧版本也不能证明之前的请求不会稍后提交。

## 4. 结果解释与下一步

| 结果 | 用户提示 | 下一步 |
| --- | --- | --- |
| 401 `REAUTH_REQUIRED` | 请重新验证管理员身份 | 完成认证后刷新详情再提交 |
| 403 | 当前账号无权操作此任务 | 返回任务列表；不显示其他租户或管理员资料 |
| 428 / 400 | 请先刷新任务状态 | 取得有效版本；不自动猜测版本 |
| 412 `RESOURCE_VERSION_CONFLICT` | 任务状态已更新 | 刷新详情，检查是否已经开始核实 |
| `EXECUTION_RECHECK_REQUIRES_REVIEW` | 此任务当前无需重新核实 | 展示最新状态和时间线 |
| `EXECUTION_RECHECK_CANCELLED` | 任务已取消，仍需人工确认设备现状 | 保留取消状态；不恢复观察或重发规则 |
| `EXECUTION_RECHECK_REQUIRES_POLICY_RECEIPT` | 暂无可靠回执，无法自动确认 | 转人工调查，保留设备占位 |
| `EXECUTION_RECHECK_WINDOW_CLOSED` | 本任务的核实时间已结束 | 转人工调查，不延长旧授权 |
| `EXECUTION_RECHECK_LEASE_ACTIVE` | 仍有操作正在处理 | 稍后刷新，不抢占现有任务 |
| `EXECUTION_RECHECK_UNAVAILABLE` | 设备核实服务暂不可用 | 保留当前状态，允许稍后刷新 |
| `EXECUTION_CONTEXT_CHANGED` | 设备或规则信息已变化 | 核对当前设备注册和规则，旧任务不复用 |

除明确的认证/版本错误外，上表业务拒绝使用 409。网络断开或响应丢失时只查询详情恢复状态，不将未知结果显示为“未提交”。查询恢复必须核对租户、任务、设备、注册、发布记录及单调版本；旧响应、身份变化后的迟到响应不能覆盖当前界面。

当前详情不暴露完整服务端受理条件，不能仅凭 `NEEDS_REVIEW` 推断操作可用。联合交付必须补齐下面的独立资格投影，客户端入口据此显示可操作状态及拒绝原因，保留 POST 的最后裁决。旧版客户端严格检查原因码，不认识 `MANUAL_DEVICE_RECHECK_REQUESTED`；发布时须先补齐原因解析、时间线文案和交互恢复，再联合验收并启用服务端开关。

### 独立资格投影（隔离候选回归通过，尚未合入）

`GET /api/v1/tenants/{tenant}/managed-android/executions/{id}/review-eligibility`

精确返回七个字段：`id`、`publicationId`、`deviceId`、`registrationId`、`revision`、`allowed`、`reason`。前五项必须与当前执行详情一致；`allowed=true` 时 `reason=ELIGIBLE`，否则返回稳定原因码。OWNER / ORG_ADMIN 可获得执行资格判断；AUDITOR 可以读取但得到 `ADMINISTRATOR_REQUIRED`，儿童与其他无权角色返回 403。

拒绝原因包括 `EXECUTION_RECHECK_REQUIRES_REVIEW`、`EXECUTION_RECHECK_CANCELLED`、`EXECUTION_RECHECK_REQUIRES_POLICY_RECEIPT`、`EXECUTION_RECHECK_WINDOW_CLOSED`、`EXECUTION_RECHECK_LEASE_ACTIVE`、`EXECUTION_RECHECK_UNAVAILABLE`、`EXECUTION_CONTEXT_CHANGED`、`EXECUTION_VERSION_EXHAUSTED`。不返回内部策略版本、原执行者资料、租约令牌或提供方资源。

该读取不要求刚完成多因素认证，不续租、不清零次数、不写审计、不调用外部提供方。成功返回 `no-store` / `Vary: Authorization`，**不返回 ETag**：连接器可用性与时间窗口可在任务版本不变时变化，不能把任务版本当作此投影的强表示版本。响应中的 `revision` 仅用来与详情对齐和构造后续任务变更的 If-Match。

GET 和 POST 应复用同一资格判断规则；POST 仍在写事务与权限锁内重新验证。客户端在确认前刷新详情及资格，身份/选中设备改变时丢弃迟到响应。资格读取失败或投影与详情不一致时显示“暂时无法确认能否复核”，不通过试发 POST 获取资格，也不把旧投影永久缓存为授权。

## 5. 配置与授权

`manager.emm.execution.manual-review.enabled` 默认 `false`。启用时必须同时启用 `manager.emm.execution.device-recovery.enabled` 并存在对应消费者；这仅是本入口依赖，不能代替整个平台的生产启用验收。

审计分别保留系统状态变更和实际请求管理员的 `MANAGED_EXECUTION_DEVICE_RECHECK_REQUESTED`。确认人和原执行者按稳定顺序锁定租户成员，再锁定绑定、发布与任务，避免以新的确认人替换旧发布授权。

合入共享后端时，必须保留家庭身份模块的租户级再次认证规则；当前隔离基线仍使用旧版 `RecentAuthentication`，不能直接覆盖共享身份实现。
