# 儿童求助记录：设备、云端与管理端

本功能让已注册 Android 设备上的儿童明确选择求助类型并提交云端记录，供当前家庭所有者、监护人或机构管理员在管理端查看和确认已看到。它**不是紧急呼叫、报警、实时短信或人工值守服务**。儿童端与管理端持续提示：存在即时危险时应直接寻求现场可信任的成人或当地紧急服务。云端 `201/200` 只证明服务端收到记录；成人点击“已看到”只证明管理台留痕，不证明已联系孩子或问题已解决。

此前代码阶段完成后端打包、两端 Dart 静态分析、两端 Web 构建及儿童端 Android 调试包构建。本轮专项验收另完成儿童端152项测试、H2受影响40项、MySQL求助28项及完整后端844项通过（20项条件跳过），详见[验收记录](releases/stage-child-help-verification.json)。尚未完成真实设备到正式服务的跨进程求助验收，也未部署本阶段到生产环境；构建结果不等于实际送达或成人响应保证。

## 范围与数据

求助类型固定为 `NEED_HELP`、`UNCOMFORTABLE_CONTENT`、`DEVICE_PROBLEM`，不收集自由文本、图片、摄像头、定位或儿童联系方式。服务端从设备专用 opaque 凭证取得租户、设备和注册周期，核对设备及儿童档案仍有效，然后写入 `child_help_requests` 和同事务审计。儿童不能提交管理员身份或更改目标家庭。每个注册周期和客户端请求 UUID 唯一；同一编号同一类型重放返回原记录，换类型返回冲突。单设备每分钟最多新建十条，原请求重放不消耗名额。

新表及索引直接纳入未发布的 1.0.0 初始建库基线，并登记到主体数据分类清单。主体级求助记录的内部有界删除步骤见[求助记录删除步骤](erasure-child-help-plan.md)；完整删除编排、保留期限、实际数据库验收和备份恢复后的再删除尚未完成，不应将当前流程标记为完整的数据删除闭环。

服务端状态仅 `OPEN` 与 `ACKNOWLEDGED`。后者无“处理完成”语义。家庭所有者、监护人和机构管理员在本租户读取、按时间分页、筛选 `OPEN` 并以强版本确认已看到；并发确认只有一个写入成功。机构教师只能查看和确认当前数据库成员关系允许访问的学生求助，范围可来自当前班级或直接分配的学生档案，不能查看其他学生；转班、班级归档、教师范围或成员版本变化后，每次读取和确认都会重新核对范围。家庭空间的教师角色、儿童和审计员不能调用收件接口。设备只能按原客户端请求编号读取自己的当前注册周期记录。收件列表在授权查询内关联儿童当前昵称，便于教师定位学生；设备响应不携带昵称，求助表不复制昵称。所有响应禁止缓存，不包含成人身份或求助自由文本。审计事件保留设备发起与成人确认两项事实。

| 接口 | 用途 |
| --- | --- |
| `POST /api/v1/device-api/help-requests` | 设备提交 `clientRequestId` 与 `reasonCode`；新建 201、原样重放 200 |
| `GET /api/v1/device-api/help-requests/{clientRequestId}` | 网络结果未知后按原编号核对，不生成新请求 |
| `GET /api/v1/tenants/{tenantId}/help-requests?state=OPEN&limit=20&cursor=...` | 管理员收件箱，时间倒序、稳定分页 |
| `GET /api/v1/tenants/{tenantId}/help-requests/open-count` | 顶部每分钟刷新、前台恢复时刷新的有界数量，最多显示 1000+ |
| `POST /api/v1/tenants/{tenantId}/help-requests/{id}/acknowledge` | `If-Match` 强版本；只标记已看到，记录审计 |

## 设备持久化与失联

儿童端在发送 HTTP 之前生成 UUID，并通过现有 `flutter_secure_storage` 加密存储和原生提交屏障保存原编号、类型和 `PREPARED` 阶段。若断网、进程中断或响应格式不完整，原记录继续保留；界面先按原编号查询，服务端未找到时才能手动重试**相同编号与类型**。客户端不自动重发求助，也不在后台自行创建请求。收到服务端与本设备、原编号及类型匹配的记录后持久化 `CONFIRMED`；旧确认不能倒退成未查看。只有确认过的本地记录可以被显式新求助覆盖。注册周期改变时使用不同的加密存储键，旧周期数据不会展示；正常退出的本应用私有数据清理纳入此键前缀。

重试动作自身先查询云端：已收到则只恢复确认，明确未找到时才提交原编号，查询失败时保留记录而不发送。应用 UI isolate 内同一注册周期的提交、重试和刷新互斥，页面重建也不会越过上一页面尚未结束的存储写入；读取已持久化快照不占用写操作入口，前台恢复时可继续显示待核对记录。存储异常统一为可识别错误，不解释为云端成功。此保护不构成多进程存储锁或实际 Android 断电恢复认证。

服务端新建事务使用 `READ_COMMITTED`，在既有主体、设备及凭证锁内查询最新求助记录和限额计数，避免 MySQL 默认快照让并发原编号重放误报错误或超出十条限额。专项验证与当前边界见[求助行为验收计划](child-help-verification-plan.md)。

## 展示与后续交付

管理端导航和顶部徽标对有权查看求助的成人及机构教师开放。教师工作台的计数、收件页及确认动作只使用当前班级/学生范围；教师不能由此取得策略或设备管理权。徽标是前台在站内轮询的结果，浏览器关闭、网络断开或人员未登录时不会主动通知。首页显示待查看求助数，并引导到收件页；收件页按原记录版本确认，失败时要求刷新核对，不把网络错误解释为确认成功。

管理台确认窗口直接展示已捕获记录的对象昵称及完整主体编号、求助类型、完整设备编号和提交时间，缺昵称使用完整主体编号，不追加目录请求。确认仍只有原来的一个步骤，长内容可滚动，保留“已看到不等于已联系或已解决”的说明。确认窗口复用原父路由和权限租约，工作空间变化、页面移除或服务端明确拒绝后只关闭自己的窗口，不关闭独立覆盖通知。

读取或确认返回 401、403、`WORKSPACE_CHANGED`，或返回表明记录已不可用/范围已失效的 `HELP_REQUEST_UNAVAILABLE` 时，当前求助页面捕获失效：隐藏私有记录、清除分页并阻止旧回调与晚到读取恢复内容。重新打开时重新读取并授权，不把旧本地会话状态当作仍有访问权。普通网络/服务失败继续保留原结果未定标记；行内“刷新核对”只读取列表，沿用读取开始时的操作代次资格，不自动重发确认，也不把刷新成功当成已提供帮助。当前静态候选与未运行范围见[求助工作台阶段记录](reviews/help-workbench-20261026.md)；上方历史验收不覆盖本次改动。

上线前还需要：正式消息渠道与失败重试/值守规则、儿童数据保留期限及删除作业、已处理后的后续跟进记录、真实设备离线/重启/存储损坏验证、无障碍与电视遥控验收。中国大陆机构客户应把响应责任、值守时间和不可用时的线下流程写入合同与操作手册。本阶段没有这些外部交付证据，不宣传为全天候安全救援。
