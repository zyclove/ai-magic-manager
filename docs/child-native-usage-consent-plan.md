# Android 使用摘要真实授权与撤回闭环

## 要验证的产品事实

当前代码已有监护人观察授权、设备侧系统特殊访问引导、Android `UsageStatsManager` 聚合来源、授权版本化上传和儿童/监护人报表。上一阶段只在系统许可及云端同意均关闭时验证 `NOT_AUTHORIZED`。本阶段在专用 API 34 调试模拟器与真实 Spring 隔离数据库上，验证两项独立授权共同开启后能产生真实系统聚合报告，撤回云端同意后即使系统许可仍开启，服务器也不再提供报告并清除保存的摘要。

1. 已确认的同一设备注册与签名配置仍从正式 `ProductionChildRuntime` 加载。监护人通过正式管理接口以近期 MFA 夹具、`If-Match` 和幂等键开启使用摘要；不能在设备测试中直接修改数据库授权行。
2. 宿主先核对专用模拟器当前 `GET_USAGE_STATS` 未授予，再通过 Android `appops` 在这台已拥有的调试设备上授予该应用；前台打开系统设置一小段时间，生成真实系统使用记录。设备通过 Pigeon 来源读取系统授权与 `UsageStatsManager`，由正式观察代理向 Spring 上传；不插入伪造的使用时长。
3. 验证服务端已保存当前授权版本、报告 ID、序号和至少一项可见应用聚合；儿童端和成人端读取 `OBSERVED`，且仍标注 `OS_AGGREGATE` / `AGENT_REPORTED_UNVERIFIED`，不当作强制额度或精确计费证据。
4. 监护人通过正式接口撤回使用摘要，验证服务端摘要与回执头清除。保持设备系统许可为允许，再由同一设备重新读取云端授权，确认不会上传或显示旧摘要；报表为 `NOT_AUTHORIZED`。
5. 每个原生阶段结束都恢复该应用原 `appops` 模式；最后精确清理运行目录、加密键和私有票据，恢复普通 APK，保持 UID 与首次安装时间，不清空应用数据、不卸载、不触碰其他 AVD。

## 拒绝条件与边界

- 专用 AVD 名称、序列、包名或安装身份不符就停止。授权前若系统许可已由其他操作者授予，不覆盖原设置。
- 实际 `UsageStats` 聚合可能因系统记录尚未生成而没有可见应用；此时验收失败并保留诊断，不填充模拟记录冒充真实采集。
- 设备侧仍使用普通应用权限，不获得 DPC/EMM 能力；该阶段不证明后台常驻、防强停、电视兼容或系统级应用阻止。
- 成人身份及 MFA 是 Spring 测试夹具；真实 OIDC、物理设备、OceanBase 和容量仍需单独验收。

本阶段实际结果见 [验收记录](child-native-usage-consent-acceptance.md) 与 [机器验收记录](releases/stage-child-native-usage-verification.json)。
