# 设备审批接收组件实施计划

完整计划 Task 5/7/8 的设备接收基础。目录为 `packages/device_access`，与正在独立推进的 `packages/device_policy` 分离；使用当前已验证环境中的 Dart、JOSE、Sembast、crypto、collection。

## 约定

- 验证外置可信公钥环、ES256/独立类型、完整租户/儿童/设备/注册绑定、基础/应用/规则引用、协议与原批准期限。宿主提供当前已验证基础匹配函数和可信时间，不默认信任系统墙钟。
- 当前只接收 CONFIGURE_ONLY，始终 systemEnforced=false。配置接收与原生规则执行分别验收；不能从文档保存成功推导已解锁。
- 授权文档不变，传输尝试编号单独保存。相同审批版本不能替换签名文档，同一请求不能改原授权范围与期限；更高撤回版本保留水位，旧文档不复活。
- Sembast 事务同时保存文档/撤回水位、已观察时间和待发送回执。只有提交成功后返回 STORED；存储异常不报告成功。收到或保存的用户数据不写异常文本。
- 回执采用 request/document/attempt/phase 的稳定关联；同尝试拒绝后，只能用新尝试恢复；旧 ACK 不能清除新尝试。缺基础可报告 BASELINE_MISSING，期限已过可报告 EXPIRED；无效签名不从其载荷提取可信回执目标。
- 在服务端已经 STORED 的尝试上，本地后续验证失败只返回本地诊断，不生成矛盾 REJECTED；宿主只发送持久队列，不直接把所有异常转换成拒绝回执。
- 重开数据库重新验签并核对元数据；恢复读取再次检查原期限、时钟下限和当前基础。过期批准不成为活动配置；撤回在原批准截止之后仍保存。时钟回拨阻止批准恢复，但不阻止有效撤回使配置失活。
- 有界记录/回执数量，容量耗尽整体回滚；宿主需处理积压与注册清理。硬件防回滚、静态加密、安全时钟、HTTP 同步/自动重试、儿童宿主和原生执行继续实现，不在此组件阶段伪造完成。

## 验证

1. 新接口行为 RED→GREEN；非法签名/用途/绑定/规则/时限、不可变模型。
2. 实际文件数据库关闭重开、并发重复、拒绝恢复、撤回和旧 ACK、容量/损坏/时钟异常。
3. Dart 分析、VM 和适用 Chrome 检查；独立 Nimbus/后端签名器互操作。
4. 完成后记录实际证据与剩余范围，不将组件通过等同于真机执行或完整 APR 验收。

## 本阶段结果

- 已实现独立 verifier、不可变模型、journal 和强关联 ACK。文档/水位/队列同事务；无效签名不生成可信回执目标；服务端拒收原样保留，已保存尝试的本地后续失败只诊断。
- 验签 24 项 RED→GREEN；初始 journal 24 项中 23 项因未实现失败，1 项 ACK 模型通过，再完成持久化实现。新增跨平台检查时发现同名 Sembast 内存库在 close 后仍保留数据，改为每项创建前清理该独立内存库。
- 完整 VM 56 项通过，Chrome 32 项通过，analyze 无问题。实际后端 JAR 的 Envelope/Document/Receipt 记录、Jackson 和 Nimbus 签名器互操作通过；检查使用临时测试密钥，不接触生产密钥。逐项证据及检查边界见完整实施记录。
- C 盘临时空间耗尽曾导致测试编译复制失败；改为当前进程的项目 D 盘 TEMP/TMP 后继续，未删除系统或其他任务文件。此环境问题不计为业务检查失败。
- HTTP 自动同步/退避、可信时间、安全存储、儿童宿主集成和 Android/TV 原生执行仍待完成；本阶段不标记完整 Task 5/7/8 或总目标完成。

## HTTP 阶段执行记录

- Ruling：有界同步保存“本轮完整扫描”的续点和代次，扫描结束回到首页 — 服务端 UUID 只排序资源，旧申请撤回不会产生新 UUID — 把它当永久增量游标会漏撤回。
- Ruling：单条文档错误/历史回执冲突记录诊断并继续读取后续项；401/403 等身份错误中止 — 避免旧错误饿死新的撤回 — 宿主必须对诊断关联的配置停止使用缓存，不能将局部扫描完成误作全部成功。
- 已实现成熟 HTTP SDK 的 HTTPS/opaque/取消/限制、严格分页和 ACK 关联，重复触发合并、事务续点、回执重放、退避准备检查、重试竞争后重新读取当前文档。同步结果显式保留积压、Retry-After 和未知提交状态。
- RED→GREEN：传输 11 项缺实现失败后 12 项通过；同步初始 13 项失败后通过；额外严格分页/整数模型检查复现 2 项边界并修正；结果积压检查复现 1 项未填写并补齐。最终验证与 Spring/Dart 实际证据见完整实施记录。
- 首次 Spring/Dart 真实 HTTP 联调 1 项通过（0 skip），包含六次独立进程；成人身份/基础准备和设备激活为显式夹具。当前仍未接儿童宿主、安全时间和 Android/TV 执行；这些范围继续推进。
- Ruling：协议中的计数按有界安全整数的数值检查；JavaScript 的整值浮点与整数无法通过 Dart 运行时类型区分 — Chrome 实测 `2.0` 可被视为 int — 可移植检查使用 `2.5`/越界/错误后继，VM 另保留其更严格的 double 类型拒绝检查，不编造 Web 的词法整数保证。
- 审批 HTTP 联调显式由 `device.access.package` 启用，同时需要 `device.dart.command`；已知通用发布脚本仍由另一工作阶段维护且尚未准备本包依赖，因此本轮不隐式借通用 Dart 开关触发新包。审批组件加入全量发布门槛仍是后续必做项，不能把单独联调通过当作发布门槛完整。
