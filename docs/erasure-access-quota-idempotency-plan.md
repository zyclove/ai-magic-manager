# 审批与配额结果归属（1.0.0）

## 实现范围

承接[通用幂等结果清理](erasure-idempotency-plan.md)，为审批、设备审批、配额和配额计划的 10 个生产操作接线显式归属。归属从当次真实业务响应的不可变 `subjectId` 获取，与业务变更、审计、缓存响应同一事务提交。

| 操作 | 归属来源 |
| --- | --- |
| `access.request` | 实际请求记录的主体；适用于成员请求入口 |
| `access.device.request` | 实际设备请求记录的主体 |
| `access.device.cancel` | 原设备请求的主体 |
| `access.decide` | 被批准或拒绝的请求主体 |
| `access.cancel` | 原成员请求的主体 |
| `access.revoke` | 被撤销授权的请求主体 |
| `quota.create` | 新建额度池的主体，含 TOTAL 与 APPLICATION |
| `quota.adjust` | 原额度池不可变主体 |
| `quota.plan.create` | 新建计划的主体 |
| `quota.plan.update` | 原计划不可变主体，含调整和暂停 |

以上均是单主体结果；一个儿童的额度跨设备使用不会变成跨主体共享结果。审批人、教师、设备调用者和儿童不是同一个归属概念，不能用当前调用者代替被处理主体。

回调接线保留原有权限、近期 MFA、领域锁、请求摘要、版本条件、状态协调和只读恢复逻辑。缓存重试不重新推断归属，也不重复写入请求、决策、额度账目、计划版本或归属行。

## 清理和权限顺序

沿用 `ERASED` 永久拒绝重放标记。有效权限下，原请求键即使过期或内容变化也返回 410 / `IDEMPOTENCY_RESPONSE_ERASED`；原结果恢复不能将其改写成“无结果”或触发重新提交。

当前权限或原业务资源读取可能先于缓存查询。例如配额调整、计划更新需要锁定活动主体；主体归档或成员撤权时应先拒绝访问，不为返回 410 绕过原有授权。

设备检查使用真实不透明凭证认证和领域事务。测试中的注册/凭证 SQL、成人 JWT/MFA 及已提交的 ERASED 标记为明确夹具，本阶段不声称重新验证原生注册、真实成人 MFA 或完整删除 worker。

## 租户资源标识边界

独立 MySQL HTTP 回归复现：默认不区分大小写的文本排序规则允许大写租户路径命中小写 UUID 的会员行；之后严格归属校验抛内部异常，返回 500。H2 的普通大小写敏感查询未暴露这一分支。

`TenantAccess` 现在在授权 SQL 及 `subjectFilter`、`canReadSubject` 的成人捷径之前检查规范 UUID，拒绝大写、缩写、畸形或空租户标识为 403 / `SCOPE_DENIED`。使用完整小写 UUID，不限制 UUID 版本或 variant。系统返回的规范 ID 和其原结果重放保持可用，不通过数据库排序规则接受资源路径别名。

## 验证与边界

测试先观察未接线时的明确断言失败，再接入回调；大小写问题先在真实 MySQL 观察 500，再修复授权入口。定向覆盖 24 个成员审批、13 个设备审批、15 个配额/计划和 4 个资源标识用例。

重试前后比较持久化完整行，覆盖审批通知以及配额池、账目、计划、版本、发件箱、审计、响应和归属。设备 ERASED 夹具保留不透明归属与查询键，并清空原调用者、操作、请求摘要和正文，与内部处理器的标记结构一致；过期时间为有意设置的边界。测试直接构造已提交标记，不将此等同于执行删除 worker。UUID 回归直接覆盖大小写别名和成人快捷入口，未单独枚举 null、畸形输入或 UUID 各版本；本轮 journey tests 未新增变更中途失败的回滚注入。

基线为 `75efd38a2471b64c41e3ed0971dc688098490889` 加本轮 8 个源码文件。使用冻结副本、独立 MySQL 测试库、执行资源字节核对及完整后端回归；具体结果与环境跳过项见[验收记录](releases/stage-access-quota-idempotency-verification.json)。

修正夹具后的定向 H2 与独立 MySQL 各 56 项全部通过，临时 MySQL 库和用户已清理。完整后端回归共 992 项：970 项通过、22 项按设备/外部环境条件跳过、无失败或错误，已打包 `1.0.0`。首轮旧夹具的完整回归与 MySQL 记录单独归档，由最终修正候选的验收取代。

旧审计基线的 46 个 `execute` 调用中，已接线创建档案及本轮 10 个操作；其余 35 个调用仍待明确归属。新增查询或其他会话改动按各自验收基线记录。这不代表全部个人副本已经覆盖，也不完成公开删除提交、自动 worker、全局完成水位或真实旧备份恢复再删除。本阶段不改变 V1 建库文件，不更新运行服务。
