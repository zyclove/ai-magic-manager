# 幂等结果归属与清理（1.0.0）

## 范围

本阶段处理通用 `idempotency_requests` 中的个人资料响应副本。首个业务接线是 `subject.create`：创建档案后，用实际生成的档案 ID 在同一事务记录归属。沿用 Spring JDBC、事务、Flyway 和既有独立删除账本。

这仍是内部恢复处理器。公开删除提交、自动 worker、全局完成水位及真实旧备份恢复再删除尚未完成；前端继续保持 `executionAvailable=false`。

## 结果归属

| 状态 | 含义 |
| --- | --- |
| `SCOPED` | 明确归属于同一租户内 1 至 100 个不同主体 |
| `NON_SUBJECT` | 调用者显式确认结果不含主体资料 |
| `UNCLASSIFIED` | 尚未完成归属接线，不能据此宣告全部副本已清理 |
| `ERASED` | 个人响应已清理，旧请求键永久拒绝重放 |

归属集合去重、排序、不可变；租户和主体必须是规范 UUID。主体只保存带版本域分隔的 SHA-256 摘要，不通过昵称、响应正文、当前分组或事后关系猜测归属。旧调用签名显式记录 `UNCLASSIFIED`。

响应父行保留随机 UUID、租户范围、调用者摘要、操作摘要、请求键摘要和时间元数据；归属行保留独立 UUID、同一复合父键及主体摘要。两个 UUID 的唯一索引用于有界恢复扫描。原始操作可能含设备或退出操作 ID，因此也纳入清理。

## 清理与重试

清理响应时清空 `response_body`、原始调用者、原始操作及请求内容摘要，保留不透明父键和归属记录。共享结果涉及任一目标主体时，整份缓存响应清理；其他主体的业务记录保持原有内容。

`execute` 和 `findCommitted` 在比较新请求内容、检查过期时间和读取响应之前检查 `ERASED`，返回 HTTP 410 / `IDEMPOTENCY_RESPONSE_ERASED`。过期、改动请求内容和只读原结果查询均不能恢复响应或再次执行旧操作。业务权限在访问缓存前核验。

## 恢复处理器

| 阶段 | 每次处理 |
| --- | --- |
| `DATA` | 最多 25 个明确关联目标主体的响应；清理和检查点同事务提交 |
| `VERIFY` | 按父行 UUID 续扫最多 25 行，校验状态、摘要和归属 |
| `RECHECK` | 按归属 UUID 续扫最多 25 行，独立核对父行及孤立归属 |
| `DONE` | 仅表示此内部步骤完成；再次调用重新进行有界核验 |

使用原有作业锁、独立账本核验、租约和 fencing token。每页按完整复合父键排序，先锁父行，再锁归属，避免不同主体的共享缓存采用相反锁序。父行的归属集合最多读取 101 行，以拒绝超过 100 个主体的损坏集合。

归属不明的全局响应也会阻止完成，包括插入到已保存游标之前的响应。已安全清理的 DATA 批次可先提交；后续验证明确报告归属阻断。恢复过程中绕过外键形成的孤立归属不能消失在父表扫描之外。未知版本、无效阶段或游标格式、负计数、租约丢失及存储错误均拒绝继续，当前事务回滚。检查点格式校验不证明业务库管理员伪造的有效阶段和游标可信。

所有处理以业务入口已经排空、全局维护暂停持续生效为前提。中途解除暂停不在处理器承诺范围内。

并发用例覆盖同一作业的两个调用，独立代码复核检查了不同作业的共享父行锁序；本阶段尚未直接执行两个不同主体作业同时处理共享响应的并发场景。

## 后续接线

审计基线 `cc78efa0dcbc19e3f2a0beae9a8bf974a8539450` 中，20 个生产调用文件有 46 次 `execute`、6 次 `findCommitted`。本阶段接线 1 次创建档案调用；其他调用保持 `UNCLASSIFIED`，因此不能声称通用缓存已全面覆盖。

后续优先接线审批、配额与计划、观察授权、设备退出，再处理支持诊断、报表多主体快照、策略发布和成员变更。租户级或全局操作必须逐项明确归属；多主体结果使用操作发生时的不可变范围。
