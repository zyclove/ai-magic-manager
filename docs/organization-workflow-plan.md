# 机构班级、名册与教师工作流

依据 IAM-01、ORG-01 与 EXT-01。完整产品目标保持不变，继续实现班级授权、教师设备查看/有限申请，以及后续课堂、设备组、批量和集成工作。

## 实施裁定

- Ruling: 班级目录和成员范围归入现有 tenant 模块，学生档案仍由 subject 模块维护。TenantAccess 提供范围判断，其他模块不直接查询班级表。这样保持现有模块依赖方向，避免 tenant 与 subject/fleet 互相依赖。
- Ruling: 教师可以直接绑定一个旧档案，或被明确授予一至多个班级；新邀请和权限编辑使用 classIds（最多 50 项），与 subjectId 互斥。既有教师单档案数据继续有效。班级授权只在对应成员权限版本内有效，撤销/重新加入不得复活旧范围。
- Ruling: 班级名册是本机构已存在的学生档案关联，不导入家庭活动或建立跨租户共享。班级、名册、邀请和授权都带 tenant_id；教师只能看到当前获授班级内的必要学生/设备状态。
- Ruling: 班级创建、修改、归档、名册调整/转班需要当前 OWNER/ORG_ADMIN 和近期 MFA；修改使用强版本与幂等请求。转班同时检查源/目标版本，在一个事务中更新双方名册。
- Ruling: 班级变更使用现有成员控制行，先锁受影响教师成员，再锁班级/档案和下游资源。权限丢失同步撤销对应教师的待办授权；失败整体回滚。不能独占 tenants 外键父表再等待下游审计。
- Ruling: 教师可发起范围内的有限临时访问申请，不能审批自己或他人的申请、修改组织安全底线或读取其他申请人的自由文本。沿用有界审批与 CONFIGURE_ONLY 文档，不声称系统已经解锁。

## 实施顺序

1. 班级目录、版本化名册、原子转班和归档，建立真实 SQL/HTTP 负向与并发用例。
2. 邀请/成员 classIds、权限历史，后端统一教师范围判断及名册失权联动。
3. 范围内学生/设备、教师申请与结果，查询最小化和旧 JWT/缓存重试校验。
4. 管理端班级/名册页面、教师入口、成员班级选择、完整错误/恢复/窄屏与键盘交互。
5. 全量后端/Flutter、真实 MySQL、浏览器与本地运行更新；记录实际证据和未完成范围。

课堂会话、许可模板、独立设备组、批量任务、SSO/SCIM、EMM 供应商接入仍是完整目标的一部分，不以本阶段班级授权替代最终交付。

## V19 首批实现：班级与教师只读范围

- V19 新增班级、名册、成员/邀请班级范围和权限历史字段。邀请范围同时约束租户与邀请外键；成员班级授权绑定当前权限版本。
- 班级创建、改名、归档及名册写入要求当前 OWNER/ORG_ADMIN 和近期 MFA；列表、详情及名册允许范围内教师只读。单班最多 500 个档案关联，教师最多获授 50 个班级。
- 学生可同时在多个班级。移出其中一个班级后仍按其他有效班级授权；归档班级立即停止该班授权。教师不能查看已归档学生的名册详情、学生档案或设备。班级人数为包含归档档案的关联总数，以保持班级强版本含义稳定；教师名册只返回当前未归档学生。
- 转班携带源 If-Match 与目标 targetVersion，同一事务完成双方调整。重复幂等请求返回原结果；目标冲突或并发第二次操作不会丢失学生关联。
- Teacher 仅开放班级、学生和设备/能力状态查询。内部设备工作流与应用清单仍使用原成人/儿童权限门槛；策略、审批和其他学生信息没有随设备查看范围自动开放。
- 成员编辑支持班级多选、不可用班级提示、权限历史中的前后 classIds。空范围教师不会显示为“工作空间范围”。旧单档案教师继续兼容。
- 班级页面覆盖新建、改名、添加、移出、转班、归档、空/错/加载状态。未知提交冻结原内容并复用幂等键；版本冲突禁用旧版本重提，提供“关闭并刷新”。手机导航标题去除拥挤重复，保留工作空间切换。
- 归档班级后，已有待接受邀请仍保留记录，但接受时会重新验证班级并拒绝失效范围；管理员可取消并重新邀请。当前审计记录操作类型与班级标识，逐学生名册变更历史仍待补齐。

## 教师有限申请扩展

- 复用现有审批状态机。CHILD/TEACHER 可读取范围内设备的可申请规则、提交最长 3600 秒窗口、查看和取消本人待决申请；教师不能审批、修改策略、设备、档案或应用清单。
- 独立 AccessRequestDeviceScope 提供申请专用的设备观察/锁定事实；原 DeviceAccess 管理工作流门槛保持原有角色集合。范围授权在幂等缓存之前执行，真正新建时再次锁定策略、主体和设备，核对注册周期与最新基础版本。
- OrganizationScopeChanged 的同步监听复核每个受影响教师的当前学生范围。最后一条有效范围丢失时，PENDING→INVALIDATED、APPROVED_PENDING_DELIVERY→REVOKED，并记录审计；仍有其他班级或旧单档案授权时保留访问。签名撤回沿用设备下次读取机制，不声称已在系统执行。
- Ruling：儿童与教师的列表、详情、交付历史都限定精确申请人和当前主体范围，避免新增教师申请后儿童读到教师的自由文本；原先同档案不同儿童身份之间共享的申请详情不再开放。
- 创建/审批的幂等回放返回当前存储状态和强版本，防止已撤回窗口仍显示为有效批准；期限始终使用原批准绝对截止时间。
- 选项分页每次有界扫描当前策略版本，可出现空页但保留游标。只投影设备适用的应用名称/身份及可申请规则；公共规则单独返回，避免按应用重复扩大响应。
- 前端提供“我的访问申请”、设备/应用选择、规则多选、分钟和选填理由、加载更多、空态、规则刷新、未知结果原样重试及取消确认。取消确认返回后保留详情；真正成功才关闭并刷新。
- 首次实现时未新增或运行测试套件；后续验证见下节。已有机构用例中“教师审批列表一律 403”的过时预期已同步为仅本人空列表。236/38/31 等历史数字属于此前班级只读阶段，不能用作教师扩展的验证数字。
- 独立只读审阅发现 1 个 P2：范围事件按教师分组锁申请，与列表按申请编号锁存在反序。修复为对整个事件一次按申请编号排序的当前锁定查询，避免跨教师分组反序，并读取在成员锁之前已提交的新申请。后续专项覆盖两个教师账号顺序与申请编号相反、撤权与审计员列表并发，均成功完成且全部相关申请失效。

课堂、设备组、逐学生名册变更历史、批量与集成继续列入完整目标。后续 SQL、浏览器夹具证据与真实用户 OTP、设备执行证据分别记录。
