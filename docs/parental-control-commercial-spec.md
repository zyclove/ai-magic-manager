## 1. 产品线与价值主张

| 产品线 | 购买者 / 使用者 | 核心价值 | 必须披露的边界 |
|---|---|---|---|
| 家庭版 | 监护人 / 成人与孩子 | 统一规则、合理时间安排、可解释限制、临时通行 | 普通设备可能被撤权/强制停止；无法过滤全部 App 内容 |
| 教育机构版 | 学校/教育机构 / 管理员、教师、学生 | 配发设备治理、班级授权、批量规则、合规与审计 | 强能力依赖受管注册、供应商、型号与接口资格 |
| 客户私有化版 | 机构 IT/采购 / 同上 | 数据边界、企业集成、可控升级、内部运维 | 客户资源责任和外部联网依赖明确，不默认支持完全离线 EMM |
| OEM/渠道合作版 | 设备厂商/渠道 / 家庭或机构 | 经认证设备与管控体验集成 | 每个 OEM/型号单独认证，定制能力不可自动推广到所有设备 |

首发经营范围明确为**中国大陆、机构合同优先**。先完成机构采购、试点、验收、合同核验与服务交付闭环；家庭版保留基础体验和既有安全功能，但不预设家庭自助购买、应用商店内购或固定价格。机构试点以已验证的 Android 设备模式与兼容型号逐项签收；在尚无合规 EMM 合作方和 Android Management API 准入时，受管系统能力不可作为现货承诺。视觉识别和 AI 助手独立试点后决定是否上架，不能作为基础安全的必需条件。

### 1.1 业界能力参照与差异验证

- Google Family Link 的屏幕时间管理可作为时段、应用限额和家长交互的参照；本项目不因此获得 Google 的特权或等价能力。[Family Link 官方说明](https://support.google.com/families/answer/7103340)

- 官方 EMM/DPC 的注册、策略、证据和管理生命周期用于实际系统执行；家长产品 UX、审批、跨设备用量和商业权益由本产品领域实现。

以上是功能设计参照。销售比较表必须逐条标记设备条件、区域、试点证据和验证日期，不使用未核验竞品价格/效果，不把供应商 SDK 当作自己的系统特权。

## 3. COM-01：从体验到付费的家庭旅程

1. 成人查看实际设备支持说明与隐私条款，选择区域和账户；可以先使用兼容性检查。
2. 完成注册、设备授权与首条基础策略，确认规则实际生效或有限控制。
3. 管理端展示试用资格、期限、费用、续费方式和取消入口；试用开始/自动续费条件明确告知。
4. 成人在合规渠道购买；服务端验证渠道事实后发放权益，客户端支付成功动画不直接改变授权。
5. 今日页与账单页分别展示设备保护状态、订阅状态；支付故障不伪装成设备故障。
6. 到期前提醒，管理员可以续费、取消、改套餐、导出或转移；渠道政策不同采用对应适配器。

激活定义为：设备完成绑定、模式/边界已披露、至少一条基础规则有当前生效证据、恢复路径可用。BYOD 与受管模式激活指标分开报告，不能把点击“开启保护”统一算成强管控激活。

**验收 COM-01-A：** 用户购买前能看到不支持原因；支付中断不重复扣费/重复发权益；儿童不能购买或取消；恢复购买不会把别人的订阅绑定到当前家庭。

## 4. COM-02：账单、订阅与权益实现

### 4.1 领域与供应商边界

- ProductCatalog：套餐、币种、周期、税费展示、价格版本和可售区域。
- BillingAccount：付款主体，与家庭/机构 tenant 分开；一个采购主体可支付多个明确授权租户。
- Order/Subscription：商店或支付服务的订阅引用、开始/续费/终止事实与来源。
- EntitlementSnapshot：可重建的权益版本、适用租户、容量、有效期和来源；设备不获取支付密钥。
- Invoice/Adjustment：账单、税票引用、退款、贷项、争议和采购订单；法定票据由适用专业服务生成。

支付表保存供应商引用和必要金额，不保存原始银行卡资料。金额使用币种与最小货币单位整数或明确精度 Decimal，禁止 float；跨币种报价/发票的汇率日期和来源单独记录。

优先区域适用的成熟支付/商店 SDK；Stripe 仅是可评估候选，不推定其适用于所有经营主体和地区。Android/iOS 应用内数字服务购买须逐区域核验商店规则与例外，网站结算入口不能假设可任意引导。[Google Play 支付规则](https://support.google.com/googleplay/android-developer/answer/9858738)、[Apple 审核规则](https://developer.apple.com/app-store/review/guidelines/)

### 4.2 事实驱动状态

试用、计费、付款、退款、争议和权益分别建状态，不把所有财务事件压成单条状态链。cancelAtPeriodEnd 不等于立即停服务，退款也不必然代表其他有效订单的权益失效。

~~~mermaid
sequenceDiagram
  participant U as 成人管理端
  participant P as 商店/支付供应商
  participant B as Billing
  participant E as Entitlement
  U->>P: 购买或续费
  P-->>B: 签名通知/可验证购买事实
  B->>B: 验签、持久去重、核对当前事实
  B-->>P: 收件确认
  B->>E: outbox：订阅事实已更新
  E->>E: 按目录/合同生成新权益版本
  E-->>U: 当前权益及生效时间
~~~

供应商回调用官方库校验签名及原始请求体，持久化已接收事件后快速响应，再异步处理；去重键为 provider+account+eventId。回调可能重复、延迟和乱序，不能按最后收到的消息覆盖当前订阅事实；按供应商序号/版本或 API 查询对账。[Stripe webhook 说明](https://docs.stripe.com/webhooks)

订阅与 outbox 同事务提交，权益消费幂等；支付服务故障时保留最近确认权益并按已配置宽限规则处理。对账作业检查供应商、账单和权益三者差异，人工补单必须有独立财务权限及审计。

**验收 COM-02-A：** 回调伪造、重复、乱序、超时重试、退款/拒付、取消后续费成功、跨账户恢复购买、数据库切换和权益缓存陈旧均不会无依据授予或移除权益。

## 5. COM-03：退订、降级和服务终止

### 5.1 降级规则

预告权益变化 → 预览受影响设备/报告/集成 → 宽限期 → 管理员选择保留资源或迁移 → 新权益生效 → 记录未完成项并提供恢复入口。

- 基础规则、儿童解释和必要恢复不因支付事件突然解除；持久系统策略继续依平台有效性运行。
- 超出基础套餐容量时冻结新增高级资源，允许管理员查看状态并安全退出多余设备；不能承诺免费无限延续高级云服务、历史、供应商费用或 SLA。
- 权益降级不能使已有明确限制静默放宽。需替代为基础策略时先预览、确认和验证；无法联系管理员时保持现有基础配置，停止新高级变更并持续显示待处理。
- 高级历史到期按事先披露的保留规则处理，提供导出窗口；安全审计不按营销权益随意删除。
- AI/视觉撤回立即停止可选处理；退订不代替撤回隐私授权，也不能因购买重新开启采集。
- 长期账户关闭/合同终止需完整退出、数据导出、凭证撤销和删除作业。离线设备无法确认清理时如实记录残留风险。

宽限期、通知频次、导出期限、保留和最低服务能力都须配置并写入合同/告知，产品目录变更留版本。平台彻底停止服务时提供提前通知、导出和正规解除路径；不承诺云端停止后永久继续提供远程保护。

**验收 COM-03-A：** 取消订阅、付款逾期、数量降低、家庭拆分和平台终止各有状态与提示；无断网自动无限续期，无因欠费立即开放全部 App。

## 6. COM-04：机构采购与客户交付

| 阶段 | 客户操作 / 内部工作 | 出口产物 |
|---|---|---|
| 需求核验 | 设备所有权、OS/OEM、GMS、区域、人数与场景 | 范围、限制、兼容型号、数据责任 |
| 技术评估 | EMM 准入、SSO/名册、网络、恢复与擦除后果 | 可行性记录与不支持项 |
| 试点 | 使用代表性设备/教师/学生，约定支持范围 | 功能、体验、故障和隐私反馈 |
| 报价/合同 | 容量、服务期、驻留、支持、实施、供应商费用 | 合同、数据处理约定、采购订单 |
| 租户开通 | 绑定合同、区域、管理员、IdP、权益 | 可审计开通记录 |
| 实施 | 导入校验、分批注册、模板配置、恢复演练 | 逐设备/功能验收证据 |
| 培训 | 管理员、教师、客服的范围与故障流程 | 培训资料、责任人及支持入口 |
| 上线 | 小范围到全量，审核告警和执行率 | 客户签收、已知限制、回滚计划 |
| 续约/退出 | 容量调整、兼容升级、导出与移交 | 续约记录或退出/删除清单 |

定义计费设备为合同中占用受管容量的设备；是否在线和实际使用时长不决定账单，避免为了扣费收集更多儿童行为。若采用学生席位计费，绑定规则、多个设备和退学调整在合同中明确，不能叠加同一资源的两种主计费方式。

设备转让/转校先核验资产与管理责任，按照 END-01 退出旧管理域并新注册；不直接变更 tenantId 将历史活动一起转交新机构。机构采购授权不能替代适用的学生/监护人告知与地区要求。

**验收 COM-04-A：** 超容量、批量重注册、转校、采购到期、合同扩容、首位管理员离职与 EMM 费用变化有可复核流程，不因销售手工改数据库绕过审批。

### 6.1 中国大陆机构合同首发工作流

| 步骤 | 负责人 | 必须记录的事实 | 未满足时的结果 |
|---|---|---|---|
| 线索与技术发现 | 销售、解决方案人员 | 采购主体、使用地区、设备所有权、型号、系统版本、是否已有受管提供方 | 仅出兼容性意见，不给出强管控承诺 |
| 试点方案 | 产品、交付、安全 | 设备模式、可验证功能、盲区、恢复路径、目标规模与验收方法 | 不进入正式报价 |
| 内部报价草稿 | 平台运营 | `CN/CNY/CONTRACT/ORGANIZATION` 报价项、期限、设备名额、功能与税费口径 | 草稿不可购买、不可生成权益 |
| 独立审核 | 财务/法务审批人 | 报价版本、依据、审批主体及近期认证；与草稿作者分离 | 仅形成已审核草稿，不自动发布 |
| 合同签署与核验 | 有权限的合同运营、财务 | 已签合同引用、采购主体、服务期、容量、交付条件、双方批准及证据摘要 | 不开通付费权益 |
| 租户映射与开通 | 客户成功、租户所有者 | 合同与目标租户的双方确认、来源版本、开通范围及审计 | 不允许销售人员直接改库授权 |
| 交付与签收 | 交付、客户管理员 | 逐型号/模式能力报告、设备注册结果、规则回执、应急恢复演练 | 不能把采购权益表述为系统限制已生效 |
| 续约或退出 | 财务、客户成功、客户管理员 | 新合同版本、到期、扩缩容影响、数据导出与退出清单 | 不静默延长合同或清除设备数据 |

合同核验采用可替换的服务端连接器；当前无已接入的合同验签方、电子签平台或财务系统。连接器须查询可信合同事实并保留不可变版本、双人审批和审计，账本只接收核验后的标准化来源事实。上传截图、客户端回调、口头承诺和已审核报价均不能单独开通权益。原始合同与儿童活动分库存放并限权；业务库只保存必要引用和证据摘要。首发前需按经营主体完成合同、税票、隐私告知、数据驻留和售后责任的逐项审核，此处不预判法定合规结论。

## 7. COM-05：私有化与渠道交付

### 7.1 标准交付包

OCI 镜像/签名、Helm Chart、配置 schema、版本锁定/BOM、数据库迁移、依赖/许可证清单、环境诊断、备份恢复 runbook、升级与回滚兼容矩阵、支持工具和管理员培训。

| 责任 | 平台方 | 客户方 |
|---|---|---|
| 应用、业务配置 | 版本、缺陷修复、升级包、配置规范 | 配置审批、管理员操作 |
| 基础设施 | 经验证容量/部署建议 | Kubernetes/网络/数据库/存储资源与值班 |
| 数据保护 | 数据最小化、授权、删除能力 | 区域、备份、访问、保留配置与执行责任 |
| 外部供应商 | adapter、依赖说明、可观测性 | 合同/账号/配额按约定提供 |
| 故障恢复 | 软件恢复流程与诊断支持 | 实际基础设施切换与恢复执行 |

客户是否由平台代运维另行约定，不能让合同责任和实际部署权限冲突。

MySQL 是默认 OLTP profile，OceanBase 需单独兼容、性能、升级与恢复证据；Keycloak 的数据库单独遵循官方支持矩阵。离线环境无法使用公网商店/EMM/推送/分类时，逐项提供受支持替代方案或标记缺失，不宣传全功能相同。

离线许可优先成熟许可服务/库或标准签名许可证，限定客户/实例/容量/期限并提供可恢复宽限流程，不自研密码算法。许可验证失效停止新增高级管理能力，不触发擦除、秘密开放或破坏必要恢复。离线硬件绑定、时钟可信度和克隆风险列入验收。

### 7.2 OEM 和渠道约束

伙伴只访问授权客户/设备，销售权限不等于查看儿童数据；渠道租户、客户租户和支持授权分开。预装、系统签名或 OEM 特权必须有合法合作与具体接口证据，不能把一台定制电视的能力推广到普通 Android。

定制项通过 connector/主题/配置扩展，共享主干代码与升级链；客户专属功能注明支持版本和退出成本。渠道结算按合同和订单事实进行，不使用儿童活动作为佣金依据。

**验收 COM-05-A：** 新环境可安装/升级/恢复，离线包依赖明确；许可过期、硬件替换、数据库差异、外部 EMM 中断及渠道越权有安全处理。

## 8. COM-06：运营管理台与支持

| 控制台区域 | 关键功能 | 权限边界 |
|---|---|---|
| 产品目录 | 套餐/区域/权益、版本、上架/下架 | 双人审核影响有效合同的变更 |
| 商业账户 | 订单、合同、发票引用、退款、对账 | 财务与客服分权，不含儿童活动 |
| 客户成功 | 注册进度、支持联系人、培训、续约 | 只看必要租户级健康统计 |
| 平台运维 | 服务、队列、配额、版本、故障 | 不默认浏览儿童明细 |
| 支持授权 | 客户发放 support grant、期限与范围 | 有客户授权才读取诊断；全量审计 |
| 兼容目录 | 型号/OS/模式/供应商/证据与退役 | 能力证据不足不能发布“强控制”标记 |
| 数据请求 | 导出、删除、地区处理队列 | 专门权限、时限、完成证明 |

客服流程：识别账户但不索取密码 → 查状态页和脱敏诊断 → 获取必要范围授权 → 定位 correlationId → 处理/升级 → 通知状态 → 关闭与复盘。客服不能口头保证远程策略已生效，必须查设备/供应商证据。

SLA 分开定义 API 可用性、连接服务、策略接受延迟、受支持在线设备生效延迟、支持首次响应与恢复目标。端到端时延必须说明起止时间和管理模式，外部供应商或离线设备影响如实归因；排除条款不能掩盖平台自身责任。24×7/15 分钟响应只在值班预算、人员和演练通过后签约。

**验收 COM-06-A：** 客服无法跨客户查询儿童记录，support grant 自动到期；退款人员无设备擦除权限；事故有统一时间线、影响范围和客户通知。

## 9. 数据、成本、定价与试点

### 9.1 指标口径

| 指标 | 定义与用途 |
|---|---|
| 有效激活率 | 已验证基础旅程完成 / 合格注册，按设备模式分组 |
| 规则执行覆盖 | 当前有证据生效的目标规则 / 本次目标规则，未知单列 |
| 审批完成率/时延 | 有效请求的决定与设备生效分别统计 |
| 授权退化率 | 观察到授权/能力退化的设备 / 可观测设备；离线单列 |
| 恢复成功率 | 经授权恢复并有结果证据 / 恢复请求，离线待确认单列 |
| 家庭留存/续费 | 以成人账户/订阅事实统计，不采集跨 App 广告标识 |
| 机构扩容/续约 | 合同周期、有效容量与客户验收事实 |
| 单位服务成本 | 每家庭/合同设备的云、供应商、支持与交付成本 |

不以阻止次数、申请拒绝率或孩子使用越少作为唯一成功指标；需要结合必要学习/联系未受误封、可解释度、恢复成功与用户反馈。指标埋点只记录必要事件，不留原始视频、聊天或完整网址。

### 9.2 成本公式

`月服务成本 = 区域固定基础成本 + 在线连接成本 + 策略/事件处理 + 数据保留 + EMM/分类/推送/模型费用 + 支持工时 + 交付摊销`。

`渠道后净收入 = 已确认收入 - 税费影响 - 支付/商店费用 - 退款/贷项`；毛利按统一财务口径计算，未确认收入与获客费用单列，不能混淆服务毛利、贡献利润与现金流。

`在线连接 = 注册设备 × 峰值在线比例`，`心跳速率 ≈ 在线连接 / 心跳间隔秒数`。百万注册设备只是容量情景，需进一步确定事件频率、遥测聚合、下发规模和数据期限。成本模型使用实际供应商报价与压测，不用注册数量直接推定数据库 QPS 或售价。

先评估家庭/学校价格敏感度、兼容设备占比、支持成本和退订原因，再确定套餐参数。促销试验只面向成人，在不降低隐私/紧急保护的前提下比较转化；不因儿童风险告警触发恐吓销售。

### 9.3 试点到 GA 的决策

试点前：型号/区域/模式明确、代表性工作负载明确、验收项与目标阈值经产品/技术/安全/商务批准。试点中：按功能编号采集脱敏证据与反馈。试点后：分别报告成功、部分、失败、未知、误封、恢复、资源成本与支持工时。

以下任一未解决不进入对应能力 GA：不可控擦除风险、跨租户/儿童越权、紧急恢复缺失、设备模式夸大、支付事实不能对账、数据驻留/授权依据未明确、外部 API 无合法准入、备份恢复未演练、核心功能只有 UI 而无执行证据。

市场开通以区域清单管理：支付/商店、身份与监护告知、数据驻留、内容分类、通知、本地语言/时区、客服支持、供应商资格逐项签收。不得笼统宣传已满足全球所有法规。

## 10. 商业接口与验收交付

| 接口资源 | 用途 | 必需控制 |
|---|---|---|
| GET /api/v1/product-catalog | 区域适用产品与价格版本 | 成人端，不能泄露客户专属合同 |
| GET /api/v1/tenants/{id}/entitlements | 当前权益与期限 | 租户范围、版本与来源 |
| POST /api/v1/billing/checkout-sessions | 成熟供应商结算会话 | 付款主体授权、幂等、渠道规则 |
| POST /api/v1/billing/subscriptions/{id}/cancel | 当期结束或约定即时取消 | 明确后果、近期认证、审计 |
| POST /api/v1/billing/downgrade-previews | 预览资源与历史影响 | 不直接解除策略 |
| POST /api/v1/provider-webhooks/{provider} | 供应商通知 | 验签、持久去重、快速响应、异步对账 |
| POST /api/v1/support-grants | 客户授权诊断 | 范围、期限、撤销和访问审计 |
| GET /api/v1/compatibility-catalog | 可售设备能力与证据日期 | 按型号/OS/模式/区域，声明限制 |

后台产品目录、合同、退款、渠道授权和客服提升权限都需要独立管理范围；设备凭证不能访问账单 API。

商业交付按 COM-01～06 与功能编号联合验收：付款正常但设备不支持时，结果不能标成“管控成功”；设备仍有基础规则但订阅到期时，结果不能标成“订阅有效”。每个产品包交付功能清单、兼容清单、价格与权益版本、责任合同、隐私说明、用户指引、运营/支持 runbook、退出方案与证据包。

## 12. 产品目录、合同与容量的生命周期

ProductCatalog 采用不可变发布版本；目录草稿与有效销售版本分开。SKU 至少包含区域、币种、周期、渠道、权益键、容量单位、历史期限、支持级别、供应商前置条件、兼容目录版本和停售处理方式。

ContractSnapshot 保存批准时的价格/权益/期限/责任范围；续费按明确的新版本确认，不通过修改目录静默影响在期合同。特殊折扣、试点期限、扩容及赠送权益由授权操作产生独立来源，不用散落的数据库手工字段。

容量分四种数值：合同容量、已占用容量、待预留容量、可新增容量。注册请求事务内预留，取消/过期安全释放；设备离线不自动释放计费席位，重复注册不重复占位，换机必须关联明确移交。容量不足冻结新增动作，不破坏既有基础策略和必要恢复。

产品目录发布需要技术确认可执行范围、产品确认体验与限制、财务确认计量/价格口径、区域发布责任人确认适用条件；各角色审核的事实与版本可追踪。兼容能力退役时同步售前页、设备提示、存量合同处理和退出指引。

## 13. 账单异常、对账与补偿清单

| 场景 | 服务端事实与处理 | 成人端显示 | 审核证据 |
|---|---|---|---|
| 客户端成功、回调未到 | 查询渠道购买事实，保持待验证 | 等待验证、恢复购买/查询 | 订单引用、渠道状态、查询时间 |
| 回调重复/乱序 | 持久去重，核对当前事实及来源版本 | 当前订阅状态，不重复赠送 | eventId、验证结果、权益版本 |
| 付款后数据库提交未知 | 通过幂等订单及渠道查询收敛 | 查询原订单，避免再次购买 | 原订单、供应商幂等键、对账结果 |
| 退款/争议 | 按有效购买来源重建权益 | 退款/争议与服务影响分别说明 | 金额币种、处理权限、供应商事实 |
| 财务手工调整 | 独立权限、原因、审批与期限 | 来源明确的调整记录 | 操作/批准者、变更前后、审计 |
| 商店与直接合同并存 | 分别验证购买主体和适用租户，不重复叠加同权益 | 有效来源、取消入口 | 来源优先规则、容量合并策略 |
| 逾期或降级 | 预告、宽限、资源选择和基础规则收敛 | 影响预览、待处理设备 | 生效日期、通知、管理员选择 |
| 供应商停服 | 暂停新销售/高级变更，准备替代和退出 | 真实影响、可用基础能力 | 供应商通告、替代认证、合同处理 |

账单事实、权益投影、缓存、设备配置分别有版本与对账任务；投影可从验证事实重建。设备不接收银行卡资料、商店签名秘密或支付回调。数据保留与安全审计不能被套餐目录任意删改。

## 14. 商业运营落地与产品完整性

统一建立功能编号 → 技术证据 → 兼容目录 → SKU → 合同 → 客户验收映射；只有通过对应设备/区域验证的能力才进入可售目录。营销页面不能用“全面防强制退出”“识别所有不良内容”等超出实际平台支持的表述。

客户成功按基础激活、规则生效覆盖、必要恢复、支持问题、合同状态跟进。采购付款人、技术管理员和数据责任人分别登记；账号交接不自动转移账单责任。渠道只能获得合同范围内的订单/客户信息，不能读取儿童活动或绕过客户诊断授权。

更完整的售前到回款、渠道/财务/支持分权、单位经济、故障与退役流程见[产品实施与功能闭环](parental-control-product-delivery-spec.md)。售价、商业收益和 SLA 目标在试点数据和正式审批前均保持待确认，不填虚构数值。
