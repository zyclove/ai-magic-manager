## 1. 用户能理解的状态

| 状态 | 界面文字 | 含义 | 主要操作 |
| --- | --- | --- | --- |
| PENDING | 等待准备 | 请求已保存，可能在排队、读取或等待重试 | 查看详情；有权限时取消 |
| ADMITTED | 已进入执行 | 已建立执行记录 | 查看执行进度 |
| REJECTED | 无法继续准备 | 资格变化、到期或重试结束等原因已终结请求 | 查看原因；回到规则预览 |
| CANCELLED | 已取消准备 | 后续读取结果不能再进入执行 | 查看记录 |

“已进入执行”不得显示为“已生效”。设备是否应用策略，由执行记录及独立设备反馈判断。客户端禁止根据准备状态自行创建第二次发布、延长授权或生成替代执行记录。

## 2. 公共约束

- 根路径：`/api/v1/tenants/{tenant}/managed-android/preparation-requests`。
- 使用管理员 OIDC 身份；每次请求重新查询当前数据库成员关系。OWNER、ORG_ADMIN、AUDITOR 可读，只有 OWNER、ORG_ADMIN 可取消。
- 成功响应：`Cache-Control: no-store`、`Vary: Authorization`。详情与取消附强 ETag；列表和汇总没有 ETag。
- ID 必须为规范 UUID。无机构权限返回 403；已有机构权限下，请求不存在或不属于该机构时，详情与取消统一返回 404 / PREPARATION_REQUEST_NOT_FOUND。列表和汇总对未知发布返回 403，不能用空列表伪装成功。
- 准备详情只包含十二个公开字段，不返回租约令牌、原管理员身份、上下文摘要、提供方资源、凭证或完整策略文档。

## 3. 四个操作

### 3.1 查看一个发布的准备请求

`GET {root}?publicationId={id}&limit=50&cursor={id}`

publicationId 必填；limit 为 1–50，默认 50。按请求 id 升序排列，游标必须是同一租户、同一发布中仍存在的请求 id。状态变化不改变排列次序。

```json
{
  "items": [],
  "nextCursor": null
}
```

items 使用下述详情模型。已有发布可以合法返回空数组；不存在的发布返回错误。分页失效时清除游标重新读取第一屏，并提示用户列表已更新。禁止无界自动翻页、累计分页结果推断全部完成。

### 3.2 查看状态总数

`GET {root}/summary?publicationId={id}`

```json
{
  "total": 4,
  "pending": 1,
  "admitted": 1,
  "rejected": 1,
  "cancelled": 1
}
```

计数在单条聚合 SQL 中读取，四种状态之和等于 total。没有设备生效计数，也没有“全部成功”布尔值。与另一时刻请求的详情可能短暂不同；界面显示“最近更新”时间，不将分次读取的结果强行合并成一个一致快照。total 为 0 显示“暂无准备请求”。

### 3.3 查看详情

`GET {root}/{id}`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id / publicationId / versionId | string | 准备请求、发布和不可变策略版本 |
| deviceId / registrationId | string | 设备及本次注册身份 |
| state | enum | PENDING、ADMITTED、REJECTED、CANCELLED |
| reasonCode | string | 稳定原因码；未知码显示通用提示，不能展示服务端内部异常 |
| revision | integer | 当前版本，与强 ETag 对应 |
| executionTaskId | string 或 null | 进入执行后的记录引用 |
| expiresAt / createdAt / updatedAt | integer | Unix 毫秒；客户端格式化为当地时间，不据客户端时钟修改状态 |

准备行的期限到达也不意味着客户端能自行写成 REJECTED；客户端继续查询服务端权威结果，必要时显示“等待更新”。

### 3.4 取消准备

`POST {root}/{id}/cancel`，无请求体，携带最近一次详情返回的 `If-Match: "revision"`。

服务端要求近期多因素认证，随后在同一事务内校验当前角色、版本、状态并记录审计。取消使旧读取租约失效。响应采用同一详情模型和新的 ETag；使用已经取消后的当前 ETag 重复操作，不重复增加版本或审计。

| HTTP / 错误 | 客户端处理 |
| --- | --- |
| 401 / REAUTH_REQUIRED | 重新认证后先刷新详情，再由用户确认操作 |
| 403 | 刷新权限状态；禁止自动重试写入 |
| 404 / PREPARATION_REQUEST_NOT_FOUND | 请求在当前机构不可用，停止操作并返回发布详情；不泄露其他机构是否存在同一 ID |
| 428 / VERSION_REQUIRED | 先读取详情取得 ETag |
| 400 / INVALID_VERSION | 修正版本格式；不能改成通配符绕过 |
| 412 / RESOURCE_VERSION_CONFLICT | 刷新详情，说明进度已更新；由用户重新选择 |
| 409 / PREPARATION_ALREADY_ADMITTED | 显示“已进入执行”，提供“查看执行进度”；不自动取消执行 |
| 409 / PREPARATION_ALREADY_TERMINAL | 刷新并展示最终状态 |
| 网络错误或超时 | 保留当前页面，查询同一请求确认结果；不假定取消失败或成功 |

## 4. 简化操作路径

发布结果窗口直接显示准备总数和设备列表，单条点击展开详情，不跳转到新建规则流程。每条记录只突出一个主要操作：等待时“查看进度”，进入执行后“查看执行进度”，终止后“查看原因”。取消作为明确的次要操作，执行中禁止重复点击。

初次加载、空记录、读取失败、访问被撤销和状态变化必须分别展示。读取失败保留上一份已知信息并标记“暂未更新”，不得清成零条或绿色完成。页面隐藏时停止轮询，重新显示时刷新；写操作无自动重试。具体轮询周期由客户端既有请求预算统一配置。

## 5. 验证与交付边界

### 进入执行后的连续交互

发布、准备、执行三个记录在同一个设备进度面板中连贯呈现，不要求管理员重新选择设备或新建发布。准备为 ADMITTED 时用服务端返回的 executionTaskId 读取对应执行详情，不自行推算任务 ID。

| 执行状态 | 用户文字 | 交互约束 |
| --- | --- | --- |
| READY_TO_WRITE / READY_TO_ASSIGN | 等待下发 | 显示最后更新时间；是否可取消以当前执行接口返回的状态和权限为准 |
| POLICY_WRITE_UNKNOWN / ASSIGNMENT_UNKNOWN | 正在确认下发结果 | 不显示“失败，请重试”；禁止一键重发，保留已知进度 |
| WAITING_DEVICE | 等待设备确认 | 已接受分配不代表已生效；离线显示连接状态，不虚构预计完成时间 |
| APPLIED | 设备已确认 | 必须来自独立设备证据支持的服务端状态 |
| NEEDS_REVIEW | 需要管理员核对 | 显示原因、发生时间和记录；当前正式处置流程未完成，不提供伪成功的“清除异常”按钮 |
| CANCELLED | 执行已停止 | 不宣称已撤回先前生效的规则；恢复或重新发布需要新的明确操作 |

列表以文字、图标和颜色共同提示，颜色不是唯一信号。详情优先展示“当前状态—原因—下一步”，技术日志与标识置于可展开诊断区。页面刷新、网络恢复与通知关闭只重新读取当前事实，不产生写操作。切换机构、失去权限或退出登录立即停止读取并清除该范围的详情。
