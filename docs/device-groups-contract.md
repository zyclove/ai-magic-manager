# 机构设备组：成员范围与管理交互

## 已实现范围

机构所有者和机构管理员可在“机构设备组”创建、重命名、查看、关联设备、移出设备和归档。教师、儿童、家庭成员及审计员不能访问设备组接口；服务端每次读取当前租户成员关系，写入在同一事务中锁定当前权限并要求近期多因素认证。列表按设备组 ID 分页；成员按设备 ID 分页，每组最多 5000 台。单个设备可属于多个组。

成员引用租户、设备 ID **和注册周期 ID**。加入时须为同机构的已激活设备、当前注册周期和未归档儿童档案；跨租户、旧注册周期或已撤销设备均拒绝。移出时必须携带当时的注册周期，防止旧界面误移除新成员。归档后历史成员仍可读，不能再修改；后续任何批量执行器必须显式过滤归档组、失效注册周期、已撤销设备和已归档档案。

本阶段只形成机构设备目录和可复核的目标范围。**设备组不自动下发规则、不启用 Android 系统管控、不等于策略执行回执。** 动态组条件、设备组策略继承、冲突预览、批量任务及逐设备执行对账仍在完整产品范围内。

## API 契约

路径前缀为 `/api/v1/tenants/{tenantId}/device-groups`，要求用户 OIDC Bearer JWT。写请求支持 `Idempotency-Key`，记录业务结果与审计于同一事务；变更现有组要求强 `If-Match`，冲突返回 `412`。单次未知结果应使用原请求、原键和原版本重试，不能生成新的请求冒充失败。

| 方法 | 路径 | 输入与结果 |
|---|---|---|
| GET | `/` | `limit`/`cursor`/`includeArchived`，返回 `{items,nextCursor}` |
| POST | `/` | `{name}`，新建组，返回组和 `ETag` |
| GET | `/{groupId}` | 组详情、版本、成员总数 |
| PATCH | `/{groupId}` | `{name}`，重命名，返回新版本 |
| POST | `/{groupId}/archive` | 归档，不删除成员历史 |
| GET | `/{groupId}/devices` | `limit`/`cursor`，返回成员及当前设备状态 |
| GET | `/{groupId}/summary` | 原组版本及全组成员关联状态计数 |
| POST | `/{groupId}/devices` | `{deviceId,registrationId}`，加入当前有效设备 |
| DELETE | `/{groupId}/devices/{deviceId}` | `registrationId` 查询参数，移出精确成员 |
| POST | `/{groupId}/devices/batches` | `{devices:[{deviceId,registrationId}]}`，1～50台完整核对后原子加入 |
| POST | `/{groupId}/devices/removals` | 同上，1～50条精确注册关联原子移出 |

组响应包括 `id,name,state,version,deviceCount,createdAt,updatedAt`；成员响应包括 `deviceId,registrationId,displayName,platform,state,addedAt`，不含儿童活动或系统密钥。名称经去首尾空格、长度与控制字符检查，同机构名称按大小写折叠去重。两张设备组表及复合外键直接纳入 1.0.0 的 V1 初始化基线，不提供旧开发库升级脚本；成员与设备注册周期绑定，读接口与写接口都限制机构范围。


## 界面与恢复

2026-10-13 补充：手机端现已支持创建、重命名、归档、批量加入/移出及成员状态筛选；新增只读 `/operation-results/{requestId}/query` 原结果恢复接口，区分历史提交与当前组状态。手机端持久化原请求、未知结果不自动重发；Web 原有重试行为不变。完整契约与验收范围见[手机设备组维护](parent-device-group-management.md)。

管理端导航只向机构 OWNER/ORG_ADMIN 展示。列表有空态、分页、已归档筛选及“关联不等于执行”的常驻提示。详情展示组版本、当前设备状态和完整注册周期；设备选择复用分页设备清单，已撤销设备不能选择。创建、重命名和成员操作使用固定幂等键；网络结果不明时原样重试，版本冲突关闭并刷新，多因素认证通过统一身份服务完成。

Web 的“加入设备”统一选择1～50台，单台也复用已有批量加入端点，不再要求先区分单台／批量流程。取消选择不写入，不重读原详情；确认逐项列出完整设备和注册周期编号。详情操作从打开子窗口至路由结束共用一个操作锁；返回、状态切换、其他操作及旧视图回调不能并开新流程。逐台移出与批量移出仍可使用，不改变整批原子性或服务端容量／MFA／版本校验。

多选器保留跨页选择和本地搜索；达到50台时说明先取消其他设备才能继续选择。分页明确返回403、工作空间失效或非近期认证的401后，清空原设备、选择及搜索并锁存失权，旧确认回调不能返回原选择。普通网络失败与近期认证要求保留已加载内容及选择；无效游标重载仍需显式清空重新选择。本阶段仅静态实现，组件、页面、窄屏和真实接口运行验证待资源与串行窗口恢复。
