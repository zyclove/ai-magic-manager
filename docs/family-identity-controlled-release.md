# 短信与微信配置的受控发布

本流程将已保存配置加载到指定身份实例，并核对实例实际使用的版本。当前阶段始终关闭消费者登录、账号安全和销售开关；“配置已加载”不代表短信送达、微信真机授权或收费条件通过。

## 平台管理员

在「平台管理 → 短信与微信」完成配置、格式检查及加密发布准备。发布卡集中显示当前配置、实际确认的运行版本和下一步；原始摘要、实例状态与历史操作放在展开区。

1. 核对目标配置、正式身份扩展 JAR 与家长 APK 的摘要，点击提交发布。服务端冻结目标、准备记录和运行版本，不允许另一位管理员同时覆盖。
2. 部署执行器领取此操作，在已绑定的部署主机重建指定身份服务。后端没有 Docker socket；浏览器不能提交主机地址、文件路径或命令。
3. 点击核对部署结果。后端向私有清单中的每个身份实例发送新鲜随机挑战，独立核对实际进程配置、身份扩展 JAR、实例、操作及启动时间。全部一致才显示「配置已加载，登录入口待验收」。
4. 需要回退时，从服务器提供的已确认历史版本中选择目标，先查看影响再确认。回退创建新操作，重新执行部署并重新确认，不恢复旧账号数据库或已撤销会话。

发布、回退分别要求 `identity-config:publish`、`identity-config:rollback` 及近期平台 MFA。配置编辑、格式检查权限不能代替它们。平台发布角色还获得读取和核对权限，但不会自动分配给现有管理员、家庭成员或儿童。

## 部署管理员首次准备

保留已有供应商加密密钥环。另运行 [`initialize_identity_provider_runtime.ps1`](../scripts/initialize_identity_provider_runtime.ps1)，在全新受限目录创建独立执行器密钥、实例观察密钥和固定清单：

```powershell
./scripts/initialize_identity_provider_runtime.ps1 `
  -Directory .local/family-identity-runtime `
  -EnvironmentId family-cn-pilot `
  -InstanceId identity-1
```

该工具不修改旧配置、不启动服务、不访问实例。新目录的 `identity-runtime.env` 与 [`compose.identity-runtime-control.yaml`](../deploy/compose/compose.identity-runtime-control.yaml) 只给后端三份只读文件；与现有 `identity-admin.env`、[`compose.identity-admin.yaml`](../deploy/compose/compose.identity-admin.yaml) 一起审查。环境别名必须一致；现有加密版本依赖旧密钥环，不能通过新建空环替换它。

使用 [`initialize_identity_provider_target.ps1`](../scripts/initialize_identity_provider_target.ps1) 将执行目标绑定到已经验证的消费者部署、固定项目、完整配置准备区、独立密钥、实际身份镜像与 JAR 摘要。工具核对现有项目归属，并检查固定镜像中的真实 JAR；它不会启动镜像。先核对目标文件的受限权限、路径祖先及各项引用；不得指向其他运行项目。当前主机执行器只支持一个身份实例，多实例清单会在执行前被拒绝，不能先更新其中一台就宣称完成。

执行 [`run_family_identity_release.ps1`](../scripts/run_family_identity_release.ps1) 时只传受限目标文件和管理端生成的原操作编号。密钥、供应商凭据、手机号、验证码、微信 code 和 token 不通过参数、聊天或日志传递。目标实际配置和实例确认须在隔离环境验收后，再用于正式部署。

## 生效确认与恢复

身份扩展使用进程内不可变配置快照。实际加载设置与五项秘密只在内存中参与随机证明，响应不包含原文、掩码或稳定秘密摘要。实例观察密钥和执行器密钥各自独立，也不复用验证码 HMAC、供应商密钥或加密主密钥。

服务端确认不会相信部署脚本返回的“成功”布尔值。脚本完成重建只表示已尝试执行；版本、凭据、JAR、环境、实例、开关、随机数或时间有一项不匹配，仍保持需处理。三项消费者开关必须全部关闭。所有确认只针对该次操作，旧探测不能覆盖新操作。

未知结果按原编号查询，不自动重发发布或重启。尚未被领取的操作可取消；已经开始执行或结果不明时保留活动保护，先核对原执行记录及实际实例。首次执行许可的响应丢失也不能再领一次许可执行，以免重复重启。

实例核对若因后端重启而中断，原检查超过两分钟后查询原记录即可结束等待，恢复「核对生效状态」操作。服务端只结束旧检查，不重启身份服务、不清除发布保护；管理员随后显式发起新检查。旧检查迟到的结果不能恢复为成功。

执行器领取后的准备检查失败，只有服务端确认原领取从未开始重建，才可安全放弃；取消回执丢失时先查询原领取，明确仍未开始后可重发同一安全放弃。恢复历史已确认操作仅用于查询，只有服务端证明它仍是当前确认且没有其他活动任务，才可写运行指针。普通启动和受控执行共用部署主机锁，避免一边读取旧启动参数、一边发布新配置。

完整版本目录整体只读挂载，原 `.env`、秘密和数据库不被覆盖。正常启动也须遵守已认证的活动版本指针；执行未确认时阻止普通启动悄悄恢复旧配置。只有后端确认后才将指针标为已确认。受限目标、指针、配置目录或镜像发生不一致时停止，不以放宽权限或重新导入身份域解决。

本轮可回退范围限于已确认历史版本，且验证码 HMAC、微信 AppID 与当前版本相同。跨 HMAC 或 AppID 的迁移需要另行协调未完成验证码和身份绑定范围；供应商已吊销、STS 过期或凭据失效也不能靠回退保证恢复。真实供应商验收继续依照 [十二项验收要求](family-identity-provider-acceptance.md)，本流程不能解除收费门禁。
