# 设备组成员与注册周期

设备组成员绑定 `deviceId` 和加入当时的 `registrationId`。同一设备重新注册后，旧成员关系保留作审计和人工清理，但不能被当成当前可用目标。设备组成员列表新增 `membershipStatus`：

| 值 | 含义 | 策略目标选择 |
|---|---|---|
| `CURRENT` | 注册周期一致、设备已激活、儿童档案有效 | 可以选择 |
| `STALE_REGISTRATION` | 设备已进入新的注册周期 | 排除 |
| `DEVICE_INACTIVE` | 当前设备未激活 | 排除 |
| `PROFILE_ARCHIVED` | 设备关联的儿童档案已归档 | 排除 |

机构管理员在设备组详情看到上述状态及失效提示，可移出旧成员，再按新注册周期重新加入。策略目标选择器只使用 `CURRENT` 成员，并记录每台设备在选择时的注册周期。预览请求携带设备 ID、组 ID 和组版本；服务端核对当前有效组成员集合、设备快照注册周期，并把组来源纳入预览指纹。预览响应必须含相同设备 ID、注册周期和组来源，否则客户端停止发布。发布服务再次核对组版本、成员集合和设备快照，避免预览后变更仍被确认。

当前分组选择仍是一次性明确设备快照，服务端预览接口接收显式设备 ID 并核对组来源，不提供动态组策略语义，也不承诺系统策略已执行。发布前需在真实设备重注册和并发设备组变更场景检查 UI 与 API 行为。
