# 应用身份生效时间与证据读取

## 目标与边界

应用目录声明“允许信任哪个应用”，逐设备报告说明“这个设备观察到了哪个应用”。目录本身不证明安装、用户空间、运行权限或系统策略已经应用。

本阶段补齐目录身份的服务端生效时间和可校验摘要，供受管应用证据流程组合当前绑定使用。提供方读取、证据持久化、策略执行以及界面接入仍在后续阶段；这里没有新增公共接口或开启系统控制。

## 数据与读取契约

- `application_definitions.created_at`：创建声明时由服务端 `Clock` 写入的毫秒时间。客户端不能提交；重复请求和历史结果查询不会刷新它。
- `identity_hash`：沿用现有规范，计算 `[platform, packageName, profile, 排序后的 signingDigests]` 的 JSON SHA-256。显示名称与目录的安装声明不参与身份摘要。
- `ApplicationIdentity`：不可变的内部身份视图，仅包含目录 ID、平台、包名、目标 profile、签名集合、摘要与生效时间；签名集合防御复制，日志表示脱敏。
- `ApplicationCatalog.requireEvidenceIdentity`：调用方必须已有短事务。方法锁定并重新检查当前成员管理权限，按租户读取目录，核对主键、身份摘要、签名与时间，供同一事务继续接受证据。设备权限、绑定、合同及注册由受管设备领域额外检查。

此读取允许目录管理角色 OWNER、GUARDIAN、ORG_ADMIN；它不授予受管机构能力。受管绑定的 OWNER/ORG_ADMIN 限制仍独立执行。儿童、教师、审计员、已撤销成员不能通过此接口提供可接受证据的身份上下文。

## 缺失和异常数据

`created_at` 为可空字段，既有初始化夹具及历史记录不能被静默赋予一个虚构的声明时间。缺失、负值或未来时间，以及记录主键/摘要/结构不一致，返回 `APPLICATION_IDENTITY_METADATA_UNAVAILABLE`；读取不修复数据库，不记录原始 JSON 或签名数据。

目录允许先声明未填写签名的应用，管理者仍可查看该声明。证据读取对空签名集合返回 `APPLICATION_SIGNING_IDENTITY_REQUIRED`。管理员配置签名是信任来源；目录的 `INSTALLED_VERIFIED` 等状态不进入此身份视图。

历史身份缺少时间时，后续迁移应采用显式重新确认流程，记录新生效时间并要求更新后的设备报告。不能用迁移时刻替代未记录的历史时刻，也不能回填零值后将陈旧报告视为新的验证结果。

## 与逐设备核验组合

1. 在短事务内取得当前成员权限、注册与可信绑定，再读取目录身份。
2. `evidenceNotBefore` 取注册、绑定核验和目录身份生效时间的最大值；身份修订使用返回的摘要，目标 profile 仍需提供方独立证据。
3. 事务外通过可替换连接器读取报告。
4. 新短事务重新读取全部上下文；发生撤销、重新注册、绑定或身份修订变化时拒绝接受旧报告。
5. 有效期受报告时间和本次获取时间共同限制，不能因重复读取无限延长。缺少 profile 证明时继续保持 UNKNOWN。

以上是后续接入契约，不表示本阶段已实现步骤 3–5 的存储或发布工作流。

## 数据库与交付

项目当前未发行的初始化 V1 增加单列，同时更新数据保留分类目录，保持 `SHARED_CONFIGURATION`。验证只使用新建的隔离数据库，不修改正在运行的数据库。正式发行后的已部署数据库必须使用独立向前迁移与回滚预案，不能重写已应用的 V1。

## 验证记录

隔离候选基于 `cc79eb5`，只叠加本轮文件与两个资源的新增字段。RED r2 的 1 项创建用例因时间为空产生预期断言失败：Maven 退出 1，42.1 秒，无错误或跳过。RED r1 在候选准备时因目标包目录尚不存在而停止，未启动运行时；修正准备工具后另建 r2，保留旧目录。

GREEN r1 执行 54 项，1 项失败：测试错误预期带未知字段的创建请求返回 201，项目严格 JSON 配置实际正确返回 400。修正测试为拒绝请求且数据库零行，再合法创建核对时间与摘要；生产实现未改变。

| 范围 | 项数 |
| --- | ---: |
| 新增应用身份元数据、当前权限、租户及异常数据 | 26 |
| 原有目录声明及分类历史恢复 | 3 |
| 原有受管绑定清理及数据目录回归 | 24 |

最终验收另行核对四套 XML 的精确项数、零失败/错误/跳过及源码摘要，没有仅依赖执行器的宽松总数门槛。结果和源码、日志、执行器摘要见[本轮验收证据](evidence/application-identity-metadata-20261016.json)。

这些结果是 H2 MySQL 模式与本地 MVC/事务检查，不是 MySQL/OceanBase、全后端、真实提供方或 Android/TV 验收。本阶段尚未部署。
