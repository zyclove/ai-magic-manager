# 家庭 P0：微信关单、日账单与售后退款

本轮补齐软件层面的支付维护和售后操作。没有开启新销售、调用真实商户、给用户授予财务角色或迁移本机业务数据库；实际收费仍以原首发验收为准。

## 家长操作

会员入口只展示订单当前状态、退款申请和退款进度。退款先由独立售后人员审核，批准后后台使用原交易全额原路退款；家长不需要点击供应商提交按钮。共同监护只读，敏感申请需要近期手机验证。

结果不明时保留原订单、退款号和加密恢复记录；刷新读取当前事实，不把 SDK 返回、排队成功或审核通过画成付款或退款成功。仅服务端核实退款成功才显示完成。

## 售后和财务操作

管理台新增“家庭售后与对账”，不依赖当前家庭或机构工作空间，也不进入家庭日常导航。

- 售后：查看申请 → 预览原金额及保留的续费订单 → 填写简短说明 → 确认通过或拒绝。申请人不能自审；权益发生变化须重新预览。
- 财务：选择上海账单日 → 查看任务与差异 → 排队核对原交易或记录跟进。跟进备注不会把账单改为对平，未知业务不能认领为家庭订单。
- 操作结果未知：恢复原请求和幂等键，近期 MFA 后由工作人员明确重试；不会自动审核或另建退款。

平台接口权限分别为 `family-refunds:review` 和 `family-finance:manage`，均要求近期 MFA。新身份模板只声明角色及受限 scope，未向默认角色或任何用户授权。现有部署须按 [部署说明](deployment-runbook.md) 人工配置指定人员，不能重新导入 realm 覆盖已有账号。

## 服务端恢复

到期未付订单先查单，明确未支付才请求关单，再查到可信 `CLOSED` 才释放；迟到付款按冻结周期入账。尚未预约过支付且没有渠道交易号的草稿可单独到期为 `EXPIRED`。

外部请求在数据库事务外执行，短事务保存租约、代际与退避；跨实例和旧响应不能重复发放权益。已通过人工审核的退款由后台使用原退款号推进，不明确的返回先查原退款。

微信账单申请验签，下载限制到官方地址并验证 SHA1、格式、精确分及所有汇总。退款以可信受理 `create_time` 定日；未映射流水和历史缺日期保持差异或部分核对。CSV 不直接修改会员。

## 启用与数据

新增 `FAMILY_COMMERCE_WORKER_ENABLED`、`FAMILY_BILLS_WORKER_ENABLED`，初始化、示例环境及家庭 Compose 均默认 `false`。启用真实微信集成后可分别验证后台维护与账单任务；维护不依赖新销售开关，停止新销售不妨碍已付款用户售后。

新增七张财务表及退款受理时间已纳入未发布 1.0.0 初始化基线和保留目录。仅在隔离空库验证，未清空或修改本机原数据；已有库不能直接重跑 V1。正式收费后采用向前迁移。
