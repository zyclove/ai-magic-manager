# 审计导出窗口：完成操作归属修复

日期：2026-10-21。状态：实现和独立源码审阅完成；4 条新增浏览器回归用例尚未运行。

## 用户操作

生成导出后，仅结束发起这次操作的窗口。当用户在等待期间打开其他窗口时，保留该窗口和当前页面；后台任务仍可在导出任务页核对。正常在前台完成时，关闭生成窗口后进入导出任务页。

## 修复依据

原入口使用 `showDialog`，迟到的成功回调调用 `Navigator.pop`。该调用针对导航栈顶部；生成窗口被覆盖时，可能关闭覆盖窗口。此前的权限与工作空间检查不会因同一工作空间内新增窗口而失效。

入口现复用项目已有 `OwnedDialogRoute` 与 `presentOwnedDialog`。成功回调只结束持有的导出路由，记录完成瞬间是否在前台；关闭动画完成后，再检查宿主页面仍在前台、仍挂载且权限范围有效，才导航至导出任务页。

此修改不改变生成请求、幂等键、忙碌状态、权限失效或重新安全验证的逻辑。`ExportCreateDialog`、`OwnedDialogRoute` 以及已有的 4 条导出范围测试保持原始字节。

## 回归源码

新增 `apps/guardian/test/audit_export_route_test.dart`，复用既有 Session、HTTP 和导出任务夹具，声明 4 条浏览器 Widget 用例：

1. 被覆盖期间收到成功结果：覆盖窗口保留，审计页面不跳转。
2. 前台正常成功：进入导出任务页。
3. 成功时被覆盖、覆盖窗口随完成回调关闭：仍不触发迟到跳转。
4. 导出关闭动画期间新增覆盖窗口：保留新窗口及审计页面。

第 3、4 条分别约束成功瞬间与动画结束后的前台检查。两次独立源码审阅未发现阻断问题；静态差异空白检查通过。
