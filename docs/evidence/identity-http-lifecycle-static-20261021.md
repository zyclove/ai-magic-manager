## 已接合的改动

- `ConsumerAuthenticatorFactory.init` 创建一个 JDK 17 HTTP 客户端，短信与微信 transport 借用同一客户端。配置和两个适配器以不可变绑定发布，每次 `create` 仍返回独立 Authenticator，保持请求状态隔离。
- Authenticator 接收明确的 sender/transport；验证码验证和已注入假 provider 的路径不再创建 HTTP 客户端或短信适配器。保留连接超时、请求超时、禁止重定向和中断处理。
- 缺失或禁用短信配置可初始化，原有入口可用性判断继续关闭未配置的登录路径。未调整短信签名、微信授权或密钥加载规则。
- 移除内部创建客户端的便捷构造器及无参 transport 工厂，保留三参数注入。真实源码调用检索已覆盖；MySQL 验收夹具使用保留的三参数构造。
- 补充四个 HTTP 客户端复用回归，覆盖不同 Authenticator、手机变更和验证码验证、微信与短信共用客户端、禁用及不完整配置。请求使用合成夹具和假客户端。
- 密钥快照测试明确断言初始值、文件修改后的同进程旧值和新 JVM 加载的新值，避免两个空值相等导致误通过。Probe 删除固定消费者配置与全部五个观测配置键，只设置夹具文件；不读取或打印继承秘密。
- Probe 输出重定向到测试临时目录中的唯一文件，避免未消费管道堵塞。失败时只清理本测试启动且仍存活的子进程，并限时等待、关闭流；受控测试覆盖超时及非零退出。

没有新增依赖或自建线程池。Java 17 HTTP 客户端没有 `close` API，两个适配器借用客户端；没有反射清理或关闭借入资源。
