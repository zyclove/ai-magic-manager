## 原因与修改

支付尝试进入 `PAID` 或 `CLOSED` 后，数据库仍保留原供应商参数。`attempt(ResultSet)` 原先无条件将这些参数放入响应。同一幂等键恢复的 POST 分支会直接返回这份响应，因此终态记录仍可能携带旧支付 SDK 参数；关闭销售时，GET 已有的参数隐藏逻辑没有覆盖该 POST 分支。

本次仅修改该共享响应映射：**只有 `READY` 状态读取并返回供应商参数；其他状态返回空 `parameters` 对象**。这一规则同时作用于原键恢复、查询列表，以及供应商调用期间状态已经变为终态的后续读取。GET 对销售关闭时的额外隐藏继续生效。

尝试标识、订单标识、状态、创建时间与原键绑定保留。数据库中的供应商参数及付款证据不改写；不更改支付事实、账本、关单流程、网关检查或幂等身份，不创建第二次支付。无法提供支付参数的终态仍可用于核对当前订单事实。
