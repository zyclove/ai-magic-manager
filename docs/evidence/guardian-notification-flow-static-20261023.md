# 通知与求助入口交互完善（2026-10-23）

## 已实现

- 通知页和求助快捷入口沿用现有 DeviceSubflowScope，固定本次会话、账号、工作空间、角色和代次。失效后不再接受旧请求结果或旧按钮操作。
- 切换工作空间时同步清除旧求助数量并取消旧轮询；通知页隐藏旧数据。正常入口按当前会话和空间重新创建，避免要求用户手动清理旧状态。
- 刷新、筛选、标记已读、打开申请及重试回调保留各自的数据来源。卸载页面或更换数据来源后，保留的旧回调不能影响新页面。
- 已读操作使用独立的操作标识。旧请求未完成时，新的数据来源可以立即操作；旧请求的收尾不能清除新操作的进行状态。
