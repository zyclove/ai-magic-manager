# Login layout: independent static review

No new definite static blocker was found in the three candidate files. This is a source review, not a compile, widget-test, rendered-layout or authentication acceptance result. All five new tests remain UNRUN.

Main wiring: after removing the added login_view import, all normalized text before LoginPage is identical to its saved before source. LoginPage still watches the same Session and forwards the same session.login() closure and session.error. Initialization, router/callback redirect, entry checks, theme and localization remain untouched. The original nine login/brand strings and the width>900 breakpoint are present in the extracted presentation. LoginView imports Material/design without Session, and introduces no credentials, transport or authorization logic.

Constraints: SafeArea/Row provides a finite viewport height. The brand LayoutBuilder passes that finite maxHeight as a minimum to its scroll child; the inner Column has no vertical Expanded/Flexible/Spacer, so content may exceed the minimum and scroll. ColoredBox remains outside that viewport. primary:false prevents the brand pane from claiming the primary scroll controller used by the login pane. The right pane retains the original centered scroll/maxWidth420 behavior. At320px the brand is absent; padding leaves264px for wrapped text, the full-width button and the footer's Expanded text. No obvious fixed horizontal overflow was found in the requested320px/scale1.6 or1024px/scale1.8 configurations; actual font and render behavior still requires tests.

Five tests target short wide/large-text layouts, narrow large text, expanded error details and keyboard activation. They invoke a local callback, use text-based button taps, and do not depend on exact icon-button factory runtime types or Session/browser imports. ensureVisible is used before offscreen clicks. No perpetual progress animation is present in these fixtures. Tab then Enter is a reasonable check that the first interactive control activates once; actual focus order, automatic reveal and platform behavior remain runtime obligations. The current FailureView builds detail children only after its initially collapsed ExpansionTile expands, matching the error-details assertions.

Limits: no SDK, AST/source parser, formatter, compiler, tests, browser, network or process API was called. Ordinary source/SDK-text reads and small file hashes only. No production/test/Main/Git modification or new source freeze was performed by this review. The scoped five tests cannot prove the real identity redirect, full183 regressions or all accessibility font sizes.
