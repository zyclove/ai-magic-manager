# 1.0.0 发布来源与运行核对

现有初始化、构建、启动、验证入口保持一致。发布清单新增必需的
`provenanceVersion: 1`；缺少完整来源证据时，需重新构建候选发布。

## 构建

`build-deployment.ps1` 将选定源码复制到隔离目录，在执行验证前记录每个
输入文件的路径、字节数和 SHA256，验证结束后再次核对。构建过程中输入
被改动，或部署配方发生变化时，不更新现有发布清单及构建上下文选择。

源码身份采用 `content-snapshot` 与 `sha256:<源码树摘要>`。它表示参与验证
的真实文件内容；冻结副本、未提交修改均不会被冒充为某个 Git 提交。
SDK 生成目录不属于源码清单，依赖解析若改动锁文件则需固定输入后重建。

发布清单记录全部后端、前端和可选身份组件产物，包括 HTML、字体、图标、
其他静态资源及身份提供器。完整文件集合参与校验，新增、缺失和改动都会
使候选失效。发布清单本身位于产物目录和部署目录，两份原始字节必须一致。

部署配方清单仅包含指定的公开 Dockerfile、Compose、边缘配置及发布脚本，
不采集 `.env` 或凭据。路径按 Ordinal 排序，树摘要采用 UTF-8 无 BOM 编码，
每条为 `path + NUL + 十进制字节数 + NUL + 小写SHA256 + LF`。

## 启动

`start-deployment.ps1` 和首次账本初始化在执行写操作前验证完整发布清单。
启动额外核对实际 Compose 项目、产物目录、Dockerfile、前端配置挂载及
镜像构建参数。标签从已验证清单设置，仅作用于当前进程并在结束后恢复。

后端和前端镜像携带版本、源码身份、源码树、产物树、发布清单五项标签。
服务启动并通过健康检查后，脚本读取实际运行容器使用的不可变 image ID，
再读取该 image 的标签。容器自定义标签不作为镜像来源证据。

只有全部检查成功才原子写入独立的 `release-runtime.json`。运行收据绑定
发布清单摘要、公开地址、项目、源码树、产物树及两个实际 image ID。
运行信息不回写构建清单，避免摘要循环和启动后篡改验证输入。

## 验证

`verify-deployment.ps1` 首先核对产物、配方、当前实际镜像及既有运行收据，
然后继续执行前端、登录回调、OIDC、匿名权限与后端健康检查。验证操作
不会创建或修补运行收据。服务缺失、不健康、项目不符、镜像或摘要不符时
明确失败。

同一服务的多个容器必须使用相同镜像。容器使用同一不可变镜像重建是允许
的；更换镜像后需要重新执行完整启动核对并产生新收据。

本机制核对部署来源及基础健康。登录后的业务流程、原生设备行为和外部
支付服务仍需对应的独立验证。修改脚本不会自动构建或更新已运行的服务。
