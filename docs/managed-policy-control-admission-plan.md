## 实施顺序

1. 在真实冻结发布读取用例中证明上述信息缺失。应用意图保留 `requiredOperations`，包含按规则冲突合并后的精确 kind/effect/permission；不从提供方控制枚举反推。列表不可变、无重复、顺序稳定；安装和启动同时存在时都保留。
2. 新增当前资格检查，使用现有应用目录、已核验绑定和持久证据读取；比较当前应用包名/签名/用户空间及操作集合。验证时刻的证据必须有效，且绑定、注册、应用定义与发布要求一致。
3. 准备服务在提供方 I/O 前后均执行本地检查，纳入前后快照比较；资格过期或变更时不返回可供后续写入的准备结果。目录及证据读取继续在现有短事务内，网络读取在事务外。
4. 用真实发布 SQL、模拟提供方验证：精确操作匹配、安装/启动互不冒用、逐权限检查、目录变更、证据过期/撤回、提供方调用期间变化、空基线与事务边界。

本阶段不替代资源独占归属、发布事务入队及写入前租约/授权复核。准备结果仍是内部数据，不能作为对外“已执行”状态。`ENFORCE` 发布保持关闭，直至完整链路接通。

### 对产品流程的实际影响

- 安装、启动与逐项系统权限各自保留原始请求，不能借用同应用其他操作的资格。
- 当前目录包名、签名、平台、用户空间以及绑定、设备注册或证据版本发生变化时，准备停止并返回明确原因。
- 两次检查之间撤回资格，或编译结束时证据刚好到期，均不能继续返回准备成功。
- 本阶段只增强内部准备入口，不新增对外接口，不把准备成功显示为设备已生效。现有提供方网络读取仍在事务外；本地资格比较在短事务内。

完整执行链仍需资源独占归属、发布事务入队、写入与分配前重验及设备回执接合。当前没有真实 EMM、MySQL/OceanBase、Android/TV 真机、容量或生产部署验收结论；`ENFORCE` 发布保持关闭。工作区其他家庭业务未被本次隔离回归覆盖。
