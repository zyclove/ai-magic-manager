# 受管设备与儿童端可信绑定实施计划

2026-10-15。依据现有受管注册、设备密钥和策略发布实现继续推进完整系统执行；不把注册核验或配置保存替代 `ENFORCE`。

## 当前缺口与选择

`ManagedEnrollmentService` 已校验提供方注册来源；`FleetReads` 仍把本地设备视为 BYOD，所有受管能力不可用；`PolicyService.publish(ENFORCE)` 明确拒绝。缺失的依赖是“提供方设备上确实运行着本地注册密钥所对应的、受信发布签名的儿童端”。仅把管理员输入的两个 ID 关联不能证明这一点。

采用双通道证明：服务器向已认证儿童端提供短期随机挑战；儿童端用当前注册私钥签名，再通过受管应用反馈交给提供方；服务器从已审核提供方读取同一设备、同一应用、受信发布签名下的证明，验签后才能建立关联。提供方反馈可能被其管理员查看，不放入儿童姓名、账户、租户或稳定设备 ID；证明仅携带短期随机挑战。

已有 Google 官方生成客户端包含 `ApplicationReport.signingKeyCerts`；使用 SHA-256 证书摘要，不采用已废弃的 SHA-1 指纹字段。现有 Nimbus 实现 ES256，不自研密码算法。后续 Android 侧优先采用 AndroidX Enterprise feedback SDK；合作 EMM 应实现等价的受信证据通道。

## 实施顺序与完成定义

1. **提供方证据与证明校验**：可替换网关读取目标应用反馈，限制响应体与集合大小，严格校验资源身份、应用签名摘要、安装状态、报告时间；Nimbus 验证短期挑战、当前公钥和固定用途；重复键、未知头、超长或过期证明拒绝。官方 SDK 的本地 HTTP 契约和真实 ES256 证明测试通过。
2. **持久化绑定工作流**：管理员近期认证、同租户/同学生的注册目标、独占绑定与乐观锁；挑战发放、设备领取、提供方核验、原子消费、撤销和到期；记录审计并覆盖并发/重放/跨租户与合同撤销竞态。所有首版业务表进入 V1，不原地修改现有运行库。
3. **客户端与交互**：设备独立凭证领取挑战，现有不可导出私钥签名；AndroidX 反馈适配、错误/等待/过期恢复；管理员选择本地设备并观察核验进度。没有正式应用发布签名及合规提供方时保持不可启用。
4. **执行接入**：可信绑定通过后，还需独立验证应用身份、支持的系统策略、策略分配/应用回执、失效与补偿，才能对相关规则开放 `ENFORCE`。绑定成功本身不授予全部能力。

阶段 1 不能被计为整个绑定流程或系统执行已经完成。验签器无数据库重放账本；消费一次、注册有效性、租户权限及关联关系必须由阶段 2 的事务完成。

阶段 2 的接口、状态、配置、事务与验证进度见 [受管儿童端绑定工作流](managed-agent-binding-workflow.md)。阶段 3 已交付 [管理界面](managed-agent-binding-experience.md)、[设备挑战领取与原密钥签名](managed-agent-device-proof.md) 及 [AndroidX 自动反馈与生产会话调度](managed-agent-feedback-runtime.md)。2026-10-16 已完成 [完整 Android Debug APK 构建与产物检查](managed-agent-feedback-apk-acceptance.md)，不再将该构建项列为未完成。

正式开关仍默认关闭。本地 Android 原生验证场景已准备，尚无实际运行结果；真实 EMM 闭环、真机和电视兼容、正式签名与发行验收仍需完成。APK 中存在相关类和清单不能替代这些运行证据。阶段 4 的系统执行接入也尚未完成，不能因绑定或打包成功而开放全部系统管控。

## 阶段 4：逐设备证据与执行接入

以下为待实施的接入约束，依据 `b8b00e1` 对应代码及当前工作区只读核对。它们不表示已新增接口、数据表或执行能力。

阶段进展（2026-10-16）：现有编译入口采信共享目录 `INSTALLED_VERIFIED` 的问题已复现并修正，16 项定向检查通过；详见[目标应用身份校验记录](policy-target-identity-verification.md)。该入口现在等待逐设备证据，不再因目录声明显示应用规则可执行。下文正向证据、持久执行及真实提供方接入仍待完成。

### 先修正证据作用域，再开放执行

`PolicyService.snapshot` 当前为所有目标复用同一份应用目录。修正前，`RuleCompiler.compile` 从 `ApplicationDefinition.evidenceStatus` 判断应用是否已验证；当前入口已拒绝采信该共用目录状态，仍待逐目标证据接入。目录定义是租户内声明，不能因为一台设备核验通过，就把目录记录改为 `INSTALLED_VERIFIED`，否则其他设备会继承不属于自己的安装事实。

| 数据 | 拥有者及用途 | 不得推导的结论 |
| --- | --- | --- |
| 应用目录 | catalog；显示名称、平台、包名、目标 profile、允许的发布签名 | 该应用已安装在所有设备上 |
| 儿童端应用清单 | catalog；当前注册、授权版本和序列号下的观察 | `AGENT_REPORTED_UNVERIFIED` 自动成为系统受信证据 |
| 受管绑定 | managedandroid；提供方设备与当前本地注册密钥关联 | 该设备所有应用、profile 和所有系统策略均可信 |
| 提供方应用证据 | managedandroid；精确设备、注册、绑定、包名及可证明的 profile | 未出现的应用已卸载，或未知 profile 等于 PRIMARY |
| 能力证据 | 对应提供方适配器；管理模式、系统版本、具体动作及限制 | 支持拒绝权限就支持自动授予；支持应用策略就支持配额 |
| 执行回执 | 提供方资源、策略版本、设备合规事实及获取时间 | 请求已接收就代表设备已应用 |

拟新增领域读取边界 `ManagedExecutionEvidenceAccess`，由 managedandroid 提供不可变的目标证据。policy 通过公开接口读取，不直接查 managedandroid 表；fleet 继续拥有本地设备生命周期。证据键至少包含 `tenantId / deviceId / registrationId / bindingId / providerDeviceName`，应用项还需包含 `applicationId / definitionRevision / packageName / profileScope / signingDigests`。

证据同时记录提供方报告时间、平台获取时间、到期时间、来源适配器版本、当前绑定修订号。设备重新注册、解绑、提供方企业变更、目录签名变更、证据过期均使旧证据失效。签名轮换必须由明确的发布签名策略认可，不把报告中任意一个匹配值视为全部签名可信。

编译接口应接收每个目标的应用核验结果，而不是改写共用目录状态；预览快照保存证据摘要、修订号及失效原因。发布事务重新核对同一注册、绑定、目录修订和有效期；外部 HTTP 读取在短事务外完成，事务内用版本核对接受结果，避免持锁等待提供方。

官方应用报告需要启用对应上报选项；报告缺失应展示“等待提供方报告”，不得显示“已卸载”。现有 Device/ApplicationReport 契约没有可直接等同于本地 PRIMARY 的 Android 用户编号；profile 映射必须由适配器提供可核对的依据，缺少依据时继续不可执行。[设备报告字段](https://developers.google.com/android/management/reference/rest/v1/enterprises.devices)

### 执行工作流与恢复

1. 管理员完成近期认证并确认预览；事务保存不可变发布快照、目标证据引用和待执行任务。幂等键绑定租户、操作者、请求内容和目标注册。
2. 后台执行器领取持久任务；每次外部写入前复核任务代次、授权、合同、绑定与注册。撤销后尚未发出的任务停止；已经发出的请求进入核对状态。
3. 每个设备使用平台独占的提供方策略资源。为一次发布构建完整目标策略，先确认提供方资源与版本，再分配设备；不逐条修改共享策略导致中间态泄漏或其他设备被连带修改。
4. 超时或返回身份不符记为 `OUTCOME_UNKNOWN`；查询原资源核对后再决定下一步，不能换一个命令 ID 直接重试写入。网络重试由有界退避控制，并遵循提供方限流。
5. 设备报告必须匹配本次资源及精确版本，并具备一致的合规证据，才能记为已应用。保留逐目标和逐规则结果；整批部分失败不能显示全部成功。复用已有[回执契约](managed-policy-receipt-contract.md)。
6. 回滚是一个新的、可追踪的目标版本；重新验证当前权限、绑定和应用证据。恢复旧配置也需等待设备回执，不承诺已经卸载的应用数据能够恢复。
7. 失联时展示最后已知应用版本及观察时间，等待恢复连接。云端执行器不能保证离线设备立即撤销规则；临时放行如需离线准时到期，必须另有经过验证的设备侧截止执行能力。

任务领取采用数据库乐观锁与有界租约，外部结果回写须匹配领取代次；接管者先核对前次不确定结果，防止多个实例同时发出不同版本。租约只能约束本地任务，不能撤回已发往提供方的 HTTP 请求；超时任务必须保留对账记录。

### 用户侧保持简单

默认仍为“选择设备 → 预览影响 → 确认发布”。提供方资源名、内部证据 ID 和任务租约只进入受限诊断页。普通详情展示“可执行／需要处理／暂不支持”、具体原因和下一步入口。

设备结果分别显示“等待发送、等待设备确认、已应用、部分未应用、结果待核对”。证据失效时指出“设备已重新注册”“应用身份待核验”等可行动原因，禁止只显示通用失败。预览页必须明确安装阻止可能移除已安装应用，确认记录绑定该影响说明；普通“禁止打开”不能隐式转换为卸载。[应用安装策略](https://developers.google.com/android/management/reference/rest/v1/enterprises.policies#InstallType)

### 按依赖顺序交付与验收

| 顺序 | 实施位置 | 必需证据 |
| --- | --- | --- |
| 4A | managedandroid 官方 SDK 读取及证据存储 | 真实 SDK 驱动本地 HTTP 契约；响应上限、身份、签名、过期、重复项、缺失报告与未知 profile |
| 4B | policy 目标级编译及预览快照 | 同一应用在 A 已核验、B 未核验时结果不同；重新注册、目录修订及同租户其他设备不可继承证据 |
| 4C | 持久执行器、独占策略资源及回执 | 并发领取、重复请求、未知写结果、版本漂移、撤销竞态、进程崩溃及恢复对账 |
| 4D | 管理端预览、批次详情及恢复操作 | 部分失败可解释；取消不发布；重试只作用于明确目标；回滚仍要求确认和回执 |
| 4E | 合规提供方及支持机型联调 | 应用启动/安装、运行时权限、重启、离线恢复及版本回执实测；逐动作开放能力 |

4A–4D 可先用可替换连接器完成本地实现与验证；4E 需要合规提供方和真实支持设备。用户已选择先做本地连接器，不能将本地夹具结果升级为商业提供方准入或真机能力证明。首个动作打通后继续补齐其余已规划功能，不把最小可执行子集定义为完整产品。

## 证明 v1 约束

- 固定反馈键 `ai_manager.binding.v1`；固定 JWT audience `ai-manager:managed-agent-binding`。
- ES256、P-256、公有注册 JWK；JWT 头只允许 `alg`、`typ`。不接受上传 JWK、远程密钥 URL、证书链或算法切换。
- JWT claims 只允许 `sub`（随机挑战 ID）、`nonce`（随机挑战值）、`aud`、`iat`、`exp`、`jti`（随机证明 ID）。不携带稳定业务标识或儿童资料。
- 证明最长 1000 字符，挑战最长 10 分钟，证明必须在挑战窗口内生成并在窗口内核验。时钟偏差上限 30 秒。
- 目标应用必须已安装，提供方证书列表非空，所有报告的 SHA-256 签名均被显式信任；发布签名未配置不得视为通过。
- 提供方设备状态报告及反馈更新时间必须在挑战之后，不能来自过期设备快照或未来异常时间。反馈记录的时间与签名时间相互核对。
- 验签通过只返回短期证据摘要及时间，不日志输出 JWT、nonce、完整提供方响应或稳定设备标识。
