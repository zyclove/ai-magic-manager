# 设备心跳观察状态

管理端设备列表同时显示注册状态、心跳观察状态和最后心跳时间；详情给出状态解释。观察状态取自服务端 `Device.observationStatus`，管理端不依据本机时钟另行推断，也不将最后心跳时间当作策略执行证明。列表可手动刷新以获取最新状态。

| 状态 | 界面含义 | 管理者下一步 |
| --- | --- | --- |
| `RECENT` | 服务端近期收到心跳 | 查看设备能力和具体策略执行回执 |
| `STALE` | 超过服务端观察时限，暂时无法观察 | 检查设备网络、电源和设备应用，恢复连接后刷新 |
| `UNKNOWN` | 当前注册周期没有可用心跳 | 核对配对与设备应用，等待首次上报 |
| `REVOKED` | 云端注册已撤销 | 另行核实设备本地系统管理状态 |

服务端观察时限由 `DEVICE_OBSERVATION_MAX_AGE_SECONDS` 配置，默认 180 秒；它是连接观测窗口，不是安全事件判定阈值。失联可能来自关机、网络故障、应用权限、系统限制等多种原因，不能自动判定儿童绕过管控，也不能判定本地规则已经失效。`RECENT` 也只能证明收到心跳；策略是否执行仍需看具体能力、配置下发和可信的执行证据。

状态提示在列表中以图标、文本和辅助说明呈现。图标和颜色仅帮助扫读，不单独承载含义；窄屏卡片沿用相同字段。后续若加入安全告警，需要定义独立事件来源、去重与恢复流程，不能直接把每条 `STALE` 状态变成告警。
