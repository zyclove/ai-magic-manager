# 诊断与限时支持授权实施计划

承接已批准的 implementation-plan Task 10、RPT-01 与 COM-06。报表阶段已经完成整阶段审阅及一次修复，发布仍待用户明确授权；本阶段继续实现剩余诊断能力，不重试被自动审批拒绝的服务替换或数据迁移，不改变已冻结报表候选。

## 用户目标和既有约束

管理员需要定位设备接入、能力与配置下发问题，并在自己确认范围后将必要诊断提供给明确接收人。复用 Spring 事务、数据库授权、OIDC 近期多因素认证、Jackson 严格模型、Nimbus JWE 和 Flutter Material。诊断不取得策略执行、设备擦除、媒体采集或儿童自由文本权限。

### 裁定

- Ruling: 诊断采用字段允许列表，绝不把日志、Device、策略快照或任意 Map 直接序列化。版本仅保留通过严格数字版本校验的内容；无法识别时输出缺失／已脱敏状态，不截取看似版本的自由文本前缀。代价是厂商自定义版本可能无法完整展示，排障时以稳定关联 ID 补足。
- Ruling: 诊断先复核当前管理员成员关系和近期 MFA，随后按档案→设备→配置头锁定；档案归档拒绝读取。设备撤销不等于删除，允许当前管理员查看撤销状态与该注册周期的脱敏下发证据，但不会恢复设备认证或管理权限。若后续数据删除要求更严格，需通过删除屏障统一阻止访问。
- Ruling: 预览先实现为事务内即时、无缓存、审计的结构化读取，不声称预览等于限时加密包或远程支持授权。包生成与下载另有异步状态和到期清理，必须完成后才宣布整体诊断交付。
- Ruling: 支持接收人必须绑定具体 OIDC 主体，不能凭邮箱文本、知道租户 UUID 或销售关系直接授权。将采用接收人登录后生成的短期配对请求，让客户核对受 IdP 证明的身份再授权明确设备／诊断类型／到期时间；接收人身份不冒充平台官方客服认证。客户随时撤销，接收人读取时重新核对授予者成员版本、设备注册与范围，且保留审计。此流程的存储、配对、授权及即时诊断 UI 已按下文基础步骤实现，加密包另行推进。
- Ruling: 同一设备一次预览最多 70 项原始能力（64 项报告加既有默认能力）、100 项当前配置、512 KiB 序列化结果。超过上限明确拒绝，不静默截断。未知能力仅报告数量，不输出任意自报键值；未知错误码转换为明确的未知值，不携带原文。
- Ruling: 预览事务使用 READ_COMMITTED；成员、档案、设备、配置头与下发元数据采用当前锁定读取。策略版本不可变，按租户／策略／版本绑定读取哈希且不再锁策略版本，避免与发布流程的策略→设备顺序形成反向锁。能力容量检查采用最多 65 条键的当前锁定读取，防止旧快照计数漏过新报告。

## 步骤与验证

1. 隐私投影与模块读取边界：Fleet 提供当前注册版本／能力；Delivery 只读取下发元数据，不读取 document_json、compact_jws 或回执正文；Policy 只提供不可变版本哈希。纯模型测试覆盖允许列表、敏感值、未知枚举、版本与容量。先红灯再实现。
2. 管理员诊断预览：GET `/api/v1/tenants/{tenant}/devices/{device}/diagnostic-preview`，当前权限、MFA、档案生命周期、注册绑定、稳定错误、无缓存、读取审计及序列化预检。测试跨租户、撤权、弱认证、归档、注册变化、撤销设备、并发和大容量。真实 MySQL 验证模块查询与锁定。
3. 限时支持请求／授权：稳定接收人、明确范围／类型／期限、近期认证与确认、幂等和版本、撤销与过期、当前授权复核及访问审计。不得把收件人资格或知道配对码当成客户已经授权。
4. 限时诊断包：异步加密产物、用途隔离、近期认证下载、不可部分公开、撤销／注册变化失效、到期删除；保留下载后副本的准确说明。
5. 管理端诊断界面：成熟组件展示版本／能力／错误／最后确认时间，预览与确认、授权接收人核对、任务进度、撤销、下载、后台清除与空态／错误态／键盘和手机布局；使用真实客户端 HTTP 旅程与浏览器验收。
6. 完整组合回归、非空迁移、实际数据库、真实身份检查边界、一次整个诊断阶段独立审阅及一次修复；服务更新仍须遵守已有自动审批阻挡，不绕过授权。
