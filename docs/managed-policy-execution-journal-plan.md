# 受管策略持久执行账本实施计划

2026-10-16，接续 `affee6c`。目标仍是完整的策略执行、前后端操作和设备回执；本计划记录阶段 4C 的持久化步骤，不重新定义整个产品完成标准。

## 现状与实施决定

- 已有配置发布、签名配置下发与设备传输回执；这些流程不能证明系统执行。
- `PolicyService.publish(ENFORCE)` 仍受能力及适配器门槛限制。应用身份核验也不能证明 Android 用户空间或策略执行能力。
- 已有应用控制投影回执与只读核对，但没有持久执行账本，进程崩溃后不能可靠区分“尚未调用”与“调用结果未知”。
- 决定：在 managedandroid 内新增持久任务、领取代次和状态变更记录，复用 Spring JDBC、短事务、已有审计、当前租户/注册绑定约束。任务是业务领域对象，不引入新的通用工作流框架或并行第二套任务基础设施。
- 决定：先完成可被编排层使用的账本，随后接入完整策略构建、提供方独占资源、授权复核、发布事务与管理界面。不能通过新增任务表或测试夹具直接开放生产 ENFORCE。
- 决定：1.0.0 仍是未发布的新库基线，新增表作为明确标记的 V1 追加片段；不修改正在运行的数据库，不包含同文件中其他任务的未提交片段。

## 账本约束

1. 任务关联租户、发布、设备当前注册、可信绑定和提供方资源。每次发布对同一设备最多一项任务；相同请求的不可变内容必须相同。CONFIGURE_ONLY 不接受为执行任务来源。
2. 每设备最多一个未解决任务。结果未知或需要人工核对时保留占用，防止新任务覆盖未知远端状态。已应用和明确在分配前取消才释放占用。
3. 领取使用数据库比较更新、随机领取令牌、单调代次和有界租约。旧进程不能完成被接管的任务；多实例不重复获得同一有效领取。
4. 外部写入之前必须先持久记录“可能已经发送”。政策写入或分配期间崩溃，接管者只获得读取动作，不能重新发送原写入。
5. 应用策略回执、设备分配回执、设备应用回执分别记录。只有资源和精确版本一致且合规的设备事实才可记为已应用；回执内容检查仍由提供方边界负责。
6. 普通只读 `MATCHED` 不证明写入归因。没有进一步的独占资源及不可变请求证据时，未知策略写入转入待人工核对，不能自动升级为成功。
7. 未发送的任务可以取消。可能已影响设备的任务取消只能记录取消请求并要求核对/恢复，不显示为“已恢复原策略”。本地租约和取消都不能撤回已经发出的远端 HTTP。
8. 重试有明确动作、截止时间、次数上限和下次时间；限流、网络失败不创建新命令 ID。纯读取可有界重试；写入结果未知先读后判断。
9. 账本方法是内部事务边界，不提供独立的绕过预览发布的执行 HTTP 接口。未来编排器每次外部写入前仍须重新核验操作者、合同、绑定、注册、应用证据及动作能力。
10. 新表进入数据分类目录。未知或仍可能执行的任务必须先停止/核对，删除流程不能直接擦掉未解决账本。敏感资源只进入受限诊断，普通界面显示可行动的状态与原因。
