# 策略配置发布控制台（1.0.0）

> 本阶段验收记录基于固定源码、实际测试及逐图查看；不代表整个产品或真实设备已完成验收。

## 使用流程

1. 选择设备，或使用当前设备组快照替换选择；每次最多选择 50 台。
2. 查看这些设备的规则预览，核对目标、影响和有效期。
3. 在同一个窗口内确认发布配置；返回预览仍保留已展开内容。
4. 查看保存结果。成功状态为「配置已保存 · 未执行」。

本次发布采用 `CONFIGURE_ONLY`，只保存策略配置；不能把保存成功理解为设备已经执行。设备是否执行、实际生效情况及设备回执需要单独验收。

## 常见情况

### 预览期间出现其他通知

通知保持在最前面。预览完成后保留当前设备选择和就绪结果，停止加载提示；用户关闭通知后继续查看这一次预览。不会再次预览，也不会自动保存配置。

### 提交后无法确定结果

网络中断、无效响应等情况可能导致结果不确定。系统保留原操作，用户可主动查询原结果。

- 只查询原操作，不自动重复发布、生成新操作编号或重新预览。
- 查询暂时没有结果时，继续保留原操作，不把它显示为保存成功。
- 关闭窗口、重新打开浏览器或预览过期，都不会自动清除该记录。
- 恢复记录时先展示本地状态，不自动向服务端发送请求。

### 需要最近认证

只有服务端可信响应明确证明本次尚未提交时，才提供最近认证后的显式重试。重试沿用原配置、预览和操作编号，并核对有效期。

普通认证错误、查询错误或此前已经不确定的操作，不会因此重新获得发布权限。明确未提交且已过期的操作，可由用户显式取消，再重新选择和预览。

### 账号、工作区或权限变化

原窗口立即停止可用操作并隐藏私有预览和结果。权限短暂恢复也不会重新启用旧窗口。已保留的原操作不会因撤权而被自动清除。

## 实现约定

- 界面复用 Flutter Material 3；持久层使用成熟的 `idb_shim 2.6.0+5` 和浏览器原生 IndexedDB。
- 按 1.0.0 新建数据库，不设计历史兼容或数据迁移。
- 每个操作固定创建者、租户、API、身份来源、策略、版本、预览和操作编号；不保存登录令牌或设备明细。
- 首次提交前先持久化 `UNKNOWN`。已有记录只能恢复，不能因刷新或跨标签页操作再次发布。
- 认证后重试通过事务比较完整记录和尝试编号，同一轮只有一个标签页可取得提交权。
- 旧响应不能覆盖、取消或清除较新的尝试；成功回执只清理严格匹配的原记录。
- `UNKNOWN` 不设置过期淘汰；预览有效期约束新的发布请求，不阻止查询原结果。
- 保存成功页面与确认过程使用同一自有窗口，不关闭独立通知或其他页面。
