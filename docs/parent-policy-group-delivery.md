# 手机机构设备组策略选择

日期：2026-10-13。接续手机新建、模板复制、草稿编辑和配置发布流程，复用现有设备组 API 与后端 `PolicySnapshot.GroupSelection` 契约。本阶段不新增数据库迁移或依赖。

## 产品行为

- 仅机构工作空间中的 OWNER/ORG_ADMIN 显示“从设备组选择”。家庭、监护人和审计角色仍沿用自身已有权限；后端独立鉴权。
- 设备组列表支持分页、刷新、空状态和读取错误重试。选择时重新读取组资料和当前有效成员，显示组名、修订、有效设备数、排除记录数，再由管理员确认替换当前选择。
- 使用组来源时必须选择全部当前有效设备，最多 50 台；空组不允许预览，超过上限明确要求在管理台拆分，不截取前 50 台。
- 当前有效成员由服务端 `status=CURRENT` 定义：主体未归档、设备仍有效且注册周期匹配。排除数是此次读取的成员记录总数减有效数，不表示规则已执行，也不是在线设备数。
- 组快照在详情显示设备名称和来源修订。不能在快照中勾掉部分设备；“清空分组选择，改为逐台选择”会清空设备、来源及旧预览，不暗中退回无来源的子集。
- 分组创建、改名、归档及成员维护仍由完整管理台负责。本次分组不是动态策略订阅；组后续变化不会自动扩展已保存的配置版本。

## 读取、预览与发布

1. `GET /tenants/{t}/device-groups/{g}` 读取活动组与修订。
2. `GET /tenants/{t}/device-groups/{g}/devices?status=CURRENT&limit=50` 读取完整有效成员；出现下一页或超过 50 条立即拒绝，避免不完整快照。
3. 逐项核验设备 ID、注册 ID、状态与唯一性，再读组资料，要求组修订和成员记录总数未变化。选择结果中的注册映射和名称映射不可变。
4. 预览前重新读取完整映射，要求组修订及每台设备注册周期均匹配。请求同时提交 `deviceIds/groupId/groupVersion`；客户端核对响应 `snapshot.groupSelection` 及逐台注册 ID，不接受缺失来源或替换目标。
5. 发布在近期身份验证完成后再次核对组快照，再检查预览有效期、保存本机恢复记录和提交 `CONFIGURE_ONLY`。获取令牌后、发送前再次确认账号和工作空间。
6. 服务端在预览/发布事务中重读并锁定组，比较全部当前有效成员与注册事实，弥补客户端预检查到提交之间的竞态。组修订变化、归档、成员变化、设备撤权等均可使原预览失效。

已有接口无需变更。`ParentApi.object/page` 新增可选作用域守卫，本次组资料与成员读取使用该守卫；不能据此推定项目所有旧读接口已接入。

## 失败处理

| 条件 | 行为 |
|---|---|
| 分组或成员事实变化 | 不生成/保留有效预览，提示重新选组；不自动扩大目标 |
| 超过 50 台、空组 | 阻止组选择并解释原因；不生成部分策略 |
| 响应有重复设备、失效成员、错误注册格式 | 拒绝整份响应，不挑选其中看似有效的记录 |
| 切换账号、工作空间或角色 | 关闭组选择页面，停止后续读取，丢弃旧结果 |
| 发布结果未知 | 沿用已有发布恢复契约；不因组状态变化自动重发 |

## 本阶段证据

- `policy_group_selection_test.dart` 11 项通过：完整快照、上限、空组、重复/失效成员、读取中修订变化、注册周期变化、作用域改变、确认交互，以及策略中心选组→预览参数/响应核对→切换逐台选择后清除预览。
- 手机全部测试累计 29 项通过（包括前两阶段创建与编辑测试）。
- Flutter 静态分析通过，Android 调试 APK 构建通过；构建使用示例 HTTPS 配置，不能作为已完成生产身份联调的安装包。
- 后端 `PolicyJourneyTest` 26 项通过。新增场景使用实际分组改名和设备撤权接口，证明组修订变化或设备失效后，发布返回 `POLICY_GROUP_CHANGED` 且不新增配置版本。
- 初次后端夹具尝试直接修改被组成员外键引用的注册 ID，被数据库约束拒绝；最终改为实际撤权接口验证生命周期失效，不禁用约束。客户端注册 ID 变化防护由独立模拟响应测试覆盖，不将其描述为当前数据库允许原地改写注册 ID。
- 后端验证使用独立构建目录和 H2 MySQL 模式；客户端验证使用模拟 API。真实 Android/IdP/TLS、MySQL/OceanBase 兼容、TV 遥控交互及受管系统策略执行仍需各自验收。

商业方向保持中国大陆、机构合同优先。配置保存不代表不可绕过的系统限制，且不增加合同设备名额或商业权益。
