# 儿童端申请：Android 原生持久恢复验收

## 1. 目标与能力边界

本阶段验证申请和取消操作在 Android 应用进程终止后能够按原内容恢复，并验证原生安全存储、文件加密、授权拒绝及密钥丢失的行为。

使用专用 Android API 34 模拟器、官方 `integration_test` 与 `flutter drive`。Android Keystore、`flutter_secure_storage`、原生持久化屏障、`path_provider` 和 Sembast 文件是真实实现。云端响应、初始注册、设备身份与审批事实是明确的合成夹具，不使用真实儿童资料或真实账号。

这证明 Android 模拟器上的原生进程恢复，不等同于实体手机兼容、设备系统重启、后台常驻、Android TV 遥控、商用 EMM 接入或跨应用系统限制。真实 Spring 与儿童会话/页面的 HTTP 互操作由[独立验收](child-submission-http-acceptance.md)证明，不能将两种验收拼接为已完成 Android 生产环境全链路。

## 2. 入口、隔离与前置条件

- 应用入口：`apps/child/integration_test/submission_storage_test.dart`。
- 主机驱动：`apps/child/test_driver/submission_storage_driver.dart`，复用官方驱动并限制连接和请求等待时间。
- 仅使用专用、明确归属本次验收的 debug 安装。严禁在实际儿童设备或真实账号安装上运行。
- 夹具通过固定 `.invalid` 服务来源与合成 UUID 建立独立范围。所有 HTTP 都通过显式 `MockClient`，不打开网络连接。
- 测试身份保存在独立的原生加密绑定键中，不写入产品的 `identity_record`。申请文件与文件密钥按完整租户、学生、设备、注册和服务来源范围隔离。
- `write_unknown` 拒绝覆盖已有测试身份、绑定、夹具或申请文件。其余阶段要求前序进程留下的持久状态；缺少状态必须失败。
- 阶段间保持应用安装，不卸载、不清空应用数据、不删除整个安全存储。`flutter test integration_test/...` 的卸载行为不能代替此验收。

保留安装运行方式（推荐用于后续复验）：

```text
flutter build apk --debug --no-pub --target=integration_test/submission_storage_test.dart --dart-define=SUBMISSION_STORE_PHASE=<phase>
adb -s <owned-device> install -r <built-apk>
flutter drive --no-pub --driver=test_driver/submission_storage_driver.dart --target=integration_test/submission_storage_test.dart -d <owned-device> --keep-app-running --use-existing-app=<forwarded-vm-service-url>
```

构建与安装分开执行。保留安装失败立即停止；核实原 UID/首次安装时间后，手动以 `start-paused` 启动 debug Activity，再将该进程的 VM 服务端口转发到本地，交给官方驱动连接。只移除自己建立的精确端口映射。不能把上述三行直接连续执行而省略安装身份、暂停启动和 VM 服务发现检查。

后续真实 HTTP 验收发现 Flutter 代管安装可能在 ADB 失败后自动卸载重装，因此 `--keep-app-running` 本身不足以保护数据。新旅程的[主机实现与事件说明](child-android-http-acceptance.md)提供显式保留安装和连接现有应用的做法。下文原阶段证据来自此前成功运行，所有阶段当时的 UID/首次安装时间一致；不要将后来无效安装尝试算入该历史结果。

完成阶段由官方驱动回传报告；主机核实报告 PID 与设备进程一致，再对同一专用设备执行 `am force-stop com.aimanager.child.debug` 并确认 PID 消失。申请和取消首次发送阶段在原日志预写后的请求回调中输出不含敏感数据的检查点，并保持响应未完成；主机此时直接终止 Android 进程和仅本次拥有的 Flutter 驱动，不能将驱动的预期中断当作普通测试通过。下一阶段必须从新的进程开始，并读取原日志证明其持久化。

事实恢复阶段保留会话与日志所有者直到主机终止进程，不先正常关闭数据库；密钥探针与文件清理阶段才正常关闭。由此覆盖未正常关闭进程的恢复，而非只验证 `close()` 后重新打开。

## 3. 阶段契约

| 顺序 | `SUBMISSION_STORE_PHASE` | 关键断言 |
| --- | --- | --- |
| 负向前置 | `restore_offline`，且没有前序夹具 | 明确失败，不允许以空日志作为恢复成功 |
| 1 | `write_unknown` | 实际页面选应用、输入理由、核对后提交；原日志预写后到达受控请求回调，在响应仍未完成时直接终止进程；下一阶段核对原正文、随机幂等键、创建时间及 UNKNOWN |
| 2 | `restore_offline` | 新进程离线恢复完全相同的正文、键和创建时间；未知操作不能放弃；没有自动发送申请或取消 |
| 3 | `recover_original` | 启动只查询事实；用户核对原操作后明确重试；普通重放返回过期，专用恢复使用原键/原正文；清除未完成操作并保留批准的原绝对截止时间 |
| 4 | `write_cancel_unknown` | 在另一个合成应用上正常创建申请；在线详情和取消二次确认；取消使用原申请 ID、版本 0 和独立幂等键，在响应仍未完成时直接终止进程；下一阶段核对 UNKNOWN |
| 5 | `recover_cancel` | 新进程恢复原取消 ID、原键和版本 0；用户明确重试后专用恢复返回同一申请的 CANCELLED、版本 1 |
| 6 | `reopen_final_offline` | 离线新进程恢复批准和取消两份事实；原截止时间不变；使用缓存标识，不宣布系统已解锁 |
| 7 | `reject_credentials` | 身份上下文返回 401；隐藏旧申请资料并持久化 BLOCKED，不能读取旧事实作为授权依据 |
| 8 | `verify_blocked` | 再次打开且离线，保留已知授权拒绝；不显示旧应用或申请，不发送变更请求 |
| 9 | `remove_key` | 仅删除本测试范围的原生文件密钥；原生数据库打开接口明确拒绝；文件摘要不变，不重新生成密钥或重置空数据库 |
| 10 | `verify_missing_key_cleanup` | 新进程再次确认密钥缺失与原文件未改写，再清理本测试范围的文件、绑定、测试身份和夹具 |

`cleanup` 是独立故障清理入口：只删除已确认属于本夹具的精确范围，并验证父目录和文件名。它不算正常恢复阶段，也不能用清理后重新注册掩盖数据丢失。

## 4. 主机证据与日志

正常完成的阶段通过官方驱动 `reportData` 回传阶段、原生 PID、请求计数和布尔断言结果；两项进行中终止阶段以检查点、进程终止及下一进程读取原日志共同证明。主机还必须检查：

1. 设备序列与 AVD 名称符合本次专用设备。
2. 包 UID / appId 和首次安装时间在阶段间不变，证明没有靠重新安装清空状态。
3. 设备上的实际安装 APK 摘要等于本次构建产物摘要。
4. 报告 PID 与设备进程一致；终止后 PID 不存在。
5. 各阶段对应同一份冻结源码，防止将旧构建结果计入新版本。
6. 数据文件和原生加密偏好文件中不存在明文理由、原幂等键、设备凭证和文件密钥。
7. 产品原有身份、观察记录、配置文件及其他访问范围的文件摘要保持不变。

报告不包含原始身份记录、密钥、凭证、请求正文或申请理由。含合成运行状态的本地夹具、日志和 APK 不提交；提交源码、验收契约及不含敏感资料的摘要证据。结束后恢复普通 `main.dart` 应用并停止本次启动的专用模拟器。

正式 Android 安装启用 `FLAG_SECURE`。验收保留该保护，不将被阻止的截图作为界面证据；普通入口恢复通过实际安装包摘要和系统界面语义树核对。

## 5. 离线授权状态修复

新增回归发现：曾收到授权拒绝后，再次离线复核会将持久化 BLOCKED 改成 CHECKING。两者都拒绝缓存读取，但后者丢失已知拒绝事实，影响诊断和恢复解释。

申请宿主现仅在尚未收到 HTTP 响应、失败允许重试且已有状态为 VALID/BLOCKED 时保留原状态。未经验证的 CHECKING 不转成可用状态；新的真实鉴权拒绝仍写入 BLOCKED；只有新的、范围一致的已认证上下文才能重新确认。没有新增自动变更重试。

## 6. 后续发布门槛

需继续验证 Android 多版本和实体厂商设备、系统重启、升级安装迁移、后台限制、用户退出/解除管理、Android 真实服务全链路以及商用受管模式执行。密钥缺失时默认停止恢复，不能通过卸载、清空或自动重注册宣称修复；正式恢复流程需监护人授权和明确的数据处理说明。

## 7. 本阶段实测记录

本次基于 `e72f556` 冻结候选执行，运行输入摘要与提交文件逐项核对。结果见[机器可读验收摘要](releases/stage-submission-native-verification.json)。

| 项目 | 结果 |

| 缺少前序状态的负向检查 | 1 项按预期失败；拒绝把空状态算作恢复 |
| 原生阶段 | 10 项完成：2 项请求进行中终止，8 项官方驱动正常完成后终止 |
| 原操作恢复 | 原申请正文/键/创建时间、原取消 ID/键/版本保持；未知操作不自动重试 |
| 身份拒绝与离线复核 | 新进程保留 BLOCKED，隐藏旧申请和应用资料 |
| 文件密钥丢失 | 连续两个进程拒绝打开，原文件摘要不变，未生成替代密钥 |
| 儿童端回归 / 申请 SDK 回归 | 91 / 128 项通过；两者静态检查无问题 |
| 普通 Android 入口 | debug APK 构建并安装通过；语义树核对未配置状态；保留 FLAG_SECURE |
| 收尾 | 精确范围夹具清理通过；普通应用进程及本次专用模拟器已停止 |

两项进行中终止以回调检查点和下一进程的原日志读取为证据，其驱动退出码 1 是主机主动中断结果，不计作普通测试通过。其余阶段分别核实 PID、实际安装 APK 摘要及同一安装身份，未清空应用数据。

摘要中的布尔字段只用于对应断言：`originalCreateCompared` / `originalCancelCompared` 分别在专用恢复阶段有效；`missingKeyRejectedWithoutReset` 仅在两个密钥探针阶段有效。最终清理阶段已经删除测试文件，因此 `plaintextAbsent: false` 表示该阶段不再执行明文检查，并非发现明文；先前保留文件的阶段均通过相应检查。

本阶段未重新运行后端或 MySQL 验收，也未合入并行报表候选。先前 HTTP 联调仍见独立记录；这份结果不宣称完成生产 Android 服务联调、系统重启恢复、后台防退出或系统级应用控制。
