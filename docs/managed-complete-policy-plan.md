# 完整应用与权限策略文档实施计划

接续 fb63a8d，2026-10-16。完整产品目标保持不变。本步骤为持久执行器补齐确定性提供方文档，解决应用控制与权限分开更新时的组合问题。

## 实施约定

- 新增纯编译器，复用已锁定的官方 Android Management SDK、Jackson 和现有权限/安全包清单；不新增依赖或自研协议库。
- 输入必须是服务端已解析的完整应用控制与权限集合；发布层仍必须拒绝无法执行的规则，不得把本编译器调用成功视为所有规则已受支持。
- 首个 Google 文档版本显式 BLACKLIST、PROMPT；合并逐应用控制与 DENY/PROMPT 权限，不自动授予权限。不把 BLOCKED 描述为仅阻止新安装，它可能卸载已有应用。
- 固定保留经部署配置选择的管理应用，FORCE_INSTALLED 和 USER_CONTROL_DISALLOWED；该版本要求 DEVICE_OWNER 且 API >= 30。普通用户设备、工作资料和未知系统版本拒绝编译，不能承诺所有 Android/电视支持。
- 开启应用报告，不添加摄像头/内容/位置采集配置。管理应用发布签名、分发可用性和实际设备能力由绑定与后续执行授权分别验证，编译器不证明这些事实。
- 使用确定性排序、固定适配器修订、64 KiB 上限、不可变 JSON/摘要及严格恢复读取。重复应用、重复权限、禁止包限制、未知字段/修订、改变管理应用等拒绝。
- 本轮不调用远端、不启用 Google CN、不改变 ENFORCE 门槛。独占远端资源、完整发布接入、执行器与恢复界面继续列为待实现工作。
