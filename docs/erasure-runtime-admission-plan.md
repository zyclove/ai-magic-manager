# 1.0.0 运行期工作许可与删除接受屏障

承接主体删除契约与已验收恢复作业。目标是让已运行实例的 HTTP、定时任务和异步事件，在接受删除之前停止接纳新工作并排空在途工作；不是仅靠定时轮询观察账本。正式删除提交及域处理器仍待完成，不能据本阶段开放删除按钮。

## 设计与边界

1. 独立账本的新库初始化增加工作许可及暂停意向表。登记、暂停、接受和释放均使用同一账本头行的短事务；业务操作期间不长期占用账本连接或数据库锁。
2. 许可只保存随机许可 ID、随机进程实例 ID 和开始时间。许可没有自动到期；进程崩溃或释放失败留下的许可继续阻止接受，不能把超时当作工作已停止。恢复和安全回收需另行证明实例已被隔离，当前不提供强制清空入口。
3. `append` 遇到在途工作时先持久化不可变暂停意向，然后返回明确的未接受错误。新工作此后拒绝；原许可可以退出；同一请求重试在许可归零后才写入接受记录。不同请求不得替换已暂停意向。暂停意向不是已接受删除，也不是删除完成。
4. 按当前尚无已应用水位的阶段规则，任何非空账本继续保持全局维护状态。目标级隔离和其他租户继续服务的最终体验仍需后续域处理器/完成判定；本阶段不得声称已完成该体验。
5. HTTP 使用 Servlet 过滤器统一登记并在同步响应处理结束后释放；禁止该链路启动 Servlet 异步响应。已提交响应无法改写时只记录固定故障码。健康探针不属于业务许可，存活与就绪分开；就绪反映账本未配置、失联、暂停和待恢复。
6. 沿用 Spring AOP 的程序化 Advisor，覆盖应用内 Scheduled、Async 和事件监听入口，不引入 AspectJ。同一线程嵌套操作复用许可；异步线程独立登记。定时工作在许可拒绝时不执行；异步/事务事件拒绝要保留失败语义，不能标为已完成。
7. 未配置账本的源码开发环境保持明确的无保护模式；标准 Compose/Helm 已强制账本，不能用源码开发默认值代替正式部署保护。
8. 所有新增结构直接纳入 1.0.0 的全新独立账本初始化。部署权限只允许删除许可行及未接受的暂停意向，接受记录仍不可修改或删除；不对现有 18099 账本做原地迁移。

## 验收

- [x] 许可/暂停/排空/接受的失败用例与短事务实现；双实例、并发、异常释放、旧实例残留、不变范围、身份损坏。
- [x] HTTP、健康探针、同步嵌套、真实异步及定时入口接线与失败覆盖。
- [x] H2、独立 MySQL、真实 HTTP、部署权限、全后端回归、一次最终复核及证据。

Ruling：短事务持久许可取代“在整个 HTTP 请求期间持有独立库锁” — 连接中断不能自动抹掉在途工作，接受必须等明确退出；代价是异常残留需要后续安全恢复流程，不能按时钟自动放行。

Ruling：本阶段的全局维护延续既有启动保护，不把它包装成最终目标级隔离。正式删除仍关闭，后续必须补齐目标级隔离、域处理、外部回执、完成水位、实例安全回收和真实恢复演练。

Ruling：未来正式提交与进度查询必须通过单独鉴权的控制面，不得在普通工作作用域内等待自身许可释放；本阶段没有新增绕过普通业务许可的删除控制面入口。

Ruling：取消、超时及异常完成的 Future 无法证明生产该结果的实际工作停止。遇到这些情况时保留持久许可并清理本线程作用域，后续工作重新登记；不能把 Future 已结束当作排空证明。最终复核发现异常完成分支仍会释放许可，新增真实生产线程闩锁、持久账本与 Spring 异步代理用例先复现，再统一保留许可。代价是即使生产线程后来正常结束，也需单独的安全恢复证明才能回收残留许可。

## 最终复核与回归记录

一次独立复核核对了 21 份冻结源文件及其 SHA-256，报告 1 项 P1：异常完成 Future 会提前释放许可。针对性回归先出现 6 项中 1 项断言失败，修复后许可、作用域、过滤器及代理共 28 项中 27 项通过，1 项 MySQL 条件用例跳过。真实 MySQL 再覆盖许可与代理 16 项、独立 HTTP 4 项，均通过并清理临时库与账号。

首轮完整回归为 617 项，出现 2 个断言失败、2 个错误、8 项条件跳过。三个失败来自旧测试向新增代理的字段直接赋值，未传递到监听器目标实例；改用方法设置故障或闩锁后恢复实际回滚/并发断言。另一个错误来自签名夹具的 Nimbus 校验器使用系统时钟，而域校验器使用固定时钟；将测试中的两个校验器设为同一固定时钟，产品验签与有效期规则未放宽。相关 31 项已通过。这三份测试夹具修正不在原 21 文件独立复核范围内，由最终回归覆盖。

一次合并 MySQL 测试组曾复用已初始化的临时账本，运行期启动夹具被 `ERASURE_LEDGER_NOT_EMPTY` 正确拒绝。后续将 HTTP 组置于单独新建的临时库通过；没有放宽初始化保护，也没有以清空现有账本解决问题。

部署权限静态验证 11 项、管理端维护提示与原操作重试 4 项通过。前端覆盖的是 API 客户端行为，不计作整页浏览器验收。HTTP 的真实 Servlet/MySQL 链路使用测试身份解码器，不计作真实 OIDC/MFA 验收。

最终完整后端回归 618 项：610 项通过、8 项条件跳过、0 失败/错误，Maven 汇总与 66 份测试报告一致。跳过项包括独立 MySQL 条件用例与 Android 子进程提交用例；本阶段 MySQL 许可、代理和真实 HTTP 的独立验证另列，不能把其他未执行的平台条件用例计作通过。各次测试存在重复覆盖，不累加为独立用例总数。

本轮仅交付 1.0.0 全新初始化源码，未更新现有 18099 服务或其独立账本。现有六服务健康及入口 HTTP 200 已只读确认。最终回归结果、源码与日志摘要统一记录于[本阶段发布证据](releases/stage-erasure-admission-verification.json)；正式删除、目标级隔离、安全回收与恢复演练仍未完成。
