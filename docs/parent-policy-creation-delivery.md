# 手机策略新建、模板复制与创建恢复

日期：2026-10-13。本阶段接续[草稿编辑](parent-policy-editor-delivery.md)，使用现有 Flutter Material、UUID、HTTP、安全存储及服务端幂等框架，无新增依赖或数据库表。

## 操作流程

1. 成人在策略中心点击“新建 / 恢复”，先读取当前租户、当前操作者的本机恢复记录。
2. 无待核对记录时，可以创建空策略或可复用模板。填写名称并提交后，显示创建确认和当前草稿，再点击“打开草稿”进入编辑。空草稿没有限制规则，不改变设备设置。
3. 模板详情新增“从模板创建策略”。携带模板原修订 `If-Match` 创建独立副本，副本与模板后续修改互不联动。模板本身不能直接预览或发布。
4. 有待核对创建时，先显示原名称、来源及请求编号，阻止再次创建。查询确认后打开当前草稿；查不到结果时引导核对策略列表和管理台审计，明确确认后只清除本机提醒。
5. 原模板修订冲突后，应返回刷新模板再重新复制，不自动将用户原确认转移到新修订。保存规则、选设备预览、近期认证和配置发布继续是单独步骤。

## 客户端实现

- `PolicyCreationController` 管理创建与恢复状态，`PolicyCreationStore` 保存每个本地租户/操作者最多一条待核对记录，页面只负责表单和确认交互。
- 发送前持久化随机请求编号、原名称、类型、模板编号/修订（如有）及时间。名称用于匹配原始请求；不存令牌、儿童信息列表、应用清单或规则正文。存储沿用加密及 Android 原生落盘确认。
- 落盘失败停止发送；即使存储可能部分写入，也不覆盖旧记录，要求重新读取。请求/响应失败保留记录，客户端不自动重放创建。
- 恢复成功重新读取当前草稿，名称及修订可能已经变化；不把幂等日志里的旧快照当作当前状态。已确认结果仍保留本机记录，直到成人选择打开草稿；记录删除失败可重查重试。
- 获取令牌之后、发送之前再次检查账号、租户、角色及页面有效性。账号或作用域改变后关闭页面，旧异步响应不更新新工作空间。
- 此机制防止同一安装内未决创建的误重复，不提供不同设备之间的草稿名称唯一性。恢复元数据在退出登录后仍按原操作者隔离保存，直至该操作者核对清除；其他账号不能通过界面加载它。

## API 契约

既有创建接口保持不变：

- `POST /api/v1/tenants/{tenant}/policies`：`Idempotency-Key`，正文 `name/kind/rules`；手机首次创建只提交空规则。
- `POST /api/v1/tenants/{tenant}/policies/{template}/copies`：`Idempotency-Key`、原模板 `If-Match`，正文 `name`。

新增只读恢复查询：

```http
POST /api/v1/tenants/{tenant}/policy-draft-creation-results/{requestId}/query
Authorization: Bearer <管理员令牌>
Content-Type: application/json

{"operation":"EMPTY_DRAFT","name":"工作日学习","kind":"POLICY"}
```

复制查询正文为：

```json
{
  "operation": "TEMPLATE_COPY",
  "name": "一年级工作日学习",
  "kind": "POLICY",
  "templateId": "原模板 UUID",
  "templateRevision": 4
}
```

查询使用 POST 正文，避免名称进入 URL 和普通访问日志。成功返回 `200 PolicyDraft`、`Cache-Control: no-store`；不产生草稿、版本、下发事件，也不续期幂等记录。适用当前 OWNER/GUARDIAN/ORG_ADMIN；必须仍具有租户内写权限。

| 检查 | 行为 |
|---|---|
| 请求编号 | 必须小写 UUID；绑定当前租户、当前操作者及原操作类型 |
| 原参数 | 原名称、类型、模板编号/修订必须匹配幂等记录指纹；不符返回 409 |
| 形状 | EMPTY_DRAFT 不接受模板字段；TEMPLATE_COPY 必须 POLICY 且有模板编号及非负修订；混用返回 400 |
| 当前权限 | 原创建人已失去写权限则拒绝；其他监护人即使知道请求编号，也不能查询原操作者记录 |
| 日志可用 | 重放有效期结束后仍可读取已保存的引用；记录被清理或不存在返回 404 `POLICY_CREATION_RESULT_UNAVAILABLE`，不能推定从未创建 |
| 当前资源 | 从匹配日志取资源编号后，按租户重读当前草稿并校验类型；不重放原创建动作 |

恢复查询目前专门支持手机空草稿创建和模板复制。若其他客户端原创建包含非空规则，不能使用 EMPTY_DRAFT 参数恢复该请求，指纹核对会拒绝；应按该客户端的原有恢复契约处理。

## 验证与后续门槛

- 后端独立目录 `PolicyJourneyTest`：25 项通过，包含新增空草稿/模板副本恢复、原参数不符、当前权限变化、幂等重放到期、模板后续更新、错误参数不创建数据。
- 手机 `policy_creation_test.dart`：11 项通过（9 项流程状态验证、2 项页面操作）；与已有草稿编辑 7 项合计 18 项通过。覆盖落盘前不发送、落盘失败、未知响应跨实例恢复、模板原修订、404 不自动清除、返回形状/权限错误、令牌等待中切换作用域、清理失败及操作者隔离。
- Flutter 静态分析与 Android 调试 APK 构建通过；构建使用示例 HTTPS 地址，不是已连接生产身份服务的交付包。
- 测试使用模拟客户端接口和后端 H2 MySQL 模式；这不是实际 Android IdP/HTTPS 的联调证明，也不替代 MySQL/OceanBase 验证。
- 尚需实际 Android 进程回收/安全存储故障演练、字体缩放和低网速交互验收。当前不存在合规 EMM 提供方，所有配置创建、复制和恢复均不能表示设备系统限制已执行。

首发商业定位保持“中国大陆、机构合同优先”。本阶段不开放应用内购买或让普通管理员自行增加合同权益。
