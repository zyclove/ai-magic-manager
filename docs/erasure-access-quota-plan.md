## Task 1: 审批、临时授权与配额关联图

- [x] 先编写失败用例，再实现 17 个存储的真实删除：7 个 access、8 个 quota 及 2 个关联 notification 存储。
- [x] 先扫描配额事件，验证事件类型、JSON 标识与实际主体归属；之后按叶子到根顺序每批最多删除 25 行。事件扫描每批最多 25 行。检查点与删除同事务提交。
- [x] 每批验证接受范围中的租户、主体、设备注册代际；历史请求/租约/槽位缺失注册、跨主体配额关联、孤立或未知配额事件均阻断，不能默默跳过。
- [x] 完成步骤后重新检查相关数据及孤立事件，保持恢复作业 CLAIMED、全局维护状态；步骤完成不表示整个主体已删除。
- [x] H2、独立 MySQL、初始化与模块边界、已有处理器回归、完整后端回归及一次最终复核。

接口：`ErasureAccessQuotaProcessor.process(Claim, limit)` 返回阶段、本批删除行数、累计行数与批次数。复用 `ErasureRecoveryJobs.applyBatch`；新增步骤 ACCESS_QUOTA，先 EVENTS，再通过 VERIFY 有界复核进入 DATA。DONE 后调用进入 RECHECK，分页未全部检查时不返回完成。首版初始化允许这些阶段的游标。观测处理器的 OBSERVATION_REPORTS 步骤不变。

Pre-flight：共同接口为恢复作业事务与步骤表。新增 EVENTS 阶段必须保持已有 REPORTS/DATA/DONE 及其约束有效；两处理器的步骤键不同，不能覆盖对方检查点。

Ruling：配额事件先验证并清理，再删除其父记录。事件缺少外键且包含副本，父记录先删除会丢失归属依据；未知类型或无法解析的归属阻断本步，代价是损坏的同租户事件需要人工修复后才能继续。

Ruling：不做配额余额结算或发放补偿。删除的是被接受主体的全部配额记录，其他主体的池、租约或计划如被交叉关联则拒绝处理；代价是损坏的共享关联不能自动猜测修复。

Ruling：在已有接受屏障下运行内部处理器；公开受理、其他域、通用幂等与通知副本、审计保留和完整恢复演练仍需继续实现。本阶段不能开放完成按钮。

## 验证与复核重点

测试需证明：17 个存储完整覆盖、共享策略及他主体/租户保留、旧注册与新注册分离、未接受历史注册阻断、跨主体关联阻断、事件类型/JSON/父标识校验、实际物理删除批次上限、回滚、可恢复、并发、过期租约、版本与计数异常、DONE 后数据再现阻断。

Review Focus：检查无外键引用的归属，事件删除后还能否判断剩余数据，外键删除顺序、跨租户 SQL 条件、检查点重入、DATA/DONE 重查及是否错误宣布全局完成。当前阶段不提供其他域或公开流程完成证明。

## 最终复核修复

一次独立只读复核发现 2 个 P2，已用 5 个失败用例复现并在同一修复轮处理：

- 请求删除会级联通知及阅读记录，突破物理行数上限且漏计。现改为显式清理通知叶子，验证通知的主体/设备与请求一致，并将每行计入上限。另验证同一管理员读取的其他主体通知仍保留。
- DATA/DONE 原先仅检查配额聚合列，无法发现重新出现的 JSON 目标引用。现每轮数据删除前有界复核保留事件的完整载荷，DONE 重入也执行分页 RECHECK。所有页完成前不会返回 DONE。

Ruling：DONE 的重复检查可以暂时返回 RECHECK；累计删除行数不变，实际复核批次会增加。代价是保留事件较多时需要更多调用；后续工作调度必须持续处理 VERIFY/RECHECK，不能把一次未返回完成当成失败。当前沿用已排空的全局接受屏障，不支持绕过屏障的并发直写数据库；生产规模吞吐还需验证。

复核明确未认证其他域、公开受理与前端确认、全局完成水位/目标级隔离、通用幂等和其他消息副本、审计保留政策、真实旧备份恢复、已部署库升级及生产规模性能。本阶段继续保持这些范围未完成；首版初始化无需旧开发库迁移。原复核快照保留，修复后以失败复现、H2/MySQL 及完整回归证据验收，不重复发起复核。
