# 商业产品目录与发布控制

## 1. 术语与边界

| 名词 | 含义 | 不代表 |
|---|---|---|
| 产品定义 | 有版本的功能集合、基础/加购容量和适用客户类型 | 可在任何地区售卖 |
| 报价项（Offer） | 特定地区、渠道、币种、周期、设备模式与生效期的成人/采购方报价 | 已通过渠道支付或设备兼容认证 |
| 发布证据 | 法务/地区、渠道、定价、设备模式与支持能力的独立批准记录 | 客户已购买 |
| 来源事实 | 支付/合同/私有许可渠道核验后写入的版本化事实 | 设备已有系统控制权限 |
| 有效权益 | V28 账本按来源有效期、撤销和合并规则计算的租户资格 | Android/TV 已执行限制 |

产品目录与[商业权益账本](commercial-entitlement-ledger.md)分别管理。目录是售前可售性与价格证据；权益账本是已核验交易事实；设备能力由注册模式、平台授权、认证适配器和回执独立证明。儿童端不展示价格、广告或购买催促。

## 2. 报价项模型

单元键为 `SKU × SKU 版本 × 区域 × 渠道 × 客户类型 × 平台 × 设备模式 × 计费周期`。固定价记录币种 ISO 4217、整数最小货币单位金额及含税/未税口径；需人工报价的合同项只记录币种与“报价待确认”，金额为空。报价项还须记录生效/到期时间、基础或加购容量、功能键、兼容认证引用/到期、渠道准入引用/到期、法务地区批准引用/到期、支持能力引用/到期及操作者。没有审批证据的字段不得用布尔值自行宣称“已认证”。

目录只保存报价草稿，不存支付密钥、原始合同、儿童使用明细或支付令牌。报价项修订使用单调版本及不可变事件；并发更新须提供预期版本，同一版本的不同内容冲突。价格或适用范围变化须生成新版本，不能静默覆盖已展示报价；下架保留历史以便退款和客户争议核查。兼容认证、渠道准入、地区法务和交付证据字段属于后续发布阶段，**当前草稿即使通过人工审批也没有发布证据**。

## 3. 发布与购买门槛

1. 平台产品运营创建草稿并提交审核。平台财务/法务审批人不得与创建人相同；审批和发布要求由 IdP 提供近期多因素认证，全部动作写审计。
2. 发布服务逐项核验地区经营资格、渠道准入、价格/税费、设备模式兼容认证、支持交付能力及有效期。至少一项缺失或过期即拒绝发布，返回可解释原因。
3. 渠道支付/合同核验适配器未正式接入时，即使报价项获批准也只能显示为“暂不可购买”，不得发起结算或写入商业权益。用户不能上传截图或客户端回调自行开通。
4. 发布后若认证或渠道资格撤销，立即停止新销售、标记受影响报价和通知成人/采购方；已购客户由独立存量处置流程处理，不篡改历史事实或静默解除儿童安全措施。
5. 任何报价项都不能将 BYOD 的有限能力描述为防卸载、不可强制停止或系统级跨应用限制。购买资格和技术能力在页面及接口分别展示。

## 4. 平台角色与 API 契约

平台产品运营、审批人与租户监护/机构管理员分别授权。租户角色不能修改全球目录；平台运营默认不能读取儿童活动或设备密钥。管理接口使用独立 `catalog:manage` 与 `catalog:approve` OIDC scope，审批人必须与创建人不同；正式生产还需接入平台员工身份治理、离职撤权与审批留痕。

当前已实现的平台人员接口（均以 `/api/v1` 开始，要求 Bearer JWT）：

- `POST /api/v1/platform/catalog/offers`：`{id,offer}`，`id` 为客户端生成的小写规范 UUID；同一操作者、同一 ID 与相同规范报价内容重放返回 `200`，首次创建返回 `201`，不同内容或单元键冲突返回 `409`。`offer` 由服务端验证 SKU、地区、渠道、平台/设备模式、币种/整数金额、税费、容量、功能和有效期；事件记录创建者。
- `PUT /api/v1/platform/catalog/offers/{id}`：只允许 `DRAFT` 修订；请求体为完整 `offer`，强 `If-Match: "版本"`，成功返回新 ETag；缺失、格式错、版本过期分别是 `428`、`400`、`412`。
- `POST /api/v1/platform/catalog/offers/{id}/submit`：`DRAFT → IN_REVIEW`，需 `catalog:manage`、强 ETag 和 `{reason}`（5–500 字符）；原因留在不可变事件中。
- `POST /api/v1/platform/catalog/offers/{id}/approve`：`IN_REVIEW → APPROVED`，需独立 `catalog:approve`、近期 MFA、与任一草稿作者/修订者/提交者不同的身份、强 ETag 和 `{reason}`。`APPROVED` 仍然不可购买。
- `POST /api/v1/platform/catalog/offers/{id}/retire`：进入 `RETIRED`，需 `catalog:manage`、近期 MFA、强 ETag 和 `{reason}`；重复下架在同版本下幂等。
- `GET /api/v1/platform/catalog/offers` 与 `/{id}`：平台操作/审批人员查看当前草稿；列表 `limit=1..100`、UUID `cursor`。
- `GET /api/v1/platform/catalog/offers/{id}/history`：同样的平台只读权限；按修订倒序，`limit=1..100` 与 `beforeRevision` 翻页，返回版本、动作、操作主体、原因、关联 ID、当时的报价快照、内容摘要和时间。

报价项响应均含 `purchaseAvailable=false`，全部响应设置 `Cache-Control: no-store`。运营和审批 scope 只由可信身份提供者发行；租户监护人、儿童、教师不得访问这些平台接口。**尚未实现 `/publish`、租户可售报价、订单/支付、合同核验或任何创建权益的公网接口**。需要待售能力时由新阶段独立设计，不以已审批状态暗示已销售。

API 返回价格时同时返回币种、计费周期、税费口径、地区、生效期与目录版本。客户端不得自行把报价换算为权益；下单前服务端重新查询目录、渠道和兼容证据。无已发布且合规的报价时返回空列表及明确的未开放状态，不填充虚构价。

## 5. 首期实施与验证

首发经营范围定为**中国大陆、机构合同优先**。新草稿预填 `CN`、`CNY`、`CONTRACT` 和 `ORGANIZATION`，价格类型预填“人工报价”；这些只是减少录入步骤的运营默认值，不构成地区合规、合同签署、收款或交付资格。机构合同须由经批准的合同核验流程产生权益事实，当前仍无已接入的外部签发方、合同审批及开通流程，因此目录始终不可购买、不可直接开通权益。家庭直销、应用商店内购和其他地区需分别完成渠道、税务、隐私、设备能力及售后证据后再设计发布。

机构合同证据的可替换验签基础与后续审批/开通链路见[机构合同证据连接器](institution-contract-evidence.md)。目前仅完成默认关闭的验签基础，尚无合同提交与权益开通接口。

当前代码已交付报价项当前表及不可变版本事件、平台人员草稿、修订、提交、独立审批、下架和历史读取。默认没有可购买商品。真实支付、合同验签、订单/退款对账和客户自助购买仍须官方渠道或合格合作方及沙箱证据后接入。项目尚未发布，1.0.0 采用全新数据库初始化基线，不把开发阶段 V28–V30 的逐版迁移作为客户安装或升级承诺。开发阶段目录 HTTP 旅程曾在 H2 MySQL 模式和独立 MySQL 8.4 临时库各通过 5 项，覆盖角色拒绝、重放、版本冲突、独立 MFA 审批、历史分页和下架；这些结果不能替代 1.0.0 新基线的最终回归。跨租户可售目录、过期证据、并发审批、OceanBase 兼容与真实合同渠道属于后续发布门槛。

## 6. 平台运营界面交付规格

平台人员使用独立的运营入口，不依赖加入某个家庭/机构租户。入口从受保护的 `/api/v1/me` 获取可信 scope；无权限时不显示目录数据，并由服务端再次拒绝。页面采用列表、详情、审核三层：列表展示 SKU、地区/渠道、状态、修订版本、更新时间及“不可购买”标识；详情把设备模式、功能和价格税费放在同一视图，并提供逐版本历史；编辑器按地区和渠道检查币种、周期、容量和适用模式，提交前预览全部变更字段。

创建与修订时使用客户端生成的 UUID 和当前 ETag，网络中断后按原 ID/内容重试；`412` 时刷新当前版本并要求人工比较，禁止自动覆盖。审批人看到完整报价快照、提交者和每次修订；审批按钮进入 IdP 近期 MFA，再回到同一报价版本执行。若版本或权限已变更，页面撤销待执行动作并重新加载。下架须确认影响范围，界面保留历史和明确的不可购买状态。窄屏采用逐项表单和固定底部主操作，宽屏采用列表/详情双栏；键盘焦点、错误定位、加载/空态和屏幕阅读标签随组件一同验收。

平台界面作为目录 API 之后的独立客户端阶段接入；页面通过受保护的 `/api/v1/me` 读取可信 scope，将全球目录入口与租户工作区分离，并在每次写操作由服务端重新鉴权。现有租户商业账户仍只展示经过核验的既有权益；它不从草稿推断可售商品、设备能力或已购买资格。上线前仍需以真实平台身份提供者验证近期 MFA、离职撤权和审核分离。

客户端阶段已实现平台目录导航、无租户入口、草稿表单与变更预览、分页列表、详情、版本历史、审核原因、近期验证回跳及过期版本提示。目录读取做响应大小和结构检查，账号变化后废弃未完成的请求；创建网络结果不明时保留原 UUID 和内容供同一请求重试。客户端不提供发布、支付、合同上传或权益开通。专项 Flutter 目录与访问测试 8 项通过，目录相关 Dart 静态分析无问题，Web release 编译通过；后端 `/me` 与目录旅程共 9 项通过。真实平台账号的浏览器操作、机构合同核验和中国大陆法务证据仍须单独验收，因此当前构建不能据此视为可销售版本。
