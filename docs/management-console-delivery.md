# 管理端交付记录

## 目标与既定设计

依据已有产品规格和用户的完整实施授权，沿用 Spring Boot、MySQL、Keycloak OIDC、Flutter。用户指定的管理员账号仅配置在本地身份服务，密码不进入源码、设计文档或前端包。

管理端采用中文、浅色工作台、深蓝品牌色、可折叠侧栏、宽屏表格与窄屏列表。工作空间隔离贯穿导航、查询和操作；空态提供下一步，失败提供重试与关联编号，敏感操作明确后果并要求现有 MFA。

## 本次实施顺序

1. 配置管理员、OAuth 授权码 + PKCE、会话退出、近期多因素认证。
2. 补齐当前身份、成员和邀请查询、租户资料维护接口，保留数据库授权、ETag 与审计。
3. 创建 Flutter 管理端与共享视觉组件，接入所有已有管理 API：概览、档案、设备注册/详情/退出、应用、时间计划、策略/预览/版本、审批、成员、审计、设置。
4. 完成加载、空态、错误、分页、搜索、表单验证、并发冲突、键盘与响应式交互。
5. 对新增接口执行权限与行为测试，Flutter analyze/test/build，真实浏览器及 MySQL/Keycloak 联调。
6. 独立代码审阅，修复严重问题，记录证据并保持服务运行。

## 能力边界

本次管理端必须忠实呈现现有后台契约。真实 EMM、Android/TV 系统执行、支付渠道、模型供应商、容量/高可用认证仍按完整实施计划逐项推进，不能用演示数据或成功提示替代。不具备执行适配器的配置明确为未执行。
