# 应用与权限完整策略文档

## 当前范围

新增 `GoogleCompletePolicyCompiler`，将已解析的应用控制及逐应用运行时权限合成一份官方 SDK `Policy` 文档。它是纯编译器，没有网络请求、后台任务、公开接口或设备能力授权。

本阶段本地冻结验证已通过 276 项检查。完整发布接入、远端独占资源、发送器和人工恢复界面继续实施；已有窄投影更新方法不会因这个编译器而改变行为。中国大陆 Google 生产禁用规则保持不变，后续机构合作方实现自己的适配器。

## 输入与输出

- 输入：受信服务端取得的 API 等级、DEVICE_OWNER 模式、完整应用控制集合、完整权限集合，以及来自部署/绑定信任配置的管理应用包名。来自儿童端的字符串不能证明任何系统权限。
- 输出：固定 `schemaVersion=1`、`adapterRevision=google-complete-policy-v1` 的规范化 JSON 和 SHA-256；与执行账本的文档格式一致。
- 编译结果不保留调用方集合；每次请求 SDK 对象都重新生成副本，修改其中一个对象不会改变已保存的文档或下一次请求。
- 规则按应用包名、权限名称排序，相同含义及不同输入顺序生成相同字节。摘要用于内容一致性；本身不证明授权、签名或远端资源归属。

| 控制输入 | 文档语义 |
| --- | --- |
| ALLOW | AVAILABLE，disabled=false |
| BLOCK_LAUNCH | AVAILABLE，disabled=true |
| BLOCK_INSTALL | BLOCKED，disabled=false；可能卸载已有应用，发布前必须明确告知 |
| 权限 DENY | 对应 permissionGrants 条目 DENY |
| 权限 PROMPT | 对应 permissionGrants 条目 PROMPT，不自动授予 |
| 管理应用 | FORCE_INSTALLED，USER_CONTROL_DISALLOWED，保持启用 |

管理应用使用固定 PROMPT 基线；不能通过业务规则改变其权限或禁用它。未列出的普通应用不因这份 BLACKLIST 文档被整体移除。此版本没有应用白名单、Kiosk、清屏、擦除或位置采集等隐含动作。

## 保护与兼容

- 此文档版本最低 API 30（Android 11），并要求 DEVICE_OWNER；其他模式或低版本直接拒绝，不偷偷移除管理应用保护。
- `FORCE_INSTALLED` 方案要求管理应用可通过相应受管分发渠道取得，并满足发布签名、包名与当前绑定校验。编译成功不证明分发或防绕过能力；启用前必须实测实际设备回执。
- 复用系统安全包和配置的恢复应用清单，禁止这些应用被阻止或拒绝权限。
- 应用/权限重复、无效包名、非运行时权限、含权限规则的 BLOCK_INSTALL 组合均拒绝，不猜测管理员的真实意图。
- 管理应用计入 200 个应用的总上限，每应用最多 64 个权限条目，最终文档最多 64 KiB。超限返回可解释的编译错误，不能截断或仅发送一部分。
- 开启 `applicationReportsEnabled` 以支持已有绑定反馈和应用事实读取。报告可能包含应用清单，必须纳入机构设备告知、访问限制与数据保留设置；没有开启摄像头或页面内容采集。
- 发布编排器还须检查所有源规则均被正确处理。时段、额度、网站、特殊权限等不能因本编译器不接收这些输入而被静默丢弃；未支持时应阻止该执行发布。

## 持久恢复

恢复时需要保存的摘要、当前管理应用配置及可信设备模式/API 等级。读取首先限制长度并校验摘要，严格拒绝重复 JSON 键、尾随数据、错误类型和未知字段/修订。

固定的原可信摘要用于发现内容变化；重新编译检查支持的字段语义、报告配置和固定管理应用基线。管理应用缺失/替换、自动授予等不受支持的设置会被拒绝，但编译器不能凭一个随内容更新的新摘要推断管理员原意。原始请求一致性仍由不可变发布和执行账本保护。旧文档不能通过新的配置被悄悄重解释；若修订不兼容，执行器应进入可诊断的拒绝/待核对流程。

恢复成功依然不代表可以发送。执行器还须重新验证租户授权、合同、当前注册和绑定、应用身份及用户空间、策略来源、远端独占资源，并遵守账本的写前记录和租约限制。
