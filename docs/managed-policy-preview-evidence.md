# 逐设备应用核验与策略预览

## 本阶段范围

把已保存的受管应用核验结果接入策略预览和发布前复核。同一应用在不同设备、不同注册下独立展示，应用目录仍只表示管理员声明。当前实现不开放 `ENFORCE`，`profileScope` 仍为 `UNKNOWN`，`systemControlAvailable` 仍为 `false`。

本阶段不调用提供方网络、不迁移数据库、不修改系统设备能力。现有刷新入口负责获取报告；预览只读取、重新验证当前本地记录。Android 验证按用户安排延后。

## 用户流程（前端对接目标）

1. 管理员选择规则与设备，点击“查看影响”。默认仍是一次预览操作。
2. 每台设备独立显示应用核验状态和当前规则限制；同一应用在设备 A 核验通过，不改变设备 B 的结果。
3. 尚未绑定、报告缺失或结果过期时，提供明确下一步。复杂原因放入可展开详情，不要求用户理解提供方资源名。
4. 身份已核验时显示报告时间和有效期，同时说明系统控制条件仍未满足。不得显示“已应用”“已管控”。
5. 确认保存时服务端重新读取当前事实。可读取的核验记录、绑定、注册或相关资格已变化，返回 `PREVIEW_STALE`，要求重新查看影响。权限已撤销时直接拒绝访问，可能返回 403。

| 状态 | 推荐文案 | 下一步 |
| --- | --- | --- |
| `UNAVAILABLE` / `MANAGED_BINDING_REQUIRED` | 此设备尚未完成受管绑定 | 完成设备绑定 |
| `UNAVAILABLE` / `MANAGED_APPLICATION_ADMIN_REQUIRED` | 需要机构管理员核验 | 联系机构管理员 |
| `ABSENT` | 尚未核验此设备上的应用 | 进入该设备的应用核验 |
| `PENDING` | 正在核验 | 稍后重新查看 |
| `WAITING_REPORT` | 等待设备报告 | 根据刷新冷却时间重试 |
| `VERIFIED_IDENTITY` | 应用身份已核验 | 查看时间；继续说明系统控制尚不可用 |
| `STALE` | 核验结果已过期或设备信息已变化 | 重新核验并预览 |
| `REJECTED` | 应用信息未通过核验 | 查看具体原因 |
| `FAILED` | 暂时无法读取报告 | 到达允许时间后重试 |

未知原因应使用中性文案和诊断码，不推断为可执行。按钮是否可用仍须由当前角色、绑定状态和刷新接口决定；预览 DTO 本身不授权刷新。

## 接口契约

沿用 `POST /api/v1/tenants/{tenantId}/policies/{policyId}/previews`。请求仍使用草稿 `If-Match`、`deviceIds` 和可选分组信息。

新增 `targets[].applicationEvidence`，同一内容也进入 `snapshot.targets[].applicationEvidence`。设备按 ID 排序，应用按应用目录 ID 排序。没有应用规则时返回空数组。时间为 UTC Unix 毫秒。

| 字段 | 类型 / 空值 | 含义 |
| --- | --- | --- |
| `deviceId` / `registrationId` | string | 此次快照的精确设备及当前注册 |
| `applicationId` | string | 租户应用目录 ID |
| `bindingId` | string / null | 已验证上下文的本地绑定 ID；不可用时允许为空 |
| `bindingVersion` | integer | 绑定版本；缺失为 0，不作为可写入的版本凭证 |
| `definitionRevision` | string / null | 当前应用声明的修订摘要；无法验证时为空 |
| `evidenceVersion` | integer | 本地应用核验记录版本；缺失为 0 |
| `state` / `reasonCode` | string | 固定状态及可解释原因 |
| `profileScope` | string | 本阶段恒为 `UNKNOWN` |
| `systemControlAvailable` | boolean | 本阶段恒为 `false` |
| `reportedAt` / `retrievedAt` / `expiresAt` | integer / null | 仅当前有效的身份记录返回时间；不可用或陈旧时为空 |

新增事实 DTO 不包含凭证、原始签名报告、提供方资源、注册密钥或内部上下文摘要。原有 `snapshot.applications` 仍包含管理员声明的签名摘要；不能误称整个快照从不包含签名摘要。

证据状态与 `rules[].status`、`rules[].effectiveEffect` 分开解释。规则仍优先遵守能力不支持、自动授权不支持、平台不符、profile 不明等限制。即使提供方报告能证明应用身份，也不能据此把 `effectiveEffect` 设置为已生效。

发布接口保持原状。事实加入不可变快照与哈希；发布重新计算后不一致即返回 409 `PREVIEW_STALE`。预览有效期不超过其中有效身份记录的最早到期时间。重新刷新即使再次核验通过，也会改变记录版本，要求重新预览。重复成功发布仍遵守原有幂等契约。

## 领域边界与事务

`ManagedPolicyEvidenceAccess` 是 managedandroid 提供的公开读取边界。policy 通过该接口取得批量设备快照和最小应用事实，不访问 managedandroid 内部表。`ManagedApplicationEvidenceStore` 复用已有验证器，不另造第二套身份判断。

预览与发布外层事务明确使用 `READ_COMMITTED`。读取边界要求已有该隔离级别的事务；内层注解不能替代外层配置。

批量读取顺序：成员授权 → 机构绑定 → 全部学生（排序）→ 全部设备（排序）→ 合同容量 → 当前绑定 → 应用记录。前置读取只用于确定锁定对象，设备锁取得后再次核对学生和注册。每台设备只验证一次绑定，每个应用声明只解析一次，每个绑定最多读取 201 行用于检测超过 200 的异常数据。

应用缺少可信签名、目录元数据不可用、绑定尚未验证、合同失效、连接器不可用等明确情况可以成为 `UNAVAILABLE`。四个纯验证方法允许其领域异常由调用者处理，避免正常不可用情况把外层预览事务标成只能回滚。固定原因白名单不包含权限拒绝；越权、非预期领域异常和数据库故障仍向外抛出并回滚。

预览不进行提供方 HTTP，也不延长应用证据有效期。绑定已持锁，因此遵守同一绑定锁的刷新完成和撤销不能在读取中途改变应用事实。H2 检查不代替 MySQL/OceanBase 的隔离及锁语义实测；设备组联表锁与本次批量锁的并发关系仍需实库验收。
