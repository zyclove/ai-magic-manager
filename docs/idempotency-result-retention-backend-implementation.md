## 阶段状态

## 已接合的行为

| 场景 | 后端行为 | 管理端含义 |
| --- | --- | --- |
| 同一原请求在既有 24 小时内重放 | 沿用请求摘要、授权及原键约束；读取载荷前核对可信时间 | 不重复执行业务 |
| 成功结果在固定 90 天内恢复 | 在当前授权事务中读取历史结果，再映射当前可见信息 | 历史结果与当前状态分别处理 |
| 首次确认结果到期 | 当前最外层事务提交到期事实后，HTTP 层返回 410 / `IDEMPOTENCY_RESULT_EXPIRED` | 原结果已不可恢复；不能推断业务未提交 |
| 已记录到期或已物理清理 | 保持不可恢复；不依赖新的墙钟判断重新开放 | 核对当前记录，不能自动换键重试 |
| 主体已擦除 | 在请求内容比较和到期检查前返回 410 / `IDEMPOTENCY_RESPONSE_ERASED` | 保持永久拒绝，不恢复个人响应 |
| 时间无法确认 | 503 / `IDEMPOTENCY_CLOCK_UNTRUSTED`，当前事务回滚 | 稍后核对；不能解释为原操作未发生 |
| 维护关闭或积压 | 逻辑截止仍有效；未清理不代表可继续恢复 | 逻辑到期与物理清理分别展示 |

恢复接合覆盖 23 个底层查询调用、21 个领域恢复方法、设备侧两层事务，以及 17 个控制器中的 21 个 HTTP 适配点。成功响应结构、既有 ETag、缓存响应头、授权检查及原有缺失错误保持原路径。

## 事务与防重复执行

通用恢复服务返回 `IdempotencyLookupOutcome<T>`，区分找到、缺失和到期。领域服务用 `requirePresent` 保持原缺失错误，用 `map` 只映射找到的结果；到期状态不执行映射。

到期不能在仍有外层事务时抛出异常，否则到期事实会被回滚。控制器在最外层服务代理返回后调用 `toHttpResult()`；该适配器会拒绝在仍有活动事务或事务同步上下文中转换。设备恢复的外层事务也传播同一类型。

父记录及唯一防重摘要不删除，普通期限清理保留 `request_hash` 和必要主体归属。物理清理不会把 `UNCLASSIFIED` 改成非主体数据；未分类记录仍阻止声明完整主体擦除。主体擦除继续使用既有永久拒绝语义。

## 时间依据及持久元数据

结果在业务处理、归属保存和响应序列化完成后，通过同一写事务连接取得主库时间，保存 `result_committed_at` 和固定 90 × 24 小时后的 `result_expires_at`。它们仅在业务事务成功提交后有效，不使用提前取得的请求、预览或占位时间，也不以恢复访问续期。这里记录业务事务内的结果提交时间，不声称获得数据库物理提交瞬间的时间戳。

`IdempotencyResultTime` 复用 Spring JDBC、注入的 `Clock` 和当前事务。它读取 `CURRENT_TIMESTAMP(3)`，检查查询前后的节点时间有无回拨，并交叉检查数据库与节点时间的偏差。默认最大偏差 5 秒，配置范围 1～300 秒，没有停用校验或退回单机时间的生产开关。

每条成功结果还保存 `result_last_observed_at`：初始值等于结果提交时间，成功恢复、首次到期和物理清理均在同一事务推进。数据库时间早于最后可信观察时拒绝处理，使检测不只限于“早于创建时间”。父行锁串行化观察值更新，最后观察时间不会改变固定截止时间。

| 元数据 | 用途 |
| --- | --- |
| `result_storage_state` | 区分保留载荷与已物理清理 |
| `result_committed_at` | 成功结果的固定时间起点 |
| `result_expires_at` | 该记录不可续期的恢复截止 |
| `result_policy_revision` | 写入时策略修订，后续配置不追改旧记录 |
| `result_last_observed_at` | 跨节点及重启后的记录级可信观察下界 |
| `result_expired_at` | 已提交的逻辑到期事实，值固定为恢复截止 |
| `result_redacted_at` | 实际物理清理时间，后续主体擦除不覆盖先前时间 |

运维仍须保证写库、应用节点及 JDBC 会话使用正确的 UTC 时间配置，并独立监测校时。数据库与节点同时发生一致的错误无法仅由这段应用代码识别。MySQL 主库时间、事务连接、时区及故障切换行为仍待实际验证；OceanBase 兼容性也须单独认证。

## 有界维护与配置

维护复用同步 `@Scheduled`、既有擦除 WorkPermit、Spring 事务及 Micrometer。调度入口调用独立事务服务；每批事务超时 10 秒，发现候选后按固定复合键顺序锁父记录，再锁归属，锁后重新核对状态和时间。多个副本发现同一记录可安全收敛，不引入新的分布式锁平台。

| 环境配置 | 默认值 | 范围或约束 |
| --- | --- | --- |
| `IDEMPOTENCY_RESULT_RETENTION_DAYS` | 90 | 首版只接受已确认的 90 天 |
| `IDEMPOTENCY_RESULT_POLICY_VERSION` | 1 | 正整数，仅用于新结果 |
| `IDEMPOTENCY_MAX_CLOCK_SKEW_SECONDS` | 5 | 1～300 秒；超出偏差拒绝处理 |
| `IDEMPOTENCY_RETENTION_ENABLED` | false | 仅控制物理维护 |
| `IDEMPOTENCY_RETENTION_BATCH_SIZE` | 100 | 1～500 |
| `IDEMPOTENCY_RETENTION_INTERVAL_SECONDS` | 300 | 1～86400 秒 |

维护只记录聚合计数和异常类型，不记录完整响应、原始幂等键或请求内容。失败回滚整批，不留下半个清理结果。必要拒绝标记和主体归属仍会增长，当前参数不能作为百万设备容量已经达标的证据。
