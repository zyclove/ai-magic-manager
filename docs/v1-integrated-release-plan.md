# 1.0.0 前后端整合发布实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: executing-plans；内联执行，最后一次独立复核。

**Goal:** 备份现有本机环境后，以完整同源快照构建、初始化并运行新版前后端，验证真实管理员登录和响应式操作。

**Architecture:** 沿用已有 Docker Compose 六服务、独立业务/身份/删除账本数据库、Spring Boot 与 Flutter 发布脚本。源码冻结到提交 `db9a720ff17e4cb98be35f93cd2eb964ec103071`；共享未提交工作不进入发布。新环境使用独立回环端口 18101，原 18100 环境保留。

**Tech Stack:** 既有 Java 17/Maven、Flutter/Dart、MySQL、Keycloak、Nginx、Compose、Playwright。

**本阶段修正：** 首次构建发现儿童端旧测试与已接受的自动同步约定不一致。保留产品逻辑，测试等待启动同步结束后再执行独立操作，并检查启动、前台恢复、五分钟定时、后台暂停和销毁行为。四个测试文件作为明确记录摘要的覆盖层进入冻结源码；后续共享分支提交不混入。

**Spec:** `docs/version-1.0.0-initialization.md`、`docs/deployment-runbook.md`、用户已授权备份后更新服务、指定管理员及前后端全部运行。

## Global Constraints

- 全新 1.0.0 数据库；不升级或清空已有开发库，不回退独立账本。
- 备份配置、密钥、发布物及三个数据库，限制文件权限，不输出密码或令牌。备份完成不等于恢复演练完成。
- 同一源码快照运行后端全量验收、客户端 HTTP 联调、全部应用/内部包静态分析及已有测试，然后构建前端发布物；失败时修复根因，不绕过检查。
- 新账本仅显式初始化一次；如存在回执或已初始化内容，复用并核验，不重复建账本。
- 仅给指定管理员配置已有授权角色；近期 MFA 仍要求真实绑定，不伪造认证声明。
- 浏览器验证实际 PKCE 登录、首屏、主要导航/对话框及桌面/手机布局；源代码通过不能替代运行服务及浏览器证据。
- 所有阶段保留未完成的真机、外部服务、完整删除及备份恢复限制，不宣称全部产品完成。

## Review Focus

- 快照来源、客户端/后端产物和 Compose 指向一致，不能将后来 WIP 或其他发布物混入。
- 旧环境备份完整、保密、可定位，明确账本不随业务旧备份回退。
- 新环境空库执行 V1/V2，启动保护和独立账本权限正常，普通重启不得重新初始化。
- 密码/token 不进入日志、截图或提交；浏览器身份、OIDC issuer、API origin 一致。
- 登录、未授权接口拒绝、手机布局和导航真实可用；外部服务及真机缺口明确。
