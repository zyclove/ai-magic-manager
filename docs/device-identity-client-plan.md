# 儿童端设备身份与宿主接入实施记录

2026-10-09。承接完整实施计划 Task 2/7/8，使用 professional-product-engineering、executing-plans 与 TDD 继续现有已授权方案。上一阶段 e4e9edb 已推送，本阶段先完成儿童宿主必须依赖的身份生命周期，再接界面/原生适配；完整目标保持不变。

## 本阶段设计

- `packages/device_identity` 为纯 Dart 协议组件，复用 jose、http、uuid 成熟 SDK，不自己实现密码或网络栈。
- 宿主显式提供已确认的 HTTPS API origin、监护人票据与安全存储。二维码不能自动更改服务地址；票据不是管理员权限。
- 原密钥、认领意图与后续 pending 凭证使用单个安全存储记录原子替换，发送前持久化。SDK 不附带明文文件存储，不提供儿童删除/重置身份的方法。
- 软件 ES256 适配器使用 JOSE，私钥只能写入宿主的加密私有存储；不宣称不可导出硬件密钥。后续 native signer 可替换，不改状态机。
- 认领响应丢失保持不确定状态；使用原密钥、新 proof/jti 恢复，不自动重建注册。恢复更换配对码，原期限不能延长。
- 确认只能由云端管理员完成。未确认设备凭证不会提供给配置拉取；第一次经过验证的实际心跳成功后才记录 ACTIVE。401 保留状态，不能推断已撤销或擅自重置。
- 心跳序号和完整 pending 请求先保存；重复/丢失 ACK 重放相同序号/请求。ACK 必须绑定 registrationId 和 sequence。
- 轮换先保留旧 active，持久 pending 后才用新凭证激活。激活未知结果保持 pending，以新凭证重试；不能因超时回退旧凭证。申请响应丢失可用旧凭证显式取消，再重新申请。
- 所有网络请求有界、HTTPS、拒绝重定向；错误只输出稳定代码/状态，票据、私钥、配对码和凭证不得进入日志或异常。

## 验证计划

1. 先写真实 JOSE、HTTP 以及故障注入行为测试，看到缺实现失败后实现。
2. 测试安全存储写失败时不能发送、重建宿主恢复、未知心跳重放、错误 ACK、两阶段轮换/激活/取消和凭证期限。
3. 增加实际 Spring HTTP/Nimbus 与 Dart 跨进程注册/恢复/确认/轮换/撤销联调；成人 JWT/MFA 明确作为引导夹具，设备证明与 HTTP 路由使用真实实现。
4. 静态分析/格式/全包回归通过后独立构建验证；按用户授权阶段性提交推送 dev，不混入并行审批包。

## 决策与门槛

Ruling: 安全存储由儿童宿主通过平台 SDK 提供，纯协议层只定义原子 secret record 接口 — 避免在 Dart 文件数据库存私钥或凭证 — 成本是 native 插件仍需单独真机验证。

Ruling: 不把首次 401 当作撤销 — 管理员确认前和凭证失效均可能返回认证错误 — 成本是宿主需展示等待确认/需要监护人检查，而不是自动删除状态。

界面进入实施时使用 12ui-design 和既有 Flutter 设计体系，遵循真实状态与遥控焦点规范。本机 Android SDK 可用、adb 当前没有连接设备；代码/虚拟机联调不能当作真机安全存储、重启恢复或系统阻止应用证据。
