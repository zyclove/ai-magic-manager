# 中国大陆机构合同首发：产品与运营执行手册

> 状态：联调与试点准备；不是对外可销售声明。适用区域仅中国大陆，首选机构签约渠道。更新：2026-10-11。
>
> 系统事实以[合同接口](institution-contract-evidence.md)、[产品目录](commercial-product-catalog.md)、[权益账本](commercial-entitlement-ledger.md)和实际部署版本为准。本手册规定谁在什么证据下推进流程。

## 1. 首发范围与产品承诺

**首发商品单元**为一个经批准的 `CN / CNY / CONTRACT / ORGANIZATION / QUOTE` 报价版本，绑定明确的设备模式、功能集合、基础或加购名额、服务期和客户合同。机构先以代表性真机完成兼容与恢复试点，再确定可签收的功能。报价中软件、EMM/设备、实施、培训、支持和外部服务分别列项；税费口径、金额、付款条件、开票主体由线下正式报价与合同确认，当前目录不存机构合同价格，也不提供线上结算。

系统把四种事实分别呈现：**报价已审核、合同事实已核验、商业权益已入账、设备策略已执行**。任一事实不能代替后一事实。机构权益只决定允许使用相应产品服务，不赋予 Android/TV 系统管理权限。没有受管资格或型号验证的设备只能销售并交付经过实测的有限能力；儿童必要恢复和基础安全不随合同撤销突然失效。

当前没有合格外部合同签发方、Android Enterprise EMM 合作方或 Android Management API 准入。合同提交开关默认关闭，目录 `purchaseAvailable=false`；机构强系统管控、真实签约和收费均处于发布阻断状态。允许在隔离测试环境使用临时签名断言验证连接器，但不能把测试权益或界面状态当作客户交付证明。

## 2. 阶段、责任与出口证据

| 阶段 | 主责与复核 | 必须留下的出口证据 | 系统状态/停止条件 |
|---|---|---|---|
| 商机确认 | 销售；解决方案复核 | 采购主体、目标地区、设备清单、所有权、目标人数/设备数、学校管理责任、数据责任联系人 | 未识别设备模式时仅提供评估，不承诺强控制 |
| 技术试点 | 交付；Android/安全复核 | OS/厂商/型号/受管方式矩阵、应用/时段/网络逐项执行回执、重启/离线/恢复演练、盲区 | 不支持的功能从报价和合同交付项剔除或明确标注 |
| 报价草稿 | 产品运营；财务/法务复核 | 版本化 SKU、容量类型/数量、功能、平台/模式、服务期、成本与税费口径、审批理由 | `DRAFT → IN_REVIEW → APPROVED`；审批与草稿作者分离；仍不可购买 |
| 合同核验 | 合同运营提交；独立审批人复核 | 签发方已确认双方签署的短期 JWS、来源引用/版本、签约主体引用、摘要、服务期、报价对照 | `PENDING_REVIEW → AWAITING_CUSTOMER`；不一致、过期或来源不可核验时驳回 |
| 机构确认 | 当前机构 OWNER/ORG_ADMIN | 本机构采购主体、服务期、名额、功能、设备模式与合同引用再次核对；近期 MFA | `AWAITING_CUSTOMER → APPLIED`；同事务写账本、事件、审计；未确认时零新权益 |
| 部署与签收 | 客户管理员、交付；客户成功复核 | 批次清单、注册和设备身份、策略回执、异常/补救、培训、恢复路径、客户签收 | 只把实际证据为“已应用”的能力记为交付完成 |
| 运营与续约 | 客户成功；财务/安全复核 | 容量占用、合同到期、续约新来源版本、服务事件、支持记录 | 无新签名事实不自动续期；扩容和撤销分别复核 |

客户或销售人员不能通过手工改数据库、上传截图、口头承诺、客户端成功页或伪造设备回执推进任何阶段。平台人员默认不能读取儿童活动；机构只能看到自己合同的业务事实与脱敏时间线。

## 3. 合同工作台操作顺序

1. **报价准备。** 产品运营建立机构合同报价，独立角色审批。审批后仍检查 `purchaseAvailable=false`。正式合同所用报价 ID 和版本必须与签名断言一致；报价改变时创建新版本及重新签发的合同事实，不能用旧版本继续审批。
2. **外部签发。** 合格合同系统在双方签署确认后按需签发短期 RS256 JWS。签发方自行保存原始合同、法定签署与撤销记录；平台仅保留规范化事实、证据引用及 JWS 摘要。JWS 不通过聊天、工单或客户端长期存储。
3. **平台提交。** 合同运营以独立 `contract:manage` 权限、近期 MFA 和固定 UUID 提交。网络结果不明时用同一 UUID 和原断言核对/重试；断言已过期则先查原记录，再由签发方重新签发，禁止改用新 UUID 盲目重复提交。
4. **独立审批。** `contract:approve` 审批人读取合同、当前报价对照和事件时间线，核对来源与签署证据后填写具体理由。提交人与审批人不能相同；版本变化返回 `412` 时重新读取，不能自动覆盖。发现差异可以驳回，不应尝试人工强行开通。
5. **机构确认。** 机构 OWNER/ORG_ADMIN 在自己的工作空间读取脱敏合同事实、报价适用平台/模式、名额、功能与期限；确认时重新认证。服务端复核当前成员身份、报价、合同状态和有效期，然后原子入账。页面显示“商业权益已记录”时仍须查看设备能力和执行回执。
6. **签发方撤销。** 签发方发送更高来源版本的已签名 `REVOKED` 事实，独立审批通过后直接撤销该来源权益，无需等待受影响机构点击同意。客户成功负责通知、解释影响和提供基础保护/设备安全退出路径；当前自动通知与财务对账尚未完成，不得宣称自动闭环。

客户端 OIDC 重新认证仅在原标签保存十分钟内的合同 ID 与拟操作类型，并绑定原操作者、机构和角色。回到工作台后重新读取合同和报价，必须由人再次提交；审核理由和短期签名断言不随跳转保存或自动重放。

## 4. 异常处置与补偿边界

| 异常 | 操作员可见结果 | 恢复与审计要求 |
|---|---|---|
| 签发方未配置、密钥或来源不可核验 | 提交禁用或拒绝 | 保持关闭；由签发方/安全团队完成资格、JWKS 轮换、查询与吊销验收，不开放人工“跳过验签” |
| 报价版本、名额、功能、销售范围或签署窗口变化 | 对照列出差异，批准/确认暂停 | 复核来源，修订报价与合同并重签；服务端写路径再次加锁校验 |
| 采购主体或租户映射不明 | 人工发布阻断 | 核对签约实体、客户授权与机构租户，不凭用户自报名称开通；映射接口尚未交付 |
| 重复提交、来源版本倒退或 `If-Match` 陈旧 | 原结果、409 或 412 | 读取现有合同、事件和账本，沿原请求核对；不得创建第二份相同来源权益 |
| 机构管理员离职、被撤权或换租户 | 确认被拒绝 | 按正式成员/所有者交接流程恢复，不由平台运营代点机构确认 |
| 批量设备离线、无 EMM 或模式不支持 | 权益可有，执行状态仍未知/不支持 | 分批恢复并收设备回执；合同交付项未达成时发补救计划或调整范围 |
| 合同到期、撤销或降低容量 | 来源权益重算 | 预览超额资源、停止新增高阶资源、保持必要恢复与基础规则；财务争议和客户通知单独跟踪 |
| 原始合同、票据或付款争议 | 工作台只显示引用与摘要 | 回签发方/财务系统核对原始记录；平台不以断言摘要当作合同文件摘要 |

客户可看到合同状态、报价对照、服务期限和机构脱敏事件；内部审批理由、操作人、关联请求 ID 仅在有平台合同权限时展示。客服访问诊断须走有范围、有期限的客户授权，不把合同运营权限当成儿童数据访问权限。

## 5. 上线与停止销售门槛

以下各项必须由对应负责人附证据签收；任何“未通过”均保持合同提交关闭、目录不可购买，不在销售材料中写成现货。

| 门槛 | 负责人 | 最低验收证据 | 当前判断 |
|---|---|---|---|
| 经营主体、合同模板、签署/票据/隐私与未成年人告知 | 法务、财务、隐私 | 适用主体批准记录、客户模板、票据与留存责任 | 待外部确认 |
| 合同签发方及采购主体映射 | 商务集成、安全 | 供应商合同、签名算法/JWKS 轮换、重查/吊销、故障演练、主体映射 | 未接入；发布阻断 |
| 受管能力与型号认证 | Android/TV、交付 | 真机模式矩阵、重启/卸载边界、策略回执、恢复演练 | 无 EMM 合作方；强能力阻断 |
| 安全与隐私治理 | 安全、隐私 | 密钥治理、角色分离、租户隔离、审计、保留/删除与事故响应 | 部分实现，需环境验收 |
| 技术容量与恢复 | SRE、DBA | 目标规模压测、MySQL 或经认证 OceanBase、备份恢复、故障切换与发布回滚 | 尚无合同生产容量证据 |
| 真实业务操作验收 | 产品、QA、客户代表 | 真实 IdP 双人审批、合同签发方、机构确认、撤销、浏览器/真机操作与客户签收 | 本地联调通过，真实链路未完成 |
| 支持与服务级别 | 客户成功、SRE | 支持入口、值班与响应演练、外部供应商责任矩阵、试点客户签收 | 待试点与演练 |

试点复盘至少分开报告：合格商机数、兼容性通过率、合同审核耗时、机构确认耗时、设备注册成功率、按设备模式的策略执行率、误限制与恢复成功率、支持工时、每设备月度服务成本和续约风险。指标都要有分母、时间窗与证据来源；不能用“已支付设备数”代替“已受保护设备数”。

## 6. 发布后的配置与回退

部署时 `manager.contract.evidence-enabled` 与 `manager.contract.active-submissions-enabled` 均以 `false` 为安全默认。正式启用需要签发方 HTTPS issuer、专用 audience、HTTPS JWKS、密钥轮换和事故流程；配置由部署管理员审批，不能通过普通管理台临时绕过。先在隔离试点租户验证创建、审批、机构确认、撤销与失败回滚，再逐批开放。集群所有后端副本必须使用一致配置；滚动切换期间先排空仍允许 ACTIVE 的旧副本，才能对外宣布暂停生效。

停止新销售时将 `active-submissions-enabled=false`，会阻止新 ACTIVE 合同提交、已提交 ACTIVE 合同批准以及机构确认，同时允许当前可信签发方继续发送更高来源版本的 REVOKED 事实，经独立审批撤回权益。关闭 `evidence-enabled` 会停止新断言受理，也会阻止已入库待审合同的批准和待机构确认合同的入账，包括待审撤销；已有记录仍可读取或驳回。因此它只适用于签发方不可信等更严重的事故，并须另行启动客户通知、财务核对和应急处置；不能把关闭验签开关当作普通停售。停售不应抹掉已有合同/审计或撤销有效客户的基础保护。对已入账来源的商业纠错使用更高来源版本的受控事实与独立审批；数据库快照恢复后必须重算账本、合同来源版本和设备策略证据，不能用旧页面状态宣布恢复成功。正式备份恢复、真实 MySQL 并发与客户环境回退演练仍是上线前任务。
